## 목표

AgentDeck 앱 경유 세션에서, 저장소의 위험 명령 가드 훅이 `ask`를 낸 도구 호출은 권한 모드(`일반`·`모두 허용`·`자동`·`Bypass`)와 관계없이 승인 카드로 올라오고, 카드에서 명령 전문과 가드가 묻는 사유를 보고 고를 수 있다. 가드가 묻지 않는 호출은 지금처럼 모드대로 지나간다.

## 범위

- **만들 것**: 권한 콜백이 「가드가 물은 호출」을 알아보고 모드와 관계없이 카드로 보내는 처리. 그런 카드는 Bash 명령을 자르지 않고(긴 명령은 접기·펼치기) 가드 사유를 함께 보이며, 「항상 허용」을 내지 않는다(도구 이름 단위로 Bash 전체를 여는 규칙이 가드 질문까지 덮지 않게). 각각의 단위 테스트를 먼저 쓴다.
- **건드릴 곳**: `02_Project/00_Source/main/04_Claude/permission/permissionCoordinator.ts`와 같은 권한 경로의 이벤트 타입(`shared/` 권한 요청 이벤트), 승인 카드 컴포넌트(`renderer/src/03_Agent/` 쪽 카드), 그 테스트(`02_Project/01_TestCode/`). 실측으로 필요가 확인되면 `main/04_Claude/sdkOptions.ts`·`run/claudeAgentRun.ts`의 권한 배선.
- **하지 않을 것**: 가드 훅·`.claude/settings.json` 등 판정 장치 변경, 권한 모드 기본값 변경, 시작·실행 중 모드 매핑의 의미 정리(M05 Backlog 3), Bypass 실행 중 전환의 표시 어긋남, 카드 시각 디자인 개편, PR 60 병합(사용자가 픽스 뒤로 미뤘다).
- **완료조건**
  - G1 보고서 3절의 사례(단일·멀티 × `일반`·`자동`·`Bypass` × 새로 시작·턴 사이·턴 안, 그리고 긴 명령)를 같은 방법(독립 clone + 로컬 bare origin + 임시 userData)으로 다시 돌려, 가드 `ask` 줄이 있는 모든 사례에서 카드가 뜨고 거부하면 bare 저장소에 `master`가 생기지 않는다.
  - 그 카드의 화면 글자(innerText 인용)에 `push`·`master`와 가드 사유가 보이고 「항상 허용」 버튼이 없다.
  - 가드가 묻지 않는 명령(예: `git status`)은 `자동`·`Bypass`에서 카드 없이 실행된다.
  - 구현 문맥 없는 검수자 PASS, 하드 게이트 다섯 종 exit 0, `npm test`는 이 기계 기준(`--testTimeout=30000`, M05 Backlog 57) 실패 0.

실행 단계 일괄 승인 대상 (사용자 「그럼 병합 먼저 하지말고 픽스 진행해줘」)

- 저장소 밖 실험 스크립트로 SDK 호출(작은 모델, 짧은 프롬프트), 독립 clone + 로컬 bare origin + 임시 userData로 앱 실행과 Playwright 조작, 하드 게이트 다섯 종, `npm test`, 하위 에이전트·검수자 기동, 커밋, 작업 브랜치 push, `gh pr create`

실험의 안전 규칙 — G1 goal 문서의 「실험의 안전 규칙」을 그대로 따른다

- 앱과 앱 세션은 독립 clone에서, clone의 `origin`은 로컬 bare 저장소. 임시 `--user-data-dir`. 이 저장소 작업 트리를 앱 세션에 열지 않는다.
- 가드 질문 명령은 허용돼도 해가 없는 것만(`git push origin HEAD:master` → 로컬 bare). `gh pr merge`·`gh api`·브랜치 삭제·보호 설정 변경은 쓰지 않는다. 카드는 허용하지 않고 거부한다.
- 결정적 로그 줄은 검증 기록과 보고에 인용한다. 실험 폴더 삭제가 가드에 막히면 사용자에게 명령을 건넨다.
- 실험이 앱 소스 밖 변경이나 진짜 원격을 요구하면 멈추고 묻는다.
