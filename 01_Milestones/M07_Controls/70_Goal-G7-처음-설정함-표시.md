# M07 G7 — 「처음 설정함」 표시를 앱 데이터 폴더 밖으로 옮긴다

- 마일스톤: M07 사용자 컨트롤 · 작성: 2026-11-18 · 상태: 실행 중 · 검증 강도: 강(권한 판정의 닫힌 실패 경로 변경)
- 작업 브랜치: `feat/m07-g7-setup-marker` — master `4d41cd5e`(PR 72) 위에서 갈랐다. G5·G6 종결 표기와 병합 승인 기록을 함께 싣는다.
- 순서: 로드맵 다음 goal 「병합 버튼」은 사용자의 필수 검사 설정을 기다린다. 이 goal은 그 사이에 한다(Backlog 19, 사용자 결정 「막는다」).

## 목표

G5는 「처음 설정함」 표시 `first-setup.json`을 `controls.json`·`controls-seal.json`과 같은 앱 데이터 폴더에 둔다. 세 파일을 함께 지우거나 폴더째 지우면 앱은 첫 실행으로 보고, 사용자가 꺼 둔 허용 노드를 전부 켬으로 되살린다.
이 goal이 끝나면 표시는 앱 데이터 폴더 밖에 있다. 폴더 안 파일이 모두 사라져도 표시가 남아 있으면 앱은 실행을 열지 않고 패널의 확인을 기다린다.

## 범위

- **만들 것**
  - 표시 거처 — 앱 데이터 폴더의 이웃 폴더 `<폴더 이름>-guard/first-setup.json`(Windows 설치본이면 `%APPDATA%/agentdeck-guard/`). 경로는 앱 데이터 폴더에서 유도하므로 임시 userData 테스트에서도 같은 규칙으로 돈다.
  - `controlsStore.ts`가 표시를 새 거처에서 읽고 쓴다. 판정 규칙은 G5 그대로다 — 표시가 있고 두 파일이 모두 없으면 `mismatch`.
  - 옛 표시(`userData/first-setup.json`)가 있으면 새 거처로 옮겨 적는다. 옛 파일은 지우지 않는다.
  - 새 거처를 앱 세션 잠금(Edit 거부 규칙과 Bash 잠금)에 더한다.
- **건드릴 곳**: `02_Project/00_Source/main/04_Claude/permission/`(`controlsStore.ts`·`enginePathLock.ts`), 필요하면 `main/02_Common/`, `02_Project/01_TestCode/` 미러, 이 goal 문서, `M07_Controls/01_Work_Pin.md`·`99_Backlog.md`·G5·G6 문서(종결 표기), `98_Management/01_GateState/gate-config.json`의 `planPath`(1단계).
- **하지 않을 것**
  - L1을 넘는 보호. 표시도 사용자 권한으로 지울 수 있다. 에이전트가 표시까지 찾아 지우는 경우는 잠금(L3)이 실수만 막는다.
  - `controls.json`·봉인 파일의 거처 변경.
  - 패널 화면 변경.
- **완료조건**
  - 단위 테스트가 고정한다: 앱 데이터 폴더의 세 파일을 모두 지워도 새 거처에 표시가 있으면 `mismatch`다. 표시가 없고 두 파일도 없으면 `none`이다. 옛 표시는 새 거처로 옮겨진다. 새 거처를 쓰는 Bash 명령과 파일 편집이 앱 세션에서 거부된다.
  - 하드 게이트 다섯 종 exit 0, `npm test` 실패 0, PR의 `hard-gates` 통과.
  - 이 브랜치 빌드본의 실제 앱(임시 userData)에서, 노드를 끈 뒤 앱 데이터 폴더의 세 파일을 지우고 보내면 실행이 거절되고 패널에 경고가 뜬다.
  - 구현 문맥 없는 검수자 1회의 지적이 반영되거나 Backlog로 넘어가 있다.
