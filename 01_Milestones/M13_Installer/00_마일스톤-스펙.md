## 목표

Windows 설치 파일 하나로 앱을 깔고, 처음 켤 때 GitHub 계정을 앱 안에서 잇고, 앱이 비공개 릴리스 저장소의 새 Release를 감지해 무결성을 확인한 뒤 스스로 업데이트한다. 그 설치본만으로 이 저장소 밖의 새 프로젝트 하나에서 마일스톤 하나를 완주한다(v1 완료선).

## 범위

- **만들 것**
  - 패키징 — electron-builder로 NSIS 설치 파일(`.exe`) 하나. `productName`, 앱 ID, 버전 표시(M06 Backlog 6), zod 의존성 명시(M10 Backlog 10), 실행 트리와 작업 트리 분리(M07 Backlog 2). 게시자 서명은 하지 않는다(비전).
  - GitHub 기기 인증 — 앱이 GitHub 기기 인증을 직접 한다(3회차 4번). OAuth App의 클라이언트 ID는 앱 설정에 넣는다(비밀 값이 아니다). 받은 토큰은 Windows 자격 보호(`safeStorage`)로 저장하고, 화면에 다시 보이지 않는다.
  - 자격의 쓰임 — 그 토큰으로 Release를 읽고, 앱의 GitHub 읽기(PR 카드)와 실행기의 원격 동작(`GH_TOKEN`으로 gh·git에 넘김)을 한다. 노드 세션에는 지금처럼 자격을 넘기지 않는다(제안). gh CLI는 실행기의 도구로 계속 쓰고, 첫 실행 안내가 설치 여부를 확인한다(제안 — gh를 REST 호출로 바꾸는 일은 범위 밖).
  - 첫 실행 안내 — 설명서 없이 Claude 로그인 확인, GitHub 기기 인증, gh 확인, 프로젝트 열기, 헌장·Taste 문답(M12), 첫 마일스톤 시작까지 이어진다(비전 「완성형의 최소선」).
  - 자동 업데이트 — 비공개 저장소의 Release를 쓰는 사람의 토큰으로 읽어 새 버전을 감지하고(수단은 electron-updater의 GitHub 공급자가 첫 후보다 — 수단을 바꾸는 것은 범위 변경이 아니다), 내려받은 파일의 sha512를 Release의 `latest.yml`과 대조한 뒤 설치한다. 협업자가 아니면 읽기가 거부되고 앱은 「업데이트를 받을 권한이 없어요」로 안내한다.
  - 릴리스 저장소 — 비공개 릴리스 전용 저장소(제안 이름 `bass131/AgentDeck-Releases`)에 Release를 둔다(3회차 3번). 소스 저장소는 공개 그대로다.
  - 릴리스 후보 — 에이전트가 설치 파일과 `latest.yml`을 빌드하고 릴리스 노트 초안을 쓴다. 게시는 사람이 한다(헌법 10조). 첫 Release는 `v0.2.0`, 업데이트 실측용 둘째는 `v0.2.1`(제안).
- **건드릴 곳**
  - 판정 장치: `98_Management/01_GateState/gate-config.json`(`planPath`·`workPinPath`), `package.json`의 `scripts`(설치본 빌드 명령 — M11에서 3조 보호 표면이 됨).
  - `package.json`(의존성 `electron-builder`·`electron-updater`·`zod`, 빌드 설정), `electron-builder` 설정 파일, `02_Project/00_Source/`, `02_Project/01_TestCode/`, `01_Milestones/M13_Installer/`, `01_Milestones/00_Roadmap.md`, `README.md`(설치 안내).
- **하지 않을 것**
  - 게시자 서명, macOS·Linux 설치본, 공개 Release, 저장소 비공개 전환(비전).
  - gh CLI를 걷어내는 일, 팀원 연결.
  - Release 게시, 저장소 만들기, OAuth App 등록(사람 몫).
- **완료조건**
  - 설치 파일로 이 PC에 깔고, 개발 서버 없이 뜨고, 작업 트리와 다른 실행 트리에서 돈다(goal 1, 실측).
  - 기기 인증이 시험 서버로 끝까지 돌고, 실제 GitHub에서 사용자 승인 한 번으로 토큰이 저장된다(실제 쪽은 goal 6).
  - 업데이트 — 로컬 업데이트 피드로 감지·내려받기·무결성 불일치 거부·설치를 실측한다(goal 4). 실제 비공개 Release `v0.2.0` → `v0.2.1` 업데이트를 실측한다(goal 6, 게시는 사람).
  - v1 완료선 — 새 프로젝트 저장소에서 설치본만으로 마일스톤 하나를 완주하고, 사람 개입(헌장·Taste 문답, 브레인스토밍 승인, 마일스톤 병합)과 예외 호출의 횟수와 이유를 기록한다(goal 6). 이 실측의 사람 몫은 사용자가 직접 한다(제안 — 완료선이 사람 개입을 세는 시험이다).
  - 마일스톤 회귀 검증 `PASS` 줄이 아래 검증 기록에 있다.
