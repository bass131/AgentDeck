# Dawnholder 현황판 대비 점검

M05 H5에서 썼다(2026-11-15). 구현하지 않고 목록과 추천만 남긴다.

## 평문 개요

Dawnholder 현황판은 여러 파트(리드·작업자 여럿)를 한 화면에서 지휘하는 도구라서, 보기 다섯 종과 결정 응답, 깨움 도구까지 갖췄다.
AgentDeck 현황판은 메인 세션 하나가 goal 한 장을 끝까지 미는 루프를 **읽기만** 하는 화면이다. 그래서 기능 수를 맞추는 것이 목표가 아니다.
들여올 가치가 큰 것은 「사람이 손으로 고치는 문서가 실제와 어긋났을 때 알려 주는 것」과 「PR처럼 저장소 밖에서 끝난 일을 알아보는 것」이다.
쓰기가 필요한 기능(결정 응답, 깨움, 계획 검토)은 읽기 전용 보장과 맞지 않아 들이지 않는다.

### 추천 상위 3개

1. **PR 상태 읽기** — `gh pr view`를 읽기 전용으로 불러, 「병합 대기」 항목의 PR이 병합되면 「병합됨, goal 문서 갱신만 남음」으로 바꾸고 CI 실패는 빨강으로 보인다. 지금은 병합 뒤에도 goal 문서를 고칠 때까지 「병합을 승인해 주세요」가 남는다.
2. **진척 표시 낡음 알림** — Dawnholder 「갱신 필요」처럼, goal 문서를 마지막으로 고친 뒤 커밋이나 검증 기록이 더 쌓였는데 `[>]` 표시가 그대로면 「진척 표시가 낡았을 수 있어요」를 사실 줄로 보인다. 진척 단계 표시는 사람이 손으로 옮긴다.
3. **Orca 워커 보고 소식** — `orca orchestration inbox`를 읽음 표시를 바꾸지 않고 읽어, 메인에게 온 `worker_done`·`escalation`·`question`을 최근 소식 몇 줄로 보인다. 이번 H5처럼 보조 세션이 보고를 보내도 지금 화면에는 흔적이 없다.

세 항목은 `01_Milestones/M05_Structure/99_Backlog.md` 61~63번에 한 줄씩 있다.

## 들이지 않는 것과 이유

- **쓰기 경로** — (H7에서 결정 응답(2)은 사용자 요청으로 들였다. 아래는 H5 당시의 판단이고, 깨움·계획 검토에는 그대로다.) 결정 응답(2), 깨움(11·12), 계획 검토(18)는 모두 터미널이나 파일에 쓴다. AgentDeck 현황판은 GET·HEAD만 받고 쓰기 API가 0이라는 보장을 README에 걸었다. 이 보장을 깨는 대신 에이전트의 `PushNotification`과 대화가 그 일을 맡는다(H4 결정 대장).
- **여러 파트 전제** — 보기 다섯 종(1), 상태판(7), 파트 표(17)는 파트가 여럿일 때 값이 있다. 메인 하나에서는 화면만 늘린다.
- **판정 장치를 건드리는 원천** — 사용량 목표선(8)의 Claude 값은 statusline 로그를 쓰는 쪽이 있어야 한다. 그 설정은 `.claude/` 아래라 계획에 명시된 Step으로만 고친다(헌법 3조).

## 추천 항목의 구현 메모

구현은 하지 않는다. 다음 goal을 쓸 때 출발점으로만 쓴다.

- **PR 상태 읽기** — `lib/git.mjs`의 허용 목록처럼 `gh pr view <번호> --json state,mergedAt,statusCheckRollup`만 셸 없이 부른다. 호출은 「병합 대기」 항목이 있을 때만, 60초 간격으로 한다. `gh`가 없거나 인증이 없으면 그 블록만 「미확인」이다. 병합되면 `judgeHand`의 병합 항목 문구만 바뀌고 알림 키는 그대로라 다시 울리지 않는다.
- **진척 표시 낡음** — goal 문서의 마지막 커밋 시각(`git log -1 -- <goal 경로>`)과, 그 뒤의 커밋 수·검증 기록 줄 수를 비교한다. 값은 원문에서만 오고, 표시는 노랑 세모 사실 줄이다. 알림음 대상이 아니다.
- **Orca 워커 보고** — Dawnholder는 `orchestration inbox`를 읽음 표시를 바꾸지 않고 최근 200건 읽는다. 같은 명령을 허용 목록에 두고, 메인 handle로 온 것만 최근 5건 보인다. 메인 handle을 정하는 규칙이 필요하고, 그것이 가장 어려운 부분이다(Dawnholder 웹 README 「설정」).

## 확인하지 못한 것

- Dawnholder 화면을 실제로 띄워 보지 않았다. 표의 내용은 문서와 파일 목록에서 읽은 것이다.
- Dawnholder README 1041줄 가운데 표에 쓴 절의 머리 부분만 읽었다. 세부 동작(깨움 판정 갈래, 사용량 계산식)은 표에 옮기지 않았다.
