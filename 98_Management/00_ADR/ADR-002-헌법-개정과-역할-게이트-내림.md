# ADR-002 — 헌법 2·3·9조 개정과 역할 게이트 내림

- 상태: 채택 · 날짜: 2026-11-11 · 마일스톤: M03 Harness Refresh Phase 4
- 맥락 문서: `01_Milestones/M03_Harness_Refresh/_MilestonePreview.md` (결정 대장), `00_분류표.md` (근거 사실), `04_헌법-개정-문안.md` (집행 문면)
- 판정 근거: M03 결정 대장 [USER] 2026-11-11 — 계획 승인 문답 안건 1(완화 방향의 직접 확인)과 안건 3·4·5·6(추천안 채택)

## 배경

M01·M02에서 세운 하네스는 두 종류의 장치를 함께 품고 있었습니다.
하나는 「누가, 어떤 세션에서 일하는가」를 묶는 분업 강제입니다. 헌법 2조의 `--resume` 금지와 Phase 경계마다 새 워커 세션, 헌법 3조의 메인 세션 편집 범위 제한, 그것을 집행하는 역할 게이트(`30_role-gate.cjs`)가 여기에 속합니다.
다른 하나는 「검증과 완료가 근거에 연결됐는가」를 지키는 게이트입니다. 검증 기록 줄, 실패 카운터, 마감 요약 게이트, 위험 명령 가드가 여기에 속합니다.

2026-09-18 합의는 둘을 갈랐습니다.
구현 방법과 분업은 메인 에이전트가 판단하고, 필수 검증과 완료 처리는 프로그램으로 관리한다는 방향입니다.
2026-11-10 결정은 그 방향을 이 저장소에 적용해 분업 강제를 완화하고 검증·완료 게이트는 유지하기로 했습니다.
사용자는 2026-11-11 계획 승인 문답에서 이 방향을 직접 확인했습니다(안건 1 「맞아」).

이 문서는 그 방향을 헌법 문면과 훅 배선으로 옮기면서 내린 되돌리기 어려운 선택 넷과, 고르지 않은 쪽을 버린 이유를 남깁니다.

## 근거 사실 — 분업 강제는 이미 집행되지 않았다

완화의 근거는 선호가 아니라 실측입니다. `00_분류표.md` 「근거 사실」 절의 F1 두 건이 그것이고, Phase 4 워커가 hook-log 원문과 다시 대조했습니다.

| 표지 | 사실 | 실물 |
|---|---|---|
| F1 · 2조 | `--resume` 기동 기록 세 줄이 전부 경고만 받고 진행했다. SessionStart 훅은 기동을 막을 수 없다 | hook-log 1484·1485·1486줄 — `hook: start-brief`, `source: resume`, `verdict: allow` (2026-08-11·2026-08-25, 세션 eaa74de0) |
| F1 · 3조 | fork 하위 에이전트의 Write를 역할 게이트가 워커로 판정해 허용했다 | hook-log 1494줄 — `roleSignal: input:agent_id=aa3754689d130ba05 · agent_type=fork`, `rule: 워커-허용` (2026-11-10) |

2조는 훅이 막을 수 없는 자리의 금지였고, 3조는 메인 대화를 통째로 물려받는 fork가 통과하는 금지였습니다.
집행되지 않는 규칙은 지키는 쪽에만 비용을 지웁니다.

## 결정 1 — 2조는 삭제하지 않고 「재개의 정본은 생존 문서」로 낮춘다

`--resume` 금지와 Phase 경계마다 새 세션 의무를 뺍니다. 언제 새 세션을 열지는 메인 세션이 판단합니다.
의무로 남는 것은 둘입니다. 재개의 정본이 생존 문서 네 종이라는 것, 그리고 통과 여부를 기억이 아니라 검증 기록 줄에서 다시 읽는다는 것입니다.
현행 2조의 목적이던 확증편향 차단은 마감 검수 한 자리에만 남깁니다 — 마감 검수는 구현 문맥을 물려받지 않은 에이전트가 하고, fork는 검수자로 쓰지 않습니다.

대안은 2조 삭제였습니다.
1조·4조와 기동 훅이 「문서로 재개한다」를 전제하므로 그 근거 문장이 헌법에서 사라지면 전제가 고아가 됩니다.
조항 번호는 M01·M02의 결정 대장과 훅 주석이 번호로 참조하므로, 자리를 비우는 것보다 내용을 바꾸는 편이 참조를 끊지 않습니다(안건 3).

## 결정 2 — 3조는 「보호 표면」 조항으로 바꾼다

누가 편집하는가는 제한하지 않습니다. 직접 구현할지 하위 에이전트에 맡길지는 메인 세션이 판단합니다.
대신 판정 장치 — `.claude/hooks/`, `.claude/settings.json`, `98_Management/01_GateState/`, 두 헌법 파일 — 는 계획 문서에 명시된 Step으로만 편집합니다.
근거는 2026-09-18 합의의 권한 분리 조건입니다. 에이전트가 검증 정책과 완료 기록을 계획 밖에서 바꿀 수 있으면 검사를 통과했다는 사실이 아무것도 보증하지 못합니다.

보호 표면 부분은 기계로 막지 않습니다.
「계획에 명시됐는가」는 기계가 판정할 수 없고, 새는 사례가 관측되지 않은 자리에 강제를 미리 더하지 않는다는 판단입니다. 사후 감사 표면은 git diff입니다.

대안은 3조 삭제였습니다. 판정 장치를 계획 밖에서 고치는 것을 막는 문장이 헌법에서 사라지므로 버렸습니다(안건 4).

## 결정 3 — 계획 게이트를 스폰 자리에서 편집 경로로 옮기고, 역할 게이트를 내린다

스폰 게이트(`20_plan-gate.cjs`)의 판정 ①(계획 규격)·②(실패 카운터)·③(결정 대장 주도권)은 M03 Phase 2에서 편집 경로 게이트(`31_edit-plan-gate.cjs`)로 옮겨 올렸습니다.
`01_Milestones` 밖 편집마다 발화하고, 역할은 읽지 않습니다 — 메인이 직접 고쳐도 어떤 경로로 뜬 하위 에이전트가 고쳐도 같은 판정을 받습니다.
판정 ④(라우팅)는 분업 규격이라 차단에서 빼고 로그 필드로만 남겼습니다.
이 이동이 3조 완화 뒤에도 7조(FAIL 세 번이면 멈춤)를 기계로 집행하게 합니다. 유지 대장 AD-02의 확정 수리 방안(안 B)을 모든 편집 주체로 넓힌 것이기도 합니다.

Phase 4는 남은 두 배선을 함께 내립니다 — 편집 도구 자리의 `30_role-gate.cjs`와 스폰 자리(`^(Task|Agent)$`)의 `20_plan-gate.cjs`입니다.
역할 게이트는 폐기 대상이라 fork 통과를 수리하지 않고, 배선·smoke 테스트 케이스 다섯 건·파일을 함께 내립니다. 배선만 내리면 죽은 코드와 그것을 검사하는 테스트가 남습니다.
`20_plan-gate.cjs` 파일은 판정부를 `_lib/plan-verdict.cjs`와 공유하고 테스트가 직접 구동하므로 남깁니다. 내리는 것은 스폰 자리의 배선뿐입니다.

순서가 안전장치였습니다. 새 게이트를 먼저 올리고(Phase 2), 구멍을 닫고(Phase 2·3), 역할 게이트는 하네스 편집 전체의 마지막에 내립니다.
역할 게이트를 먼저 내렸다면 나머지 하네스 수정이 작성자와 검수자의 분리 없이 진행됐을 것입니다.

대안은 스폰 게이트를 현 자리에 두는 것이었습니다. 3조를 완화한 뒤에는 메인이 스폰 없이 직접 고치는 경로에 7조의 기계 집행이 없어, 게이트가 위임에만 비용을 지우게 되므로 버렸습니다(안건 5).

## 결정 4 — 9조는 대상을 바꿔 「게이트 해제 수단은 사용자 전용」으로 남긴다

역할 게이트가 내려가면 `MOODIE_SESSION_ROLE`이 여는 것이 없습니다. 이 변수를 읽던 분기는 `40_pass-watcher.cjs`와 테스트 헬퍼·픽스처에서 함께 정리합니다. pass-watcher의 `role` 로그 필드는 훅 입력의 `agent_id` 유무만으로 채웁니다.
9조의 취지 — 탈출구는 사용자 전용 — 는 지금 실재하는 해제 수단 둘로 옮깁니다. 마감 요약 게이트를 푸는 `node .claude/hooks/50_stop-gate.cjs release`와, 상태 저장의 잠금을 끄는 테스트 전용 환경변수 `AGENTDECK_STATE_SEAM`입니다.
`release`는 허용 목록의 `Bash(node *)`로 실행 가능한 실물이라 규범 없이는 열려 있습니다.

대안은 9조 폐기였습니다. 실행 가능한 해제 수단이 규범 밖에 남으므로 버렸습니다(안건 6).

## 결과

헌법 2·3·9조가 `04_헌법-개정-문안.md`의 승인 문안으로 두 헌법 파일에 같게 바뀌고, 조항 번호 1~10은 그대로입니다.
기동 훅의 resume 문구는 위반 경고에서 「통과 여부는 검증 기록 줄에서 다시 읽어라」는 안내로 바뀝니다. 생존 문서 네 종 확인과 시각·pin 주입은 그대로입니다.
`settings.json`에서 역할 게이트와 스폰 자리 계획 게이트의 배선이 빠지고, 편집 경로 게이트·위험 명령 가드·TDD 가드·자동 장전·250줄·Stop 훅은 남습니다.
`30_role-gate.cjs` 파일의 삭제는 사용자가 직접 실행합니다(M02 [USER] 안건 6 선례).

남는 한계는 셋입니다.
Bash 경유 쓰기는 여전히 편집 도구 훅 밖입니다(8조, ADR-001 결정 3).
보호 표면은 규범이라 계획 밖 편집을 사전에 막지 못하고 git diff로만 사후 감사됩니다.
내림의 효과 — 메인 세션 편집에 역할 게이트 줄이 없고 계획 부재 시 편집 경로 게이트가 거부한다는 것 — 는 이 문서가 아니라 Phase 4 Step 7의 hook-log 실측으로만 판정합니다.
