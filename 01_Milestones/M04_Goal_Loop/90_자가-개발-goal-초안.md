## 조사 결과 (2026-11-13, 읽기 전용 · 코드 판독만, 앱 실행 없음)

조사는 구현 문맥 없는 하위 에이전트가 했다. 경로는 `02_Project/00_Source/` 기준이다. 아래는 그 보고의 요약이며 실행으로 확인한 항목은 없다.

완료선을 끊는 배선 결손은 코드상 찾지 못했다. Claude 백엔드 경로에는 세션 기동, 승인 카드, 질문 모달, Bash 실행, 지속·재개·중단이 다 있다.

막는 것

1. **앱의 기본 권한 모드가 승인 게이트를 지운다** (규모 중). 단일 패널 기본은 `auto`, 멀티 패널 기본은 `bypass`다 (`renderer/src/lib/pickerOptions.ts:87-88`). 두 모드에서 앱의 승인 콜백은 모든 도구를 묻지 않고 허용한다 (`main/01_agents/permissionCoordinator.ts:130-132`). 가드의 `ask`가 이 콜백으로 넘어오면 자동 허용될 것으로 추정된다. 그러면 헌법 10조의 병합 승인이 앱 경유로는 지켜지지 않는다. `normal` 모드의 「항상 허용」도 도구 이름 단위라 Bash 전체가 열린다 (`permissionCoordinator.ts:190-197`).
2. **모델 목록이 옛 세대다** (규모 소). `shared/knownModels.ts:1-11`은 `claude-opus-5`·`claude-fable-5`·`claude-sonnet-5`·`claude-haiku-4-5`·`claude-opus-4-8`만 안다. 목록 밖 ID는 버려지고 전환도 거부된다 (`main/01_agents/runArgs.ts:54-55`, `:71-79`). 옛 ID가 아직 호출되는지는 확인하지 못했다. 같이 고칠 곳은 `shared/modelEffort.ts`, `shared/ipc/agent.ts`, `pickerOptions.ts`다.

불편하지만 막지는 않는 것

- Codex 백엔드는 stub이다 (`main/01_agents/CodexBackend.ts:24-37`). 완료선은 Claude만으로 닿는다.
- 승인 카드가 Bash 명령을 80자로 잘라 보여 준다 (`permissionCoordinator.ts:68`). 긴 `gh pr merge` 명령의 전문을 못 보고 승인하게 된다.
- PR 생성 전용 UI가 없다. 에이전트가 Bash로 `gh`를 돌려야 한다.
- 배포 도구가 없다. `package.json`에 `package` 스크립트가 없어 `npm run dev`로 띄워 써야 한다.
- SDK는 선언과 설치가 `0.3.201`로 일치한다. 최신인지는 조회하지 않았다. 코드의 폴백 상수는 `0.3.186`이다 (`main/01_agents/ClaudeCodeBackend.ts:14`).

실행해야 알 수 있는 것

- 앱이 지금 실제로 뜨고 로그인 자격으로 세션이 붙는지.
- `auto`·`bypass`에서 가드의 `ask`가 실제로 어떻게 처리되는지 (1번의 핵심).
- 이 저장소의 훅(기동 시각 주입, 마감 요약 게이트, 편집 계획 게이트)이 앱 경유 세션에서 CLI와 똑같이 발화하는지. 설정 출처 구성(`main/01_agents/sdkOptions.ts:97-119`)은 그렇게 돼 있다.
- 자기 자신을 고칠 때의 위험 — dev로 띄운 채 renderer 소스를 고치면 리로드로 진행 중인 화면 상태가 날아가는지, 하드 게이트의 `npm run build`가 실행 중인 앱의 `out/`을 덮어써도 되는지.
- 앱을 껐다 켠 뒤 긴 작업이 온전히 이어지는지.

## 범위 (안)

- **만들 것**: 앱 경유 세션에서 병합 승인이 사람에게 올라오는 권한 처리, 현행 모델 ID 목록, 자기 저장소를 고칠 때의 안전한 실행 방식(작업 트리 분리 등은 실측 뒤 결정), 승인 카드의 명령 전문 표시.
- **건드릴 곳**: `02_Project/00_Source/`의 권한 조정기·모델 목록·승인 카드와 그 테스트. 구조 재편 뒤라 경로는 달라질 수 있다.
- **하지 않을 것**: Codex 백엔드 구현, 배포·설치본 제작, PR 전용 UI.
- **완료조건**: 앱 안에서 이 저장소의 약 등급 goal 하나를 합의부터 PR 생성까지 끝내고, 그 세션의 hook-log에 승인 질의가 `gh pr merge` 한 건뿐이며 그 질의에 앱 화면에서 답했음을 확인한다.

## 첫 단계 (안)

앱 코드를 고치기 전에 「실행해야 알 수 있는 것」 다섯 가지를 실측한다. 막는 것 1번의 규모는 그 결과로 정해진다.
