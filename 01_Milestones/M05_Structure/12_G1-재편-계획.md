# M05 G1 재편 계획 — 도메인 기준과 G2 이후 goal

- 작성: 2026-11-13 · 소유: `10_Goal-G1-구조-감사.md` · 근거: `11_G1-감사-보고서.md` · 이동 맵: `13_G1-이동-맵.md`
- 이 계획은 G2 이후 goal 한 장의 출발점이다. 각 goal은 착수 때 이 절을 복사해 goal 문서로 쓰고, 실측으로 범위를 좁힌다. 범위를 넓혀야 하면 로드맵 규칙대로 멈추고 묻는다.

## 재편 원칙

1. **프로세스 폴더 안에 도메인 폴더를 둔다.** `main/NN_Domain/`, `renderer/src/NN_Domain/`, `shared/NN_Domain/`이다. 세 트리는 도메인 번호와 이름을 똑같이 쓴다. 한 트리에 없는 도메인은 그 트리에서 비워 둔다.
   이유: renderer는 샌드박스, main은 Node라는 경계가 폴더로 보여야 하고, tsconfig 두 벌이 프로세스 폴더 글롭으로 나뉘어 있다. 도메인 우선 배치도 빌드는 되지만 이 둘을 다시 짜야 한다(감사 보고서 5절).
2. **빌드 진입점 셋은 옮기지 않는다.** `main/index.ts`, `preload/index.ts`, `renderer/index.html`(과 `src/main.tsx`)이다. 옮기지 않으면 빌드 설정은 별칭 추가만 필요하다.
3. **테스트 루트 `02_Project/01_TestCode/`는 유지한다.** 배치는 `01_TestCode/<main|renderer|shared>/NN_Domain/`로 소스를 비춘다. TDD 가드의 테스트 경로 고정(`33_tdd-guard.cjs:31`)과 `collection-baseline.test.ts`의 위치 기준을 건드리지 않기 위해서다.
4. **이동과 동작 변경을 한 goal에 섞지 않는다.** 이동 goal은 내용 무변경 `git mv` 커밋과 import 수정 커밋으로만 이뤄진다. 중복 통합·계약 변경은 이동이 끝난 뒤의 별도 goal이다.
5. **추상화는 확인된 중복에서만 만든다**(사용자 성향 27). 감사가 위치 쌍으로 확인한 중복만 통합 대상이다.
6. **프리픽스는 `NN_Xx`(숫자, 언더스코어, 대문자 시작)다**(사용자 성향 8). 도메인 폴더 이름에만 적용하고, 도메인 안의 파일 이름은 바꾸지 않는다.

## 도메인 (세 트리 공통)

| 도메인 | 정의 |
|---|---|
| `00_App` | 프로세스 부팅과 의존 조립(composition root)만 한다. renderer는 최상위 store 조립을 함께 둔다. |
| `01_Ipc` | 채널 등록·핸들러·공통 입력 검증(main), 채널 묶음(shared), `window.api` 클라이언트(renderer, G10에서 신설)다. 핸들러는 입력을 검증해 도메인 함수로 넘기기만 하고, 도메인 로직은 두지 않는다(G5 개정, 사용자 판정 2026-11-14). |
| `02_Common` | 도메인을 모르는 공용 부품이다. main은 확인된 중복 유틸, renderer는 공용 컴포넌트와 테마, shared는 기본형(`BackendId`, `DiffLine`)이다. |
| `03_Agent` | 백엔드 중립 에이전트 실행이다. 실행 요청·중단·모드 전환·권한·질문 응답, 이벤트 계약, 실행 상태, sub-agent·orchestration 표시를 맡는다. |
| `04_Claude` | Claude SDK 어댑터다(main 전용). 실행 pump, 스트림 정규화, 권한 조정, SDK 옵션을 맡는다. |
| `05_Conversation` | 한 대화 안의 스레드다. 스레드 모델(reducer)과 렌더, 입력창, 입력 팔레트를 맡는다. |
| `06_Sessions` | 대화와 멀티 세션의 목록과 영속이다. |
| `07_Workspace` | 작업 폴더·참조 폴더, 파일 읽기·목록·첨부, 뷰어와 diff 표시다. |
| `08_Git` | 저장소 상태·로그·커밋·diff 계산과 git 화면이다. |
| `09_Lsp` | 언어 서버 수명주기와 JSON-RPC다. renderer의 LSP 표시는 뷰어 안에 있어 `07_Workspace`에 둔다. |
| `10_Engine` | 엔진·앱 설치와 업데이트, 계정 사용량, What's New다. |
| `11_Settings` | 스킬·MCP·슬래시 명령 설정, 프로필, UI 환경설정, 테마 선택이다. |
| `12_Window` | 프레임 없는 창 제어·기하·줌·단축키와 화면 배치(단일 Shell, 멀티 그리드)다. |

`10_Engine`과 `11_Settings`의 main 구현은 지금 Claude 전용이다(감사 보고서 1절 3번). Codex 백엔드가 stub인 동안은 나누지 않는다 — 드러나지 않은 문제는 방어하지 않는다는 성향 25를 따른다. Codex를 붙이는 goal이 그 분리를 맡는다(Backlog).

## G2 이후 goal 목록

순서는 의존 순서다. 각 goal은 하드 게이트 다섯 종과 `npm test` 실패 0으로 독립 병합된다.

### G2 — 이동 기반 (별칭, 타입 검사 사각지대, 경계 규칙) · 강
- 만들 것: 별칭 `@main`·`@renderer`·`@shared`·`@preload`를 tsconfig 두 벌, electron-vite(main·preload·renderer), vitest에 같은 값으로 둔다. e2e·integration·hooks·`_lib` 테스트를 타입 검사 대상에 넣는다. eslint `no-restricted-imports`로 renderer→main, shared→main·renderer, main→renderer import를 막는다.
- 건드릴 곳: `tsconfig*.json`, `electron.vite.config.ts`, `vitest.config.ts`, `.eslintrc.cjs`, 사각지대 테스트의 타입 오류.
- 하지 않을 것: 파일 이동, import 경로의 일괄 교체, vitest include 글롭 문자열(baseline이 고정한다).
- 완료조건: 별칭 import 하나가 dev·build·vitest에서 모두 풀린다. 금지 방향 import를 넣은 확인용 파일에 lint가 실패한다(확인 뒤 삭제). 하드 게이트와 `npm test`가 통과한다.

### G3 — 죽은 코드와 복제 검사 테스트 정리 · 강

- 건드릴 곳: 해당 소스와 테스트, `collection-baseline.test.ts`의 개수.
- 하지 않을 것: 안 쓰는 채널 3개의 제거(계약 변경은 G10), 동작 변경.
- 완료조건: 감사 보고서의 죽은 코드 목록이 전부 사라지고, 바뀐 테스트가 실물 모듈을 import한다.

## 공통 위험과 대응

- **테스트의 경로 문자열 1,247건과 `vi.mock`.** 이동 goal마다 옮긴 파일을 가리키는 경로를 전수 검색해 고친다. `vi.mock`은 타입체크가 못 보므로 해당 테스트를 실행해 mock이 걸렸는지 확인한다.
- **헌법 8조 — 파일 이동은 계획에 명시되고 승인된 `git mv`만 된다.** 이 계획의 이동 맵이 「계획에 명시된 이동」이다. G1 PR의 병합 승인이 이동 맵의 계획 승인을 겸한다고 본다(결정 대장 `[AI]` 줄, PR 본문에 명시). 각 goal은 이동 맵의 행만 옮기고, 맵에 없는 이동이 필요하면 맵을 고치는 커밋을 먼저 남긴다.
- **TDD 가드.** 소스 import 수정이 테스트 편집 없이 세 번 이어지면 막힌다. 소스와 테스트의 import 수정을 번갈아 한다.
- **CSS가 전역이다.** 이동으로 import 순서가 바뀌면 충돌 규칙(`@keyframes rise` 등)의 승자가 바뀐다. G7·G8은 화면을 띄워 확인한다.
- **판정 장치의 경로 문자열.** 훅 테스트가 `main/index.ts`를 문자열로 쓴다. 진입점을 옮기지 않으므로 건드리지 않는다.
