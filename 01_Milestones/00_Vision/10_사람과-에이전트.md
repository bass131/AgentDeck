# 사람과 에이전트의 경계

- 상태: 초안 · [개요](00_개요.md)

## 사람의 몫

| 언제 | 사람이 하는 일 | 결과물 |
|---|---|---|
| 처음 한 번 | 전역 Taste를 세운다 | 전역 Taste 스펙 |
| 프로젝트를 열 때 | 궁극 목표·기획·작업 영역·프로젝트 Taste를 세운다 | 프로젝트 헌장(목표 + 프로젝트 Taste) |
| 마일스톤마다 | 메인 세션과 브레인스토밍해 방향을 합의한다 | 마일스톤 스펙 한 장 |
| 마일스톤 끝 | 보고를 읽고 `master` 병합 버튼을 누른다 | 병합 |
| 예외가 왔을 때 | 결정하거나 방향을 고친다 | 답 |
| 원할 때 | 작업 그래프를 직접 고치거나, 에이전트와 논의해 고치게 한다 | 바뀐 그래프 |

되돌리기 어려운 행위는 언제나 사람 몫이다 — 릴리스, 패키지 배포, GitHub 보호 설정 변경, 강제 push.

## 에이전트의 몫

- 마일스톤 스펙을 goal로 나눈다.
- goal마다 구현하고, 검증하고, PR을 만들고, 검사를 통과하면 마일스톤 브랜치에 스스로 병합한다.
- 문서화와 현황판 갱신을 한다. 사람이 「무엇이 개발됐고 전체 시스템이 지금 어떤지」를 언제든 볼 수 있어야 한다.
- 운영을 한다 — Backlog 정리, 기존 실패 수리, 의존성 업데이트, CI 관리.
- 다음 마일스톤을 스스로 시작하지 않는다. 마일스톤 사이의 운영은 사람이 정한 범위 안에서만 한다.

## 사람을 부르는 사건

| 사건 | 급함 | 그동안 에이전트는 |
|---|---|---|
| 범위나 완료조건을 바꿔야 하는 결정 | 바로 알린다 | 그 goal에서 멈추고 기다린다 |
| 같은 곳의 검증 실패 세 번 | 바로 알린다 | 같은 방법을 네 번째로 시도하지 않고 멈춘다 |
| 마일스톤이 끝나 병합 대기 | 나중에 봐도 된다 | 다음 마일스톤을 시작하지 않고 기다린다 |
| 사용량 한도로 멈춤 | 나중에 봐도 된다 | 안전한 지점에서 멈췄다가 한도가 풀리면 스스로 이어 간다 |

애매하면 범위 밖으로 친다. 완료조건 밖의 새 아이디어는 Backlog에 한 줄로 남기고 묻지 않는다.

## 알림

- PC 알림만 한다. 휴대폰 알림은 지금 넣지 않는다 — 감당할 비용이 없다.
- 바로 알리는 사건은 Windows 알림과 앱 안 표시로, 나중에 봐도 되는 사건은 앱 안 표시로만 알린다(제안).
- 알림의 세부(소리, 반복, 자리 비움 감지)는 `90_열린-질문.md` 2.

## 화면에서 보이는 방식

- 메인 세션은 언제나 보인다.
- 서브에이전트와 노드별 담당 세션은 평소에는 「무슨 작업 중인지」 한 줄로 보인다. 원하면 눌러서 채팅 세션 전체를 본다.
- 현황판은 앱 안에 있다. 마일스톤 진척, goal 상태, 검증 기록, 열린 PR, 기다리는 결정을 한곳에서 본다.

## 검증은 누가 하나

- 결정론적 검사(테스트, 타입체크, 린트, 빌드, CI)는 프로그램이 판정한다.
- 결정론으로 판정할 수 없는 것(Taste, 설계의 타당성)은 구현 문맥을 물려받지 않은 별도 에이전트가 판정한다. 만든 에이전트가 자기 결과물을 판정하지 않는다.
- 사람은 검증자가 아니다. 사람이 직접 봐야만 판정할 수 있는 것이 생기면, 그것을 판정할 수 있게 Taste 스펙을 보강하는 것이 먼저다(제안).
