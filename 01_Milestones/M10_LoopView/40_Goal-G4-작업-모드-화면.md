## 목표

작업 모드가 시안의 배치가 된다. 왼쪽은 프로젝트 사이드바, 가운데는 탭(그래프 자리, 메인 대화, 노드 작업 세션 보기 전용), 오른쪽은 「현황판」과 「파일·변경」 탭이다. 임시였던 루프 화면 옆 열은 현황판으로 바뀐다.

## 범위

- **만들 것**
  - 프로젝트 사이드바(시안 장면 「goal 진행」 왼쪽) — 작업 모드에서 최근 채팅 대신 프로젝트(저장소) → 작업 폴더(지금은 기본 체크아웃 하나, 브랜치 이름) → 메인 대화, 지난 메인 대화 기록(보관본, 보기 전용), 「프로젝트 열기」. 프로젝트마다 진행 꼬리표(브레인스토밍·진행 중·멈춤·병합 대기). 목록은 앱 설정에 작업 폴더 경로로 저장한다(워크트리를 더할 때 한 단계 아래에 붙는 꼴). 채팅이 사람의 답을 기다리면 채팅 모드 칸에 표시한다(Backlog 5의 사이드바 몫).
  - 가운데 탭 — 맨 앞 「그래프」 탭 자리(내용은 G5), 메인 대화 탭(G3의 `MainChatView`를 그대로 올림), 노드 작업 세션 탭(시안 장면 「노드 세션」). 노드 세션 탭은 현황판의 노드 한 줄에서 열고, 채팅과 같은 모양으로 그 세션의 전체 기록을 보이며 입력칸이 없다(보기 전용).
  - 노드 세션 기록 — main이 `loop.sessionEvent`의 꼬리표(key·kind·노드·goal)별로 세션 사건을 모아 작업 폴더 단위로 보관한다(상한을 둔다). 탭을 늦게 열거나 모드를 바꿨다 와도 처음부터 보인다. 읽기 IPC 하나.
  - 오른쪽 「현황판」 탭(시안 장면 「goal 진행」「사람 부름」「병합 대기」 오른쪽) — 여섯 칸: 마일스톤 진척, goal 목록, 노드 세션 한 줄(누르면 세션 탭), 기다리는 결정(멈춤 이어 가기·래치 풀기 같은 사람 판정), 열린 PR과 병합 버튼(마일스톤 PR은 사람의 병합 버튼 — 헌법 10조의 길 그대로), 최근 검증 기록. 지금 루프 화면의 기능(폴더 고르기·열기·시작·닫기·이어 가기·래치 풀기·작업 세션 취소)을 빠짐없이 옮긴다. 칸의 값은 `LoopStatus`에서만 온다.
  - 오른쪽 「파일·변경」 탭(시안 장면 「파일·변경」) — 지금의 탐색기·변경된 파일·할 일·서브에이전트를 접어 넣는다. 작업 모드에서 왼쪽 탐색기 열은 접는다.
  - `LoopStatus`에 지금 노드가 메인 노드인지 싣고, 브레인스토밍 중에는 「작업 세션 취소」를 보이지 않는다(Backlog 14).
  - 쓰는 곳이 없어진 멀티 모드 잔여물 정리(Backlog 3) — 세션 탭이 다시 쓰지 않는 것만.
  - M09 실주행 구동기의 선택자를 새 배치에 맞춘다(G6이 쓴다).
- **건드릴 곳**: `02_Project/00_Source/renderer/src/`(`12_Window/`, `13_Loop/`, `00_App/`, `06_Sessions/`, `05_Conversation/`·`03_Agent/`의 재사용 부품과 보기 전용 경로, 탐색기·변경 파일 부품), main의 세션 기록 보관과 IPC(`main/05_Loop/`, `main/01_Ipc/handlers/loop.ts`), `shared/` IPC 계약, `02_Project/01_TestCode/`(시험, 수집 기준선, e2e 구동기), `01_Milestones/M10_LoopView/`. 판정 장치 변경 없음(1단계 `gate-config.json` 전환만).
- **하지 않을 것**: 그래프 캔버스와 「노드 설정」 탭, 알림(G5), 연습 저장소 실주행(G6), 워크트리 만들기와 작업 폴더 여럿 나란히 돌리기, 메인 대화 엔진 동작 변경, 새 의존성, README 갱신(Backlog 7 — G6 캡처 뒤).
- **완료조건**
  - 작업 모드의 세 영역이 시안 배치대로 그려지고, 왼쪽 탐색기 열이 접히며, 채팅 모드로 돌아가면 지금의 채팅 배치가 그대로다(시험, 실제 앱 캡처).
  - 현황판 여섯 칸의 값이 `LoopStatus`와 같다 — 같은 상태를 넣으면 칸마다 그 값이 보인다(시험). 루프 화면에 있던 동작이 모두 현황판에 있고, 사람 판정 버튼은 지금과 같은 IPC로만 간다(시험).
  - 노드 세션 탭은 입력칸 없이 그 세션의 전체 기록을 채팅과 같은 모양으로 보이고, 늦게 열어도 처음부터 보인다(시험).
  - 프로젝트 사이드바가 저장된 작업 폴더를 보이고 「프로젝트 열기」로 더하며, 진행 꼬리표가 상태와 같다(시험).
  - 브레인스토밍 중 「작업 세션 취소」가 보이지 않는다(시험).
  - 실제 앱(빌드본, 2번 모니터, 임시 userData, 원격 없는 로컬 저장소)에서 세 영역과 두 오른쪽 탭, 메인 대화 탭이 보인다(캡처).
  - 하드 게이트 다섯 종 exit 0, `npm test` 실패 0, 독립 검수 반영, goal PR의 `hard-gates` 통과, 정형 절차로 병합.
