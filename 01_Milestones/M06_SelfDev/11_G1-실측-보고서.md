## 5. 자기 자신을 고칠 때의 위험 — 문제 있음

- 빌드 쪽: `out/`에서 띄운 앱에 새 대화, 입력창 초안, `window.__g1marker`를 심었다. clone의 renderer 문자열 하나를 고친 뒤 clone에서 `npm run build`를 돌렸다.
  - 빌드 동안과 뒤에도 앱은 반응했고 표지·초안·옛 문구가 그대로였다. 번들 이름은 `index-CHvCgOGi.js`에서 `index-DcpphBpj.js`로 바뀌었고 옛 파일은 지워졌다. renderer는 단일 번들이라 지연 로드가 없어 깨지지 않았다.
  - 다시 불러오자(`page.reload()`) 새 번들이 실렸다. 표지와 초안은 사라졌고 새 문구 `무엇을 도와드릴까요, g1probe님? [G1-BUILD]`가 보였다. main 프로세스는 옛 코드 그대로다. IPC 계약을 바꾼 빌드라면 이 시점에 renderer와 main이 어긋날 수 있다(실측 안 함).
  - 빌드는 `out/`을 비우고 다시 쓴다. 그 사이에 창을 다시 불러오면 빈 폴더를 읽을 수 있다(실측 안 함).
- dev 쪽: clone에서 `npm run dev -- -- --user-data-dir=<임시>`로 띄웠다(electron-vite가 `--` 뒤 인자를 `ELECTRON_CLI_ARGS`로 넘긴다). 닉네임을 다시 묻지 않고 g1probe 대화들이 보여 임시 userData가 쓰였음을 확인했다. 원격 디버깅 포트로 붙어 조작했다.
  - 컴포넌트 편집(`Conversation.tsx` 문구): `[vite] (client) hmr update /src/05_Conversation/Conversation.tsx` 뒤 Fast Refresh 실패로 `Shell.tsx`·`AppGate.tsx`까지 갱신 범위가 올라갔다(`Could not Fast Refresh ("decisionReasonTypeLabel" export is incompatible)`). 그래도 페이지를 다시 불러오지는 않았다. 표지와 선택기(Haiku · 일반)가 남았다.
  - 그 직전 턴은 HMR 2초 전(11:53:46 Stop)에 끝나 있었다. 「실행 중인 턴이 HMR을 견디는가」는 확인 못 함이다.
  - 컴포넌트가 아닌 모듈 편집(`pickerOptions.ts` 주석): `[vite] (client) page reload src/03_Agent/pickerOptions.ts`. 페이지 전체가 다시 불려 표지가 사라지고 선택기가 Opus 5 · 자동으로 돌아갔다.
  - 턴 도중 리로드: Vite 리로드는 턴이 끝난 1초 뒤에 와서 타이밍을 맞추지 못했다. 그래서 같은 효과인 `page.reload()`를 턴 본문이 `127`까지 스트리밍된 순간(02:56:12Z)에 직접 불렀다.
  - 결과: 화면에서 그 턴의 답이 사라졌고 끝까지 나타나지 않았다(40초 관찰). 그런데 SDK 대화 기록에는 그 턴이 `260 이백육십`까지 `"stop_reason":"end_turn"`(02:56:16Z)으로 끝나 있었다. 앱의 대화 기록 파일(`chats/*.json`)에는 사용자 메시지만 있고 답이 없었다. 턴은 뒤에서 끝났고 앱만 그것을 잃었다.
- 판정: 앱으로 이 저장소의 renderer를 고치면 리로드가 진행 중인 턴의 화면 기록을 잃게 한다. 실행 중인 앱과 고치는 저장소를 분리해야 한다. 앱은 별도 빌드본에서 띄우고, 저장소의 `npm run build`는 그 빌드본과 다른 `out/`을 쓰게 하면 된다.

## 하지 못한 것과 무대의 흔적

- 2번 모니터 배치: 실험 시점에 디스플레이가 하나뿐이었다(`screen.getAllDisplays()` 길이 1). 창은 주 모니터에 떴다.
- CLI 대조는 로그 꼴 비교로 대신했다. 같은 조건의 CLI 세션은 띄우지 않았다.
- 격리의 빈틈: SDK가 앱 세션 대화 기록을 사용자 전역 폴더 `~/.claude/projects/C--Dev-AgentDeck-g1probe/`에 남겼다(세션 파일 8개). 이 폴더는 지우지 않고 남겼다 — 사용자 판단으로 지운다.
- 무대 폴더 삭제: `C:\Dev\AgentDeck-g1probe`, `C:\Dev\AgentDeck-g1probe-origin.git`, 스크래치패드의 `udd`는 가드가 재귀 삭제를 막아 남겼다. 가드를 피하는 다른 꼴의 명령은 쓰지 않았다. 정션은 먼저 `rmdir`로 끊어 두었으므로, 사용자가 외부 셸에서 지워도 메인 `node_modules`는 다치지 않는다.
- 실험은 사용자 주간 한도를 썼다. Opus 5 한 턴과 Haiku 4.5로 30턴 안팎이다.
