실행 단계 일괄 승인 대상 (로드맵 예외로 합의 문답 없이 진행한다)

- `npm run dev`·`npm run start`로 앱 실행, Playwright Electron 하네스로 창 조작과 스크린샷(창은 2번 모니터), 앱 안 대화 세션(사용자 로그인 자격 — 파일은 읽지 않는다)
- 실험용 독립 clone(이 저장소 밖 경로, `node_modules`는 정션)과 그 `origin`이 될 로컬 bare 저장소 만들기, 실험 뒤 지우기
- 하드 게이트 다섯 종, 하위 에이전트 기동, 커밋, 작업 브랜치 push, `gh pr create`

실험의 안전 규칙

- 앱과 앱 세션은 실험용 독립 clone에서 띄운다. clone의 `origin`은 로컬 bare 저장소로 바꿔 둔다 — 앱 안 에이전트가 진짜 push를 해도 GitHub에 닿지 않는다. 이 저장소 작업 트리를 앱 세션에 열지 않는다. clone에는 추적 안 되는 로컬 파일(`settings.local.json` 등)이 없으니 훅 결과를 읽을 때 감안한다.
- 앱은 `--user-data-dir`로 임시 userData를 쓴다(e2e 하네스와 같은 방식) — 사용자의 실제 작업 폴더·대화 기록을 열거나 쓰지 않는다. 재시작 실험은 같은 임시 폴더를 다시 쓴다.
- 가드가 묻는 명령은 허용돼도 해가 없는 것만 쓴다 — 예: `git push origin HEAD:master`(origin이 로컬 bare라 GitHub에 닿지 않는다). `gh pr merge`·`gh api`·브랜치 삭제·보호 설정 변경은 쓰지 않는다. 승인 카드가 뜨면 허용하지 않고 거부한다 — `auto`·`bypass`에서 「카드 없이 실행됐다」면 그것이 발견이다.
- 권한 모드는 시작 모드와 실행 중 전환 둘 다, 단일 패널과 멀티 패널 둘 다 본다. 사례마다 셋을 모은다 — clone hook-log의 가드 `ask` 줄, 카드가 떴는지(스크린샷), 실행됐는지(bare 저장소 ref). 긴 명령 하나로 승인 카드의 80자 자르기도 본다.
- 순서는 기동 → 훅 → 권한(`normal` 먼저, `bypass` 마지막) → 재시작 → 자기 수정·빌드(파괴적이라 마지막)다. 앱 안 프롬프트는 짧게 한다(사용자 사용량).
- 결정적 로그 줄은 보고서에 인용한다 — 스크린샷과 clone은 지워진다.
- 실험에 앱 소스 변경이나 진짜 원격을 향한 가드 명령이 필요해지면 범위 변경이다 — 멈추고 사용자에게 묻는다. 앱 세션이 마감 요약 게이트에 걸리면 그것도 4번 증거다 — 해제하지 않고 앱을 닫는다.
