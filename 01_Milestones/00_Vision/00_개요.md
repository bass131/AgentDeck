# AgentDeck 비전 스펙 — 개요

## 한 문단 요약

AgentDeck은 사람이 목표와 Taste만 정하면 에이전트가 마일스톤 단위로 구현과 운영을 끝까지 맡는 데스크톱 작업 환경이다.
사람은 처음에 궁극 목표·기획·작업 영역·Taste를 세우고, 마일스톤마다 메인 세션과 브레인스토밍해 방향을 합의한다.
그 밖의 goal 분해, 구현, 검증, PR, goal 병합, 문서화, 현황판 갱신은 에이전트가 한다.
사람에게는 마일스톤이 끝났을 때의 보고와 병합 버튼, 그리고 진짜 예외만 돌아온다.

## 왜 만드는가

에이전트가 일을 그르치는 원인은 모델이 아니라 구조다. 텍스트 지시는 에이전트가 끝까지 지키지 못한다.
그래서 지켜야 할 순서와 검사를 결정론적인 작업 그래프로 만들고, 그 그래프를 프로그램이 실행하게 한다.
이것은 노션 「Moodie's Agentic Engineering」의 Layer 0 Goal Based Loop를 실제로 돌리는 일이다. 노션은 작업 성격에 따라 Layer를 나눈다고 적는다.
AgentDeck은 그 생각을 프로젝트 유형별 템플릿으로 옮긴다. 프로그램 개발과 게임 개발은 서로 다른 그래프를 쓴다.

## 누가 쓰는가

- 1순위는 유영호 한 사람이다.
- 그래도 완성형 소프트웨어로 배포한다. 나중에 건네고 싶은 사람이 생기면, 그 사람이 설명서 없이 설치해 쓸 수 있어야 한다.
- 저장소는 비공개다. 팀원끼리 연결해 함께 일하는 기능은 넣지 않는다 — 중앙 서버가 필요해 비용이 든다.

## 궁극 목표의 완료선

새 프로젝트를 하나 열어 목표와 Taste 스펙만 쓰고, 마일스톤 여러 개를 사람 개입 없이 완주한다.
사람이 하는 일은 마일스톤 브레인스토밍과 마일스톤 끝의 병합 버튼뿐이다.
숫자 완료선(마일스톤 몇 개, 개입 몇 번)은 아직 정하지 않았다 — `90_열린-질문.md` 1.

첫 두 대상은 프로그램 개발(첫 소재 AgentDeck 자신)과 게임 개발(첫 소재 Dawnholder의 서버·백엔드·하네스 몫)이다.

## AgentDeck이 맡는 것과 맡지 않는 것

- AgentDeck은 지금의 Orca + Claude Code CLI 작업 환경을 대체하는 메인 작업 환경이 된다.
- 실행기는 공식 Claude Code를 재사용한다(2026-09-18 결정). Codex는 구독이 없어 지금은 쓰지 않는다.
- AgentDeck이 맡는 것은 목표, 작업 그래프, 검증, 현황판, 문서, 화면이다.
