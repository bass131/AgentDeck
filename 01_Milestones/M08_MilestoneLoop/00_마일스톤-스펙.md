## 목표

헌법 10조의 goal 병합이 효력을 갖는다. 에이전트가 goal을 마일스톤 브랜치에 로컬로 병합하고 push해도 장치와 어긋나지 않고, 그 길을 이 마일스톤 안에서 한 번 실제로 돌린다.

## 범위

- **만들 것**
  - 병합 길 장치 — 로컬 `git merge --no-ff`가 묻지 않고 지나가고(`.claude/settings.json`), 마일스톤 브랜치로 가는 PR에도 `hard-gates`가 돈다(`.github/workflows/hard-gates.yml`).
  - CLI 쪽 실측 — 서버 보호가 없다고 볼 때 CLI 세션이 `master` 병합·`master` 직접 push·강제 push·브랜치 삭제를 어느 장치에서 막는지(설정 거부 규칙, 위험 명령 가드) 실측해 표로 남긴다. 앱 쪽 실측은 앱 장치가 바뀐 뒤다.
  - 병합 경계 ADR과 안내 글 — 마일스톤 단위 병합 결정을 ADR로 남기고, 효력 날 뒤 틀리게 되는 안내 글(가드 `MERGE_HINT`, 앱 `mergeDeny.ts`의 거부 사유)과 감시 줄 시험(`smoke.test.mjs`)을 맞춘다(M07 Backlog 36).
- **건드릴 곳**
  - 판정 장치(헌법 3·11조, 이름으로): `.claude/settings.json`, `.github/workflows/hard-gates.yml`, `.claude/hooks/dangerous-cmd-guard.mjs`의 `MERGE_HINT` 글, `.claude/hooks/smoke.test.mjs`, `98_Management/01_GateState/gate-config.json`(`planPath`·`workPinPath`).
  - `98_Management/00_ADR/`(새 ADR), `02_Project/00_Source/main/04_Claude/permission/mergeDeny.ts`의 거부 사유 글과 그 시험, `01_Milestones/M08_MilestoneLoop/`, `01_Milestones/00_Roadmap.md` 진행 기록, `99_Others/Dashboard/docs/병합.md`.
- **하지 않을 것**
  - 앱의 병합 길 변경(사용자 1A). 앱 `mergeDeny`는 소스상 로컬 `git merge`를 막지 않는다(2026-11-18 소스 열람, 실행 실측 아님).
  - 가드 판독 재설계(M06 Backlog 20·21, 사용자 3A). 규칙을 소스 수정 없이 바로 넣는 기능은 Backlog로 둔다.
  - 가드의 `gh pr merge`·병합 API 거부 범위 좁히기(헌법 10조 — 대상과 관계없이 거부).
  - 앱 쪽 비공개 전환 실측, 저장소 공개 범위 변경(사용자 몫).
- **완료조건**
  - 첫 goal 병합 뒤, 둘째 goal을 에이전트가 `milestone/m08-milestone-loop`에 로컬 `git merge --no-ff`로 병합하고 push했고, 그 사이 권한 질문이 뜨지 않았다(세션 기록).
  - 둘째 goal의 PR(기준 `milestone/m08-milestone-loop`)에서 `hard-gates`가 돌아 통과했고, GitHub가 그 PR을 병합됨으로 닫았다.
  - CLI 쪽 실측 표가 goal 문서에 있고, 각 행이 가드·설정 실측 입력과 판정(거부·질문·통과)을 갖는다.
  - 마일스톤 회귀 검증 `PASS` 줄이 아래 검증 기록에 있다.
