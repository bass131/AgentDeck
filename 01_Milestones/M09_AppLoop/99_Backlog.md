12. (범위 밖, G5 독립 검수 사소 3) 「스펙을 쓰는 노드」 판정이 세 곳에서 갈린다 — 프롬프트 규칙은 `role main`, 카드 응답자는 `role main`과 화면 응답자 있음, 스펙 확인은 `role main`과 `docs`에 milestoneSpec(읽는 문서 목록). 화면 응답자 없이 포트를 만들면 규칙이 질문 도구를 요구하는데 카드가 거부돼 FAIL이 쌓인다(지금 프로덕션은 늘 응답자를 준다). 술어 하나로 모을지, 템플릿에 「쓰는 문서」를 둘지 정한다. 메인 노드 FAIL 뒤 재시도 프롬프트에 직전 FAIL 사유를 싣는 것도 함께 본다.
11. (범위 밖, G5 실주행 관찰) 앱 PR 카드는 고전 브랜치 보호만 읽는다 — 룰셋으로 지키는 `main`을 「보호가 없어 필수 검사가 없어요」로 보이고, fine-grained 토큰에 Administration 읽기가 없으면 403으로 버튼을 닫는다(닫힌 실패는 의도). 룰셋의 필수 검사(`rules/branches/<b>`)를 함께 읽을지 정한다. CI 게이트는 같은 머리에 `hard-gates`가 둘(push·pull_request) 돌 때 하나가 성공하면 다른 하나가 도는 중이어도 pass했다 — 같은 이름의 검사가 모두 끝날 때까지 기다릴지 정한다.
10. (범위 밖, G5 실주행 관찰) 메인 노드는 세션 한 턴이라 글로 물으면 대화가 끊긴다 — G5는 질문 도구 규칙과 스펙 파일 확인으로 막았고, 이어지는 대화는 M10 화면(메인 세션 대화 안의 브레인스토밍, 로드맵 M10 행)에서 다룬다. 작업자·검수 노드는 자동 판정이 묻기로 넘긴 호출을 기본 거부해(7회) 검수 세션이 시험을 직접 돌리지 못한다. 재기동 뒤 루프 화면은 사람이 다시 열어야 실행기가 돈다. e2e 구동기는 기동 직후 사이드바 버튼 클릭이 두 번 실패해 다시 눌렀다.
9. (범위 밖, 확인 안 함 — G4 확인 검수 반영 보고) `ensureBranch`의 goal 브랜치 push는 아직 이름으로 간다(머리 확인 뒤 SHA 없이). 래치 풀기의 받지 않을 키 후보로 `remote.<이름>.proxy`(빈 값으로 바꾼 것)와 `http.curloptResolve`(호스트를 다른 IP로 돌림)가 남았다. 대기열 답을 쓰는 화면은 닫기 실패 시 이미 답한 카드를 잠깐 다시 답할 수 있게 보인다(보내면 거부 사유가 뜸).
8. (범위 밖, 확인 안 함 — G4 검수 반영 보고) 읽기 전용 잠금은 PowerShell 꼴 `$env:GIT_PAGER=…; git log`를 지나보낸다(`PS_ENV_SET`이 자격 이름만 봄 — 트리 대조가 겹으로 덮음). `ensureBranch`는 시작 SHA가 없을 때 아직 로컬 ref를 읽는다(`recordedStart ?? headSha(from)`). 래치 풀기가 거부하는 위험 값·remote url·ssh·gh 파일 변경은 앱 안에 빠져나갈 길이 없고 사람이 직접 되돌린다.
7. (범위 밖, 확인 안 함 — 소스 판독) 병합 거부의 래퍼 판독 차이와 남은 꼴: 앱 `commandsOf`는 래퍼 값 옵션을 정확 일치로만 봐 묶음·줄임(`timeout -vs KILL 30 gh pr merge`, `sudo -iu root …`, `env --chd …`)을 가드와 달리 놓칠 수 있다. env 표에 `--argv0`이 없고, `-S` 고유 이스케이프(`\_`·`\c`·`${VAR}`)는 모델링하지 않았으며, heredoc 소비자 판독이 `-S`를 모르고, 다시 판독 깊이 한도가 가드 3·앱 4라 그 너머는 통과한다. `setsid`·`flock`·`chroot`·`su -c`·`runuser`·`script -c`·`ssh host cmd`·`parallel` 래퍼는 두 표 모두 모른다. `master`는 서버 보호가 따로 지킨다 (G3 작업자 보고).
6. (G3 인계, 확인 안 함) 앱의 병합 거부 노드(`mergeDeny.ts`)는 `env -S "gh pr merge …"`처럼 따옴표 문자열을 명령으로 다시 읽는 꼴을 놓칠 가능성이 높다(루프 잠금은 G2에서 `env -S`를 다시 판독함). 앱 노드는 실측해 고치고, 저장소 하네스의 위험 명령 가드(판정 장치)에도 같은 구멍이 있는지는 사용자에게 알린다. 잠금 쪽 남은 오탐 — `source .venv/bin/activate` 뒤 위치 모름이 호출을 넘어 남음, CDPATH 글자가 커밋 메시지에서도 걸림, 앞 명령이 있으면 뒤 `cd`를 실패 가능으로 봄 — 도 G4 실측과 함께 정한다 (G2 4차 반영 보고).
5. (G3 인계, 범위 안) 설정 대조의 오탐과 푸는 길 — 사용자가 직접 쓴 `gh`가 `remote.origin.gh-resolved`를 적거나, 전역·include 파일이 정상으로 바뀌어도 다시 열기가 막히고 푸는 길은 스냅숏 파일 삭제뿐이다. 로컬 `core.hooksPath`(husky 저장소)는 실행기가 `-c`로 덮는데도 거부된다. 래치 해제 경로와 함께 사람 확인 카드로 정한다. `pr create -R`과 `pushurl`은 G4 실주행에서 실측한다 (G2 재검수 반영 보고). 같은 부류로, 사용자의 `gh auth login`·`refresh`가 `hosts.yml`을 바꿔도, 이 변경 전에 쓴 스냅숏(ssh·gh 항목 없음)으로 다시 열어도 막히며, 단독 `ENV=` 할당도 거부된다 (G2 마지막 반영 보고).
4. (G3·G4 인계, 확인 안 함) 실행기 PATH에 사용자가 쓸 수 있는 폴더(`%APPDATA%\npm` 등)가 있으면, 세션이 그곳에 심은 sh shim이 git이 sh로 부르는 기존 설정 명령(사용자의 lfs filter 등)을 가로채 실행기 자격으로 돌 수 있다. G2는 잠금에서 전역 패키지 설치만 거부했다. 실행기 PATH를 시스템 폴더와 git·gh 설치 폴더로 좁힐지, G4 실주행 전에 실측으로 정한다 (G2 재검수).
3. (G3·G4 인계, 범위 안) 작업 노드 세션은 `settingSources`(user·project·local)를 그대로 읽어, 사용자 설정이 자기 토큰을 가진 MCP 서버를 실으면 루프 잠금과 자격 없는 환경을 둘 다 우회해 원격에 쓸 수 있다. 노드 세션의 MCP·설정 원천을 좁힐지, 사람 대화 노드(브레인스토밍)의 카드 응답자, `close()`의 취소를 FAIL로 셀지, `mode-auto-bypass-allow`가 꺼져 있을 때 루프 시작 전 검사를 G3가 정한다 (G2 2차분 보고).
2. (G2·G3 인계, 범위 안) 실행기 호출 직렬화(`exclusive`)는 끝나지 않는 노드 동안 `load`·`submit`까지 줄을 세운다. 상태 읽기는 줄 밖에 두고, 세션 포트 시간 제한·저장소당 실행기 하나·취소 경로를 둔다. CI 게이트의 기다림(gh 오류, PR 머리가 push한 SHA와 영영 다른 경우 — 남이 goal 브랜치에 push)에 상한을 두어 멈춤으로 바꾼다 (G1 재검수 사소 2, G2 인계).
1. (G2 인계, 범위 안) 작업 노드 세션이 작업 저장소의 `.agentdeck/run-state.json`·`verification.md`를 직접 쓰면 G1 실행기의 자기 일관성 검사만으로는 위조를 못 막는다. G2의 잠금 노드가 원격 쓰기와 함께 `.agentdeck/` 쓰기를 거부하고, `.agentdeck/`의 git 취급(무시·커밋 제외·실행기가 정한 시점 커밋)을 정한다. goal을 다시 나누는 길을 넣으면 FAIL 계수를 잇는다(헌법 11조) — G3 메모 (G1 독립 검수 중요 2·7, 헌법 대조).
