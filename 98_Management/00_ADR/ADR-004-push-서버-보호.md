# ADR-004 — `master` 보호는 서버가 하고, 작업 브랜치 push는 묻지 않는다

- 상태: 채택 · 날짜: 2026-11-13 · 마일스톤: M05 (끼운 하네스 goal H1)
- 대체: ADR-003 결정 2(「push의 무질의 통과는 만들지 않는다」)를 대체한다. ADR-003의 나머지 결정은 그대로다.
- 맥락 문서: `01_Milestones/M05_Structure/15_Goal-H1-push-서버-보호.md` (결정 대장·검증 기록)
- 판정 근거: H1 결정 대장 [USER] 2026-11-13 — push 질의 문답, 끼울 시점 문답, 하네스 설계 문답

## 배경

ADR-003 이후 goal 하나의 사용자 입력은 합의, push 승인 창, 병합 승인 셋이었다.
사용자는 자리를 비운 동안에도 루프가 돌아야 하고, PR 직전에 push 창에서 멈추는 것이 사고라고 밝혔다 (2026-11-13).

ADR-003의 실패는 가드 하나가 「이 push가 `master`에 닿는가」를 판정해야 했다는 데 있었다.
명령 문자열과 저장소 상태로는 그 판정이 닫히지 않았고, 독립 검수가 여섯 번 불통과시켰다.

## 결정

### 1. `master`를 지키는 것은 GitHub 서버다

`master`에 고전 브랜치 보호를 건다. PR 필수(승인 0명), 관리자에게도 적용, 강제 push 금지, 삭제 금지다.
저장소가 public이라 무료로 쓸 수 있다. 서버는 push가 실제로 무엇을 바꾸는지 보고 거부하므로, 명령 문자열을 읽을 필요가 없다.

승인 0명인 이유는 사용자가 혼자 쓰는 저장소이기 때문이다. 병합의 사람 판정은 `gh pr merge`의 승인 다이얼로그가 맡는다.
상태 검사 필수는 두지 않는다. CI가 없고, 하드 게이트는 커밋 전에 로컬에서 돈다(헌법 6조).

### 2. 가드는 서버 보호 위의 이중 안전장치다

일반 push는 질의하지 않고, 설정은 `Bash(git push*)`를 `allow`에 둔다. 가드는 여전히 어떤 명령에도 명시적 통과를 내지 않는다.
가드가 잡는 것은 셋이다.

- 차단: 강제 push(`--force`, `-f` 묶음, `--force-with-lease`, `--force-if-includes`, `+` refspec)와 `git switch -C`. 작업 브랜치의 이력을 서버 보호 없이 덮기 때문이다. fetch의 ref 덮어쓰기(`+`·`:` refspec, `--prune`과 refspec)는 질의다.
- 질의: 원격 삭제, `--mirror`·`--all`·`--tags`·`--prune`, `master`가 글자로 보이는 push, `send-pack`. 서버가 `master`는 지키지만 작업 브랜치 삭제와 태그는 지키지 않는다.
- 질의: 보호 설정을 바꿀 수 있는 `gh api` 쓰기 호출과 `gh repo edit`·`gh repo delete`. 서버 보호를 끄는 길을 막는다.

가드 판독이 꼴 하나를 놓쳐도 `master`는 서버가 지킨다. ADR-003에서 수렴하지 않던 검수 조건들은 이제 `master` 사고가 아니라 작업 브랜치의 질의 누락이다.

가드의 셸 판독은 넓히지 않는다. H1에서 판독을 넓힌 수리 두 번이 독립 검수를 불통과했다. 줄 이음·리다이렉트·주석을 셸처럼 읽게 하자, heredoc 커밋 메시지와 이스케이프 꼴에서 새 사각이 나오고 기존 `reset --hard` 규칙이 회귀했다.
그래서 가드는 기준 판독(`9910a31`) 위에 push·gh 규칙만 얹는다. 판독이 못 읽는 꼴의 작업 브랜치 강제 push는 감수한다. 통제는 작업별 브랜치 분리다 — 한 goal의 손실은 그 브랜치에 갇히고, `master`에는 PR과 병합 승인을 거쳐서만 들어간다 (H1 결정 대장 [USER] 2026-11-13, 강제 push 문답).
버린 쪽은 GitHub ruleset으로 모든 브랜치의 강제 push를 서버에서 막는 안이다. 사용자가 고르지 않았다.

### 3. 보호 설정 변경은 사용자 전용이다

헌법 9조의 게이트 해제 수단에 「GitHub 브랜치 보호 설정의 변경과 해제」를 더한다.
에이전트는 보호를 끄거나 바꾸지 않는다. 가드의 `gh api` 질의는 그 규범의 기계 사본이다.

## 감수한 것

- 가드의 `gh api` 판독은 변수 확장이나 스크립트 안의 호출을 못 본다. 서버 보호 해제는 규범(9조)과 git diff·hook-log 사후 감사에 기댄다.
- 관리자 적용을 켰으므로 사용자도 `master`에 직접 push할 수 없다. 급할 때는 사용자가 보호를 잠시 끄고 다시 켠다.
- 권한 창을 생략하는 권한 모드에서는 가드의 질의가 창이 아니다(ADR-003 감수 항목 그대로). 이 경우 병합 승인도 사라지지만, 서버 보호는 PR을 거치게 하는 것까지는 남는다.

## 되돌리는 법

설정의 `Bash(git push*)`를 `allow`에서 `ask`로 옮기고, 가드의 push 규칙을 「전부 질의」로 되돌리고, 헌법 9·10조를 M04 문면으로 되돌린다.
서버 보호는 남겨도 해가 없다. 끄려면 사용자가 저장소 설정에서 끈다.
