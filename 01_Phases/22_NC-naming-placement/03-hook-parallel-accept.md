## 📚 학습 포인트

- **fail-open과 fail-closed** — 판정기가 "모르겠으면 통과"(fail-open)면 규칙을 못 찾는 순간 방어가 사라지고, "모르겠으면 차단"(fail-closed)이면 오탐이 일을 막는다. 이 저장소의 `classifyHarnessPath`는 미스 시 `'unrelated'`를 반환하는 **fail-open**이라, 경로가 바뀌는 것만으로 봉인이 조용히 없어진다.
- **advisory 티어의 존재 이유** — 안전 속성(봉인·파괴·비가역)은 fail-closed 차단이 맞지만, 품질 규범(명명)은 사후 교정이 싸고 보안 결과가 없다. 차단형으로 만들면 **오탐 하나가 핫픽스를 막는** 나쁜 교환이 된다.
- **골든 픽스처가 곧 지도** — "훅이 보는 경로 리터럴 전수 지도" 같은 문서를 따로 만들면 드리프트한다. 픽스처는 **기계가 검증하는 지도**라 낡으면 red로 알려준다.

### 설계 결정 3건 (계획에 없던 판단)

**① 번호를 하드코딩하지 않고 `(?:\d{2}_)?` 로 받았다.** `(?:00_harness|01_adr|...)` 로 나열하는 대안이 있었으나, 번호는 **「읽는 순서」라서 문서가 하나 끼어들면 재정렬된다**(ADR-027의 촘촘 번호가 감수한 비용). 하드코딩하면 재정렬마다 봉인이 조용히 풀린다. 봉인 방향은 집합을 넓히는 쪽이라 존재하지 않는 번호가 매치돼도 무해하다 — **fail-closed 쪽으로 넓히는 것은 공짜다.**

**② `done-report-policy.mjs` 의 중복 정규식을 상수로 추출했다.** 계획은 "원자 수정"(두 곳을 같이 고침)이었지만, **복제가 남아 있는 한 다음 사람이 또 한쪽만 고친다.** `REPORT_HTML_RE` 하나로 끌어올려 갈라질 수 있는 것 자체를 없앴다. ⚠️ 다만 이건 **수용 방향**이라 P06 일몰 대상이며, 그 사실을 상수 주석에 박아뒀다.

**③ 「신규 생성물 한정」을 예외 목록이 아니라 `git ls-files` 로 판정했다.** 계획은 동결 예외 목록을 넣는 것이었으나, 목록은 낡는 순간 동결 파일에 상시 경고가 뜨고 그 노이즈가 **승인 피로 → 우회 습관**이 된다(이 Phase가 스스로 경고한 경로다). git 추적 여부로 판정하면 **소급 스캔이 구조적으로 불가능**해져 관리할 목록이 사라진다. 도구 생성물 예외(`artifacts`·`out`·`test-results`)만 남겼다 — 그것들은 미추적이라 git 판정으로는 안 걸러지기 때문이다.
