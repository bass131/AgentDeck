## 판정 축과 읽는 법

판정은 세 값으로 접습니다.

- **deny** — 차단입니다. 현행 가드는 exit 2로, 원본 가드는 `permissionDecision: "deny"` JSON으로 냅니다.
- **ask** — 승인 질의입니다. 현행 가드가 비가역 축(push·publish·release)에 쓰며, 차단과 동등으로 읽습니다 (M01 결정 대장 [USER] 2026-08-09).
- **allow** — 통과입니다. exit 0에 출력이 없는 상태입니다.

기대 판정의 원칙은 「원본 동등 이상」입니다.
원본이 잡던 표면은 반드시 잡고, 원본보다 넓게 잡는 것은 그대로 둡니다.
반대로 하류에서 실행되지 않는 언급·인용문을 잡는 것은 오탐이므로 기대 판정을 allow로 둡니다 — 오탐도 동등성 결함입니다.

**플래그** 열의 ✔은 현행 구현이 기대 판정과 어긋남이 확인된 표면입니다.
그 항목은 기대-실패 플래그로 등재되어 「실측이 기대와 다르면 통과」로 집계됩니다 — 하드 게이트를 유지하면서 Red를 기록하는 장치입니다 (플래그 의미론은 `.claude/hooks/_lib/runner.mjs`가 소유).
Phase 1이 18건을 등재했고 **Phase 2가 전건을 수리해 지금은 잔여 0건**입니다 — 플래그 열은 비었고, 각 행의 근거 열에 그 표면이 무엇이었는지가 남아 있습니다.

## heredoc pipeline

heredoc이 붙은 명령은 pipeline 전체를 한 항목으로 등재합니다.
기대 판정의 기준은 본문이 어디로 흘러가는가입니다 — **하류 실행 소비자**(`bash`·`sh` 류)나 **파일 sink**(실행 스크립트 생성)가 있으면 deny이고, 커밋 메시지처럼 실행되지 않는 소비자뿐이면 allow입니다.
면제 대상은 셋뿐입니다 — `git commit -F -`, operand 없는 `cat`, operand 없는 `tee`.
Phase 2의 양방향 픽스처 일곱(ⓐ~ⓖ)과 경계 픽스처는 `.claude/hooks/cmd-guard-surface.test.mjs`가 소유합니다.

|---|---|---|---|---|---|---|
| HD-01 | `git commit -F - <<'EOF'` + 본문 `fix: git push 재시도 로직 보강` | allow | allow | allow | | 커밋 메시지 · 실행 소비자 없음 · 파일 sink 없음 |

## 인용 벗기기와 세그먼트 분할

두 구현의 전처리가 다르고, 회귀와 오탐이 모두 이 차이에서 나왔습니다 — Phase 2가 양쪽의 장점만 남기는 방향으로 수리했습니다.

- **원본** — 명령 문자열을 `&&`·`||`·`;`·`|`·`&`·개행으로 나누고, 각 세그먼트를 공백으로 토큰화한 뒤 **토큰에서 따옴표 문자를 제거**합니다. 그래서 `"rm" -rf dist`와 `git reset "--hard"`를 잡습니다. 대신 인용 안의 본문도 명령으로 읽어 `git commit -m "a && rm -rf /"`를 오탐합니다.
- **Phase 1 시점의 현행** — 문자 단위로 훑으며 따옴표 안의 내용을 **세그먼트에서 통째로 버렸습니다**(Backlog 3). 그래서 커밋 메시지 오탐이 없는 대신, 인용으로 감싼 명령·플래그를 보지 못했습니다(RM-08·GR-02).
- **Phase 2 수리 후** — 따옴표는 세그먼트 분할에서만 경계로 쓰고(인용 안에서는 나누지 않음) 내용은 버리지 않으며, 토큰화 단계에서 따옴표 문자를 벗깁니다. 인용 우회는 잡히고, 인용문 오탐은 아래 명령 위치 판정이 막습니다.
- **명령 위치 판정** — 규칙은 세그먼트의 머리 토큰에만 적용합니다. git 계열은 원본도 머리 판정이고, Phase 2는 `rm`·`del`·`npm`·`gh`까지 같은 판정으로 통일했습니다. 머리 토큰은 `git.exe`·대문자 `Git`도 git으로 읽고, git 전역 옵션(`-C <경로>`·`--git-dir=…`)은 건너뜁니다.
- **명령 위치의 확장 둘** — 래퍼(`sudo`·`xargs` 류)는 다음 토큰으로 명령 위치를 넘기고, `find`의 `-exec`류도 다음 토큰이 명령입니다. 머리에서 이어질 때만 인정하므로 인용문 속 `sudo rm -rf`는 오탐하지 않습니다.
