# ROOT_LAYOUT — 저장소 루트에 무엇이 왜 있는가

> **이 문서가 소유하는 것**: 루트에 널려 있는 파일·폴더가 **방치가 아니라 계약**이라는 사실과, 각각이 *왜 루트여야만 하는가*의 기술적 근거.
> **명명 규범의 정본은 [ADR-039](adr/ADR-039-naming-convention.md)** — 여기는 그 규범의 「동결 경계」가 루트에서 어떻게 구체화되는지를 파일 단위로 편 것이다.
> **실측 기준일**: 2026-07-26 (NC 마일스톤 Phase 02).

---

## 왜 이 문서가 필요한가

루트를 보면 소문자 점파일과 대문자 `.md`와 카테고리 폴더가 뒤섞여 있어 **정리가 안 된 것처럼 보인다.** 실제로는 그중 **보정 없이 옮길 수 있는 파일이 0개**다. 이 사실이 어디에도 적혀 있지 않으면, 다음 세션이 선의로 "정리"하다가 빌드·테스트·훅을 동시에 부순다.

📌 **판정 기준은 ADR-039의 4축이며, 루트는 대부분 축0(통제권)과 축1(기계 계약)에서 결론이 난다** — 우리가 이름을 정할 수 없거나, 이름이 런타임에 해석되거나 둘 중 하나다.

## 1. 루트 파일 16개 — 전부 동결

| 파일 | 왜 루트여야 하는가 | 축 |
|---|---|---|
| `package.json` | **npm이 cwd에서 찾는다.** 옮기면 `npm run` 전체가 죽는다. 협상 대상이 아니다 | 축0 |
| `package-lock.json` | npm이 `package.json` **옆에서만** 인식한다 | 축0 |
| `tsconfig.json` | `tsc`·에디터·언어 서버의 기본 탐색 위치. 내용은 `references` 두 줄뿐이지만 **그 두 줄의 상대경로 기준점이 자기 위치**다 | 축1 |
| `tsconfig.node.json` | 위 `references`가 상대경로로 가리킨다. `99_Others/{scripts,tests}` 리터럴 포함(`:23-26`) — 옮기면 그 경로도 함께 틀어진다 | 축1 |
| `tsconfig.web.json` | 〃 (renderer 쪽) | 축1 |
| `electron.vite.config.ts` | electron-vite CLI가 **루트에서 이름으로 탐색**한다 | 축0 |
| `vitest.config.ts` | vitest 기본 탐색 위치 + `99_Others/tests/**` 리터럴(`:11`)의 상대 기준점 | 축1 |
| `playwright.config.ts` | playwright 기본 탐색 위치 + `testDir` 리터럴(`:20`)의 기준점 | 축1 |
| `.eslintrc.cjs` | ESLint가 **cwd에서 상위로 거슬러 올라가며** 찾는다. 하위로 내리면 루트 파일이 lint 대상에서 빠진다 | 축0 |
| `.gitignore` | git이 루트에서 인식(하위 배치는 그 폴더에만 적용) | 축0 |
| `.gitattributes` | 〃. ⚠️ **`.claude/hooks/**` 를 LF 줄바꿈으로 고정**하는 계약이 여기 산다 — Windows에서 훅이 실행되는 근거다 | 축0 |
| `dev.bat` | `%~dp0` 가 **배치파일 자기 위치**를 가리킨다. 옮기면 조용히 다른 폴더를 기준으로 돈다 | 축1 |
| `LICENSE` | 옮기면 GitHub의 **라이선스 자동 인식**을 잃는다(저장소 사이드바 표기) | 축0 |
| `README.md` | GitHub이 저장소 첫 화면에 렌더하는 위치 | 축0 |
| `CLAUDE.md` | **Claude Code가 루트에서 자동 로드**한다. 프로젝트 헌법의 진입점 | 축0 |
| `AGENTS.md` | **Codex가 루트에서 자동 로드**한다. Codex 어댑터의 진입점 | 축0 |

> ⭐ **읽는 법**: 축0은 *"우리가 정할 수 있는 이름이 아니다"*, 축1은 *"이름이 런타임에 해석된다"* 이다. 둘 다 **논쟁의 여지가 없다** — 취향이 아니라 도구의 요구사항이다.

## 2. 루트 폴더 12개

### 2-1. 카테고리 폴더 5개 (ADR-028 — 규칙 적합)

| 폴더 | 무엇 |
|---|---|
| `00_Documents/` | 기획·결정·규범·보고서 |
| `01_Phases/` | 마일스톤별 Phase 문서와 종결 기록 |
| `02_Source/` | 애플리케이션 코드 |
| `98_Management/` | 관리 구획 — OpenGate 배치파일(ADR-038) |
| `99_Others/` | 테스트·스크립트 등 부수물 |

⚠️ **`98_Management/Harness_OpenGate` 는 개명 대상이 아니다.** 이미 규칙 적합이고, 범위에 넣는 순간 **부트스트랩 자물쇠**에 걸린다 — 유지보수 창을 여는 플래그 경로가 `supervisor-guard.sh:42-43` 에 **문자열로 하드코딩**돼 있어, 그 폴더를 먼저 옮기면 창을 열어도 열리지 않아 남은 봉인 파일을 고칠 수 없게 된다. **범위 설계로 위험을 없애는 편이 관리하는 것보다 항상 싸다.**

### 2-2. 엔진·시크릿 폴더 4개 (동결 — 축0)

| 폴더 | 왜 이 이름이어야 하는가 |
|---|---|
| `.claude/` | Claude Code가 **이름으로 탐색**. 훅·에이전트·정책·스킬·상태 |
| `.codex/` | Codex가 이름으로 탐색. ⚠️ **CORE-12 — Claude는 읽기도 금지** |
| `.agents/` | 두 엔진 공용 스킬 브리지. Codex가 `$CWD/.agents/skills` 를 포함한 3경로를 탐색 |
| `.env/` | 시크릿 구역. ⚠️ **CORE-03 — 읽지 않는다.** 존재만 기록하고 내용은 열지 않는다 |

> 📌 `.env` 는 **파일이 아니라 폴더**다(2026-07-26 실측). 헌법·정책이 `.env*` 글롭으로 표기하는 이유이며, 글롭이라 파일/폴더 어느 쪽이어도 덮인다.

### 2-3. 도구 생성물 폴더 3개 (동결 — 축1·축2)

| 폴더 | 누가 만드나 | 왜 못 옮기나 |
|---|---|---|
| `artifacts/` | 도구 산출 | 어떤 설정도 출력 경로를 지정하지 않아 **기본값이 cwd 상대**로 떨어진다 |
| `out/` | electron-vite 빌드 | 〃 (`outDir` 미설정) |
| `test-results/` | playwright | 〃 (`outputDir` 미설정) |

⚠️ **루트 `artifacts/` 와 `00_Documents/Artifacts/` 는 서로 다른 것이다.** 전자는 도구 생성물(동결), 후자는 사람이 정리한 문서 자산(개명 대상 → `04_Artifacts`). 이름이 비슷해 **한쪽 규칙을 다른 쪽에 잘못 적용하기 쉬운 자리**라 여기 명시한다.

> ⚠️ 세 폴더 모두 `.gitignore` 매칭이라 **git 이력과 무관**하다. 즉 지워도 이력 손실이 없고, 다시 만들어진다.

## 3. 이 문서를 고쳐야 하는 때

- 루트에 **파일이나 폴더가 늘어날 때** — 늘어난 것이 왜 루트여야 하는지 한 줄을 못 쓰겠다면, 그건 루트에 있으면 안 된다는 뜻이다.
- 도구 설정에 **출력 경로가 명시될 때** — `outDir`/`outputDir` 를 지정하는 순간 §2-3의 동결 근거가 사라진다.
- ⚠️ **각 항목은 *왜 루트여야만 하는가*의 기술적 근거여야 한다.** "관례라서"·"원래 그랬어서"는 근거가 아니다 — 그렇게 쓰기 시작하면 이 문서는 설명이 아니라 변명이 된다.
