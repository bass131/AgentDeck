# M09 G4 — 사람 게이트와 모델 게이트 · 앱 안에서 루프를 돌리는 구동자와 화면

- 마일스톤: M09 (마일스톤 스펙 `01_Milestones/M09_AppLoop/00_마일스톤-스펙.md`) · 작성: 2026-11-19 · 상태: 실행 중 · 검증 강도: 강(앱 소스 50줄 이상, 권한 판정 노드 변경)
- 작업 브랜치: `feat/m09-g4-gates` · 기준 브랜치: `milestone/m09-app-loop`(`92c2d0e7`, G3 병합 뒤). G3 종결 기록을 함께 싣는다.

## 목표

앱에서 작업 저장소 하나를 골라 마일스톤 루프를 시작하면, 실행기가 앱 안에서 노드를 차례로 돌린다. 사람은 브레인스토밍 질문 카드에 답하고, 스펙 승인 카드에서 한 번 승인하고, 마일스톤 PR 카드의 「병합」 버튼으로 한 번 병합한다. 모델 게이트는 구현 문맥이 없는 검수 세션이 판정한다. 사람을 부르는 예외는 화면에 한 줄로 보인다. 연습 저장소 실주행(G5)에 필요한 앱 쪽 길이 모두 이 goal에서 생긴다.

## 범위

- **만들 것**
  - 루프 구동자(main) — 저장소별 `OpenedLoop`를 갖고 `step()`을 끝(사람 대기·CI 대기·멈춤·완료)까지 돌린다. 상태가 바뀔 때마다 화면에 밀어 준다. 앱을 끌 때 `stopApp`에서 닫고, 다시 켠 뒤 같은 저장소를 열면 생존 문서에서 이어 간다(`load`). CI 대기는 시간 간격으로 다시 `step()`한다.
  - IPC 묶음 `loop`(shared·renderer 새 도메인 폴더 `13_Loop`, main은 `05_Loop`) — 열기·시작·상태 읽기·사람 판정 넣기·질문 답·래치 풀기·닫기와 상태 push. 채널 수 고정 시험과 계약 시험을 맞춘다.
  - 브레인스토밍 노드의 카드 응답자 — `role: main` 노드 세션의 질문(AskUserQuestion)과 권한 카드를 화면 카드로 보내고 답을 세션에 돌려준다. 사람 속도라 이 노드에는 60분 시간 상한을 두지 않고 화면의 취소로 끝낸다. 다른 노드는 지금처럼 거부 응답자다.
  - 스펙 승인 카드 — `.agentdeck/milestone-spec.md` 본문과 그 sha256을 보이고, 승인·반려(사유)를 넣는다. 판정은 본 해시에 묶인다 — 실행기가 판정을 받을 때 파일 해시가 다르면 거부한다(병합 버튼의 「보인 SHA로만」과 같은 규칙).
  - 실물 `ReviewPort` — 노드마다 새 세션을 구현 문맥 없이 연다. 주는 것은 goal 문서와 실행기가 만든 diff(작업 트리 대 마일스톤 브랜치)뿐이다. 세션은 자격 없는 환경과 루프 잠금에 더해 읽기 전용 잠금(저장소 안 모든 쓰기 거부)으로 돈다. 판정은 마지막 줄 `VERDICT: pass|fail` 꼴만 받고 그 밖은 `fail`(fail-closed). `pass`는 검수한 트리 해시에 묶이고, 실행기는 커밋 직전 트리 해시가 같은지 다시 본다.
  - 예외 한 줄 표시 — `waiting(human|ci)`·`needs-user(reason)`·`halted`·래치를 화면 한 줄로 보인다(사유 원문, 래치 파일 경로 포함).
  - 마일스톤 PR 카드 — 실행기가 연 마일스톤 PR을 기존 `PrCard`(작업 저장소 `cwd`, 번호)로 보인다. 병합은 사람이 그 카드의 「병합」 버튼으로 하고, 실행기의 `milestone-merge` 게이트는 병합 사실로만 통과한다(G1 그대로).
  - 래치와 설정 스냅숏을 사람이 푸는 길 — 화면에 바뀐 키·파일을 보이고 사람이 「확인하고 풀기」를 누르면 실행기가 스냅숏을 새로 받고 래치를 지운다. 위험 키·grafts·`http_unix_socket`은 풀기에서도 계속 거부한다(G2 다시 열기 규칙 그대로).
  - 기준 브랜치 — 템플릿의 `base: "master"` 고정을 버리고 열 때 origin의 기본 브랜치(`refs/remotes/origin/HEAD`, 없으면 gh 저장소 정보)를 읽어 쓴다. 연습 저장소는 `main`이다.
  - goal PR 본문의 검증 줄 — 실행기가 goal PR을 만들 때 `.agentdeck/verification.md`의 그 goal 줄을 본문에 싣는다(G2 결정 대장 [AI], 사용자 3A 확인).
  - Backlog 3 인계 — 노드 세션의 설정 원천(`settingSources`)에서 사용자 MCP 서버가 실리지 않게 좁히거나 거부를 확인하고, 앱 「자동」 모드 허용 설정이 꺼져 있으면 루프 시작 전에 사유를 보이고 멈춘다. `close()` 취소는 FAIL로 세지 않고 멈춤으로 둔다.
- **건드릴 곳**
  - 판정 장치(헌법 3조 — 스펙 「건드릴 곳」): `98_Management/01_GateState/gate-config.json`의 `planPath`(1단계).
  - 판정 장치 밖: `02_Project/00_Source/main/05_Loop/`, `main/04_Claude/permission/`(읽기 전용 잠금), `main/03_Agent`·`main/04_Claude`의 최소 변경, `main/00_App/`(배선), `main/01_Ipc/`, `shared/13_Loop/`(새), `shared/ipcContract.ts`·`shared/01_Ipc/`, `renderer/src/13_Loop/`(새), `renderer/src/01_Ipc/index.ts`, 루프 화면을 여는 최소 진입점(`renderer/src/00_App` 또는 기존 메뉴), `02_Project/01_TestCode/`, `01_Milestones/M09_AppLoop/`.
- **하지 않을 것**: 연습 저장소 실주행(G5), 앱 안 현황판·알림·사용량 한도(M10), 그래프 편집 화면, 새 의존성, CLI 하네스 변경, 이 저장소에서 원격 쓰기를 하는 시험, 앱이 실행기에 별도 토큰을 넣는 길(사용자 결정 「A 실주행 동안만 바꿔 둔다」로 필요 없어짐).
- **완료조건**
  - 시험이 가짜 세션·검수와 실제 git(임시 저장소와 bare 원격)으로 구동자를 돌려 브레인스토밍 질문 → 화면 답 → 스펙 승인 → goal 둘 → 검수 → 병합 → 마일스톤 PR까지 가고, 도중에 구동자를 새로 만들어도 이어 가는 것을 본다.
  - 시험이 스펙 승인 판정은 본 해시와 파일이 다르면 거부되고, 검수 `pass` 뒤 트리가 바뀌면 커밋하지 않고 멈추며, 검수 출력이 꼴에 맞지 않으면 `fail`인 것을 본다.
  - 시험이 읽기 전용 잠금이 검수 세션의 저장소 안 쓰기와 원격 쓰기를 거부하고 읽기 명령은 막지 않는 것을 본다.
  - renderer 시험이 질문 카드·스펙 승인 카드·예외 한 줄·마일스톤 PR 카드·래치 풀기 카드가 상태에 따라 보이고 답이 IPC로 가는 것을 본다.
  - 하드 게이트 다섯 종 exit 0, `npm test` 실패 0, 독립 검수 반영, goal PR의 `hard-gates` 통과, 정형 절차로 병합.
