### ADR-028: 루트 디렉토리 재구성 — 번호접두 *최상위* 카테고리 (`00.Documents`·`01.Phases`·`02.Source`·`99.Others`)

**결정**: 레포 루트의 콘텐츠 폴더를 번호접두 카테고리 4개로 묶는다 (ADR-027의 "번호접두 시각순서" 철학을 *최상위*로 확장). 구분자=`.`(점), 정렬=논리/중요도 순.

| 옛 경로 | 새 경로 | 비고 |
|---|---|---|
| `docs/` | `00.Documents/` | 하네스 brain (PRD·ARCHITECTURE·ADR·UI…) |
| `phases/` | `01.Phases/` | `/work:plan` Phase 정의 |
| `src/` | `02.Source/` | 앱 소스 (`main`·`preload`·`renderer`·`shared` 내부 이름 불변) |
| `tests/` · `scripts/` · `out/` | `99.Others/{tests,scripts,out}/` | 테스트·빌드보조·산출물 |

- **ADR-027 제외규칙의 *상위 적용***: ADR-027은 "최상위 `src/{main,preload,renderer,shared}`는 번호접두 *제외*"라 했다. 본 ADR은 그 상위인 `src/` 컨테이너 자체를 `02.Source/`로 옮길 뿐, 내부 4폴더 이름은 불변. electron-vite 진입점·`@shared`/`@renderer` alias는 *타깃 경로*만 갱신(`src/`→`02.Source/`).
- **구분자 `.`(점) 선택**: ADR-027 하위폴더는 `_`(언더바)였으나 최상위는 `.`으로 시각 구분 강화(영호 선택). 경로 세그먼트 *중간*의 점은 확장자가 아니므로 모듈 해석 무탈.

**이유**: 루트를 열었을 때 "문서 → Phase → 소스 → 기타" 순으로 파일시스템이 답하게 함(탐색·온보딩 비용↓). 영호 직접 폴더 정리.

**트레이드오프 / 불변**:
- (⚠️ 큰 단점 — 생태계 마찰) `src/`는 JS/Electron 사실상 표준 관례. `02.Source/`는 모든 도구·예제·신규 기여자의 기본 가정과 *영구적으로* 어긋난다(신규 도구 도입·온보딩 시 반복 마찰). 정리정돈의 시각적 명료성 ↔ 도구 생태계 영구 마찰의 교환 — 영호 단독 결정으로 수용.
- (이동 비용) 테스트→소스 상대 import **1192곳** 깊이보정(`../../src`→`../../../02.Source`) + cwd기준 소스-읽기 10곳 + config 8개(electron.vite·tsconfig[node/web]·vitest·playwright·package.json·eslint·gitignore) 배선.
- (⚠️ hook 리터럴 함정 — ADR-027 재확인) `risk-detector`·`tdd-guard`·`convention-size-guard`·`reviewer-auto-trigger`의 `*src/*` glob·`$PROJ/tests` lookup은 rename에 안 안전 → 동반 갱신(`.claude/hooks/**`=영호 단독, 수동 승인 하 적용). `tdd-guard` 테스트 lookup·`reviewer-auto-trigger` 경계glob 2건은 에이전트 자동매핑이 놓쳐 직접 정독으로 포착.
- (불변) `@shared`/`@renderer` alias = *타깃 경로*만 갱신, 별칭명 불변 → 소스 내부 import 무변경. 신뢰 경계·IPC 단일정의·엔진 추상화(ADR-003) 불변. 빌드 산출물 `out/`은 루트 유지(electron-vite 기본값 — gitignore 재생성물이라 카테고리화 실익 < 도구 마찰).

**위험도**: [M] — 구조 재배치(빌드·하네스 경로 동반, 기존 결정/거동 불변).

**현황(2026-06-30)**: ✅ **영호 직접 폴더 이동 + AI 배선**. 브랜치 `feature/rf1-trackC`. 검증: typecheck green / vitest **3619 통과(거동 불변, 기준선 일치)** / electron-vite build 3타깃 green. 분할 커밋(빌드배선 → hook기능 → 하네스docs → 본 ADR). 역사적 기록(기존 ADR 항목·`.claude/CHANGELOG.md`)은 옛 `src/`/`docs/` 경로를 *그대로 보존* — 본 ADR이 옛→새 매핑을 제공.

### 개정 1 (2026-07-25, HR2 P07~P09 — 영호 승인): 구분자 `.`(점) → `_`(언더바) 전환

**철회(supersede)**: 원 결정 `:13`의 **구분자 선택**을 철회한다.
> *"구분자 `.`(점) 선택: ADR-027 하위폴더는 `_`(언더바)였으나 최상위는 `.`으로 시각 구분 강화(영호 선택)."*

**존치**: 번호접두 카테고리 체계 · 정렬 순서(논리/중요도) · 내부 4폴더 이름 불변 · alias 별칭명 불변 · 원 ADR의 트레이드오프 서술 전부(생태계 마찰은 **해소되지 않는다** — 아래 참조).

#### 개명 매핑표 (P08이 이 표를 근거로 `git mv` 실행)

| 옛 경로 | 새 경로 |
|---|---|
| `00.Documents/` | `00_Documents/` |
| `01.Phases/` | `01_Phases/` |
| `02.Source/` | `02_Source/` |
| `98.Management/` | `98_Management/` |
| `99.Others/` | `99_Others/` |

> `98.Management`는 원 ADR(2026-06-30) 이후 ADR-038(2026-07-24)로 신설된 폴더라 원 표에 없다. 개명 대상에는 포함된다.

#### 이유 — "시각 구분"보다 강한 근거가 나중에 드러났다

원 결정이 `.`을 고른 이유는 **최상위와 하위의 시각 구분**이었다. 이번에 그것을 포기하는 이유는 취향 통일만이 아니다.

⚠️ **`.`은 정규식 메타문자다.** 훅이 경로를 판정할 때 `00\.documents`처럼 **이스케이프해야 하고**, 그 이스케이프가 실측 고장의 구조적 원인이었다 — `shell-policy.mjs:220-223,244`의 정규식이 경로를 못 알아보면 `'unrelated'`로 판정해 **조용히 통과시킨다**(fail-open). 에러도 로그도 남지 않는다. `_`는 메타문자가 아니므로 이 함정 자체가 사라진다.

즉 이번 전환의 이득은 **① 구분자 1종 통일(ADR-027 하위폴더와 일치) ② 훅 경로 판정에서 이스케이프 소멸**이고, 후자가 더 실질적이다.

**트레이드오프**:
- **(잃는 것 — 원 결정이 명시적으로 원했던 것)** 최상위/하위의 **시각 구분 상실**. 루트를 열었을 때 `00_Documents`와 하위 `01_agents`가 같은 모양이 된다. 영호가 그 구분보다 통일을 택했다.
- **(⚠️ 해소되지 않는 것 — 과장 금지)** 원 ADR `:18`이 *"큰 단점"* 으로 적은 **생태계 마찰은 그대로다.** `02_Source/`도 `src/`가 아니다. 이번 변경은 비표준 A에서 비표준 B로 가는 것이지 **표준 복귀가 아니다.**
- **(이동 비용)** 추적 파일 **698개 / 3,111줄**, 테스트 상대 import **814건 / 434파일**(`git mv`는 하나도 안 고친다), 빌드 체인 7파일, 런타임 경로 리터럴 3자 동기.
- **(이력 단절)** `git mv`의 이력 보존은 **파일 단위 `--follow` 한정**이다(실측: 디렉토리 로그는 1커밋으로 접힌다). 보완 = 최상위 개명 항법 노트 신설(P08).

#### ⚠️ hook 리터럴 함정 — **2회차**다

원 ADR `:20`이 이미 같은 함정을 기록했다:
> *"`*src/*` glob·`$PROJ/tests` lookup은 rename에 안 안전 → 동반 갱신. `tdd-guard` 테스트 lookup·`reviewer-auto-trigger` 경계glob 2건은 **에이전트 자동매핑이 놓쳐 직접 정독으로 포착**."*

이번 P07이 마주한 *"부분 수정이 가장 나쁘다"*(`tdd-guard`의 `:30` 대상 판정과 `:37-40` 테스트 탐색을 짝으로 고쳐야 하는 문제)와 **정확히 같은 사고의 2회차**다. 기록해 두는 이유는 3회차를 막기 위해서다 — 개명 시 훅 경로 리터럴은 **grep 자동매핑을 신뢰하지 않고 전수 정독**한다.

⚠️ **추가로, 이번에는 자기 자신을 잠그는 경로가 하나 더 있다** — `supervisor-guard.sh:30`의 `GATE_FLAG`가 `98.Management`를 하드코딩한다. 그 폴더를 먼저 옮기면 **OpenGate를 열어도 열리지 않아** 남은 봉인 파일을 고칠 수 없게 된다(부트스트랩 자물쇠). 그래서 **훅 경로 선행(P07) → 개명(P08)** 순서가 강제된다.

**위험도**: [H] — 구조 재배치 + 봉인 경로 동반(하네스 판정 정규식이 걸린다). 원 ADR의 [M]보다 높은 이유는 이번엔 **봉인 자체가 경로에 의존**하기 때문이다.

**관련**: ADR-027(하위폴더 `_` 컨벤션 — 통일 대상) · ADR-037/038(봉인 경로) · `01.Phases/21_HR2-opus5-renewal/07-hook-path-precedence.md`(선행 근거) · `08-folder-rename.md`(실행).

**현황(2026-07-25)**: 채택. 실행 = HR2 P07(훅 경로 선행) → P08(`git mv` + 빌드 체인) → P09(대량 치환) → P10(Codex 대칭, 실행 주체 별도).
