## 1. 아키텍처

1. **단일 패널과 멀티 패널이 실행 로직을 따로 구현했고 동작이 이미 갈라졌다** [실측]. 전송은 `renderer/src/store/slices/runtime.ts:62-157`와 `store/panelSession.ts:274-339`, 중단은 세 벌(`runtime.ts:159-173`, `panelSession.ts:382-387`, `:633-638`), 권한 응답도 세 벌이다. 단일 쪽만 중단 시 열린 메시지를 끊고 대기열을 비운다. 질문 응답은 단일 쪽에만 있다. 같은 상태가 전역 store, `bgRuns`, panelSession 모듈 전역 Map 세 곳에 산다.
2. **UI 계층도 단일·멀티가 복제됐다** [실측]. 스레드 렌더(`Conversation.tsx:534-609` 대 `shell/panel/PanelView.tsx:277-333`, 패널 쪽에 `notice`·`compact-boundary` 분기 없음), 선택기(`PanelPicker.tsx`는 `ComposerPicker.tsx`의 사본), 입력 팔레트(`hooks/useInputPalettes.ts` 443줄이 단일 쪽 훅 셋 302줄을 재구현), 입력창(`PanelComposer.tsx` 대 `Composer.tsx`). `'multi'/'single'` 분기가 Sidebar 12회, Shell 6회다.
3. **Claude 전용 코드가 중립 계층에 섞였다** [실측]. `main/01_agents` 23파일 중 18개가 Claude 전용이고, `07_engine` 전체와 `05_settings`(`.claude/skills`·commands·MCP)도 Claude 전용이다. 백엔드 교체 인터페이스(`AgentBackend`)가 이 코드들을 감싸지 못한다.
4. **순환 의존** [실측]. `main/01_agents` ⇄ `main/07_engine`(`backendStatus.ts`가 registry를 import, 반대는 동적 import), `main/02_fs/diff.ts` ⇄ `git.ts`, renderer feature 다섯 쌍(agent↔conversation, agent↔shell, conversation↔notice, conversation↔file, file↔layout). 경계를 강제하는 eslint 규칙(`no-restricted-imports`)이 없다.
5. **IPC 계층에 도메인 로직이 있다** [실측]. `main/00_ipc/agentRuns.ts`(RunManager 219줄), `engineCheckUpdate.ts`(버전 비교), `handlers/multi.ts:27-66`(병합 로직). 반대로 `main/06_window/controls.ts`는 ipcMain 채널 10개를 직접 등록한다.
6. **조립 지점이 셋이고 인스턴스가 이중으로 생긴다** [실측]. `main/index.ts`, `00_ipc/context.ts`(전역 싱글톤 6개), `registerIpc`. `ClaudeCodeBackend.ts:66,74`는 호출마다 skills·MCP store를 새로 만든다. 워크스페이스 루트의 원천도 둘이다(`ipcState.currentWorkspaceRoot`와 `roots`).
7. **계약 모듈과 구현 폴더가 어긋난다** [실측]. git 계약 ↔ `main/02_fs/git.ts`, `usage.get`(personalization 계약) ↔ `main/07_engine/usage.ts`, engine 계약 안의 `app.getVersion`·`backend.list`, fs 계약 안의 `image.saveData`·`dialog.pickFolder`. 채널 값의 namespace가 모듈 이름과 다른 경우가 14개다.
8. **renderer의 서랍 구분이 무너진 곳** [실측]. `lib/` 53파일 중 24개는 소비 feature가 하나뿐이다. `*SampleData.ts` 파일이 실제 타입과 상수의 거처다(`multiAgentSampleData`의 `PickerState` 등). 단일 화면은 `layout/Shell.tsx`, 멀티 화면은 `features/shell/MultiWorkspace.tsx`에 있다. `features/notice`에 엔진 업데이트 게이트와 실행 알림이 함께 있다.

## 2. 컨벤션

- **테스트 이름의 37~44%가 과거 작업 ID다** [실측]. vitest 417개 중 155개(37.2%), renderer 260개 중 113개(43.5%), agents 85개 중 40개(47%). 계열은 gap·lr·m·bf·cp·tg 외 13종이다. 같은 대상이 여러 이름으로 흩어졌다(panelSession을 import하는 테스트 40개, repl 계열 8개, continuity 계열 7개).
- **테스트 배치에 소스 대응 규칙이 없다** [실측]. renderer 260, agents 85, main 53파일이 각각 한 폴더에 평평하다. 폴더까지 소스와 대응하는 테스트는 64개뿐이다. `01_TestCode/agents/`는 사실상 `main/01_agents`의 테스트다.
- **폴더 프리픽스가 사용자 규칙 `00_Xx`와 다르다** [실측]. main은 `00_ipc`처럼 소문자, renderer와 shared는 프리픽스가 없다. 번호에 의미가 없다.
- **경로 별칭이 정의만 되고 쓰이지 않는다** [실측]. `@shared`·`@renderer`가 tsconfig에 있지만 사용 0건이고, vitest와 electron-vite의 main·preload 설정에는 별칭이 없다. renderer는 `../../../../../shared`까지 올라간다.
- **오류 처리 규약이 없다** [실측]. 빈 `catch {}`가 main 26곳, renderer 38곳이다. 핸들러 실패 표현이 여섯 가지다(`throw`, `{accepted:false}`, `{ok:false}`, `[]`, `null`, `{path:''}`).
- 파일명 대소문자가 섞였다(클래스 파일의 Pascal/camel 혼용, feature 폴더 `whats-new`만 kebab). 이름 접미사 `*Request`와 `*Req`가 공존한다 [실측].

## 3. 인터페이스

- **채널 하나의 타입을 세 곳에서 손으로 맞춘다** [실측]. shared의 요청·응답 타입, preload의 `Promise<X>` 시그니처, main 핸들러의 반환 주석이 따로다. 핸들러 70개 중 69개가 반환 타입을 각자 적는다. 어긋나도 컴파일러가 못 잡는다.
- **renderer가 `window.api`를 직접 부른다** [실측]. 33파일(컴포넌트 15, store 10), 메서드 57종이다. 감싼 계층은 `lib/prefs.ts` 하나다. 테스트 약 91파일이 `window.api` mock을 각자 만든다 [근사 실측].
- **같은 개념의 타입이 여러 벌이다** [실측]. `AgentRunInput`과 `AgentRunRequest`(필드 10개 복사), 권한 응답 union 세 벌, `{model,effort,mode}` 모양 여섯 벌, `'user'|'assistant'` 세 벌, `QueryFn` 두 시그니처.
- **권한 모드 매핑 표가 네 벌이고 서로 어긋난다** [실측]. `main/01_agents/runArgs.ts:10`은 `auto→acceptEdits`, `claudeAgentRun.ts:31`은 `auto→auto`다. 시작할 때와 실행 중 전환할 때 `auto`의 의미가 다르다. 의도인지는 코드로 판정할 수 없다 [추측 보류]. M06의 권한 처리와 직결된다.
- preload 노출 API 76개의 모양이 제각각이다 — 네임스페이스(`git.*`, `lsp.*`)와 평면 이름이 섞이고, 인자도 요청 객체와 위치 인자가 섞였다 [실측]. 응답 확인 모양이 `{accepted}`와 `{ok}` 두 가지다.
- AgentEvent 29종 중 `'model-fallback'`만 kebab이고, main·renderer는 이름 붙은 이벤트 타입을 쓰지 않고 `Extract<…>`로 27번 다시 유도한다 [실측].

## 5. 재편에 걸리는 장치 [실측]

- 테스트가 소스를 상대 경로로 1,247건 가리킨다(`await import(` 898회, `vi.mock(` 125회). `vi.mock` 경로 문자열은 타입체크가 못 보며, 틀리면 mock이 조용히 빠진다.
- 소스 파일을 문자열 경로로 읽는 테스트가 13개 이상이다(csp, theme, stream-render-parity, `claude-backend-supported-commands`, `mainDomains.smoke` 등).
- `collection-baseline.test.ts`는 vitest include 글롭 두 줄과 테스트 파일 수 417개를 고정한다. 테스트를 `01_TestCode` 안에서만 옮기면 통과하고, 개수가 바뀌면 고쳐야 한다.
- 판정 장치 `.claude/hooks/33_tdd-guard.cjs:31`은 테스트 경로를 `02_project/01_testcode/`로 고정한다. 테스트 루트를 유지하면 건드릴 필요가 없다.
- 빌드 진입점 셋(`main/index.ts`, `preload/index.ts`, `renderer/index.html`)과 `main/index.ts:24`의 `'../preload/index.js'`는 경로에 묶였다. 옮기지 않으면 빌드 설정은 별칭 추가만 필요하다.
- 배럴 주석에 공개 심볼 개수가 박혀 있고 capsule smoke 9개가 그 개수를 단언한다. CSS가 전역이라 import 순서가 바뀌면 충돌 규칙의 승자가 바뀐다.
