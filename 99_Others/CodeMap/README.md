# AgentDeck 코드 지도

AgentDeck 앱 소스(`02_Project/00_Source`)를 읽어 만든 HTML 한 장짜리 코드 지도다. 프로세스부터 도메인 폴더, 파일, 클래스·함수·컴포넌트, 멤버 순서로 한 단계씩 펼쳐 볼 수 있다. 고른 위치의 소스를 줄 번호와 구문 강조로 함께 보여 준다. 처음 보는 사람을 위해 폴더 설명, 메시지 흐름 따라 읽기, 컨벤션 예시 코드도 넣었다. 저장소는 읽기만 하고, 결과물은 모두 이 폴더에 둔다.

## 다시 만들기

저장소 루트에서:

```sh
cd 99_Others/CodeMap
node extract.mjs && node build.mjs
```

- **이 폴더 안에서 실행한다.** 소스·TypeScript 경로와 `codemap.json`, 템플릿 읽기는 스크립트 위치 기준이라 어디서 불러도 같지만, `descriptions.json`·`guide.json` 읽기와 `codemap.html` 쓰기는 현재 폴더 기준이다.
- 결과물 `codemap.json`·`codemap.html`은 `.gitignore`가 막는다. 커밋하지 않고 필요할 때 다시 만든다.

- `extract.mjs`는 소스를 읽어 `codemap.json`을 만든다.
  - TypeScript 컴파일러는 저장소의 `node_modules\typescript`를 `require`로 빌려 쓴다. 따로 설치할 것은 없다.
  - 손으로 쓴 `descriptions.json`(폴더·파일 설명)과 `guide.json`(따라 읽기·컨벤션 예시)을 합친다.
  - 예시 코드 조각은 줄 번호가 아니라 **기준 문자열(anchor)** 로 찾는다. 소스가 바뀌어 줄이 밀려도 따라간다. 기준 문자열을 못 찾거나 두 번 이상 나오면 실행 끝에 「경고」로 알려 준다.
  - 경로를 바꾸려면 `node extract.mjs --src <00_Source 경로> --ts <typescript 패키지 경로> --out codemap.json --desc descriptions.json --guide guide.json`을 쓴다.
- `build.mjs`는 `codemap.template.html`에 JSON과 소스 원문을 넣어 `codemap.html`을 만든다.
  - 소스 원문 287개(약 962KB)는 gzip으로 묶은 뒤 base64로 바꿔 넣는다. 이렇게 하면 약 311KB가 된다.
  - 브라우저가 내장 `DecompressionStream`으로 이를 푼다. 외부 라이브러리나 CDN을 쓰지 않아서 오프라인으로 열린다.

## 보는 법

브라우저로 이 폴더의 `codemap.html`을 연다(예: `file:///C:/Dev/AgentDeck/99_Others/CodeMap/codemap.html`). 처음이면 오른쪽 「처음이라면」 안내대로 **따라 읽기 → 트리 → 컨벤션** 순서로 보면 덜 헤맨다.

- **구조 트리**
  - 프로세스·도메인·폴더·파일 아래에 회색 줄로 「이 폴더가 하는 일」이 나온다(`descriptions.json`).
  - 이름을 누르면 그 노드가 펼쳐지고 상세와 코드가 뜬다. 동그라미나 `▸ n`을 누르면 접기와 펼치기만 한다.
  - 「펼치기」 버튼으로 프로세스·도메인·파일·선언·멤버 단계까지 한 번에 펼친다.
  - 「모양」의 기본값은 「자동」이다.
    - 칸 너비에 들어가면 가로로 뻗는 **그래프**로 그린다.
    - 들어가지 않으면 들여쓰기 **목록**으로 그린다.
    - 그래프나 목록으로 고정할 수도 있다.
  - 따라 읽기 정거장인 선언에는 `◆n` 표시가 붙는다.
  - **영역 색**: 4개 프로세스는 늘 같은 색이다.
    - main 주황, preload 보라, renderer 파랑, shared 초록
    - 트리 행 왼쪽 끝의 색 띠, 경로 줄의 배지, 상세·코드 칸 위쪽 테두리가 모두 이 색을 쓴다. 그래서 트리 깊이 들어가도 지금 어느 영역인지 보인다.
  - **이름 옆 알약**
    - 첫 알약은 한 단어 종류다: 타입·함수·훅·컴포넌트·클래스·필드·메서드·내부 함수·반환 메서드 등
    - 둘째 알약은 공개 범위다.
      - `export`: 파란 실선. 다른 파일에서 쓸 수 있다.
      - `파일 안`: 점선. export되지 않았다.
      - `내부`: 점선. 함수 안 클로저다.
      - `반환 객체`: 주황 테두리. factory가 돌려주는 객체의 멤버다.
  - **순서: 종류별**(기본)
    - 파일 안 선언을 타입·인터페이스 → 상수·값 → 함수 → 훅 → React 컴포넌트 → 클래스 묶음으로 나눈다. 각 묶음에 개수 머리가 붙는다.
    - 묶음 안은 export 먼저, 그다음 이름순이다.
    - 클래스 멤버는 생성자 → 필드 → 메서드로 묶는다. 각 묶음 안은 static 먼저, 그다음 public → protected → private 순서다.
    - 묶음 머리를 누르면 그 묶음만 접힌다. 「소스 순서」를 고르면 원래 적힌 순서로 돌아간다.
  - **factory·클로저 안쪽**: 함수 본문의 내부 함수·지역 값·훅과 함께, 그 함수가 `return { … }`으로 돌려주는 객체의 메서드·속성도 자식으로 보인다. 예를 들어 `createRunManager` 아래에 `lastUserContent`·`cleanup`(내부)과 `start`·`abort`…(반환 객체)가 있다. zustand 슬라이스 `(set, get) => ({ … })`의 액션도 같은 방식으로 보인다.
- **상세 패널**
  - 맨 위에 영역 배지와 공개 범위 배지(뜻 풀이 포함)가 나온다.
  - 선언·멤버에는 **소유** 줄이 붙는다.
    - 예: `소유 클래스 ClaudeCodeBackend (main › 04_Claude › ClaudeCodeBackend.ts)`
    - 그 아래에 역할 한 문장이 붙는다. 예: private 필드다 / 이 함수 안에서만 보이는 클로저다 / 돌려주는 객체의 메서드다 / 렌더할 때마다 실행되는 훅이다.
  - 그다음 「무슨 일을 하나」 설명이 나온다. 따라 읽기 정거장이면 그 정거장 설명도 나온다.
  - 맨 아래에 **쓰는 곳**이 나온다.
    - 이 파일이나 선언을 import하는 파일을 영역별로 묶어 보여 준다.
    - `index.ts` 같은 다시 내보내기를 한 단계 따라가고, 「○○ 거쳐」로 표시한다.
    - 멤버와 내부 선언은 따로 import되지 않으므로 소유자를 쓰는 파일을 보여 준다.
  - 그 아래에 종류별 정보가 나온다.
    - 클래스: 멤버 표
    - 함수·컴포넌트: 시그니처·훅
    - 파일: import 양방향
    - 도메인: 도메인 의존
- **코드 보기**
  - 파일·선언·멤버를 고르면 그 파일 소스가 줄 번호와 구문 강조로 나온다. 고른 범위는 노란 띠로 강조하고 그 줄로 스크롤한다.
  - 소스 안의 import 경로 문자열(밑줄 점선)을 누르면 그 파일로 간다. 「트리에서」는 지금 파일을 트리에서 고르고, 「줄 바꿈」은 긴 줄을 접는다.
  - 구문 강조는 직접 짠 간단한 토크나이저다. 주석·문자열·템플릿·숫자·키워드·타입·함수 호출·JSX 태그·정규식을 칠한다.
- **따라 읽기**: 입력창에서 보낸 메시지 하나가 어디를 지나는지 8정거장으로 보여 준다.
  - 각 정거장에는 파일·함수, 「여기서 하는 일」, 「왜 여기서 나뉘었나」, 실제 코드 조각이 있다.
  - 「트리·코드에서 이 정거장 보기」를 누르면 트리 위에 따라 읽기 막대(이전·다음·목록·닫기)가 뜬다. 동시에 트리에서 그 노드가 강조되고, 코드 칸이 조각 범위를 연다.
- **컨벤션**
  - 위쪽에 「이 프로젝트는 이렇게 쓴다」 8가지가 실제 코드 조각과 함께 있다. 각 항목에는 대표 파일 1개와 이유 한 문장이 붙는다. 이유의 근거가 코드나 주석에 없으면 「근거 없음」이라고 적었다.
  - 가운데 「관찰 — 한 파일 안에 섞여 있는 곳」은 규칙 위반이 아니라 읽기 헷갈리는 곳을 파일 이름과 함께 모은 것이다.
    - 타입과 로직이 번갈아 나오는 파일
    - 화면 파일의 로직 export
    - 화면 파일 안 모듈 상태
    - 화면과 훅이 한 파일에 있는 곳
    - `state/` 파일 안 React 훅
  - 아래쪽에는 1차의 숫자 통계가 그대로 있다.
- **도메인 의존**: 프로세스별 도메인×도메인 import 행렬과 프로세스 사이 요약이 있다. 칸을 누르면 실제 import 목록이 나온다.
- **검색·지금 위치·테마**: 1차와 같다. 검색은 접힌 곳까지 찾고, 경로 줄을 누르면 그 단계로 간다. 「◐ 테마」로 다크와 라이트를 바꾼다.

### 화면 너비에 따른 배치

| 창 너비 | 배치 |
|---|---|
| 1500px 이상 | 3단: 트리 \| 상세 \| 코드 |
| 900–1499px | 2단: 트리 \| (상세·코드 탭) |
| 900px 미만 | 1단: 트리·상세·코드 탭 |

- 칸 너비는 `minmax`와 비율(`fr`)로 정한다. 글자 크기와 여백 일부는 `clamp`로 정한다.
- 페이지 가로 스크롤은 없다. 코드 보기와 예시 코드 조각 안의 긴 줄만 가로로 스크롤한다.
- 범례는 접을 수 있다. 좁은 화면에서는 처음부터 접혀 있다.

### 바로가기 주소(URL 해시)

예를 들어 `codemap.html#tour=4`는 따라 읽기 4번 정거장으로 바로 연다. `codemap.html#sel=main%2F04_Claude%2FClaudeCodeBackend.ts%3A%3AClaudeCodeBackend`는 그 클래스를 고른 상태로 연다. 쓸 수 있는 키는 아래와 같다.

- `view=tour|conv|deps`
- `sel=<노드 키>`
- `tour=1..8`
- `pane=detail|code|tree` (좁은 화면에서 처음 보일 탭)
- `shape=graph|list`
- `order=source` (기본은 종류별)
- `level=1..5` (1 프로세스, 2 도메인, 3 파일, 4 선언, 5 멤버까지)
- `theme=dark|light`
- `q=검색어`
- `proc=renderer`
- `mode=runtime`

## 수치 읽는 법

- 「도메인 33」은 프로세스×도메인 폴더 쌍의 수다. 예를 들어 `main/03_Agent`와 `shared/03_Agent`는 따로 센다.
- 「함수」에는 React 컴포넌트가 빠져 있고 훅(`use…`)은 들어 있다.
- 의존 행렬의 칸은 「파일→파일 import 연결」 수다. 한 파일이 같은 대상 파일에서 이름을 여러 개 가져와도 1로 센다.
- 이름 규칙의 「기대 꼴」은 저장소 문서에 명문화된 것이 없다. 그래서 일반 TypeScript·React 관례로 추론했다.
- `≈`가 붙은 타입은 타입 표기가 없어서 초기값으로 짐작한 것이다.
- 추출은 구문 트리만 읽는다. 타입 검사기를 쓰지 않으므로 추론 타입이나 상속받은 멤버는 나오지 않는다.

## 파일

| 파일 | 내용 |
|---|---|
| `research.md` | 도구 조사와 결론 |
| `extract.mjs` | 추출기 (소스 + 설명 + 가이드 → `codemap.json`) |
| `descriptions.json` | 손으로 쓴 설명: 프로세스 4, 도메인 33, 주요 폴더·파일 10 |
| `guide.json` | 손으로 쓴 따라 읽기 8정거장과 컨벤션 예시 8개. 코드 조각은 기준 문자열로 지정한다 |
| `build.mjs` | HTML 빌더 (`codemap.json` + 소스 원문 gzip + 템플릿 → `codemap.html`) |
| `codemap.template.html` | 화면 코드 (바닐라 JS + SVG, 라이브러리 없음) |
| `codemap.json` | 추출 결과 (약 1.5MB) |
| `codemap.html` | 최종 결과. 데이터와 소스를 내장한 약 2.0MB 파일이다 |
| `shots/` | 확인용 스크린샷 |
