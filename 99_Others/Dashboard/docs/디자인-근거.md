# 현황판 디자인 근거와 참고한 패턴

README 「화면 구성」에서 분화했다(M05 H6, 2026-11-15). README가 250줄 상한에 닿아 이 절을 옮겼다.

## 시각 언어

시각 언어(색의 뜻, 토큰, 글꼴, 움직임 원칙)는 사용자가 승인한 `C:\Dev\Second_Brain_Dashboard\design\DESIGN.md`를 따른다.
영역 머리의 영문 대문자는 내리고 한국어 제목만 남겼다. 좁은 폭에서 한국어 본문을 먼저 읽게 하려는 것이고, 본보기와 다른 점이다.
색은 다섯 뜻만 쓴다. 노랑은 사용자가 할 일, 빨강은 깨짐·멈춤, 초록은 완료, 파랑은 진행 중·방금 바뀜, 회색은 쉼·대기다.
H6의 큰 카드·링·숫자 카드도 이 다섯 토큰(`--todo`·`--broken`·`--ok`·`--info`·`--ink-3`)과 그 옅은 면(`*-tint`)만 쓴다. 새 색 토큰은 없다.

## 참고한 공개 패턴

구성·상호작용은 아래 공개 자료의 패턴을 참고해 직접 구현했다. 코드와 에셋은 가져오지 않았다.

- GitLab Pajamas 「Mini pipeline graph」 — 단계 상태를 아이콘 줄로 압축하고 전체 상태는 따로 배지로 둔다 → goal 칩 줄.
- Tekton Dashboard 로그 보기 — 진행 중인 것만 펼치고 나머지는 접으며 접기 상태를 유지한다 → 「원문 보기」와 기억되는 접기 상태.
- openstatus 「Four iterations of an incident timeline」 — 최신순, 중요한 사건은 카드, 시스템 사건은 한 줄 → 막은 검사 카드와 묶인 통과 줄.
- Dawnholder 현황판(`C:\Dev\DawnHolder_Dashboard`) — 한눈에 상태가 보이는 색 면과 숫자 → H6의 「지금 하는 일」 큰 카드, 진척 링, 숫자 카드.

## 움직임

움직임은 실제 사건에만 묶는다: 값이 바뀐 항목의 파랑 변경 선, 바뀐 영역의 머리 선, 단계 상태가 바뀐 표시의 한 번 튐, 접기를 펼칠 때의 내려앉음.
같은 내용이면 영역을 다시 쓰지 않으므로 훅 기록이 초마다 들어와도 다른 영역은 깜빡이지 않는다. `prefers-reduced-motion`이면 모두 끈다.

H6의 등장 동작(큰 카드, 진척 링의 호, goal 칩)은 CSS `animation`이 아니다. 「지금」 영역은 글자 하나만 달라도 통째로 다시 쓰이므로, CSS로 걸면 SSE 갱신마다 다시 돈다.
그래서 `app.js` `enter`가 그린 뒤의 `[data-enter]` 요소에서 [키, 상태]를 모아 지난번 기억과 비교하고(`chime.js` `enterKeys`), 처음 보이는 키와 상태가 바뀐 키에만 `play()`로 한 번 건다.
`play()`는 동작 줄이기 설정과 숨은 탭에서 아무것도 하지 않는다. 지금 goal 칩은 살짝 커졌다 돌아오고, 링의 호는 0에서 제 길이로 차오른다.
