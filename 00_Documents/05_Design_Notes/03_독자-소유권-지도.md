# 쟁점 02 — 독자 소유권 지도 + 주석 판정 질문

**질문 한 문장**: 이 워크플로우의 모든 표면(문서·코드·주석·상태 파일)을 누가 소유하고, 어떤 레지스터로 쓰며, 주석의 합격 기준은 무엇인가?

## 왜 필요한가

- 영호의 원 문제 제기 (2026-07-31): 기계적 문체가 블랙박스다. 주석이 많다고 좋은 코드가 아니다. 문서에 맥락이 과다하다.
- 백지화 실측 (2026-08-01): 주석 18,846건을 지웠더니 가독성이 오히려 개선됐다.  
  "압축 은어는 어떤 독자에게도 봉사하지 않는다"는 가설이 실측으로 확인됐다.
- 쟁점 01이 거처(노션 2부 / 저장소 인스턴스)를 정했으니, 이제 표면별 문체 소유권을 확정할 차례다.

## 지도 (제안)


| 표면                        | 독자          | 레지스터                                          | 압축 허용 |
| ------------------------- | ----------- | --------------------------------------------- | ----- |
| 노션 1권 (이론본)               | 사람          | 해요체 강의 톤, 비유·함정 장면, Why 한 세트                  | ✕     |
| 노션 2권 (세팅·실행예시본)          | 사람 + 에이전트   | 서사가 흐름을 끌고, AI-Ready 실물은 코드블록·접기에 격리          | ✕     |
| 저장소 실행 재료 (헌법·규칙·스킬)      | 에이전트        | 명령형 "~한다", 표·글롭·판정 질문. 서사 없음, 단 완성 문장         | ✕     |
| 논의본 (`00_Documents/05_Design_Notes/`) | 사람 + 에이전트   | 평문 완성 문장, 문장 단위 줄바꿈                           | ✕     |
| 기록 (ADR·보고서·세션 로그)        | 미래의 사람      | 검색 전제 — 날짜·키워드·결정 이유 박제                       | ✕     |
| 코드 본문                     | 사람 + 에이전트   | 구조가 곧 문장 — 이름·캡슐화·작은 단위로 말한다                  | —     |
| 코드 주석                     | 사람 + 에이전트   | 아래 판정 질문 통과분만                                 | ✕     |
| 기계 상태 파일 (pin·로그·카운터)     | 기계(에이전트 전용) | **유일한 압축 허용 구역** — 좌표·키워드 위주                  | ○     |


핵심 원칙: **압축 은어는 어떤 독자에게도 봉사하지 않는다.**  
AI-Ready는 은어가 아니라 구조다 — 자기완결성·표·명령형·예시가 AI-Ready를 만들고, 압축은 그저 사람을 배제할 뿐이다.  
압축이 정당한 곳은 사람이 애초에 독자가 아닌 기계 상태 파일뿐이다.

## 주석 판정 질문 (제안)

판정 질문 하나: **"이 주석을 지우면, 미래 독자(사람이든 에이전트든)가 틀린 행동을 하는가?"**  
Yes만 살아남는다. 허용 3종:

1. **외부 제약** — 코드 밖 세계가 강제하는 것 (API 한계, 플랫폼 버그, 규격).
2. **순서·불변식 계약** — 코드가 스스로 표현할 수 없는 실행 순서·불변 조건.
3. **실측된 사고** — "여기서 이렇게 하면 이런 사고가 났다"의 박제.

금지 패턴 (백지화에서 제거된 부류):

- 다음 줄이 뭘 하는지 번역하는 주석 — 코드와 중복.
- 변경 경위·리뷰어 설득용 서술 — 커밋 메시지와 ADR의 몫.
- 구조 냄새를 가리는 설명 — **주석은 방취제다**: 설명이 필요할 만큼 복잡하면 주석을 달 게 아니라 구조를 고친다.

기계 지시어(eslint-disable, @ts-expect-error, @vitest-environment 등)는 주석이 아니라 도구 설정이다 — 판정 대상에서 제외, 무조건 보존.

근거 (실측, 2026-08-01 백지화): 790파일에서 주석 18,846건 제거·기계 지시어 243건 보존.  
이후 가독성 개선(영호 육안 판정) + 전체 테스트 기준선 14 실패 → 0 실패(변환 부하 감소 추정).

## 승격안 (논의 대상)

1. **독자 소유권 지도** → 노션 04장에 절로 추가 — 기존 "질문 1(독자가 누구인가)" 표를 이 지도로 확장.  
   쟁점 01의 이론/실물 구도도 같은 편집에서 04장에 반영.
2. **주석 판정 질문** → 노션 02장 산출물 규칙 4로 신설 + 03장 매핑 표에 행 추가 (03장 운영 규칙 1: 규칙과 행은 한 세트).  
   03장 행 제안: 현재 P → 목표 **S** (reviewer 점검 항목에 판정 질문 탑재).  
   H(훅으로 주석 검사)는 과잉 — 주석 판정은 판단이 살아 있는 일이라 결정론화 부적합.
3. 저장소 인스턴스 쪽 집행 사본은 v2 부트스트랩(쟁점 08) 때 규칙 파일로 작성.

## 추천 (Claude, 2026-08-01)

지도와 판정 질문은 위 제안대로.  
승격 1·2는 쟁점 07(노션 정합 소보수)과 묶어 한 번의 노션 편집 세션으로 처리 — 합의된 진행 순서 "02(+07)"와 일치한다.

## 결정

**확정 (2026-08-01, 영호)**

- 지도와 판정 질문은 제안대로 확정.
- 승격: 주석 규칙 → 노션 02장 산출물 규칙 4 신설 + 03장 표 행 추가(현재 P → 목표 S).  
  독자 소유권 지도 + 쟁점 01의 이론/실물 구도 → 노션 04장.
- 쟁점 07(정합 소보수)과 같은 노션 편집 세션에서 일괄 진행.

**승격 목록** (2026-08-01 노션 편집 완료, 육안 검증 통과):

- 독자 소유권 지도(표면 7행 표 + 압축 원칙 + 거처 구도 전제부) → 04장 「독자 소유권 지도」 절 신설 (질문 1 직후).

- 쟁점 07 동시 처리: 03장 "⚠️ 세 곳" → "두 곳" 교정, 03·04장 깨진 callout 마크업 수리, 04장 tutorials 빈 자리 → 2권으로 갱신, Diátaxis 인용 재검증("섞지 말 것"은 원문 표현이 아니라 채택 규칙임을 명시).
