# M01 — Bootstrap · Moodie 하네스 인스턴스화 (자립화)

- 마일스톤: M01 (M05 마감 문답에서 드러난 미착수 작업 — "검증 끝난 Moodie 시스템을 AgentDeck에 옮기기") · 작성: 2026-08-09 · 상태: 실행 중

## 사람용 개요

이 마일스톤은 AgentDeck을 스스로를 감독하는 저장소로 만드는 작업입니다.

지금까지 AgentDeck의 작업 규율은 옆 저장소인 Moodie_Agent_Workflow에만 실물로 있었습니다.
그곳에는 편집을 감시하고 계획을 검사하는 훅(hook, 특정 사건이 일어날 때 자동으로 실행되는 작은 프로그램)이 갖춰져 있고, 그 훅들이 세션의 규율을 기계로 집행합니다.
AgentDeck에는 그 장치가 없어서, 규율이 사람의 기억과 그때그때의 지시에만 의존해 왔습니다.
이 마일스톤이 끝나면 AgentDeck은 자기 저장소 안의 훅으로 자기 마일스톤을 감독하게 됩니다.

증명하려는 것은 세 가지입니다.
첫째, 표준 레이아웃(저장소의 폴더 배치 규격)을 규격과 1:1로 물리적으로 갖춥니다.
둘째, 옮겨온 훅의 감독 아래에서 실제 작업 한 건을 사람의 개입 없이 끝까지 완주합니다.
셋째, 그 결과를 마일스톤 보고서 표준의 첫 적용 사례로 남깁니다.

작업은 여섯 단계로 나뉩니다.
1단계는 계획과 규격 문서를 저장소에 등재해 착륙지를 만드는 일이고, 2단계는 폴더 배치를 규격대로 실제로 옮기는 일입니다.
3단계는 위험한 명령을 막는 기존 가드의 빠진 규칙을 채우는 일, 4단계는 훅 일곱 종을 옮겨 심고 켜는 일입니다.
5단계는 켜진 훅이 실제로 기대대로 발화하는지 하나씩 실측하는 일이고, 6단계는 그 감독 아래에서 무인 작업 한 건을 완주하는 일입니다.

핵심 용어를 미리 풀어 둡니다.
게이트(gate)는 조건을 만족하지 못하면 다음 단계로 못 넘어가게 막는 검문소를 뜻합니다.
fail-closed는 판단이 애매하거나 정보가 없을 때 통과가 아니라 차단을 기본값으로 삼는다는 뜻입니다.
work-pin은 세션이 바뀌어도 작업 좌표를 이어 주는 단 하나의 인수인계 문서를 가리키며, 이 폴더의 `01_Work_Pin.md`가 그 파일입니다.

## 개요

- **목표**: AgentDeck이 Moodie에서 이식한 훅 하네스로 자기 마일스톤을 감독하는 자립 워크스페이스가 된다. 노션 05장 「Bootstrap 실전 예시」의 첫 실적용이다.
- **스코프**: 포함은 계획 등재와 착륙지 구축, 표준 레이아웃 물리 완성, 위험 명령 가드 보강, 훅 일곱 종 이식과 활성화, 발화 실측, 무인 실증 한 건이다. 불포함은 `Bash(node *)` 경유 임의 쓰기의 차단 구현과 훅 두 종(31_reset-gate·60_end-signal)의 이식이며, 앞의 것은 유지 대장의 부채로, 뒤의 것은 범위 밖으로 남긴다.
- **도메인 태그 어휘**: `structure`(문서·레이아웃 등재), `layout`(소스 배치 이동), `guard`(위험 명령 가드), `harness`(훅 이식·활성화), `verify`(발화 실측), `dogfood`(무인 실증). 이 여섯이 이 저장소의 태그 어휘다.
- **라우팅 판독**: 태그 여섯 종에 Phase 여섯 개이고 의존이 1→2→3→4→5→6의 선형 사슬이라 병렬 쌍은 없다. 태그 종수가 둘 이상이므로 라우팅 표는 크로스 도메인으로 판독되며, 검수선은 리뷰어 1차에 Codex 교차 검수 2차를 더한다.

## 완료선

이름은 자립화이고, 완료선은 세 조항입니다.
첫째, 표준 레이아웃을 규격과 1:1로 물리 완성합니다.
둘째, 이식한 하네스의 감독 아래 실작업 한 건(유지 대장 MA-05, README 링크 수리)을 무인으로 완주합니다.
셋째, 보고서 표준을 처음 적용한 마감 보고서를 남깁니다.

여기서 "하네스 감독"은 편집 도구 표면(Edit·Write 계열 훅 일곱 종)과 Bash의 파괴·비가역 표면(위험 명령 가드)의 감독을 뜻합니다.
`Bash(node *)` 경유의 임의 쓰기는 이번 범위에서 차단하지 않고, 헌법의 금지 조항과 유지 대장의 부채로 남깁니다.
차단을 구현하면 오탐이 무인 루프를 멈추는 비용 패턴이 실측돼 있어 채택하지 않았습니다.

## Phase 흐름

| Phase | 이름 · 태그 | 목표 | DoD (결정론 판정) |
|---|---|---|---|
| 1 | 착륙지·계획 등재 · `structure` | 계획 문서, gate-config 단독, 00_Documents 5분할, 헌법 2종, ADR-001, stale 아카이브, .gitignore 정합 | 미러에서 Moodie 원본 훅 두 종(20·10)을 stdin 구동해 allow와 생존 문서 검출을 확인 |
| 2 | 표준 레이아웃 물리 완성 · `layout` | `git mv` 두 건과 결합점 전수 수정 | 이동 전 기준선 채취 후, 이동 뒤 typecheck·lint·npm test 전량·build·`npm run test:e2e`가 기준선과 동일하게 green |
| 3 | cmd-guard 대조 보강 · `guard` | 결손 규칙 다섯 건과 git 머리 토큰 판정, 그리고 테스트 | 테스트를 먼저 쓰고 `npm run test:hooks` green, 기존 무회귀 |
| 4 | 훅 7종 이식·활성화 · `harness` | 훅 수정 이식, fixtures 개작, 스모크 러너 신설, settings 병합 | 미러 스모크 전건 통과 후 커밋, 그다음 settings 병합을 최후 파일 편집으로 수행하고 병합 커밋 뒤 세션 종료 |
| 5 | 발화 실측 · `verify` | 새 세션에서 프로브 체크리스트 전건 실측 | 훅별 기대 판정 표 전건 일치, hook-log에 본 세션 session_id로 각 1건 이상, start-brief의 `source != resume`, role-gate 3쌍, 동시 세션 상태 프로브 무손실 |
| 6 | 무인 실증 MA-05 · `dogfood` | README 수리를 Orca 가시 워커로 무인 완주 | 스폰 전 plan-gate 직접 구동 영수증, 스폰 영수증 모델이 `claude-opus-5` 전체 ID, 선작성 링크 검증 스크립트 exit 0, 40 자동 장전에서 50 마감 통과, 개입 0회 |

각 Phase의 Steps와 검증 기록은 같은 폴더의 `01_Phase_1.md`부터 `06_Phase_6.md`까지 개별 파일이 소유합니다.

마감 절차는 리뷰어 1차와 Codex 교차 검수를 거쳐 마감 보고서를 쓰고, 사용자 마감 판정을 받은 뒤 Moodie 장부에 이월 한 줄을 남기고, 마지막에 사용자 승인 게이트로 push하는 순서입니다.

## 검증 기록 운용

검증 결과는 각 Phase 파일 말미 「검증 기록」의 줄로만 유효하다 (fail-closed).
줄 스킴은 `FAIL`·`PASS`·`USER-INPUT` 세 마커이며, 타임스탬프와 한 문장(무엇이 왜 — FAIL이면 시도까지)을 적는다.
스폰 게이트는 마지막 USER-INPUT 줄 이후의 FAIL만 세며, 세 번 이상이면 전진이 막히고 에스컬레이션으로 분기한다.
기록은 append-only다 — 리셋은 삭제가 아니라 기준점 이동이다.
