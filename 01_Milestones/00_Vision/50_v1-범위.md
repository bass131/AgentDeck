# v1 범위

- 상태: 초안 · [개요](00_개요.md)

## v1에 넣는 것 — 한 줄기

v1은 아래 여섯 단계가 처음부터 끝까지 이어지는 한 줄기다. 각 단계는 따로 쓸모 있게 만들지 않고, 줄기 전체가 도는 것을 먼저 본다.

1. **설치와 계정 연결** — 설치 파일로 깔고, 처음 켤 때 Claude 계정과 GitHub 계정을 잇는다.
2. **Taste와 목표 쓰기** — 메인 세션이 문답으로 전역 Taste와 프로젝트 헌장(목표 + 프로젝트 Taste)을 채운다.
3. **마일스톤 하나 무인 완주** — 브레인스토밍 → 마일스톤 스펙 → goal 분해 → goal마다 구현·검증·PR·마일스톤 브랜치 병합. 그래프는 「프로그램 개발」 기본 템플릿 하나로 고정한다.
4. **현황판과 문서 갱신** — 앱 안 현황판에서 마일스톤 진척과 시스템 현황을 본다. 에이전트가 문서를 갱신한다.
5. **마일스톤 병합 버튼** — 마일스톤이 끝나면 보고를 읽고 버튼 한 번으로 `master`에 병합한다.
6. **자동 업데이트** — 새 Release를 앱이 감지해 업데이트한다.

곁가지로 v1에 함께 들어가는 것:

- 메인 세션 상시 표시, 노드 세션의 한 줄 요약과 펼쳐 보기.
- 사람을 부르는 네 사건과 PC 알림.
- 사용량 한도 멈춤과 자동 이어 가기.

## v1의 완료선

이 저장소 밖의 새 프로그램 프로젝트 하나에서, 마일스톤 하나를 v1 설치본만으로 완주한다.
사람의 개입은 Taste·헌장 문답, 마일스톤 브레인스토밍 승인 한 번, 마일스톤 병합 한 번뿐이다.
그 사이의 예외 호출은 횟수와 이유를 기록한다.

## v2 이후로 미루는 것

| 항목 | 미루는 이유 |
|---|---|
| n8n식 그래프 편집기 | v1은 템플릿 하나로 줄기가 도는지부터 본다. 편집기는 그 템플릿이 실제로 어떻게 생겼는지 확인한 뒤에 만든다 |
| 게임 개발 템플릿(Dawnholder) | 프로그램 템플릿으로 줄기를 검증한 뒤 둘째 유형으로 연다 |
| Codex 실행기·교차 검수 | 구독이 없다 |
| 휴대폰 알림 | 비용이 없다 |
| 팀원 연결 | 중앙 서버 비용이 든다 |
| macOS·Linux 설치본 | 쓰는 사람이 Windows뿐이다 |

- 공개 저장소, 공개 릴리스.
