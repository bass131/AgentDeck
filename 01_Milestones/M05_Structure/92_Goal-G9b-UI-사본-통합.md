## 목표

단일 대화와 멀티 패널이 따로 가진 UI 사본 네 쌍 — 스레드 렌더, 모드·effort 선택기, 입력 팔레트(`/`·`@`), 입력창 — 을 컴포넌트 하나씩으로 합친다. 갈라진 UI 동작은 차이 목록의 「맞출 쪽」으로 정렬하고, 대기열(E9)도 입력창과 함께 패널에 들어온다.

## 범위

- **만들 것**
  - 스레드 렌더 하나 — R1·R2(`notice`·`compact-boundary`), R3(패널도 toolgroup을 그린다, 사용자 결정), R4·R5(시각·「중단됨」·훅 배지), R7(오류 줄은 `.conv-error`), R8(나머지 동형 사본 공유). R6의 복원 배지·Welcome·줌 같은 장식은 배치 쪽에 둔다.
  - 선택기 하나 — P1·P2(컴포넌트 하나, 널 가드는 멀티 쪽, 문구는 단일 쪽), P5(멀티에서 Shift+Tab은 입력창에 포커스가 있는 패널의 모드만 돌리고, 숨은 단일 선택기는 돌리지 않는다. 포커스된 패널이 없으면 아무것도 안 한다 — 사용자 결정).
  - 패널 질문 창 — 패널 run에 `pendingQuestion`이 오면 단일과 같은 QuestionModal을 띄우고, 답은 G9a가 놓은 `usePanelSlot.respondQuestion`으로 보낸다(G9a에서 넘어온 몫, 사용자 결정).
  - 패널 `/clear` — 패널 대화를 비우고 다음 전송이 새 엔진 세션으로 시작하게 한다(사용자 결정). 기존 IPC로 되지 않으면 멈추고 보고한다.
  - 입력 팔레트 하나 — L1(`/` 목록에 root를 넘긴다, 멀티 쪽), L2~L5(단일 쪽).
  - 입력창 하나 — Composer 하나에 밀도 prop 하나로 패널 외형을 지금처럼 둔다(사용자 결정). C1·C2(실행 중 Enter는 대기열 예약, SchedStrip), E9(중단 시 대기열 비움), C4~C7(단일 쪽). 문구·아이콘·중단 버튼 이름·선택기 구분선도 단일 쪽을 따르고, 크기와 색만 밀도 규칙으로 패널 그대로 둔다(사용자 결정). 엔진 프롬프트 계산의 입력창 사본(`Conversation.tsx`)을 G9a 코어 `enginePromptFor`로 합친다(Backlog 47 일부).
  - 항목마다 새 동작을 고정하는 테스트를 먼저 쓰거나 같은 커밋에 둔다(TDD).
- **건드릴 곳**: `renderer/src/05_Conversation/`(스레드·입력창·팔레트·PanelView), `renderer/src/03_Agent/`(선택기·`usePanelSlot`이 대기열을 노출하는 데 필요한 곳), 호출부(`12_Window` 배치), 통합으로 죽은 패널 전용 CSS 규칙의 삭제와 밀도 prop에 필요한 최소 규칙, 대응 테스트와 e2e 하네스의 가짜 세션.
- **하지 않을 것**: 상태 거처의 단일화와 `'multi'/'single'` 분기 정리(G9c), B1 Sidebar 실행 표시(세션 레지스트리가 필요해 G9c), 새 기능 — E6(단일 systemPrompt), P3(단일 effort 저장), B2(멀티 Esc 중단)는 지금 동작 유지, P4 기본 모드(auto/bypass) 유지. IPC 계약 변경(G10), main 변경(G11), 판정 장치 변경.
