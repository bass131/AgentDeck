# 60 — 이행 순서와 goal 분할, 마일스톤 배치

## 이행 원칙

- **동작을 먼저 옮기고, 그다음 바꾼다.** 첫 goal은 지금 권한 콜백의 분기(`10` 발견 3의 순서 그대로)를 노드 구조로 옮기되 판정 결과를 바꾸지 않는다. 바뀐 것이 없음을 기존 테스트가 보증한다.
- **노드 하나에 goal 하나.** 병합 버튼, 루프 진입, 기준표는 각각 따로 병합한다. 한 노드가 틀려도 다른 노드를 되돌리지 않아도 된다.
- **GitHub 설정 변경은 사용자 몫이다.** 토큰 만들기, App 설치, ruleset·필수 검사 걸기는 사용자가 하고, goal은 그 뒤의 연결과 실측만 한다(헌법 9·10조).
- **저장소 훅은 남긴다.** 앱 노드가 같은 일을 해도 CLI 세션을 위해 저장소 훅을 지우지 않는다. 가드를 줄이는 일은 기준표가 앱에 들어온 뒤에 따로 판단한다.
- **판정 장치와 헌법을 바꾸는 단계는 goal 안에 이름으로 적는다(헌법 3조).**

## goal 분할안

순서대로다. 번호는 마일스톤 배치(아래)가 정해지면 다시 붙인다. 강도는 헌법 2조 기준이다(판정 장치 변경이나 앱 소스 50줄 이상이면 강).

| 순서 | goal | 만들 것 | 강도 | 앞선 조건 |
|---|---|---|---|---|
| 1 | 판정 장치 정비 | 가드 `timeout` 지정(Backlog 30), `20_plan-gate.cjs` 처리(Backlog 31), 저장소 `settings.json`에 앱 엔진·설정 경로 거부 규칙 추가(`30` 보호 6) | 강 | 없음 |
| 2 | 컨트롤 골격 | 노드 인터페이스(여덟 칸)와 등록부, 잠금 노드, `controls.json`과 보호 1~5(엔진 경로 포함), 컨트롤 패널, 지금 권한 콜백 분기의 노드 이관(동작 무변경) | 강 | 1 |
| 3 | CI 필수 검사 | 하드 게이트 다섯 종을 GitHub Actions로 돌리는 워크플로. 사용자가 `master` 보호에 필수 검사로 건다 | 강 | 사용자의 보호 설정 변경 |
| 4 | 병합 버튼 | `40` 단계 A. PR 카드의 병합 버튼(머리 SHA 고정, 필수 검사 확인), 잠금 노드 병합 거부, 저장소 설정 `ask`→`deny`, 헌법 10조·`AGENTS.md`·pin 문구 개정, 결정 보드 병합 경로 폐지 | 강 | 2, 3 |
| 5 | 작업 루프 진입 | 합의 질문을 채팅 글이 아닌 합의 카드로 받는 노드(Backlog 25), 대리 입력 표시(Backlog 29) | 강 | 2. 시작할 때 사용자에게 「사람이 화면 앞에 있나, 위임이 기본인가」를 묻는다 |
| 6 | 기준표와 분류기 | 규칙·문장 노드 GUI, 앱 `자동`을 공식 `auto`로 잇기(`50` 실측 여덟), 분류기 모델 비교 | 강 | 2 |
| 7 | 에이전트 자격 증명 | `40` 단계 B. 세션 `GH_TOKEN` 주입, 병합 버튼의 기기 인증 전환, keyring 사람 로그인 제거 안내 | 강 | 4. 사용자가 fine-grained 토큰을 만든다 |
| 8 | 신원 분리 실측 | `40` 단계 C의 실측 셋. 결과에 따라 App 신원 전환 goal을 따로 연다 | 약 | 7. 사용자가 App·ruleset을 설정한다 |
| 9 | 가드 범위 정리 | 앱 기준표가 맡은 행을 가드에서 뺄지 판단(Backlog 20·21) | 강 | 6 |

작업 루프 진입(5)의 설계는 이 묶음에서 노드의 자리만 정했다. Backlog 25가 남긴 질문 넷은 그 goal의 합의에서 푼다. 합의를 기다린다는 신호, 화면 요소, 결정 대장과의 연결, 다른 사람 판정 지점(병합 버튼)과 같은 틀을 쓸지다.

컨텍스트 계기 오류와 AutoCompact(Backlog 26·27)는 컨트롤과 다른 주제다. 이 분할에 넣지 않고 따로 순서를 정한다.

## 마일스톤 배치 제안

- **제안: M06을 G8로 닫고, 컨트롤 작업을 새 마일스톤으로 세운다.**
  - M06 완료선 「앱 안에서 이 저장소의 goal 하나를 합의부터 PR 생성까지 끝낸다」는 G6에서 실측으로 닿았다. G6은 측정 단계 열 개(합의 → 브랜치 → 편집 → 게이트 → 커밋 → PR → 병합 카드 → 마감)를 모두 앱 안에서 지났고, 앱 밖 개입은 0회였다.
  - 컨트롤 작업은 goal 아홉 개 규모이고 완료선이 다르다. 예: 「되돌리기 어려운 행위가 모두 사람 버튼이나 서버 거부로만 일어난다」.
  - 새 마일스톤을 지금의 M07 실전 투입 앞에 두면, 설치본으로 실제 goal을 돌릴 때 병합이 이미 사람 버튼이다.
- **대안: M06 안에 이어서 넣는다.** 문서 이동이 없고 바로 이어 간다. 대신 M06의 완료선과 실제 내용이 어긋나고 마일스톤이 길어진다.
- 로드맵 순서를 바꾸는 일이라 사용자에게 묻는다. 로드맵은 「순서나 완료선을 바꿔야 하면 멈추고 묻는다」고 적는다.
