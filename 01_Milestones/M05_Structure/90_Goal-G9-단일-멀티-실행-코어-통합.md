## 목표

단일(`03_Agent/state/runtime.ts`)과 멀티(`03_Agent/state/panelSession.ts`)가 따로 구현한 실행 로직 — 전송·중단·interrupt·권한 응답·질문 응답·stale 감시 — 을 공용 코어 하나로 합치고, 두 파일은 그 코어의 어댑터로 줄인다. 갈라진 실행 동작은 차이 목록의 「맞출 쪽」으로 정렬한다.

## 범위

- **만들 것**
  - 공용 실행 코어 — `performPanelSend`의 `{readState, dispatch}` 포트 꼴을 일반화해 위 여섯 동작을 한 구현으로 둔다. runtime과 panelSession은 상태 읽기·쓰기를 코어에 넘기는 어댑터가 된다. 공개 API(store 실행 액션, `usePanelSlot` 결과 모양)는 유지한다.
  - 실행 동작 정렬 — 차이 목록 E1·E2·E3·E4·E5(키 규칙 하나)·E7·E8·E11·E15·E17. E10·E12·E14는 구조만 합치고, E16·E18은 포트 콜백(`onDone`, dispose)으로 각자 둔다. E13은 코어와 패널 어댑터에 질문 응답 경로를 놓는 데까지다 — 패널 화면에 QuestionModal을 띄우는 것은 G9b.
  - 차이 항목마다 새 동작을 고정하는 테스트를 먼저 쓰고 구현한다(TDD).
- **건드릴 곳**: `renderer/src/03_Agent/state/`, 실행 액션을 부르는 `05_Conversation`·`06_Sessions`·`12_Window` 호출부(시그니처가 바뀔 때만), 대응 테스트와 e2e 하네스의 가짜 세션.
- **하지 않을 것**: UI 통합(G9b), 상태 거처의 단일화와 분기 정리(G9c), 새 기능 — E6(단일 systemPrompt), P3(단일 effort 저장), B2(멀티 Esc 중단)는 지금 동작 유지, 제품 기본값 P4(auto/bypass) 유지, E9(대기열)는 대기열 UI와 함께 G9b. IPC 계약 변경(G10), main 변경(G11), CSS 변경, 판정 장치 변경.
- **완료조건**
  - 위 여섯 동작이 공용 코어에 각각 한 구현으로 있고, runtime·panelSession에 같은 동작의 사본이 남지 않는다.
  - 이 goal이 맡은 E 항목마다 테스트가 있고 통과한다. 테스트가 구현보다 먼저 커밋됐거나 같은 커밋이다.
  - 하드 게이트 다섯 종 exit 0, `npm test` 실패 0. 테스트 수의 변화는 `collection-baseline.test.ts`에 사유와 함께 반영된다.
  - 화면: 빌드 CSS sha256 `941086b8…120258` 동일. 다섯 하네스 39건 통과, 92장 digest가 `b1591384…3bd64cb8`과 같거나, 바뀐 장마다 E 항목으로 설명된다.
