# ADR-040: conformance 게이트에 어댑터별 준수 축 추가 — 1단계(선언 기반) 채택, 2단계(중립 receipt) 채택 보류

**결정(BZ P06 창 2, 2026-07-28 — 영호 GO 2026-07-27)**: `core-manifest.json`의 13개 조항 각각에 `claude.conformedVersion`·`codex.conformedVersion` 필드를 추가하고, `conformance-check.mjs`(G2)가 조항 `v`와 **정확 동등성**으로 대조한다 — `누락`·`낮음`·`높음`·`문자열/비정수` 네 클래스 전부 red. **1단계(선언 기반)만 채택**하고, 2단계(엔진 중립 receipt)는 **채택 보류 + 선행 조건 명시**로 남긴다.

**이유**: `BACKLOG.md` 15 — 현행 게이트가 대조하는 것은 조항 `v` ↔ `CORE.md` 헤더, 그리고 `impl` 경로의 파일 실재뿐이다. **어댑터가 조항을 실제로 지키는지는 아무도 보지 않는다.** 백로그 10이 정확히 이 맹점 위에서 자랐다 — Codex가 CORE-06 **v1** semantics에 머물러 있는 동안에도 게이트는 13/13 green이었다. 더 고약한 것은 그 맹점의 *기록*(매니페스트 note의 자기 결함 고백)이 10번 수리 때 note 교체와 함께 증발한 것이다. **이번엔 ADR 본문이 맹점을 소유한다**(아래 「한계」절) — 수리와 함께 지워질 수 없는 자리에.

**대안과 트레이드오프**:
- (a) *현행 유지* — 비용 0이나 맹점 상존. 다음에 어느 어댑터가 뒤처져도 게이트는 조용히 green이고, 이번엔 경고해 줄 문장조차 없다.
- (b) *2단계 바로 채택* — 각 엔진 doctor가 자기 축을 검증하고 엔진 중립 receipt(`clauseVersions`·hash·digest·PASS·`verifiedAt`)를 남기며, 중앙 conformance는 실행 없이 digest·신선도만 본다. 선언≠실제 갭을 닫지만, **CORE-12 「runtime이 아닌 검증 증거」 예외 ADR이 선행**해야 하고 구현 비용이 크다.
- (c) **채택: 1단계 먼저** — 갱신 누락을 red로 만드는 것(백로그 10 재발 클래스 방지)을 싸게 얻고, 자기선언 한계는 본문에 명시한 채 2단계를 선행 조건 딸린 보류로 남긴다. 잃는 것 = 선언≠실제 갭(2단계 전까지).

---

## 1. 스키마 (1단계)

각 조항에 추가:

```json
{
  "id": "CORE-01",
  "v": 1,
  "claude": { "conformedVersion": 1, "impl": [...], "verify": [...] },
  "codex":  { "conformedVersion": 1, "impl": [...], "verify": [...] }
}
```

- **`manifestVersion` 1 → 2 상향**: 필수 필드가 추가되는 스키마 세대 변경이다. 소비자(`conformance-check.mjs`·`harness-conformance.test.ts`)는 같은 커밋으로 움직이므로 기술 강제는 없지만, 버전 필드의 존재 의의가 스키마 세대 표시라면 올리는 게 정직하다. trade-off: 옛 커밋 체크아웃 시 신 체커가 옛 manifest를 명시적으로 거부할 수 있게 됨(우연 green 방지) vs 상향 자체의 비용은 0에 가깝다.
- **초기값 기입 규칙**: 추정 금지. Claude 축은 현행 구현 실측으로, **Codex 축은 부트스트랩 receipt**(아래 §2-⑤) 기준으로 기입하고 출처를 `$comment`에 명기. 현행 NC receipt(백로그 19·22·digest 검증)는 **조항별 선언 근거가 아니다** — 재사용 불가.

## 2. 수명주기 계약 (Codex 교차 리뷰 축 3 반영, 2026-07-27)

초기 필드 추가만으로는 이후 조항 개정 때 누가·언제·어느 값을 올리는지가 없다. 다음을 계약으로 명문화한다:

1. **각 어댑터는 자기 `conformedVersion`만 승인한다** — Claude 세션이 `codex.conformedVersion`을 올리지 않는다(CORE-12의 자연 귀결). 역방향도 같다.
2. **갱신 전제 = 해당 엔진의 구현·검증 receipt** — "올렸다"의 근거는 그 엔진 세션의 실측 기록이다.
3. **한쪽만 완료된 중간 상태는 G2 red를 유지한다** — 조항 `v`가 오르면 양쪽이 따라올 때까지 red가 정상 상태다. 중간 green을 만들려고 값을 선반영하는 것이 정확히 이 ADR이 막으려는 갱신 사기다.
4. **manifest 마감 주체**: 조항 개정을 시작한 유지보수 세션이 자기 어댑터 값까지 올리고, 남은 어댑터 값은 그 엔진 세션의 receipt 회수 후 **영호(또는 영호가 지정한 세션)가 마감**한다 — receipt 없는 대필 금지.
5. **부트스트랩(P06 1회)**: 초기화 전 Codex 세션에 **13개 조항별 현행 버전·근거 receipt**를 요청하고, 그 값으로 `codex.conformedVersion`을 기입한다.

## 3. 한계 — 이 게이트가 잡는 것과 못 잡는 것 (본문 소유 — 지우지 말 것)

- **잡는 것**: CORE 조항의 **의미 버전 상승에 대한 어댑터 갱신 누락**. 조항 `v`가 2가 됐는데 어느 축이 1이면 red.
- **못 잡는 것 ①**: **거짓 선언** — 자기선언이므로 값만 올리고 구현을 안 하면 green이다. 방어는 §2-2(receipt 전제)라는 절차 규범뿐, 기계가 아니다. 2단계(중립 receipt)가 이 갭의 해소안이다.
- **못 잡는 것 ②**: **경로·구현 드리프트** — CORE.md는 경로 표기 변경에 조항 버전을 올리지 않는다. 따라서 (예) CHANGELOG 이동 후 어댑터의 옛 예외가 남아도 `v`도 `conformedVersion`도 그대로라 green이다. "갱신 누락 = red"는 정확히는 **의미 버전 상승에 대한 누락만** 뜻한다. 이 갭의 후속안 = `adapterRevision`/digest 축 (BZ P07에서 백로그 신규 등재).

## 4. 2단계 — 채택 보류 (선행 조건 명시)

각 엔진 doctor가 자기 `impl`·실행 가능한 `verify`만 검사하고 엔진 중립 receipt를 남기며, 중앙 conformance는 실행 없이 digest·결과·신선도 TTL만 본다(교차 실행 없음 — CORE-12 유지). **선행 조건**: CORE-12에 「runtime이 아닌 검증 증거」 예외를 명문화하는 별도 ADR. 그 ADR 없이는 receipt 공유 자체가 격리 위반 시비에 걸린다. "안 하기로 한 것"이 아니라 **조건을 명시하고 미룬 것**이다.

## 5. 검사 구현 규칙 (P06 TDD 지침)

- 대조는 **정확 동등성** — 단순 `<` 비교는 `undefined < v === false`라 **필드 누락이 통과**한다. red 4클래스(누락/낮음/높음/비정수)를 각각 픽스처로 고정.
- **제5클래스: `conformedVersion: 0` = 선언된 갭(bootstrap gap)** — "이 조항의 어느 버전도 완전 준수하지 못함"의 명시 선언이다. red가 아니라 **경고 출력 + `gap` 필드(BACKLOG 번호) 필수** — `gap` 참조가 없는 0은 red다. 근거: 부트스트랩 receipt(2026-07-28 회수, job task-ms3t80xh-164img)가 Codex의 CORE-10·CORE-11 **선재 갭**을 드러냈는데, 선재 갭의 발견은 갱신 누락(§2-3의 red 시나리오 = 조항 개정 후 미추종)이 아니라 새 사실의 기록이다. 발견을 게이트 red로 만들면 **게이트를 살리려 값을 위조할 압력**이 생긴다 — 정확히 이 ADR이 막으려는 것. 0은 매 G2 실행마다 경고로 가시화되고, 해당 엔진이 구현을 완성해 자기 값을 올리면 경고가 사라진다. **1 이상의 낮음은 여전히 red다**(0은 부트스트랩에서만 정당한 값).
- `core-manifest.json`은 게이트의 입력이자 검증 대상 — 수정 전후 G2 즉시 실행(스키마 파손 = 게이트 사망).
- 뮤테이션 음성 1회: 일부러 `conformedVersion`을 낮춰 red 확인 후 복원, 출력 박제.
