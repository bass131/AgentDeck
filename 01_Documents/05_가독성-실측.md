# 쟁점 12 — 노션 매뉴얼 가독성 실측과 조판 규칙

**질문 한 문장**: 노션 매뉴얼의 "텍스트 벽" 가독성 손상은 어디서 얼마나 발생하고 있으며, 어떤 조판 규칙으로 재발을 막는가?

## 왜 필요한가

- 영호의 문제 제기 (2026-08-01): 02장 산출물의 규칙처럼 텍스트만 덕지덕지 붙은 구간이 가독성을 손상시킨다 — 감이 아니라 실측으로 확인하고 싶다.
- 점검(04_노션-규칙-점검.md)의 F5(해요체 재조판)·F6(예시 쌍 부족)과 같은 재조판 부채 계열이지만, 이번 실측으로 **문체 이전에 구조(조판) 결함이 독립적으로 존재**함이 확인됐다.

## 측정 방법 (2026-08-01)

- 대상: 우리 챕터 00~04 전문 + 표본(실밸개발자 2부작 — 스타일 기준선, 02_매뉴얼-스타일-참고.md에서 차용 확정).
- 단위: **시각 문단** — 노션에서 줄바꿈 없이 한 덩어리로 렌더되는 텍스트 (블록을 `<br>` 기준으로 분해).
- 지표: 문단 길이 분포(중앙값·p90·최장), 200자+/300자+ 벽 개수, 본문 1,000자당 아티팩트(표·코드·다이어그램·접기·칼럼) 밀도, 표 셀 내 텍스트 길이.
- 도구: 노션 원문 직렬화 → 마크업 제거 → 문단 단위 집계 스크립트 (scratchpad/readability/measure.mjs).

## 진단 — 세 가지 결함

1. **문단 길이 상한 부재.**
   표본은 최장 문단이 160자(렌더 약 3줄)를 넘지 않는다 — 두 페이지 전체에서 단 한 번도.
   우리는 263·372·471자 문단이 존재하고, 04장은 p90이 232자다.
   "덕지덕지" 체감의 실체는 문단당 정보량이 표본의 2~3배라는 것.
2. **아티팩트 가뭄.**
   표본은 본문 150자마다 표·코드·접기·다이어그램이 하나씩 나와 프로즈를 끊어 준다 (아티팩트+해설 짝).
   우리는 1,600자마다 하나 — 10배 차이. 특히 **02장은 콜아웃 외 아티팩트가 0개**로, 챕터 전체가 연속 텍스트다.
   우리 콜아웃도 대부분 챕터 도입·수미상관 장식이지, 본문 사이의 "핵심 포인트/함정" 분리 용도가 아니다.
3. **표 셀 논증.**
   03장 매핑 표의 비고 열에 100자+ 셀이 5개(최장 151자) — 하류 규칙 2("표 셀 안에 논증을 넣지 않는다")를 스스로 어긴다.
   표본의 최장 셀은 48자다.

## 제안 — 조판 규칙 신설 (04장 하류 규칙 후보)

> **시각 문단은 3문장·150자 이내를 목표로 한다.
> 넘치면 문장을 깎는 것이 아니라 구조로 승격한다 — 병렬 열거는 불릿·표로, 함정과 핵심은 콜아웃으로, 실물은 코드블록·접기로.**

- 수치의 근거: 표본 실측 최장 160자 — 차용하기로 확정한 스타일이 실제로 지키는 상한이다.
- 분량 규칙(200줄/250줄)과 같은 문법: 상한 초과는 다이어트 신호가 아니라 구조 분화 신호.
- 표 셀은 더 엄격하게 — 셀은 판정·좌표만, 논증은 표 밖 문장으로 (하류 규칙 2의 집행 기준을 "논증 금지"에서 "~50자 기준"으로 구체화).

### 예시 쌍 — 02장 산출물 규칙 4 (파일럿)

나쁜 예 (현재): 판정 질문·허용 3종·금지 패턴·예외·근거 다섯 계층이 372자 한 문단.

좋은 예 (제안):

```
**주석은 코드가 말할 수 없는 제약만** — 판정 질문: "이 주석을 지우면 미래 독자가 틀린 행동을 하는가?" Yes만 살아남는다.
- 허용 ① 외부 제약 (API 한계·플랫폼 버그·규격)
- 허용 ② 코드가 표현할 수 없는 순서·불변식 계약
- 허용 ③ 실측된 사고의 박제
금지: 코드를 번역하는 주석 · 변경 경위·설득용 서술 · 구조 냄새를 가리는 설명 — 설명이 필요할 만큼 복잡하면 구조를 고친다.
예외: 기계 지시어(eslint-disable 등)는 도구 설정이라 판정 대상이 아니다.
근거: 주석 전량 제거 실측에서 가독성이 오히려 개선됐다 (기록의 주소는 말미 근거 절).
```

같은 정보량, 문단 최장 약 110자 — 각 계층이 제 형식을 갖는다.

## 처분 선택지

- **(a) 국소 수리 + 규칙 신설 (추천)** — 위 벽 목록 7곳만 지금 구조 승격하고, 조판 규칙을 04장 하류 규칙에 추가.
  해요체 전환(F5)·예시 쌍 보강(F6)을 포함한 전면 재조판은 예정대로 별도 마일스톤(2권 신설과 함께).
  이유: 벽은 국소 결함이라 7곳 수리로 실측 지표가 표본 수준에 도달하고, 문체 전환은 전 챕터를 다시 쓰는 일이라 규모가 다르다.
- **(b) 전면 재조판 지금** — F5·F6까지 한 번에. 규모 크고, 2권 신설 전에 두 번 손대게 될 위험.

## 결정

**(a) 확정 (2026-08-01, 영호)** — "A로 먼저 한번 수정해보고, 괜찮으면 전체적으로 가보자."
국소 수리 + 조판 규칙 신설을 (수정본)에 먼저 적용해 육안 확인 후 원본 반영을 판단한다.
결과가 괜찮으면 전면 재조판(F5·F6 포함)으로 확대한다.

## 실행 기록 (2026-08-01)

- 01·02 (수정본) 기존 페이지에 조판 수리를 추가하고, 03·04 (수정본)을 신규 생성했다 — 원본 4장은 전부 무수정.
- 04장: Diátaxis·법전 모델·작성 순서 5·Enforcement 연결 벽 4곳 분해 + **하류 규칙 6 신설**(시각 문단 3문장·150자) + 규칙 2에 셀 기준 구체화 + 근거 절에 조판 실측 주소(이 문서) 추가.
- 03장: 100자를 넘던 비고 셀 5개를 판정 한 줄로 줄이고, 논증은 표 아래 「승격 경로 — 비고에서 꺼낸 논증」 절 신설로 이동.
- 02장: 산출물 규칙 4를 판정 질문 + 허용 불릿 3종 + 금지·예외·근거 줄로 분해. 01장: 명명 규칙 1을 시각 문단 3개로 분해.
- **수리 후 재측정** (같은 스크립트): 본문 벽(200자+) 6 → **0**, 300자+ 3 → **0**, 최장 본문 문단 471자 → 195자.
  잔여 200자+ 2건은 03·04장 말미 근거 절의 인용 목록 줄이라 본문 벽이 아니다.
  03장 표 셀: 최장 151자 → 85자, 100자+ 셀 5 → **0**. 노션 렌더링 육안 검증 통과 (표·중첩 불릿·`<br>` 분단 전부 정상).
- 범위 밖으로 남긴 것: 아티팩트 밀도(우리 0.6/1000자 vs 표본 6.7)는 벽 수리로는 안 오른다 — 예시 쌍·핵심 포인트 콜아웃 보강은 재조판 마일스톤(F5·F6)의 몫.
- **채택·원본 반영 완료 (2026-08-01, 영호)**: 수정본 내용을 원본 4장(01·02·03·04)에 전부 반영하고 fetch 대조로 검증했다.
  01·02는 국소 치환 + 근거 절 추가, 03·04는 전면 교체(replace_content).
  수정본 4종은 MCP에 휴지통 이동 권한이 없어 「(삭제용) 수정본 보관함」 페이지로 이동 — 영호가 그 페이지 하나를 삭제하면 정리 끝.
