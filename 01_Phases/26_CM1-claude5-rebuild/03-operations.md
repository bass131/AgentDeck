# Phase 03: 운영

> **상태**: pending · **마일스톤**: CM1 · **등급**: 복잡 · **담당**: 메인 + 영호 (대화 확정) → 격리 서브 (백지 작성)

운영 정책(1~2파일)·스킬(work-plan/work-run)·세션 커맨드의 초안이 drafts에 존재하고, 매 턴 상주 예산표와 새 pin 계약이 확정된다.

## ⏪ 사전 조건

- [ ] Phase 02 완료 (편성 — 운영 규범이 참조할 역할 확정)

## 📝 작업 내용

- [ ] **[벽두 1회 결정] 매 턴 상주 예산표** — pin+헌법+훅 주입의 합산 목표치와 **항목별 유일 상주처** 지정. 예: "비가역 다이얼로그 미출현 = 훅 사망 신호, 즉시 중단" 같은 감시 지침이 어디 하나에만 사는지 명시 배정(pin↔헌법 순환 낙하 차단).
- [ ] **3버킷(기계 판정/육안/비가역)** — 개념이 건강하므로 압축 유지 제안. 등급 4단계(단순/보통/복잡/대규모)의 존폐는 영호 판단.
- [ ] **DONE·5단계 보고 경량화** — 1곳 1양식으로(현행 4중 서술 해소). phase-gate-validator와의 결합은 Phase 04에 넘긴다.
- [ ] **pin 계약 재정의** — 좌표 ~5줄(MODE·WORK-ID·현재/다음·게이트 약속 상주분). 창고 기능(백로그·이월·회고)은 BACKLOG.md 한 곳으로 분리.
- [ ] **night-run 예외 유지**(실증됨) — 새 운영 문서에 압축 이식.
- [ ] **세션 커맨드 3종(start/end/review) 간소화** + work-plan↔work-run 짝 재작성(한쪽만 고치면 어긋나는 짝임을 유지).

## ✅ 완료 조건

- [ ] 상주 예산표가 `_decisions.md`에 박제(수치 + 항목별 상주처)
- [ ] 새 pin 계약 초안 + 운영 정책·스킬·커맨드 초안이 drafts에 존재, 영호 육안 확정
- [ ] pin 신계약이 Phase 04 훅 감량의 입력으로 명시 전달(circuit-breaker의 pin grep 등 결합 지점 목록 포함)

## 📚 학습 포인트

- 컨텍스트 예산(context budget) — 매 턴 상주하는 토큰은 "무료"가 아니라 주의(attention)를 소비하는 비용이라는 관점.
- 계약(contract)으로서의 포맷 — pin 포맷을 바꾸면 그걸 파싱하는 훅이 조용히 죽는다(실사(實死) 이력 있음).

## ⚠️ 함정

- pin을 줄이며 "헌법이 담겠지", 헌법을 줄이며 "pin이 담겠지" — 예산표 없이 두 감량을 병행하면 감시 지침이 짝으로 낙하한다.
- 보고 경량화가 "보고 폐지"로 미끄러지지 않게 — 보고는 영호 학습 루프의 일부다(CORE-13 결).
