# M10 G2 — 메인 대화 엔진 · main 프로세스가 작업 폴더별 메인 대화를 갖고, 브레인스토밍이 그 대화의 여러 턴이 된다

- 마일스톤: M10 (마일스톤 스펙 `01_Milestones/M10_LoopView/00_마일스톤-스펙.md`) · 작성: 2026-11-19 · 상태: 종결(PR 101을 `milestone/m10-loop-view`에 로컬 병합 `5e765317`, 2026-11-19) · 검증 강도: 강(앱 소스 50줄 이상, 판정 경계)
- 작업 브랜치: `feat/m10-g2-main-chat` · 기준 브랜치: `milestone/m10-loop-view`(`c0e89709`, G1 병합 뒤).

## 목표

main 프로세스가 작업 폴더(저장소 루트, `repoKeyOf`)마다 메인 대화 하나를 갖는다. 대화는 루프 세션 포트(원격 쓰기 잠금, 자격 없는 환경)로 돌고 재기동 뒤에도 이어진다. 브레인스토밍 노드는 그 대화의 여러 턴이 되고, 실행기 사건은 대화 기록에 남는다. 화면(G3)이 붙을 IPC와 상태가 준비된다.

## 범위

- **만들 것**
  - 메인 대화 저장소 — `userData/loop/<repoKey>.main.json`(SDK 세션 id, 대화 기록, 사건 기록, 대기 중인 카드). 키는 `repoKeyOf`다. 렌더러가 아니라 main이 소유한다(작업 모드를 내려도 사건을 잃지 않음). 채팅의 대화 목록(`userData/chats`)에는 들어가지 않는다.
  - 메인 대화 턴 — 같은 SDK 세션을 `resumeSessionId`로 이어 쓴다. 작업 폴더마다 턴 대기열 하나로 직렬화한다(사용자 턴, 브레인스토밍 시작 턴, 사건 턴이 같은 세션을 동시에 이어 쓰지 않음). 세션 id가 무효면 생존 문서로 새 세션을 연다.
  - 여러 턴 브레인스토밍 — brainstorm 노드(role main)가 돌면 메인 대화에 시작 턴을 넣는다. 스펙이 바뀌지 않고 끝난 턴은 FAIL이 아니라 「사용자 기다림」이다. 스펙 초안이 서면 기존 스펙 승인 게이트(사람)가 승인·반려를 받는다(시안의 「스펙 승인 / 이어서 고치기」). 반려되면 같은 대화로 돌아와 반려 사유를 담은 턴을 이어 간다. 규칙 글은 코드에 둔다(템플릿 글을 바꾸면 템플릿 해시가 바뀌어 진행 중 상태가 막힌다).
  - 쓰기 창 — 메인 대화의 파일 쓰기는 `.agentdeck/milestone-spec.md`와 `.agentdeck/decisions.md`뿐이고, 실행기 커서가 brainstorm 노드에 있을 때만이다. 프롬프트가 아니라 잠금 층(PreToolUse)에서 막는다. Bash는 쓰지 못한다. 원격 쓰기 잠금과 `strictMcpConfig`는 그대로다.
  - 실행기 사건 기록 — 노드 시작·끝(판정)·FAIL·멈춤·예외·goal 병합·마일스톤 PR을 사건으로 기록하고 IPC로 내보낸다. 사건 줄은 모델 없이 만든다. 메인은 경계(goal 병합, 멈춤, 마일스톤 PR)에서만 짧은 턴으로 말한다.
  - 세션 사건 배선 — `openLoop`의 `onSessionEvent`를 세션 id로 묶어 내보낸다(G4의 노드 세션 탭이 같은 길을 쓴다).
  - 메인의 정해 둔 동작 셋(합의 「(제안)」) — SDK 공개 API(`createSdkMcpServer`·`tool`)의 앱 안 도구로 둔다. ① 멈춤: 구동자의 일시 정지 깃발 — 지금 노드가 끝나면 다음 노드로 가지 않는다. 실행 상태·검증 기록은 바꾸지 않는다. ② 이어 가기: 그 깃발만 내린다. ③ Backlog에 적기: `.agentdeck/backlog.md`에 한 줄을 덧붙인다(실행기가 쓴다).
  - 새 메인 대화 — 지난 기록을 보관하고 생존 문서로 새 세션을 연다(사용자가 부를 때만).
  - 재개 — 앱을 껐다 켜도 기록과 세션 id에서 이어 간다. 시작 턴을 다시 넣지 않는다. 꺼질 때 기다리던 질문 카드는 다시 묻는다.
  - IPC — 메인 대화 읽기(기록·사건·대기 카드), 사용자 턴 보내기, 새 메인 대화, 카드 답, 상태 push. `LoopStatus`에 「메인이 사용자를 기다림」과 「일시 정지」를 싣는다.
- **건드릴 곳**: `02_Project/00_Source/main/05_Loop/`(새 메인 대화 모듈 포함), `main/04_Claude/`의 세션 옵션·잠금 훅 연결부, `main/01_Ipc/handlers/loop.ts`, `main/00_App/bootstrap.ts`, `shared/13_Loop/`, 공유 IPC 계약, `02_Project/01_TestCode/`(시험, 수집 기준선), `01_Milestones/M10_LoopView/`. 판정 장치 변경 없음(이 goal의 1단계 `gate-config.json` 전환만).
- **하지 않을 것**: 렌더러 화면(메인 대화 보기, 대화 안 카드 — G3), 작업 모드 배치(G4), 그래프·알림(G5), 사용량 한도 멈춤(M11), 템플릿 파일 변경, 새 의존성.
- **완료조건**
  - 사람 판정은 사람만: 메인의 도구로는 스펙 승인·반려, FAIL 세 번 멈춤 풀기, 래치 풀기를 할 수 없고, 메인의 어떤 동작도 `USER-INPUT` 줄을 만들지 않는다(시험).
  - 쓰기 창: brainstorm 밖에서 메인이 스펙·결정 대장을 고치려 하면 잠금이 거부하고, 그 밖 경로는 언제나 거부한다(시험).
  - 여러 턴: 스펙을 바꾸지 않고 끝난 턴이 FAIL을 쌓지 않고 사용자 기다림이 되며, 반려 뒤 같은 세션으로 이어진다(가짜 세션 시험).
  - 직렬화와 재개: 동시에 들어온 턴이 한 줄로 서고, 재기동 뒤 시작 턴 없이 이어지며 대기 카드를 다시 묻는다(시험).
  - 실측: 실제 SDK로 메인 대화 두 턴을 잠금 아래에서 이어 쓰고(두 번째 턴이 첫 턴 내용을 기억), 앱 안 도구 하나를 부르는 탐침을 한 번 돌린다(결과를 검증 기록 줄에).
  - 하드 게이트 다섯 종 exit 0, `npm test` 실패 0, 독립 검수 반영, goal PR의 `hard-gates` 통과, 정형 절차로 병합.
