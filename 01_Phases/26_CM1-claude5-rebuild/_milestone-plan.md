## Context — 왜 하는가

- 모델은 Claude 5 세대(메인 Fable 5 · Worker Opus 5)로 넘어왔는데, 하네스 텍스트는 구세대 모델을 가정한 채 누적 성장만 해 왔다. Boris Cherny(Claude Code 헤드)의 권고 — "새 모델 세대에는 하네스를 지우고, 더 적은 가이드로 모델을 관찰한 뒤 필요한 것만 다시 넣어라"(Anthropic도 Claude Code 시스템 프롬프트 ~80%를 삭제, 성능 향상 실측) — 를 적용한다.
- 전수 인벤토리 실측(2026-07-29): 문서성 텍스트 **약 5만 줄**. 병리 3종 실증 — ① 같은 규칙의 2~6중 서술 → "동기화 책임" → 이력 비대 → 컨텍스트 오염의 자기 강화 루프 ② 이력의 본문 침투(죽은 참조 20+곳, 문서 간 정면 모순) ③ 구세대 가정의 조직론 스캐폴딩(메인 실행 차단, 에스컬레이션 8흐름 규정집 등). 상세 = `_scout-diagnosis.md`.
- 접근 = **청소가 아니라 이사**: 새 최소본에 가져갈 것만 싣는다. 남는 것은 아카이브(git+폴더 보존)이고, Opus 5가 실제로 실수하는 게 **관측**되면 실측 근거와 함께 복원한다.

## 확정된 진행 원칙 (영호 결정)

1. **영역별 Phase + 각 Phase에서 영호와 직접 대화로 요구사항 확정** — 일괄 결정이 아니라 실물을 보며 짜맞춘다.
2. **작성자/검증자 분리** — 새 산출물 작성은 오염되지 않은 Opus 5(max effort) 서브가, 브리프·의미 누락 검증은 메인이, 최종 확정은 영호가.
3. 봉인은 트랙 내내 존중 — 초안은 스테이징, 실경로 반영은 영호의 OpenGate 창에서만.

### 층별 작성 방식 (설계 비평 반영)

- **산문 층**(CORE·정본 문서·정책·에이전트 서술·헌법): 깨끗한 서브의 **백지 작성**. 브리프는 산문이 아니라 **구조화 결정 카드**(불릿 계약)로 — 산문 브리프는 구 문체를 운반한다. ⚠️ 프로브 실측(2026-07-29)으로 **서브에도 프로젝트 CLAUDE.md가 전문 자동 주입됨이 확인**됐다 — 산문 층 백지 작성은 하네스가 없는 격리 환경에서 스폰하는 것이 **필수**다(조건부에서 확정으로 승격). 격리 = **저장소 밖 빈 디렉토리**(⚠️ git worktree는 CLAUDE.md·`.claude/**`가 딸려와 격리가 아니다 — plan-auditor 🔴2). 메커니즘은 Phase 00의 격리 스폰 런북 프로브로 실측 확정.
- **코드 층**(훅 글루·판정 엔진·테스트): 백지 재작성 **금지**. 방어 로직은 실사고의 결정체(epoch 오버플로 클램프·fail-closed 5경로 등)라 재작성 = 방어 회귀 리스크. **보존 이식 + 삭제 위주 감량**으로 하고, 기능 제거는 해당 케이스 테스트 삭제와 짝으로 묶는다. 코드 층 작업자는 구 코드를 읽는 일반 Worker(오염 개념 비적용 — 로직이지 문체가 아님).

## 공통 Phase 루프

① 카드 제시(메인 — 현물·규모·증상·결정 포인트) → ② 대화 확정(영호+메인) → ③ 브리프(구조화 결정 카드, 구 문안 인용 금지) → ④ 작성(층별 방식) → ⑤ 이중 검증(메인=의미 누락 / 영호=육안) → ⑥ `_decisions.md` 한 줄 박제(새 CHANGELOG 규율의 파일럿 겸용).

## 제약

- **CORE-11**: 하네스 변경 = 영호 단독 통제. 실경로 반영은 전부 영호의 OpenGate 개폐로만, push/PR/merge는 ask 게이트 불변.
- **CORE-12**: `.codex/**` 불가침. CORE 의미 변경분은 전부 Codex 세션 백로그 등재.
- 훅·에이전트 편집은 같은 세션 검증 불가(스냅샷) — 검증은 항상 다음 세션.
- 목표치(상주 ~75%↓, 하네스 규범 8,282→2,000줄대)는 방향이지 약속 아님 — 관찰로 조정.
