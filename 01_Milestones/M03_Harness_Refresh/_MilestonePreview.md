# M03 — Harness Refresh · 하네스 갱신

- 마일스톤: M03 (2026-11-10 「하네스 분업 강제 완화」 방향의 집행 계획) · 작성: 2026-11-10 (rev1) · 상태: 승인 — 2026-11-11 계획 승인 문답, 집행 중
- 이름·번호·작업 브랜치는 안건 7의 판정으로 확정됐다 — M03 Harness Refresh, `chore/m03-harness-refresh`.

## 사람용 개요

이 마일스톤은 M01·M02에서 세운 감독 하네스를 지금의 Claude Code에 맞게 갱신하는 작업입니다.
방향은 둘입니다. 「누가, 어떤 세션에서 일하는가」를 묶던 분업 강제는 내립니다.
「검증과 완료가 근거에 연결됐는가」를 지키는 게이트는 남기고 구멍을 닫습니다.

분업 강제를 내리는 근거는 그것이 이미 집행되지 않는다는 실측입니다.
헌법 2조의 `--resume` 금지는 훅이 막지 못합니다. 세션 기동 훅은 경고만 낼 수 있고, resume 기동 기록 세 줄이 전부 그대로 진행됐습니다.
헌법 3조의 편집 제한은 fork 하위 에이전트가 통과합니다. 역할 게이트가 fork를 워커로 판정하기 때문입니다.
집행되지 않는 규칙은 지키는 쪽에만 비용을 지웁니다.

이 마일스톤이 끝나면 네 가지가 사실이 됩니다.
첫째, 좌표가 맞습니다. 두 헌법 파일과 게이트 설정이 종결된 M02가 아니라 현재 마일스톤을 가리킵니다.
둘째, 남기기로 한 게이트의 알려진 구멍이 닫힙니다. 위험 명령 가드의 회귀 2표면과, 새 도구가 만든 표면이 대상입니다.
셋째, 워커와 리뷰어가 현행 모델 ID로 뜹니다.
넷째, 헌법 2·3조가 개정되고 역할 게이트가 내려갑니다. 직접 구현할지 위임할지는 메인 세션이 판단합니다.

순서가 안전장치입니다. 새 게이트를 먼저 올리고, 구멍을 닫고, 역할 게이트는 맨 마지막에 내립니다.
지금 하네스에서 메인 세션은 `.claude/`를 고치지 못해 워커를 거칩니다.
역할 게이트를 먼저 내리면 나머지 하네스 수정이 작성자와 검수자의 분리 없이 진행됩니다.

작업은 네 단계입니다.
1단계는 계획 등재와 좌표 동기화입니다.
2단계는 남기는 게이트의 구멍을 닫고, 계획 게이트를 스폰 자리에서 편집 자리로 옮겨 올립니다.
3단계는 모델 ID를 교체합니다. 라우팅 정책을 먼저, 에이전트 정의를 그다음에 고칩니다.
4단계는 헌법 2·3·9조를 개정하고 역할 게이트를 내립니다.
앱의 SDK와 모델 목록은 이 마일스톤에 넣지 않습니다. 하네스 변경과 앱 변경이 섞이면 회귀의 원인을 가를 수 없습니다.

핵심 용어를 풀어 둡니다.
역할 게이트는 메인 세션의 `01_Milestones` 밖 편집을 막는 훅입니다.
스폰 게이트는 하위 에이전트를 띄우기 직전에 계획 문서의 규격, 실패 횟수, 결정 대장을 심사하는 훅입니다.
편집 경로는 편집 도구가 호출될 때 훅이 지나는 자리입니다. 메인이든 하위 에이전트든 편집 도구로 파일을 고치면 이 자리를 지납니다.
fork 하위 에이전트는 새 문맥으로 시작하지 않고 메인 대화 전체를 물려받아 시작하는 하위 에이전트입니다.

## 개요

- **목표**: 좌표가 현재 마일스톤을 가리키고, 유지하기로 한 게이트의 알려진 구멍이 테스트로 닫히며, 에이전트 정의가 승인된 모델 ID로 뜨고, 헌법 2·3·9조 개정과 역할 게이트 내림이 실측으로 확인된 상태가 된다.
- **스코프**: 포함은 좌표 동기화(`01_좌표-동기화-목록.md`), 가드 회귀 2표면과 같은 파일의 이월 항목(M02 Backlog 2·3·10), 검증 기록 헤더 계약 정합(M02 Backlog 5), 편집 경로 계획 게이트 신설(유지 대장 AD-02의 실물화를 겸한다), PowerShell·Workflow 표면 처리, 모델 ID 교체와 리뷰어 effort 명시, 헌법 2·3·9조 개정, 역할 게이트 내림, ADR-002다. 불포함은 앱 소스(`02_Project/00_Source/`)와 SDK·모델 목록 갱신, TDD 가드 휴리스틱의 존폐(2026-09-18 미결 사안), AD-01의 기계 차단, AD-03 공통 한계 3종, 전역 스킬 파일 제안 3건(감사 H6·M4·M5), Doctor의 정리 제안, 브랜치 삭제·통합과 리파인 브랜치의 처분, 「노션 사례 보강」이다.
- **도메인 태그 어휘**: `structure`(계획·좌표·문면 정합), `guard`(위험 명령 가드), `harness`(훅·설정 배선), `policy`(헌법·라우팅 정책). `source` 태그는 쓰지 않는다 — 훅 테스트는 vitest가 아니라 자체 러너라서 TDD 가드의 Green 증거 게이트가 관할하지 않는다 (M02와 같은 판독).
- **라우팅 판독**: 태그 네 종에 Phase 네 개, 의존은 1→2→3→4 선형이다. `settings.json`과 훅 상태 파일을 공유하므로 병렬 쌍을 두지 않는다. 태그 종수가 둘 이상이라 크로스 도메인으로 판독하며, 검수선은 리뷰어 1차에 Codex 교차 2차를 더한다.

## 완료선

완료선은 제안 네 조항이다. 사용자 확정 전이다.

1. 좌표 정합 — 두 헌법 파일, `gate-config.json`, pin이 M03을 가리키고 감사가 지목한 사실 불일치 여덟 건이 남지 않는다.
2. 유지 게이트의 구멍 — 가드 회귀 2표면이 Red에서 Green으로 뒤집히고, 미실측 2표면은 닫히거나 실측 영수증을 갖는다.
3. 모델 영수증 — 워커와 리뷰어가 승인된 모델 ID로 실제 기동했다는 기록이 있다.
4. 내림 실측 — 메인 세션의 `01_Milestones` 밖 편집이 역할 게이트 없이 진행되고, 계획이 유효하지 않으면 편집 경로 게이트가 막는다는 것이 hook-log로 확인된다.

## 계획 승인 문답 안건

안건 1·2는 이 계획의 전제를 묻는다. 안건 3~10은 [AI] 제안의 채택 여부다. 결과는 결정 대장 [USER] 줄로 남긴다.

1. **「완화」 방향의 직접 확인** — 헌법 2·3조와 역할 게이트를 완화·내림하는 방향이 사용자의 결정이 맞는가. 이 방향은 다른 세션을 거쳐 전달됐고 직접 확인된 적이 없다. 아니라면 이 계획은 「유지」 안으로 다시 세운다.
2. **Workflow 프로브의 실행 여부** — 하위 에이전트 1기짜리 최소 프로브를 한 번 돌릴 것인가. 돌리지 않으면 Phase 2에서 Workflow 도구를 닫는다.
3. **2조** — 권고로 낮춤(추천) 대 삭제. 추천안의 다섯째 줄(마감 검수의 독립)을 넣을지도 함께 정한다.
4. **3조** — 「보호 표면」 조항으로 교체(추천) 대 삭제.
5. **스폰 게이트** — 편집 경로로 이동(추천) 대 현 자리 유지.
6. **9조** — 「게이트 해제 수단은 사용자 전용」으로 대상 교체(추천) 대 폐기.
7. **번호·이름·브랜치** — M03 Harness Refresh와 전용 브랜치 `chore/m03-harness-refresh`(추천) 대 다른 이름 또는 master 직접 커밋. pin이 예고한 「노션 사례 보강」은 M04로 미룬다.
8. **실행 모델** — Agent 도구로 띄우는 `worker` 하위 에이전트(추천) 대 Orca 분할 pane의 top-level 워커 세션. 추천안은 스폰 게이트가 자동으로 발화하고 역할 신호가 0단계에서 실측됐다.
9. **Phase 2 묶음의 범위** — M02 Backlog 2·3·5·10(추천) 대 회귀로 확증된 10·3만.
10. **PowerShell 도구** — 프로젝트 설정의 deny로 닫기(추천) 대 가드의 matcher를 넓히고 PowerShell 문법 규칙을 새로 쓰기.

**판정 결과 (2026-11-11, 사용자 직접 답)** — 안건 1은 「맞아」, 안건 2는 「돌린다」, 안건 3~10은 「추천안 일괄 채택」이다.

## 제약

- **순서** — 새 게이트를 올린 뒤에 옛 게이트를 내린다. 역할 게이트의 배선 제거는 하네스 편집 전체의 마지막이다.
- **폐기 대상은 고치지 않는다** — 역할 게이트의 fork 통과는 수리하지 않는다.
- **하네스와 앱을 섞지 않는다** — `02_Project/00_Source/`는 이 마일스톤에서 불변이다.
- **현행 헌법이 Phase 4까지 유효하다** — 메인 세션은 `01_Milestones`만 편집하고, 각 Phase는 새 워커가 수행하며, `MOODIE_SESSION_ROLE`은 에이전트가 설정하지 않는다.
- **실행 모델** (안건 8) — 각 Phase의 워커는 Agent 도구의 `worker` 하위 에이전트다. 새 문맥으로 시작하므로 2조의 「새 워커 세션」을 충족한다고 읽는다. fork는 워커로 쓰지 않는다.
- **`settings.json` 편집은 그 워커의 최후 구현 편집이다** — settings는 즉시 핫로드된다 (M01 실측). 그 뒤 허용되는 편집은 자기 Phase의 기록 추기와 pin 마감뿐이다.
- **삭제는 사용자가 직접 실행한다** — 워커는 삭제를 집행하지 않고 결과만 실측한다 (M02 [USER] 안건 6 선례).
- **계획 밖 변경 금지** — 작업 중 발견은 이 폴더의 `99_Backlog.md`에 관찰로만 남긴다.
- **정책 변경은 [USER] 줄이 먼저다** — 모델 ID와 헌법 문면은 결정 대장의 [USER] 줄이 생긴 뒤에만 고친다.
- **종료 순서** — ① 하드 게이트 다섯 종, ② 기록 추기, ③ pin 마감 요약과 스탬프, ④ 마감 커밋(메시지에 `M03-P<번호>` 토큰), ⑤ `git status` clean 확인, ⑥ Stop. 자기보다 뒤에 일어나는 일은 미리 주장하지 않고 다음 인수자가 추기한다.
- **인수 대조** — 다음 Phase의 첫 Step이 이전 Phase의 기록 줄, `git log`의 Phase 토큰, `git status`, hook-log의 관련 줄을 대조한다 (M02의 사람 감사 수준).

## 마감 절차

마감은 Phase가 아니라 이 절이 소유한다.
순서는 ① 리뷰어 1차 검수와 Codex 교차 검수, ② 마감 보고서 등재, ③ 하드 게이트 다섯 종, ④ Phase 4의 마감 커밋과 clean을 인수 대조로 확인해 Phase 4 기록에 추기, ⑤ pin 마감 요약과 스탬프, ⑥ 마감 커밋, ⑦ 사용자 마감 판정과 유지 대장 상태 확인, ⑧ 작업 브랜치의 병합과 원격 push다.
⑧은 사용자 승인 게이트다 (헌법 10조).
검수자는 구현 문맥을 물려받지 않은 에이전트로 둔다.

## 검증 기록 운용

결과는 각 Phase 파일 말미의 기록 절에 적힌 줄로만 유효하다 (fail-closed).
줄 스킴은 `FAIL`·`PASS`·`USER-INPUT` 세 마커이며, 타임스탬프와 한 문장을 적는다. FAIL 줄에는 시도한 것까지 적는다.
각 줄은 그 줄을 쓰는 시점까지 관측된 사실만 담는다. 세션 id와 기준 HEAD도 마커 있는 줄 안에 적는다.
마지막 USER-INPUT 줄 이후의 FAIL이 세 번이면 전진이 막히고 사용자 판단을 기다린다.
기록은 append-only다. 스탬프의 시각은 기동 훅이 주입한 현재 시각을 기준으로 적는다.
