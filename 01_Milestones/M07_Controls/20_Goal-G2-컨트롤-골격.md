## 목표

앱의 권한 콜백(`permissionCoordinator.ts`의 `makeCanUseTool`)이 한 함수 안에 순서대로 적어 둔 분기를, G8 설계 `30_노드-구조.md`의 노드 모양을 따르는 등록부로 옮긴다.
판정 결과는 하나도 바꾸지 않는다. 이 goal이 끝나면 다음 goal들(보호, 컨트롤 패널, 병합 버튼)이 노드를 하나씩 더하거나 빼는 자리가 생긴다.

## 범위

- **만들 것**
  - 노드 인터페이스와 등록부. 노드마다 설계의 칸(이름, 지점, 판정 주체, 결과, 보호 수준, 켜짐·잠금, 실패 정책, 시간 상한)을 메타데이터로 갖고, 판정 함수는 「결정」 또는 「다음 노드로」를 돌려준다.
  - 지금 분기 여섯을 노드로 옮긴다. 순서는 지금 그대로다. `AskUserQuestion` 처리 → `Workflow` 게이트 → 규칙 제안 없는 호출의 카드 → `자동`·`Bypass` 허용 → 읽기 도구 허용 → `acceptEdits`의 비편집 도구 허용. 어느 노드도 정하지 않으면 카드다.
  - 노드가 예외를 던지면 그 노드의 실패 정책대로 한다. 이 goal의 노드는 모두 「막는다」(거부)다. 지금 코드에는 예외 경로가 없어서, 이것이 유일하게 새로 생기는 동작이다.
  - 등록부의 노드 목록을 읽는 함수. 컨트롤 패널 goal이 쓴다.
  - 판정 특성 테스트. 바꾸기 전 코드에 대고 도구 × 모드 × 규칙 제안 유무 × 사유 유무의 판정 표를 고정한다. 중단 신호의 거부와 `cancelAll`의 갈래도 고정한다.
- **건드릴 곳**: `02_Project/00_Source/main/04_Claude/permission/`(기존 `permissionCoordinator.ts`, 새 노드 파일), `02_Project/01_TestCode/main/04_Claude/`(새 테스트), 이 goal 문서, `M07_Controls/01_Work_Pin.md`·`99_Backlog.md`, `M07_Controls/10_Goal-G1-…`(종결 기록), `00_Decision_Board.local.json`, `98_Management/01_GateState/gate-config.json`의 `planPath`(1단계).
- **하지 않을 것**
  - 판정 결과의 변경. 169행(`자동`·`Bypass` 허용)의 의미를 바꾸는 일은 기준표와 분류기 goal의 몫이다.
  - `controls.json`, 보호 1~5, 엔진 경로 봉인, 컨트롤 패널 GUI, 노드 켜고 끄기. 다음 goal들의 몫이다(분할은 결정 대장).
  - SDK `hooks` 콜백 도입. 이번 노드는 모두 `canUseTool` 자리다.
  - 카드·질문의 화면과 이벤트 모양 변경.
- **완료조건**
  - 판정 특성 테스트가 바꾸기 전 코드와 바꾼 뒤 코드에서 똑같이 통과한다. 기존 권한 콜백 테스트 다섯 파일도 고치지 않고 통과한다.
  - 노드 등록부 테스트가 노드 여섯의 순서와 메타데이터, 실패 정책(예외 → 거부)을 고정한다.
  - 하드 게이트 다섯 종 exit 0, `npm test` 실패 0.
  - 이 브랜치로 빌드한 앱의 `자동` 모드에서 G6 0칸 리허설을 다시 한다. 가드가 묻는 `git push --dry-run origin HEAD:master`가 카드로 오고, 거부하면 실행되지 않는다(hook-log `ask` 줄, 원격 불변).
