# 마일스톤 루프

- 상태: 초안 · [개요](00_개요.md)

## 흐름

1. **브레인스토밍** — 사람과 메인 세션이 다음 마일스톤의 방향을 이야기한다. 메인 세션은 모호한 곳이 없어질 때까지 묻는다.
2. **마일스톤 스펙** — 메인 세션이 합의를 사람이 읽기 좋은 스펙 한 장으로 쓴다. 만들 것, 하지 않을 것, 관찰 가능한 완료조건을 적는다. 사람이 승인하면 시작이다.
3. **분해** — 에이전트가 스펙을 goal로 나눈다. 마일스톤의 크기는 고정하지 않는다. 목표의 유형에 따라 짧을 수도 길 수도 있다.
4. **goal 실행** — goal마다 구현 → 검증 → PR → 검사 통과 → 마일스톤 브랜치에 병합. 사람은 끼지 않는다.
5. **운영** — 문서와 현황판을 갱신하고, 범위 안의 Backlog와 기존 실패를 처리한다.
6. **마일스톤 끝** — 에이전트가 마일스톤 전체 회귀 검증을 돌리고 보고서를 쓴 뒤, 마일스톤 브랜치에서 `master`로 가는 PR을 연다.
7. **사람 병합** — 사람이 보고를 읽고 병합 버튼을 한 번 누른다. 다음 마일스톤은 1부터 다시 한다.

## 브랜치와 병합

| 브랜치 | 갈라지는 곳 | 병합하는 사람 | 조건 |
|---|---|---|---|
| goal 브랜치 | 마일스톤 브랜치 | 에이전트 | CI 하드 게이트 통과 + goal 검증 기록 PASS + 강 등급이면 독립 검수 반영 |
| 마일스톤 브랜치 | `master` | 사람 | 마일스톤 회귀 검증 PASS + 보고서 |

- 근거: `master` 병합은 revert로 되돌릴 수 있다. 되돌리기 어려운 릴리스·배포·보호 변경·강제 push는 사람 몫으로 남는다(성향 29).
- goal 병합은 마일스톤 브랜치 안에서만 일어나므로, 마일스톤 도중 방향이 틀어져도 `master`는 움직이지 않는다.
- 마일스톤 브랜치에도 CI를 건다.
- 저장소가 비공개이고 GitHub 요금제가 Free라서, 브랜치를 지키는 장치는 GitHub 서버가 아니라 앱 쪽에 둔다(`60_기존에서-바뀌는-것.md` 「저장소 공개 범위」).

## 작업 그래프

- 마일스톤 루프의 순서와 검사는 텍스트 지시가 아니라 작업 그래프다. 프로그램이 그래프를 실행하므로 에이전트가 단계를 건너뛸 수 없다.
- 그래프의 노드는 두 종류다.
  - **작업 노드**: 계획, 구현, 검증, PR, 문서화처럼 일을 한다. 노드마다 담당 세션이 있다.
  - **게이트 노드**: 막거나 묻거나 통과시킨다. 판정 주체는 규칙(코드), 모델(검수 에이전트), 사람 셋 중 하나다.
- 그래프는 프로젝트 유형별 템플릿에서 시작한다. v1의 템플릿은 「프로그램 개발」 하나다.
- 사람은 그래프를 직접 고칠 수도 있고, 에이전트와 논의해 에이전트가 대신 고치게 할 수도 있다.
- 에이전트가 고친 그래프는 사람이 승인한 뒤에 적용된다 — 그래프가 판정 장치이기 때문이다.
- 사람이 직접 고친 그래프는 승인 없이 바로 적용된다. 대신 그 즉시 메인 세션에 변경 내용을 알려, 메인이 바뀐 그래프를 알고 움직이게 한다.

## 마일스톤 사이의 운영 — 예약 루프

- 마일스톤 사이의 운영(Backlog 정리, 기존 실패 수리, 의존성 확인)은 예약 루프 작업이다. 정해진 주기로 에이전트가 돈다.
- 예약을 만들 때 사람이 범위, 주기, 사용량 한도를 정한다.
- 결과물은 운영 브랜치에 쌓였다가 다음 마일스톤 병합 때 함께 사람 병합을 거친다. `master`가 사람 모르게 움직이지 않는다.

## 사용량 한도

- 앱은 Claude 구독의 남은 사용량을 본다.
- 마일스톤 도중 한도가 다 되면 goal이나 단계의 경계 같은 안전한 지점에서 멈춘다. 멈춘 지점은 생존 문서에 남는다.
- 한도가 풀리면 앱이 스스로 이어 간다. 사람은 앱 안 표시로 멈췄던 사실을 나중에 본다.

## 재개

- 세션이 끊겨도 생존 문서(마일스톤 스펙, goal 문서, 결정 대장, 검증 기록, 현황)만으로 이어서 할 수 있어야 한다. 통과 여부는 기억이 아니라 검증 기록 줄에서 다시 읽는다.
