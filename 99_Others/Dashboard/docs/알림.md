# 현황판 알림 — 알림음, 탭 제목 배지, 조용함 줄

「내 손이 필요한 일」에 새 항목이 들어오면 페이지가 짧은 알림음을 한 번 낸다. 항목이 남아 있는 동안에는 탭 제목 앞에 개수가 붙는다.
에이전트가 응답을 마치고 오래 조용하면 같은 칸에 작은 줄이 하나 보인다. 이 줄은 소리도 배지도 내지 않는다.
M05 H4에서 만들었다. 본보기는 `C:\Dev\DawnHolder_Dashboard`의 결정 알림음(`web/public/decision-sound.js`, `web/README.md` 「결정 알림음」)이다.

## 무엇이 언제 울리나

- 대상은 「내 손이 필요한 일」에 **지금 보이는** 항목이다. 판정 규칙은 `lib/progress.mjs`의 `judgeHand`이고, README 「세 질문의 판정」에 있다. 명령 승인 질문처럼 `fresh`가 있는 항목은 그 분 안에서만 보이는데, 이 필터를 거친 뒤의 목록이다.
- 그 목록에서 처음 보는 **알림 키**가 생기는 순간 한 번 울린다. 키 둘이 한꺼번에 들어오면 한 번만 운다.
- 같은 키는 다시 울리지 않는다. 항목이 사라졌다가 같은 키로 돌아와도 조용하다.
- 판단은 스냅샷이 올 때마다 한다(`app.js` `render`). 탭이 숨어 있어도 스냅샷이 오면 판단하고, 그래서 다른 탭을 보고 있을 때도 들린다.
- 「응답 마침 뒤 조용함」 줄과 그 밖의 「알아 두면 좋은 사실」 줄은 울리지 않는다.

## 알림 키 (`judgeHand`의 `key`)

같은 사실이면 같은 키다. 단계 번호와 결정 대장 게이트는 goal마다 되풀이되므로 goal 문서 경로를 키에 넣는다. 넣지 않으면 한 goal에서 울린 `merge-step:7`이 다음 goal의 7단계를 영영 조용하게 만든다.

| 항목 | 키 | 예 |
|---|---|---|
| 병합 대기 | `merge:<goal 경로>` (PR 번호는 키에 넣지 않는다) | `merge:01_Milestones/M05_Structure/98b_….md` |
| 병합 승인 단계 진행 중 | `merge-step:<goal 경로>:<단계>` | `merge-step:01_Milestones/M05_Structure/98b_….md:7` |
| 사용자 입력 줄 | `question:<파일>:<그 줄의 시각>`, 시각이 없으면 줄 번호 | `question:…/98b_….md:2026-11-15T19:14:01+09:00` |
| 실패 세 번 멈춤 | `stopped:<goal 경로>:<단계>:u<USER-INPUT 줄 수>` | `stopped:…/98b_….md:3:u1` |
| 결정 대장 게이트 | `ledger:<결정 대장 경로>:<gate>:u<사용자 결정 수>` | `ledger:…/98b_….md:ask:u3` |
| 명령 승인 질문 | `ask:<기록 시각>` | `ask:2026-11-15T19:30:02+09:00` |
| 답을 기다리는 결정(H7, 결정 보드) | `decision:<결정 id>` — 탭 제목 배지 개수에도 센다 | `decision:g11-version-compare` |

멈춤·결정 대장 키의 `u<n>`은 사용자가 답한 뒤 다시 막힌 경우를 새 사실로 치려고 넣었다. 실패 수가 3에서 4로 늘기만 하면 같은 키다.
병합 대기는 PR 번호를 키에 넣지 않는다. 머리말에 번호가 나중에 붙어도 같은 요청이라 다시 울리지 않는다.
`question`은 기록 줄의 시각이 키라서 위쪽에 줄이 더해져 줄 번호가 밀려도 같은 질문이다.
기억은 200개라, 한 항목이 보이는 채로 다른 키 200개가 울리면 그 항목이 기억에서 밀려 한 번 더 울 수 있다.

## 기억과 저장

- 판단은 `public/chime.js`의 순수 함수가 한다. 화면 요소와 소리가 없어서 Node 시험이 그대로 불러 쓴다(`test/chime.test.mjs`).
- `app.js`가 classic script라 `chime.js`도 import·export 없이 전역 `AgentDeckChime`에 붙는다. `index.html`이 `chime.js`를 `app.js`보다 먼저 `defer`로 불러, 문서 순서대로 실행된다. 모듈 스크립트로 바꾸지 않은 이유는 둘이다. 하나는 `app.js`의 적재 방식을 바꾸지 않으려는 것이고, 다른 하나는 루트 `package.json`에 `type`이 없어 Node가 `.js`를 CommonJS로 읽는다는 점이다.
- 울린 키는 이 브라우저의 `localStorage` `ad-dash-chimed`에 최근 200개까지 남는다. 그래서 새로고침해도 다시 울리지 않는다. 페이지가 닫혀 있던 동안 들어온 항목은 다음에 열 때 운다.
- 같은 현황판을 연 다른 탭이 이미 울린 키는 이 탭에서 조용하다. 저장소를 판단 때마다 다시 읽기 때문이다.
- 저장소가 없거나 막혀 있으면 페이지가 열려 있는 동안만 기억한다. 이때와 처음 여는 브라우저에서는 첫 스냅샷에 이미 있던 항목을 울리지 않는다.
- 첫 스냅샷이 비어 있어도 빈 목록을 기억으로 남긴다. 그래야 그 뒤 첫 항목이 「첫 스냅샷」으로 묻히지 않는다.
- 저장된 값이 키 목록이 아니면 기억이 없는 것으로 보고 덮어쓴다.

## 소리

- Web Audio(`AudioContext` + `OscillatorNode` + `GainNode`)로 합성한 두 음이다. G5(784Hz) 0.26초, 0.2초 뒤 D6(1175Hz) 0.4초로 모두 약 0.6초다. 음원 파일이 없어서 서버 경로도 CSP 변경도 없다.
- 「동작 줄이기」(`prefers-reduced-motion`) 설정과 무관하게 운다. 소리 켜기·끄기 설정은 없다.
- 본보기의 mp3로 바꾸려면 같은 판단 모듈을 두고 `app.js`의 `tones`만 바꿔 끼운다. 바이너리 복사와 CSP `media-src` 확인이 따로 필요하다(goal 결정 대장).

## 소리 켜기

- 브라우저는 사용자가 페이지를 조작하기 전에는 소리를 막을 수 있다(자동 재생 정책). 이때 `AudioContext`는 `suspended`로 남는다.
- `resume()`은 막혀도 거절하지 않고 기다리기만 할 수 있다. 그래서 0.3초 안에 `running`이 되지 않으면 막힌 것으로 본다.
- 울려야 했는데 막히면 「내 손이 필요한 일」 안에 「브라우저가 알림음을 막았어요. [소리 켜기]」 줄이 나온다. 누르면 resume 뒤 알림음을 한 번 내고 줄이 사라진다.
- 「소리 켜기」 칩은 노랑 테두리 알약과 스피커 모양이다. 사용자가 할 일(노랑)이고, 빨강으로 채운 멈춤 네모와 모양·색이 다르다(H5).
- 페이지의 첫 클릭이나 키 입력 때 resume으로 허용을 미리 받아 둔다. 그 뒤에는 칩 없이 운다. 칩을 누른 클릭은 칩 쪽에 맡긴다.
- Web Audio가 없는 브라우저는 소리 없이 지나가고 칩도 띄우지 않는다. 머리 옆 표시는 「알림음 없음」이다(jsdom에서 화면으로 확인, `test/m11-g5-dom.test.mjs`).
- 「원문 N개를 읽지 못했어요」 줄은 할 일이 아니라 깨짐이라 빨강 네모다. Orca 워커 소식(`inboxHandle`)과 진척 낡음 줄도 알림음·배지 대상이 아니다(M11 G5).

## 알림 상태 작은 표시 (H5)

- 「내 손이 필요한 일」 질문 글 아래에 「알림음 켜짐」(초록 스피커), 「알림음 막힘 켜기」(노랑, 눌러서 켠다), 「알림음 없음」(회색, Web Audio 없음) 가운데 하나가 작게 보인다.
- 페이지를 열 때 한 번 재 본다(`app.js` `probeSound`). 그래서 막힌 브라우저는 알림이 오기 전에도 「막힘」이 보인다. 재는 동안(최대 0.3초)은 아무것도 보이지 않고, 판정 중에 보이던 표시는 바뀌지 않는다.
- 원천은 `app.js`의 알림음 상태 하나(`sound.state`, `setSound`)다. 아래 관찰 표지 `data-chime-blocked`도 같은 값에서 나온다. 값을 글로 바꾸는 규칙은 `chime.js`의 `soundMark`·`soundBadge`다.

## 상단 띠의 손 줄 (H5)

- 「지금」이 화면 밖으로 나가 상단 띠에 「지금 하는 일」이 고정될 때, 보이는 항목이 있으면 그 옆에 한 줄이 더 붙는다. 할 일은 노랑 테두리의 「내 손 필요 …」, 멈춤은 빨강 면의 「멈춤 …」이고, 항목이 더 있으면 「외 N건」이다.
- 멈춤 항목이 있으면 그것이 먼저다. 규칙은 `chime.js` `stripHand`이고 누르면 「지금」으로 간다.

## 탭 제목 배지

- 보이는 항목이 N개면 원래 제목(`AgentDeck 현황판`) 앞에 `(N) `을 붙인다. 그중 멈춤 수준(빨강) 항목이 하나라도 있으면 `(!N) `이다. 0개면 원래 제목이다.
- 스냅샷마다 갱신하고, 화면 시계(1초)로도 갱신한다. 명령 승인 질문의 10분이 지나 항목이 빠지면 제목도 따라 바뀐다.
- 탭이 숨어 있는 동안은 화면 시계가 쉰다. 그래서 시간만 지나 빠지는 항목은 다음 스냅샷이 오거나 탭이 다시 보일 때 제목에 반영된다.

## 응답 마침 뒤 조용함

- hook-log 끝에 이어진 Stop 기록 묶음 안에 `surface-probe`의 Stop이 있으면 서버가 그 시각을 `summary.activity.quiet`(`{ at, session, after: 5 }`)로 보낸다(`lib/progress.mjs` `judgeQuiet`). 활동으로 세지 않는 기록(`pass-watcher` 등)까지 모두 친다. 같은 Stop에 `stop-gate`도 기록을 남기고 두 훅의 기록 순서는 보장되지 않아 묶음으로 본다.
- 5분 **넘게** 그대로면 화면이 「응답을 마치고 N분째 조용해요 · 답을 기다리거나 배경 작업 중일 수 있어요.」를 알아 두면 좋은 사실 줄의 맨 끝에 보인다. 꼭 5분은 아직 아니다(`chime.js` `quietMinutes`).
- 이 줄은 회색 시계와 점선 알약 모양이다. 쉼(회색)이라서 노랑 세모의 주의 줄과 모양이 다르다(H5. 그 전에는 노랑 세모를 빌려 써서 할 일처럼 보였다).
- 시간이 지나기만 해도 바뀌는 값이라 서버 스냅샷(변경 때만 온다)이 아니라 화면 시계로 판정한다. 시계는 이 값이나 보이는 항목이 바뀔 때만 「지금」 영역을 다시 그린다.
- 하위 에이전트가 배경에서 일하면 기록이 이어지므로 줄이 나오지 않는다. 알림음 대상에서 뺀 이유는 hook-log로는 사용자 답을 기다리는지, 배경 작업을 기다리는지 가를 수 없어서다. 정확한 멈춤 알림은 에이전트의 `PushNotification`이 맡는다(goal 결정 대장).

## 관찰 표지

실제 경로를 확인할 때 쓴다. 페이지의 `<html>` 요소에 남는다(`document.documentElement.dataset`).

| 표지 | 뜻 |
|---|---|
| `data-chime-count` | 울려야 했던 순간의 수. 소리가 막혀도 센다. |
| `data-chime-last` | 마지막에 울린 키들(JSON 배열). |
| `data-chime-blocked` | 마지막 시도 뒤 소리가 막혀 있는지. `1` 막힘, `0` 재생됨, `pending` 판정 중(최대 0.3초), `unsupported` Web Audio 없음. 칩이나 첫 조작으로 풀리면 `0`이 된다. 한 번이라도 울려야 했던 뒤에만 붙는다. 알림 상태 작은 표시와 같은 값이다. |

Orca 브라우저에서는 `document.title`과 이 세 값을 조회해 확인한다.
