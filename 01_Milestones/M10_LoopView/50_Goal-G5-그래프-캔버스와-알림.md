# M10 G5 — 그래프 캔버스와 알림 · 보기 전용 노드 캔버스와 「노드 설정」 탭, Windows 알림과 앱 안 표시

- 마일스톤: M10 (마일스톤 스펙 `01_Milestones/M10_LoopView/00_마일스톤-스펙.md`) · 작성: 2026-11-20 · 상태: 실행 중 · 검증 강도: 강(앱 소스 50줄 이상)
- 작업 브랜치: `feat/m10-g5-graph-notify` · 기준 브랜치: `milestone/m10-loop-view`(`b47fbfb4`, G4 병합 뒤).

## 목표

작업 모드의 「그래프」 탭에 템플릿의 노드 캔버스가 그려지고, 노드를 고르면 오른쪽 「노드 설정」 탭에 그 노드의 설정이 보기 전용으로 열린다. 사람을 부르는 사건은 비전 「알림」대로 Windows 알림과 앱 안 표시로 나온다.

## 범위

- **만들 것**
  - 그래프 읽기 — main이 열린 작업 폴더의 템플릿(`main/05_Loop/template.ts`, `templates/program-dev.json`)을 화면용 그래프로 바꿔 읽기 IPC 하나로 준다. 노드마다 id·이름·종류(작업·실행기 동작·규칙·모델·사람)·실행할 명령·통과하면 갈 노드·실패하면 갈 노드(`onFail.goto`, 최대 횟수)·등급 조건, goal 반복 틀(어느 노드들이 goal마다 되풀이되는지). 꼴은 shared 계약에 두고, 노드 위치는 그래프 안의 칸(`position`)으로 둔다 — 뒤의 그래프 편집이 같은 칸을 고칠 수 있게. 지금은 자동 배치가 그 칸을 채운다.
  - 그래프 탭 캔버스(시안 장면 「그래프 탭(캔버스)」) — 노드 카드(종류별 색 띠), 입출력 점과 다음 노드로 가는 선, 실패·반려로 되돌아가는 길은 점선, goal 반복 틀은 묶음 상자(「goal 반복 — G1 ✓ · 지금 G2」). 지금 위치는 강조, 끝난 노드는 흐리게, FAIL 수는 그 노드 카드에. 확대·축소·맞춤. 새 의존성 없이 SVG와 DOM으로 그린다.
  - 「노드 설정」 탭 — 그래프 탭이 열려 있을 때 오른쪽 첫 탭. 고른 노드의 이름·종류·실행할 명령·통과/실패 경로를 읽기 전용 칸으로, 그 노드의 최근 검증 기록 줄(`LoopStatus.recentLines`), 그 노드의 세션이 있으면 세션 탭을 여는 단추. 「보기 전용 — 편집은 그래프 편집(뒤 마일스톤)」 한 줄.
  - 지금 위치와 끝남 판정은 `LoopStatus`(`node`·`goals`·`failCount`·`phase`)에서만 온다.
  - 알림 — main이 `LoopStatus` 변화를 보고 사건을 정한다.
    - 바로 알릴 사건: 사람 판정을 기다리는 멈춤(`halted` — 같은 곳 FAIL 세 번, 범위·완료조건 변경 같은 사람 판정), 위조 래치(`latched`). Windows 알림 한 번(Electron `Notification`)과 앱 안 표시.
    - 나중에 봐도 될 사건: 마일스톤 병합 대기(`milestonePr`). 앱 안 표시만.
    - 같은 사건(작업 폴더·종류·노드·사유)은 다시 알리지 않는다. 앱을 껐다 켜도 이미 알린 사건은 Windows 알림을 다시 띄우지 않는다(앱 설정에 알린 사건 키를 남김, 상한). 해결되면(phase가 그 상태를 벗어나면) 앱 안 표시가 사라진다.
    - 앱 안 표시: 작업 모드의 현황판 「기다리는 결정」 칸 위 알림 띠와 사이드바 프로젝트 꼬리표 옆 점, 채팅 모드에서는 「작업」 모드 버튼 옆 점. Windows 알림을 누르면 앱 창을 앞으로 가져와 그 작업 폴더의 작업 모드를 연다.
- **건드릴 곳**: `02_Project/00_Source/`(main의 그래프 읽기와 알림 `main/05_Loop/`·`main/01_Ipc/handlers/loop.ts`, `shared/` IPC 계약, renderer `13_Loop/`·`12_Window/`·`00_App/`), `02_Project/01_TestCode/`(시험, 수집 기준선, e2e 구동기), `01_Milestones/M10_LoopView/`. 판정 장치 변경 없음(1단계 `gate-config.json` 전환만).
- **하지 않을 것**: 그래프 편집(노드 설정 바꾸기·잇기·위치 끌기 — 뒤 마일스톤), 사용량 한도 사건(M11), 휴대폰 알림, 연습 저장소 실주행(G6), 워크트리, 실행기 순서·판정 동작 변경, 새 의존성, 로컬 현황판(`99_Others/Dashboard/`) 변경.
- **완료조건**
  - 같은 템플릿을 넣으면 그래프 읽기가 노드·선·되돌아가는 길·goal 반복 틀을 빠짐없이 내고, 위치 칸이 모든 노드에 있다(시험).
  - 그래프 탭이 노드마다 카드 하나, 다음 선과 점선을 그리고, `LoopStatus`의 지금 노드가 강조되며 끝난 노드가 흐리다 — 같은 상태를 넣으면 같은 표시다(시험).
  - 노드를 고르면 「노드 설정」이 그 노드의 설정을 입력칸 없이 보이고, 세션이 있으면 세션 탭을 연다(시험).
  - 바로 알릴 사건이 Windows 알림 한 번과 앱 안 표시로 나오고, 같은 사건은 재기동 뒤에도 다시 알리지 않으며, 해결되면 표시가 사라진다. 나중 사건은 앱 안 표시만(시험).
  - 실제 앱(빌드본, 2번 모니터, 임시 userData, 원격 없는 로컬 저장소)에서 그래프 탭 캔버스와 「노드 설정」 탭이 보인다(캡처). Windows 알림의 실관찰은 G6 실주행에서 한다(마일스톤 완료조건).
  - 하드 게이트 다섯 종 exit 0, `npm test` 실패 0, 독립 검수 반영, goal PR의 `hard-gates` 통과, 정형 절차로 병합.
