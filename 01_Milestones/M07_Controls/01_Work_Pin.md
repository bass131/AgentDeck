## 좌표

- 로드맵: `01_Milestones/00_Roadmap.md` — M05 구조 재편(종결) → M06 자가 개발(종결) → **M07 사용자 컨트롤** → M08 실전 투입. 이 로드맵의 goal들은 헌법 11조의 일회 예외로 합의 문답 없이 이어집니다.
- 마일스톤: **M07 사용자 컨트롤** — 완료선은 「되돌리기 어려운 행위(병합, 보호 해제)가 사람 버튼이나 서버 거부로만 일어나고, 컨트롤을 앱의 공통 패널에서 노드 단위로 넣고 뺀다」입니다. 출발점은 `M06_SelfDev/81_G8-컨트롤-설계/`이고, goal 순서는 그 `60_이행-순서와-goal-분할.md`를 따릅니다.
- 현재 goal: **G8 병합 버튼 (병합 대기, PR 74)** — `80_Goal-G8-병합-버튼.md`, 브랜치 `feat/m07-g8-merge-button`(master `aaaef0e4`에서 갈랐다). PR 카드의 병합 버튼(머리 SHA 고정, 필수 검사 확인), 잠금 노드 `merge-deny`, 저장소 설정 `ask`→`deny`, 헌법 10·11·6조 개정, 결정 보드 병합 경로 폐지다. 병합 API `sha`는 공식 문서 데이터로 확인했다(goal 문서). G5~G7은 종결됐다(PR 71~73). 사용자 지시는 「Backlog나 이어서 할 goal이 없을 때까지 완주」다(병합 승인과 사용자 몫 설정에서는 멈춘다).
- SDK·CLI 동작은 공개 타입·공식 문서·요청이 돌려준 값으로만 검증합니다. 번들 내부(`claude.exe`·축소된 `sdk.mjs`)를 열람하지 않습니다(사용자 지시).
- goal마다 PR 뒤 사용자의 병합을 기다리고 다음 goal로 갑니다. push는 항상 `-u origin <브랜치>`로 원격 브랜치를 명시합니다. 병합은 사용자가 앱 PR 카드의 「병합」 버튼(또는 GitHub 웹)으로 직접 합니다. 에이전트는 PR 번호와 함께 병합을 기다린다고 알리고, 결정 보드에는 병합을 올리지 않습니다(G8, 헌법 10조).
- 멈추는 곳: 범위나 완료조건을 바꿔야 할 때, FAIL 세 번, 사용자의 병합, 승인 항목(`master` 직접 push, 릴리스, 패키지 빌드·배포, 강제 push, 브랜치 삭제), GitHub 설정 변경이 필요한 goal의 앞선 조건(사용자 몫)입니다.
- 규율: 판정 장치(`.claude/hooks/`, `.claude/settings.json`, `98_Management/01_GateState/`, 두 헌법)는 현재 goal의 진척 단계에 명시된 것만 고칩니다. 범위 밖 발견은 `99_Backlog.md`에 한 줄로 남깁니다. M06에서 남은 항목은 `M06_SelfDev/99_Backlog.md`가 계속 소유합니다.
- 모델 라우팅: 정본은 `00_Documents/02_Rules/02_모델-라우팅-정책.md`입니다.
