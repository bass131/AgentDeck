## 목표

이 goal이 끝나면 사용자는 현황판에서 병합 대기 PR을 보고 「병합」 버튼을 눌러 병합한다.
병합은 서버가 띄우는 Windows 확인 창에서 사람이 「예」를 눌러야만 나가고, 보인 머리 SHA로 고정된다.
PR이 「꼭 볼 것」 경로를 건드렸으면 그 파일의 diff를 먼저 펼쳐 봐야 버튼이 켜진다.

## 범위

- **만들 것**
  - **병합 모듈** `99_Others/Dashboard/lib/merge.mjs` — `gh`를 셸 없이 인자 배열로 부른다. 저장소는 설정 `repoPath`의 `origin`이다.
    - PR 읽기: 상태·초안·병합 여부·base·머리 SHA·mergeable, base 보호의 `checks[{context, app_id}]`, 그 머리 SHA의 check run·상태(앱 고정, 실패 > 대기 > 성공), PR 파일 목록(쪽 넘김)과 `patch`.
    - 「꼭 볼 것」 판정: `.claude/`, `CLAUDE.md`, `AGENTS.md`, `98_Management/01_GateState/`, `.github/workflows/`, 그리고 `scripts`가 바뀐 `package.json`. 이름 바꾸기는 옛 경로도 본다. `package.json`은 patch 글자가 아니라 base·head 두 SHA의 파일을 읽어 `scripts` 객체를 비교한다(hunk 문맥에 `"scripts"` 줄이 안 보이거나 큰 파일은 `patch`가 빠진다). 읽기에 실패하면 「꼭 볼 것」으로 친다. patch가 없는 「꼭 볼 것」 파일은 GitHub의 파일 diff 링크를 보이고, 그 링크를 연 뒤에 본 것으로 친다.
    - G8 앱 서비스의 검수 반영분을 그대로 지킨다: 필수 검사 앱 고정, 실패 > 대기 > 성공, base 경로 인코딩, 「Required status checks not enabled」, 409 옵션 대조, PUT 직전 재확인, 상태 번호 없는 실패는 「결과 모름」, 늦은 읽기가 소비된 SHA를 되살리지 않음. `prMerge.test.ts`의 사례 표를 `node --test`로 옮긴다.
    - 병합: 마지막으로 읽어 보인 SHA만 받는다. 직전에 PR을 다시 읽어 머리·base·열림을 대조한 뒤 `merge-async`에 `sha`, `merge_method=merge`, `merge_action=direct_merge`, `bypass_rules=false`를 싣고 결과를 기다린다. 응답 꼴은 G8 앱 서비스(`main/08_Git/prMerge.ts`)와 같다.
  - **사람 확인 창** `lib/confirm.mjs` — 유일한 사람 증명이다. 에이전트도 페이지에서 토큰을 읽어 창을 띄울 수 있으므로, 창이 실수로 확인되지 않게 만든다.
    - 맨 위에 뜨는 Windows 폼이다. 가속키 없는 버튼 「병합」·「취소」, 기본 포커스는 「취소」, 뜬 뒤 1.5초는 두 버튼을 잠근다. 타자 중이던 Enter·Space·Y가 확인으로 새지 않게 하려는 것이다.
    - PR 번호·제목·base←head·전체 머리 SHA·「꼭 볼 것」 파일 이름(화면의 펼침 게이트는 브라우저 쪽이라 주소를 직접 부르면 건너뛴다)을 보인다.
    - PR 제목·브랜치 이름은 남이 정하는 글이라 스크립트에 끼워 넣지 않고 환경변수로 넘긴다.
    - 확인은 전용 출력 한 줄 하나로만 판정한다. 비정상 종료·빈 출력·시간 초과(기본 120초)·창을 띄우지 못함은 모두 취소다. 동시에 한 창만 띄운다.
    - 서버가 창 숨김 옵션으로 띄운 자식 프로세스에서도 창이 보이는지 실측한다.
  - **서버 경로** — `POST /api/merge/read`(PR 읽기)와 `POST /api/merge/run`(확인 창 → 병합). 결정 응답과 같은 토큰·출처 검사를 거친다. 토큰은 페이지에서 읽을 수 있으므로 사람 증명이 아니다. 현황판의 기존 불변식 「바깥 쓰기는 orca 넣기 한 곳」·「결정 응답 두 경로 밖은 GET만」을 단정하는 시험·README·주석은 「병합 두 경로 추가」로 좁혀 다시 적고, 단정을 느슨하게 풀지 않는다.
  - **주입 지점** — `createDashboard`가 병합 함수·확인 함수·시간 초과를 함수 인자로 받는다. 환경변수나 설정 스위치로는 바꿀 수 없다. 실측용 서버는 병합 함수에 호출을 기록만 하는 함수를 넣는다.
  - **화면** — 「내 손이 필요한 일」의 병합 대기 항목 옆에 병합 카드를 둔다. 머리 SHA, 필수 검사 결과, 「꼭 볼 것」 파일 목록(파일마다 접힌 diff), 「병합」 버튼, 다시 읽기, 결과 줄이다. 「꼭 볼 것」 파일을 모두 펼치기 전에는 버튼이 꺼져 있다. 다른 PR(Dependabot 등)은 번호 입력으로 불러온다.
