# 열린 질문

- 상태: 초안 · [개요](00_개요.md)
- 이 스펙을 확정하기 전에, 또는 v1을 만들면서 정해야 하는 것이다. 정해지면 해당 파일에 반영하고 여기서 지운다.

1. **궁극 목표의 숫자 완료선** — 「마일스톤 여러 개를 사람 개입 없이」를 몇 개, 개입 몇 번으로 셀지. v1 완료선(`50_v1-범위.md`)은 제안만 있다.
2. **알림의 세부** — PC 알림만이라는 것은 합의했다. 소리, 반복, 자리 비움 감지, 사건별 채널은 정하지 않았다. 사용자 원문: 「범위가 너무 넓어서 이야기 더 해봐야 할 거 같은데」.
3. **Taste 정본과 Second Brain** — 앱 쪽이 정본이다. 앱에서 Taste가 바뀌면 Second Brain의 `개발-성향.md`에 다시 쓸지, 쓴다면 누가 언제 쓸지.
4. **비공개 저장소의 서버 보호** — GitHub 무료 요금제의 비공개 저장소에서는 브랜치 보호와 필수 검사가 작동하지 않는다고 알고 있다(사용자 미확인, 요금제 확인 필요). 그러면 `master`와 마일스톤 브랜치를 서버에서 지키는 장치가 사라지고 앱의 잠금 노드만 남는다. 요금제를 올릴지, 앱 쪽 장치로 갈음할지.
5. **업데이트 인증** — 비공개 Release를 쓰는 사람 자신의 GitHub 로그인으로 읽는다는 해석은 Claude가 채웠다. 맞는지, 그리고 로그인 방식(기기 인증 등)을 무엇으로 할지.
6. **그래프 수정의 승인** — 사람이 그래프를 직접 고치거나 에이전트가 대신 고칠 때, 고친 그래프가 다음 실행부터 적용되기 전에 사람 승인을 받을지(`30_마일스톤-루프.md`의 제안).
7. **마일스톤 사이의 운영 범위** — 에이전트가 마일스톤 사이에 혼자 하는 운영(Backlog, 실패 수리, 의존성 업데이트)의 한도를 누가 어떻게 정할지. 그 결과물도 마일스톤 브랜치를 거칠지.
8. **설치본 세부** — 코드 서명을 하지 않고 Windows만 지원한다는 것은 제안이다.
