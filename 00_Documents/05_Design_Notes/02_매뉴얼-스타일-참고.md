# 참고 분석 — 실밸개발자 2부작의 문체·스타일·정리 방법

**목적**: 쟁점 02(독자 소유권 지도 반영)의 재료. 영호의 노션 매뉴얼 정본이 따를
문체·스타일·정리 방법을, 실밸개발자(유튜버) 공유 페이지 2부작에서 추출한다.

**시스템 자체를 도입하지 않는다** — 어떻게 써서 독자를 유도하는지만 참고한다
(2026-08-01, 영호).

## 표본의 2부 구성


| 부     | 페이지                | 역할                 | Diátaxis 유형 |
| ----- | ------------------ | ------------------ | ----------- |
| 개념본   | 하네스 엔지니어링 완벽 가이드   | 왜 필요한가, 멘탈 모델 심기   | explanation |
| 동작구조본 | 하네스 프레임워크 튜토리얼 가이드 | 실물이 어떻게 도는가, 따라 하기 | tutorial    |


같은 주제를 두 권이 나눠 갖는다 — 개념본은 비유와 의사코드로 "이해"를 만들고,
동작구조본은 구조 트리와 단계별 절차로 "재현"을 만든다. 서로 침범하지 않는다.

## 빌릴 것


| 요소                       | 출처    | 효과                                                       |
| ------------------------ | ----- | -------------------------------------------------------- |
| "이 페이지는?" + 한 줄 요약 선두    | 양쪽    | 역피라미드 — 첫 화면에서 문서의 존재 이유가 끝남                             |
| 하나의 비유를 끝까지 유지 (말·마구)    | 개념본   | 새 개념이 나올 때마다 같은 그림에 얹혀 기억됨                               |
| 아티팩트 + 해설 짝 규칙           | 양쪽    | 코드·표·다이어그램이 나오면 반드시 직후에 평문 "핵심 포인트" 콜아웃 — 아티팩트가 홀로 서지 않음 |
| 의사코드로 개념 설명              | 개념본   | 실행할 코드가 아니라 서사를 코드 형태로 — 구조가 산문보다 정확하게 전달됨               |
| 함정 콜아웃 ("이걸 안 쓰면 무슨 일이") | 동작구조본 | 규칙의 근거를 실패 장면으로 보여줌 — 맨조문보다 강함                           |
| 구조 트리 + `←` 역할 주석        | 동작구조본 | 디렉토리가 곧 지도 — 한 화면에 시스템 전모                                |
| 템플릿은 접기(details)에 격리     | 동작구조본 | 본문은 흐름을 유지, 상세는 원할 때만 펼침                                 |
| 상태·역할 분담 표 (누가/무엇을)      | 동작구조본 | 사람·AI 경계가 표 한 장으로 정리                                     |
| 실전 사례 문제-원인-해결 표         | 동작구조본 | "docs 하나 추가로 결과가 달라짐" — 방법론의 효과를 실측으로 증언                 |
| 빠른 시작 Step 1~N + FAQ     | 동작구조본 | 처음 온 독자의 진입로와 막힘 해소를 분리 수용                               |
| 수미상관 (첫 문장을 마지막에 반복)     | 개념본   | 문서가 하나의 주장으로 닫힘                                          |
| 해요체 강의 톤                 | 양쪽    | 가르치는 문서의 레지스터 — 선언조("~한다")와 대비됨                          |


## 빌리지 않을 것

1. **시스템 자체**   
execute.py·Phase 구조·/harness 스킬 등.  
우리는 Layer 0 루프가 이미 있고, 표본보다 정교하다(입구 게이트 2중, 생성·검증 분리, DoD-as-tests).
2. **CRITICAL 키워드 의존**
  - 표본은 "CLAUDE.md에 CRITICAL이라 쓰면 강하게 따른다"를 핵심 팁으로 소개하는데, 우리 03장 기준으로 이것은 판단 층에서 결정론을 흉내내는 P등급이다.   
  - 우리 매뉴얼은 프롬프트 강조가 아니라 강제 구조(H/G)를 가르친다.
3. **모든 문서의 해요체 통일**
  - 강의 톤은 매뉴얼(사람)의 것이다.   
  - 저장소 인스턴스(에이전트)는 명령형 "~한다"가 맞다.   
  - 아래 레지스터 결론 참조.

## 레지스터 결론 — 독자 소유권 지도의 문체 축

분할 축은 이론/실물이다 (2026-08-01 영호 — 쟁점 01 참조).


| 거처               | 성격                | 레지스터                                                                                                                    |
| ---------------- | ----------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 노션 1권 (이론본)      | 큰 개념 + 세세한 규칙의 규범 | Human Ready — "~해요체" 강의 톤으로 제작한다, 비유·함정 장면. 규칙에는 Why를 한 세트로 묶는다.                                                        |
| 노션 2권 (세팅·실행예시본) | 표준 세팅 + 실행 예시     | **혼합** — Human Ready 서사가 본문 흐름을 이끌어간다. AI-Ready 실물(템플릿·집행 문장·구조 트리)은 코드블록·접기에 격리해 삽입. 표본의 "아티팩트 + 해설 짝" 규칙이 이 혼합을 지탱한다. |
| 저장소 (인스턴스)       | 실제 로드되는 실행 재료     | AI Ready — 명령형 "~한다", 표·글롭·판정 질문. 서사나 불필요한 맥락은 작성하지 않는다. Human Ready — 단 문체가 아니라 **관측성**으로: 사람이 프로젝트가 어떻게 진행되고 있고, 구조가 어떤지를 판별할 수 있는 축.     |


같은 규칙이라도 세 거처에서 형태가 다르다.  
— 이론본은 왜를 장면으로 가르치고, 세팅본은 실물 예시로 보여주고, 인스턴스는 집행 문장으로 적는다.  
이 표가 쟁점 02(독자 소유권 지도)의 뼈대가 된다.
