# M02 — Hardening · 하네스 강도 수리

- 마일스톤: M02 (M01 마감 검수의 이관 — 하네스 강도 결함 수리와 이주 잔재 정리) · 작성: 2026-08-10 (rev11) · 상태: 승인 완료 (2026-08-10) · Phase 1 진행

## 사람용 개요

이 마일스톤은 M01에서 옮겨 심은 감독 하네스의 강도를 수리하는 작업입니다. M01 마감 검수에서 하네스가 겉보기보다 무른 지점들이 발견됐습니다.
막아야 할 명령이 표기를 조금만 바꾸면 통과하고, 일부는 원본인 Moodie 가드가 잡던 것을 못 잡는 회귀였습니다.
테스트 증거를 모으는 훅은 부분 통과를 전체 통과로 채집하고, 게이트 몇 개는 판독이 느슨했으며, 동시성 무손실 검증은 실행이 사실상 직렬이라 증거가 약했습니다.

이 마일스톤이 끝나면 세 가지가 사실이 됩니다.
첫째, 위험 명령 가드가 Moodie 원본이 덮던 표면 전부와 그 이상을 덮는다는 것이 테스트로 증명됩니다.
둘째, 검수 발견 전건이 수리되거나 사용자 판정으로 명시적으로 기각됩니다.
셋째, 동시성 무손실이 진짜 동시 실행으로 재실측되고, 재실측에서 손실이 확인되면 상태 저장을 수리해 무손실을 만듭니다.
여기에 더해 이주 잔재 문서와 유효하지 않은 테스트 코드를 사용자 승인 아래 정리합니다.

작업은 다섯 단계입니다.
1단계는 계획 등재와 좌표·헌법 포인터의 M02 전환, 승인된 헌법 2조 문안 반영, 워커 역할 신호 선실측과 함께, 가드 동등성 기준표를 실패하는 테스트로 만들고, 훅을 고치는 작업 자체가 훅에 막히는 자충수 구조를 해제합니다.
2단계는 가드 우회면(heredoc 오인 포함)을 수리하고 가드 테스트를 실저장소에서 떼어 격리해, 기준표를 전건 통과로 뒤집습니다.
3단계는 게이트 판독과 증거 채집을 수리하고 동시성을 재실측·수리합니다.
4단계는 응답 표피를 검사하는 피드백형 훅을 신설하고 문서 소건을 정합하며 Orca dispatch 갭의 수리 방안을 사용자 문답으로 확정합니다.
5단계는 이주 잔재와 무효 테스트를 이름 확정 목록으로 만들어 사용자 승인 뒤에만 정리합니다 — 삭제 처분의 집행은 사용자가 직접 실행하고, 워커는 이동(`git mv`)만 집행합니다.

핵심 용어를 풀어 둡니다.
동등성 기준표는 Moodie 원본 가드가 잡는 명령 표면을 전수 열거하고 항목마다 기대 판정을 적은 대조표입니다.
기대-실패 마커는 자체 테스트 러너(`test:hooks`는 vitest가 아니라 node 직접 실행 스크립트입니다)에 두는 플래그로, 그 항목은 「실패해야 통과」로 집계되고 예상 밖으로 통과하면 러너가 실패합니다.
TDD Red는 구현보다 실패하는 테스트를 먼저 쓰는 단계를 뜻합니다.

## 개요

- **목표**: M01에서 이식한 하네스의 강도 결함 전건이 처리되고, 위험 명령 가드가 Moodie 원본 표면과 동등 이상임이 테스트로 증명되며, 이주 잔재와 무효 테스트가 사용자 승인 아래 정리된 상태가 된다.
- **스코프**: 포함은 Backlog 1~15번 전건 처리(수리 또는 명시적 기각), 가드 동등 이상 증명(heredoc 세그먼트 오인 수리 포함), 가드 spawn 테스트 전건의 실저장소 격리, 동시성 진짜 동시 재실측과 손실 확인 시 상태 저장 수리, 표피 피드백 훅 신설, AD-02 설계 검토 문답, 헌법 2조 문면 반영, 이주 잔재 정리, 무효 테스트 정리다. 불포함은 AD-02의 실물화(후속 마일스톤), AD-01의 기계 차단(존치), 31_reset-gate·60_end-signal 이식, **세션 간 인수의 기계 프로토콜**(byte offset 동결·anchor 로깅·PostToolUse 결과 영수증 류 — [USER] 결정 1로 사람 감사 수준으로 되돌렸다), `SubagentStart`·`SubagentStop` 배선 설계(실행 모델을 top-level 전용으로 고정), 표피 훅의 차단형 승격, 가드의 승인 토큰·정확 경로 allowlist 설계, e2e 상시 실패 2건이 회귀로 판정될 경우의 수리다.
- **도메인 태그 어휘**: `structure`(계획·문서 등재·정합), `guard`(위험 명령 가드), `harness`(훅·게이트 판독·상태), `feedback`(표피 피드백 훅), `design`(AD-02 설계 검토), `cleanup`(잔재·무효물 정리).
- **라우팅 판독**: 태그 여섯 종에 Phase 다섯 개, 의존은 1→2→3→4→5 선형이다 — 훅 상태 파일·hook-log를 공유하고 settings 편집의 최후-편집 규율이 있어 병렬 쌍을 두지 않는다. 태그 종수가 둘 이상이므로 크로스 도메인으로 판독하며, 검수선은 리뷰어 1차에 Codex 교차 2차를 더한다.

## 완료선

완료선은 사용자 확정 세 조항입니다 — 첫째, 검수 발견 전건(Backlog 1~15번)을 수리 또는 명시적 기각으로 처리합니다.
둘째, 위험 명령 가드가 Moodie 원본(32_cmd-guard.cjs) 표면과 동등 이상임을 테스트로 증명합니다 — 이 증명은 기계 증명(테스트 스위트·픽스처)으로 유지합니다.
셋째, 상태 파일 동시 쓰기 무손실(이 계획에서는 Phase 3이 소유)을 진짜 동시 실행으로 재실측하고, 손실이 확인되면 상태 저장을 수리해 무손실을 증명합니다.
여기에 범위 추가 2건이 더해집니다 — 이주 잔재·무효 테스트 정리는 승인된 처분 목록의 집행과 기준선 재실측까지가 완결입니다. push·publish 축의 동등성은 M01 결정 대장 [USER] 2026-08-09 판정을 따릅니다.

## 제약

- **실행 모델** — 각 Phase 워커는 Agent 도구로 스폰하는 서브에이전트가 아니라 **Orca 분할 페인의 독립 top-level claude 세션**으로 실행한다 (M01에서 실증된 orca-cycle 패턴, work-pin 규율 「Phase 경계는 전부 새 워커 세션」이 뜻하는 것도 이것이다). 기동 명령은 **`claude --agent worker`로 고정**한다 ([USER] 결정 2). `SubagentStart`·`SubagentStop` 배선 설계는 이 마일스톤의 범위 밖이다.
- **역할 신호** ([USER] 결정 2) — `claude --agent worker` 기동에서 `agent_type`·`agent_id`가 훅 입력에 실려 `30_role-gate.cjs`가 worker로 판정하는지를 Phase 1이 **선실측**한다. 판정이 worker면 그대로 진행하고, main으로 판정되면 `01_Milestones` 밖 편집이 막히므로 **env 탈출구(`MOODIE_SESSION_ROLE=worker`)로 회귀**하되 그 설정은 **사용자가 직접** 한다 — 헌법 9조가 이 변수를 사용자 전용으로 두고 에이전트의 자체 설정·지시·스크립트 삽입을 금지하므로, 회귀는 사용자 고지와 사용자 손으로만 성립한다. 실측 결과와 채택 경로는 Phase 1 검증 기록 줄로 남긴다.

인수 검증은 사람 감사 수준이다 ([USER] 결정 1) — 아래 셋도 계획 문면으로 더 단정하지 않고 실행 중 실측으로 확정한다.

- 정상 종료에서 표피 훅이 hook-log 줄을 남기는지와 그 verdict — Phase 5 인수 대조가 눈으로 확인한다.

## 마감 절차

마감은 Phase가 아니라 이 절이 소유한다 (M01 선례). 마감 절차는 Phase 5 종료 뒤 **새 세션**에서 수행한다.
순서는 ① 리뷰어 1차 검수와 Codex 교차 검수, ② 마감 보고서 등재 — `00_Documents/03_Reports/`는 `01_Milestones` 밖이라 **워커 위임으로 실행한다**(헌법 3조), ③ 하드 게이트 다섯 종 실행, ④ Phase 5의 마감 커밋·clean·정상 종료를 인수 대조로 확인해 Phase 5 검증 기록에 append, ⑤ work-pin 마감 요약·스탬프, ⑥ 마감 커밋(보고서·확인 줄·pin을 한 커밋으로), ⑦ `git status` clean 확인, ⑧ Stop, ⑨ 사용자 마감 판정과 유지 대장 상태 확인, ⑩ 원격 push(사용자 승인 게이트)다.
④의 PASS append가 이 세션의 stop-gate를 장전하므로 ⑤의 pin 스탬프가 그보다 같거나 뒤여야 ⑧이 통과한다.

## 검증 기록 운용

검증 결과는 각 Phase 파일 말미 「검증 기록」의 줄로만 유효하다 (fail-closed).
줄 스킴은 `FAIL`·`PASS`·`USER-INPUT` 세 마커이며, 타임스탬프와 한 문장을 적는다 — 마커 없는 줄은 유효하지 않으므로 어떤 용도로도 만들지 않는다. 세션 id·기준 HEAD도 마커 있는 줄 안에 적는다.
각 줄은 그 줄을 쓰는 시점까지 관측된 사실만 담는다 — 뒤에 일어날 일의 선주장은 무효다.
스폰 게이트는 마지막 USER-INPUT 줄 이후의 FAIL만 세며, 세 번 이상이면 전진이 막히고 에스컬레이션으로 분기한다.
기록은 append-only다 — 다음 인수자가 이전 Phase 절에 추기하는 확인 줄은 append-only 안의 추가 기록이라 이 규율과 충돌하지 않는다.
