# 현황판 결정 응답 — 결정 카드, 보낼 문장, 메인 입력창에 넣기

사용자 결정을 기다리는 일이 「지금 하는 일」 바로 아래 「결정 요청」 카드로 보인다(H8에서 이름과 자리를 옮겼다). 카드에서 A·B나 C 코멘트를 고르면 서버가 한 줄 문장을 만들고, 「메인 입력창에 넣기」가 그 문장을 메인 Claude 입력창에 **넣기만** 한다.
Enter는 누르지 않는다. 사용자가 메인 pane에서 Enter를 눌러야 메인 세션이 사용자의 직접 입력으로 받는다. 넣을 수 없으면 복사로 안내한다.
M05 H7에서 만들었다(사용자 요청 「결정이 필요한거 똑같이 던홀더 현황판처럼 체크할 수 있게 개선해줘」, 2026-11-16). 본보기는 `C:\Dev\DawnHolder_Dashboard`의 결정 응답 모드다.
이 기능으로 README의 「읽기 전용 보장」과 H4·H5의 「쓰기 경로를 들이지 않는다」 판단(`docs/던홀더-대비-점검.md`)이 바뀌었다. 결정 응답의 쓰기는 아래 두 경로뿐이다. 그 밖의 POST는 M07 G9·G11의 병합 세 경로(목록·읽기는 읽기 전용, 바깥 쓰기는 확인 창을 거친 병합 하나)뿐이다([`병합.md`](병합.md)).

## 결정 보드 파일

- 위치는 `01_Milestones/00_Decision_Board.local.json`이다. `01_Milestones/.gitignore`의 `*.local.json`으로 커밋하지 않는다. 브랜치와 무관한 로컬 상태라서, 브랜치를 오가도 충돌하지 않고 goal 사이에도 메인 세션이 고칠 수 있다(편집 계획 게이트가 `01_Milestones` 안은 늘 연다).
- 판정 장치 경로(`.claude/`, `98_Management/01_GateState/`)에는 두지 않는다.
- 수집은 다른 블록과 같은 오류 격리를 따른다(`lib/collector.mjs` 9번 블록, 판독은 `lib/decisions.mjs` `parseBoard`).
  - 파일이 없으면 실패가 아니라 「없음」이다. 영역이 숨는다.
  - JSON이 아니거나 맨 바깥이 객체가 아니면(쓰는 중이라 반쯤 쓰인 파일 포함) 그 블록만 「읽지 못함」이고, 화면은 직전 정상 목록을 그대로 보인다(`kept`).
  - 모양이 틀린 항목이나 칸은 그것만 빼거나 고쳐 읽고 「보드 경고」로 알린다.

```json
{ "decisions": [
  { "id": "g11-version-compare", "title": "엔진 버전 비교 두 함수를 합칠지", "state": "waiting", "pr": 55, "recommended": "A",
    "options": [ { "key": "A", "label": "그대로 둔다", "effect": "고르면 일어나는 일을 완성된 문장으로." },
                 { "key": "B", "label": "다음 goal에서 하나로 합친다", "effect": "…" } ],
    "detail": [ "## 무엇을 정하나", "- …", "", "## 왜 필요한가", "- …", "", "## 어떻게 하나", "- …", "", "## 메인 추천: A", "- …" ],
    "arrivedAt": "2026-11-15T21:50:00+09:00", "updatedAt": "2026-11-16T04:40:00+09:00" } ] }
```

| 칸 | 꼴 | 모양이 다르면 |
|---|---|---|
| `id` | 글자·숫자로 시작하는 64자 안의 `[A-Za-z0-9_.-]` | 그 항목을 뺀다. 같은 id가 두 번이면 뒤의 것을 뺀다 |
| `title` | 글 | 없으면 그 항목을 뺀다. 줄바꿈·제어문자는 공백이 된다 |
| `state` | `waiting`만 화면에 나온다 | 다른 값(예: `review`)은 경고 없이 세기만 한다(`skipped`) |
| `kind` (선택) | 지금 받는 값이 없다. `merge`는 M07 G8에서 없어졌다 | 경고하고 일반 결정으로 읽는다. `merge`면 「병합은 앱 PR 카드의 「병합」 버튼으로」를 경고에 적는다 |
| `pr` (선택) | 양의 정수, `"55"`·`"#55"`도 받는다 | 읽지 못하면 경고하고 비운다 |
| `options` | `{key, label, effect}` 배열, 키는 A·B | C 키(코멘트 자리), 중복 키, 이름 없는 선택지는 뺀다 |
| `recommended` | 있는 선택지 키 | 아니면 경고하고 비운다 |
| `detail` | 글 배열(한 원소가 한 줄). 글 하나면 줄바꿈으로 나눈다 | 그 밖의 꼴은 경고하고 비운다 |
| `arrivedAt`·`updatedAt` | ISO 시각 | 읽지 못하면 없는 것으로 본다 |

## 결정 항목의 수명

메인 세션이 보드를 손으로(Edit·Write 도구로) 고친다. 보드를 고치는 명령 도구는 아직 없다.

| 단계 | 메인이 하는 일 | 화면 |
|---|---|---|
| 질문 | 사용자 결정 요청을 채팅에 낼 때 같은 내용을 보드에 `waiting`으로 올린다. 채팅의 요청과 보드 항목은 같은 내용이어야 한다 | 카드가 나오고 알림음·탭 제목 배지가 울린다 |
| 답 | 사용자 답(채팅이든 현황판 문장이든)을 받으면 그 항목을 지운다. 후속 일은 goal 문서·Backlog에 적는다 | 카드가 사라지고 고른 답도 정리된다 |

- 글을 고칠 때마다 `updatedAt`을 갱신한다.
- 결정 id는 다시 쓰지 않는다. 지운 결정의 id를 새 결정에 붙이지 않는다. 알림음 기억(`ad-dash-chimed`)이 키 `decision:<id>`로 한 번만 울리므로, 같은 id를 다시 쓰면 새 결정이 소리 없이 들어온다.
- 답을 받고도 지우지 않으면 카드가 계속 남는다. 현황판은 「답이 전달됐다」를 스스로 알아보지 않는다(Dawnholder의 「끝남」 판정은 들이지 않았다).

## 결정 글 작성 기준

Dawnholder 「결정 글 작성 기준」을 따른다. 항목은 상세 글만 읽고 답할 수 있어야 한다.

- `detail`은 네 절을 이 순서로 둔다: `## 무엇을 정하나` · `## 왜 필요한가` · `## 어떻게 하나` · `## 메인 추천: <선택지>`.
- 「왜 필요한가」에는 실제 근거(파일과 행, 커밋, 결정 대장 줄)를 적고 측정과 추론을 가른다. 「어떻게 하나」에는 고른 뒤 누가 무엇을 하는지 적는다.
- 선택지 `effect`는 고르면 일어나는 일을 완성된 문장으로 쓴다. 「채택」·「보류」 같은 낱말만 두지 않는다.
- 축약어와 임시 기호를 쓰지 않는다. 정착되지 않은 용어는 항목마다 처음 나올 때 한 번 풀이한다. 항목은 따로 열리므로 다른 항목의 풀이에 기대지 않는다.
- 한 항목에 여러 후보를 묶지 않는다.

## 화면

- 카드 — 번호, 제목, 「추천 A」, 관련 PR, 선택지 버튼(키·이름·effect, 고르면 노랑 면과 체크), C 코멘트, 「선택 지우기」, 접힌 상세 글.
- 같은 키를 다시 누르면 고름이 풀린다. C를 고르면 입력 칸(300자)이 열리고 커서가 간다.
- 「보낼 문장」 — 서버가 만든 문장, 「메인 입력창에 넣기」(설정에 handle이 있을 때만), 「복사」, 「모두 지우기」, 결과 줄.
- 기다리는 결정 하나는 「내 손이 필요한 일」 항목 하나다(`chime.js` `decisionHand`, 키 `decision:<id>`). 그래서 H4 알림음(새 id만 한 번, 첫 스냅샷 무음), 탭 제목 배지, 띠의 손 줄, 「지금 하는 일」 카드의 노랑이 그대로 따라온다(`docs/알림.md`).
- 카드는 「지금」 밖의 자기 영역(`#decide`)에 칠한다. 다시 칠하기 키(`chime.js` `cardsKey`)는 목록 서명·읽기 상태·고름에 상세 글과 보드 경고의 글까지 넣는다. 상세 글이나 경고 글만 고쳐져도 다시 칠하고, 같으면 칠하지 않는다. 다시 칠할 때도 입력 중인 칸과 커서를 되돌린다. 코멘트를 치는 동안 스냅샷이 와도 글자가 남는다.
- 보드가 바뀌면 사라진 결정의 고름은 버리고, 남은 결정에서 사라진 키는 알림으로 이름을 알린 뒤 지운다(`reconcilePicks`). 같은 키라도 고른 선택지의 이름이나 효과 글이 바뀌었으면 그 고름도 지우고 「선택지 글이 바뀌어 고른 것을 지웠어요」로 알린다 — 사용자는 바뀌기 전 글을 보고 골랐다. C 코멘트는 선택지 글과 무관해 남긴다. 남은 고름이 있으면 문장을 다시 묻는다.
- 색은 기존 뜻만 쓴다. 노랑 = 사용자가 할 일. 다크·라이트 둘 다 같은 토큰이다.

## 문장

`현황판 결정 응답: 1) <제목> → A <이름> · 2) <제목> → C 코멘트 「<글>」` 한 줄이다(`lib/decisions.mjs` `composeAnswer`).
번호는 보드의 기다리는 항목 순서다. Dawnholder의 병합 승인 줄(`병합 승인: PR… head …`)과 단독 전송 규칙은 들이지 않았다.
병합은 보드로 올리지 않는다. M07 G8부터 병합은 사용자가 앱 PR 카드의 「병합」 버튼으로, G9부터는 현황판 병합 카드와 확인 창으로도 직접 하고, 에이전트의 병합 명령은 설정이 거부한다(헌법 10조). 문장은 게이트 해제 수단이나 승인 다이얼로그를 대신하지 않는다.

고쳐 고름 표지: 서버가 이번 수명에 이미 문장을 넣은 뒤(들어갔을 수 있는 경우 포함) 다른 문장을 넣으면, 문장 앞에 고정 글 `【고쳐 고름】 `(`server.mjs` `CORRECTION`)를 붙여 넣는다. 첫 글자 `【`는 선택 창의 키(숫자·글자·빈칸)도 명령 메뉴를 여는 `/`도 아니다 — 메인 세션이 이 꼴로 선택 창과 빈 프롬프트에 넣어 확인했다.
사용자가 Enter를 누르지 않았으면 입력창에 앞 문장이 남아 있다. 표지가 없으면 두 문장이 한 덩어리로 붙는다(검수에서 Claude Code 프롬프트가 「…A 그대로 둔다현황판 결정 응답: …」이 된 것을 봤다).
메인은 표지 뒤의 마지막 문장을 답으로 읽는다. 넣은 뒤 결과 줄은 앞 문장이 남아 있을 수 있다는 것과 마지막 문장이 답이라는 것을 알리고, Enter 전에 앞 문장을 지워도 된다고 안내한다.
표지는 목록이 바뀌어도 서버를 다시 켤 때까지 붙는다. 입력창에 앞 문장이 남았는지는 서버가 알 수 없어서다.
같은 문장 409는 같은 목록 안에서만 지킨다. 상세 글만 고쳐도 서명이 바뀌므로, 그 뒤 같은 고름을 다시 넣으면 표지를 붙여 한 번 더 들어간다.

## 서버 경로와 검사 (`server.mjs`)

결정 응답의 쓰기는 `POST /api/answer/preview`(문장만 돌려줌)와 `POST /api/answer/send`(넣기) 둘뿐이다. 두 경로의 다른 메서드는 405(`Allow: POST`)다. 그 밖에 POST를 받는 곳은 병합 세 경로(`POST /api/merge/list`·`/api/merge/read`·`/api/merge/run`, [`병합.md`](병합.md))뿐이고, 나머지 경로와 메서드는 예전처럼 GET·HEAD만 받고 나머지는 405다.
아래 검사 가운데 하나라도 걸리면 아무것도 넣지 않는다. 오른쪽은 그 검사를 지키는 시험이다.

| 검사 | 걸리면 | 시험 |
|---|---|---|
| Host가 이 서버(DNS rebinding 막기) | 403 | `answer.test.mjs` 「403: …」 |
| 페이지 토큰(서버 시작마다 무작위 32바이트, bootstrap에만 실음, 길이 비교 뒤 `timingSafeEqual`) | 403 | 같은 시험, 「the page carries a random token…」 |
| `Origin`이 정확히 이 서버. 없거나 `null`이어도 거절 | 403 | 「403: …」 |
| `Content-Type: application/json`, 본문 64KB 이하, JSON | 400·413 | 「400 and 413 …」 |
| 요청 주소를 URL로 읽을 수 있음(`//[` 같은 요청 줄이 서버를 죽이지 않게) | 400 | 「a request URL the parser rejects …」 |
| 페이지가 그린 목록 서명 = 서버의 지금 목록 서명(`decisionSig`). 서명에는 제목·선택지(키·이름·효과)·추천·PR·종류와 상세 글이 든다 — 사용자는 읽은 글을 보고 답하므로 상세 글만 고쳐져도 낡은 화면이다. 시각 칸은 들지 않는다 | 409, 페이지가 다시 그림 | 「409 stale …」, `decisions.test.mjs` 「lineFor …」·「signature …」 |
| 고른 id가 지금 목록에 있고 키가 지금 선택지(`pickKeys`) | 400 | 「409 stale …」, `decisions.test.mjs` 「picks …」 |
| 문장은 서버가 id와 키로 만든다. 페이지가 보낸 문장 칸은 읽지 않는다 | — | 「preview …」, `decisions.test.mjs` 「lineFor …」 |
| 제어문자(C0·DEL·C1·U+2028·U+2029)와 줄바꿈 제거 — 제목·이름·코멘트, 그리고 조립한 문장 전체 | 공백으로 바뀜 | `decisions.test.mjs` 「board: control …」·「one line …」·「sentence: the whole …」, 「deliver …」 |
| send는 「보낼 문장」 칸에 보인 문장을 `expect`로 함께 보내고, 서버 문장과 다르거나 없으면 넣지 않는다. 페이지는 미리보기를 기다리는 동안 버튼을 끄고 `sendLine`도 멈춘다. 예외는 서버가 붙이는 고정 글인 고쳐 고름 표지 하나이고, 결과 줄이 그것을 알린다 | 409, 페이지가 다시 물음 | 「send: a sentence other than the one the page showed …」, `decide-view.test.mjs` 「send waits for the preview …」 |
| 넣는 중 겹치기 | 409 | 「send: a second send …」 |
| 같은 문장 두 번(표지 없는 문장으로 비교). 결정 목록 서명이 바뀌면 같은 문장 표시를 지운다 | 409 | 「send: types the server sentence once …」, 「send: a changed decision list …」 |
| 다른 문장은 고쳐 고름 표지를 앞에 붙여 넣고 `corrected`·`note`로 알린다 | — | 「send: types the server sentence once …」, `decide-view.test.mjs` 「… correction note are wired」 |
| 넣기가 확실히 실패(부르기 전 거절, orca 없음 ENOENT, 0이 아닌 종료 코드, orca `ok:false`) — 글이 안 들어갔으니 같은 문장 표시를 앞 값으로 되돌려 다시 누를 수 있다 | 복사 안내 | 「send: a definite failure …」, 「deliver: ok:false, a non-zero exit …」 |
| 넣기 결과가 불확실(시간 초과로 자식을 죽임, 응답을 읽지 못함, 표시 없는 오류) — 글이 들어갔을 수 있어 같은 문장 표시를 남기고, 결과가 불확실하니 입력창을 보라고 안내한다. 그 뒤 같은 문장은 「넣었는지 확인하지 못했어요」 409 | 복사 안내(`uncertain`) | 「send: an uncertain failure …」 |
| 메인 handle(`config.local.json` `mainTerminalHandle`, `term_` + 소문자 UUID)이 없거나 형식이 틀림 | 넣지 않고 문장을 돌려줘 복사 안내 | 「send: no handle …」, 「config …」 |
| `orca terminal send --terminal <handle> --text <문장> --json`을 `execFile` 인자 배열로, 셸 없이, `--enter` 없이 한 번. 실패해도 다시 시도하지 않음 | 복사 안내 | 「deliver …」, 「send: no handle …」(실패 1회) |

handle 확인은 형식 검사뿐이다. Dawnholder의 메인 서명 추적, 설정 자동 갱신, 화면에서 handle 바꾸기는 들이지 않았다(Backlog 70).
handle은 페이지에 싣지 않는다. 스냅샷에는 넣기 버튼을 보일지(`answer.canType`)만 간다.

- 2026-11-16 포트 4320(메인 저장소 데이터, 버리는 Orca 터미널 handle)에서 카드 둘, 고른 상태와 보낼 문장, 다크·라이트, 좁은 폭, 코멘트 입력 중 스냅샷 두 번 뒤에도 글자·포커스·커서가 남는 것, 새 결정 id 하나만 울리는 것(`data-chime-count` 1→2)을 봤다.
