# M02 Phase 4 — 표피 훅 신설·문서 정합·AD-02 설계

## Phase 4 — 표피 훅 신설·문서 정합·AD-02 설계 · 태그: `feedback`·`structure`·`design` · 의존: Phase 3

**목표**: 응답 표피 검사 훅이 계획이 고정한 상수·파서·오류 계약대로 차단 없는 피드백형으로 신설되고, 문서 소건이 정합되며, AD-02의 수리 방안이 사용자 문답으로 확정된다.

Steps

1. **Phase 3 마감 인수** (인수 대조 절) — ① Phase 3 검증 기록에서 결과·세션 id·기준 HEAD를 읽는다. ② `git log`로 HEAD가 그 기준에서 전진했고 새 커밋 메시지에 `M02-P3` 토큰이 있는지 대조한다. ③ `git status`가 clean인지 확인한다. ④ hook-log에서 Phase 3 세션 id의 stop-gate 줄이 `allow`인지 눈으로 확인한다. ⑤ 하드 게이트 다섯 종을 재실행해 green을 재확인한다. ⑥ 코디네이터가 같은 실물을 대조한다. 확인이 모이면 Phase 3 검증 기록에 확인 줄을 append하고, 자기 세션 id와 기준 HEAD를 읽어 둔다.
2. 표피 검사 훅(Backlog 15번)의 테스트를 먼저 쓴다 (Red) — 상수와 판정 계약은 아래로 고정한다.
   - 검사 대상: Stop 입력 `transcript_path`의 JSONL에서 마지막 assistant 메시지의 text 블록만 **단일 `\n` 하나로** 이어 붙인 본문 (tool_use·thinking 블록 제외). 결합자를 `\n`으로 고정하는 이유는 문장 경계 규칙이 줄바꿈을 경계로 쓰기 때문이다 — 빈 문자열로 붙이면 서로 다른 블록의 괄호·화살표가 한 문장으로 합산돼 구현마다 판정이 갈린다. 코드 펜스·백틱 스팬 내부와 Markdown 링크 목적지(`](…)`의 괄호 안)는 전 표피 검사에서 제외한다.
   - 문장 경계: 종결부호(`.`·`!`·`?`·`…`) 뒤 공백 또는 줄끝, 그리고 줄바꿈·Markdown 구조 경계(목록 항목 머리 `- `/`1. `, 표제 `#` 줄, 표 행)에서 문장이 닫힌 것으로 본다.
   - 표피 ① 임시 기호: 원문자 라틴(U+24B6–U+24E9) 1회 이상. 원 숫자(①–⑳)는 목록 관행에 정당 사용이 있어 제외한다.
   - 표피 ② 괄호: 문장당 균형 잡힌 괄호 쌍 `(…)` 2쌍 이상 — 여는 괄호 단독 계수가 아니라 짝이 맞는 쌍을 센다.
   - 표피 ③ 화살표 연쇄: 문장당 `→`(U+2192) 3개 이상.
   - 표피 ④ 과장문 길이: 문장 200자 초과 (공백 포함·제외 구간 미포함).
   - 출력 계약: 항상 exit 0이고 `decision` 필드를 내지 않는다 (Stop 비차단). stdout의 `{"systemMessage": "[표피 훅] …"}`는 verdict가 `발화`일 때만 정확히 1건 내고, `통과`·`판정불가`에는 0건이다.
   - 로그 계약: 발화·비발화·판정불가 **모든** 실행이 `hook-log.jsonl`에 한 줄을 남기며, 줄은 여섯 필드를 갖는다 — `hook`, `event`(`Stop`), `session`, `agent_id`(없으면 null), `ts`, `verdict`(`발화`·`통과`·`판정불가`). 표피별 계수는 evidence에 담는다.
   - 입력 오류 계약: transcript_path 부재·JSONL 파싱 실패·assistant text 블록 부재는 exit 0으로 열되(fail-open), verdict `판정불가`와 사유를 남긴다.
   - 픽스처: 각 표피의 경계값 양쪽(균형 쌍 1/2, 화살표 2/3, 200자/201자, 원문자 0/1), 코드 펜스 제외 1건, 링크 2개 문장 비발화 1건, 목록 두 항목에 걸친 괄호 비합산 1건, text 블록 두 개에 걸친 비합산 1건과 블록 경계에서 문장이 닫히는 1건, 입력 오류 3형의 판정불가 로그 각 1건, 규칙 위반 없는 응답에서 `통과` 줄이 남고 systemMessage는 0건인 1건, payload에 `agent_id`가 있을 때와 없을 때 각각 값·null로 기록되는 2건.
3. 훅을 구현한다 (Green) — 피드백 문구에 「핵심 층(정보 밀도·명제 수·결정 요청 분리)은 기계 판정 불능이라 이 검사가 대신하지 못한다」는 한계를 명시한다. 차단형 승격은 몇 세션 실측 후 별도 사용자 판정으로, 이 마일스톤 범위 밖이다.
4. check-readme-links를 수리한다 (Backlog 13번) — 공백 든 링크 타깃·reference-style 링크 집계, 저장소 밖 형제 경로 반려, 대소문자 불일치 검출의 실패 테스트를 먼저 쓰고(Red) 수리한다. 검사기의 실물 표면은 루트 README 하나다 — 전 문서 표면의 참조 판정은 Phase 5의 grep 전수가 정본이다.
5. 라우팅 정책에 「계획 밖 변경 금지 — Backlog 보고」 조항을 추가하고 (Backlog 5번), README 67행의 옛 편제 평문을 갱신하고 (Backlog 8번), M01 Phase 2 DoD 문면과 실제 판정식의 차이(Backlog 14번)는 append-only 규율대로 정정 줄 추기로 처리한다.
6. USER-INPUT — AD-02 설계 검토: Orca dispatch 경로에 계획 게이트 심사를 넣는 방안을 최대 두 안으로 정리하고(각 안에 trade-off 한 문장), 사용자 문답으로 수리 방안을 확정한다. 현행 대응은 코디네이터가 기동 직전 plan-gate를 직접 구동하는 사람 절차(Phase 1 Step 2)이며, 여기서 정하는 것은 그 절차를 기계화할 방안이다. 결과는 결정 대장 [USER] 줄과 `98_Management/02_유지-대장.md`의 AD-02 상태 갱신으로 남긴다.
7. 신설 훅의 `settings.json` 배선을 이 세션의 **최후 구현·설정 편집**으로 수행한다 — 배선 직후부터 표피 훅이 라이브다. 이 편집 이후 허용되는 편집은 자기 Phase 검증 기록 추기와 work-pin 마감 둘뿐이다.
8. 종료 순서를 지킨다 — ① 하드 게이트 다섯 종, ② 검증 기록 추기(게이트 결과·세션 id·기준 HEAD까지만 — 커밋·clean·Stop과 자기 Stop 실측은 쓰지 않는다. 종료 Stop은 ⑥에서야 일어나므로 그 시점에 관측 불가다), ③ work-pin 마감 요약·스탬프, ④ 마감 커밋(`M02-P4` 토큰), ⑤ `git status` clean 확인, ⑥ Stop. 구현·설정 파일은 ① 이후 더 건드리지 않는다. 이 세션의 종료 Stop에서 표피 훅이 남기는 hook-log 줄이 배선 영수증이며, 확인은 Phase 5 시작 인수 Step이 한다. 별도 프로브 세션을 두지 않는다.

DoD

- 표피 훅과 링크 검사 수리의 테스트가 구현 전 Red·구현 후 Green이고 test:hooks에 배선돼 있으며, Step 2의 경계값·구조 경계·블록 경계·입력 오류·agent_id 픽스처 전건이 통과한다.
- text 블록 결합이 단일 `\n`임이 블록 경계 픽스처 2건으로 실측된다.
- 표피 훅이 출력 계약을 픽스처 실측으로 지킨다 — 모든 입력에 exit 0·`decision` 부재이고, systemMessage는 verdict `발화`일 때만 정확히 1건이며 `통과`·`판정불가`에는 0건이다.
- 모든 실행이 여섯 필드(`hook`·`event`·`session`·`agent_id`·`ts`·`verdict`)를 갖춘 로그 줄을 남긴다.
- AD-02 수리 방안이 결정 대장 [USER] 줄로 확정돼 있고 유지 대장 상태가 갱신돼 있다.
- 라우팅 정책·README·M01 정정 줄의 실물이 있다.
- settings 배선이 이 Phase의 최후 구현·설정 편집이고, 그 이후 편집은 검증 기록 추기와 pin 마감뿐이다.
- Phase 3 검증 기록에 이 Phase 시작 인수 Step의 확인 줄(커밋 전진 + `M02-P3` 토큰·clean·stop-gate 줄 확인)이 append돼 있다.
- 이 Phase의 세션 id와 기준 HEAD가 검증 기록 줄에 등재돼 있다.
- 하드 게이트 다섯 종이 전부 green이다.
- 배선 확인(표피 훅 Stop 줄), 마감 커밋·clean·정상 Stop은 이 Phase 안에서 판정하지 않는다 — Phase 5 시작 인수 Step이 append한 줄로 판정한다.
