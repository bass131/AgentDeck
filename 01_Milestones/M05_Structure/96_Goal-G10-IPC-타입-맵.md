## 목표

채널마다 요청·응답 타입을 한 맵에서 유도해 main 등록, preload, renderer가 같은 타입을 쓰게 한다. 어긋나면 컴파일이 실패하고, 컴포넌트는 `window.api`를 직접 부르지 않고 renderer `01_Ipc` 클라이언트를 거친다.

## 범위

- **만들 것**
  - 채널 타입 맵 — `shared/01_Ipc`에 채널 이름 → 요청·응답 타입 맵 하나. main 핸들러 등록 함수와 preload 노출이 이 맵에서 타입을 유도해, 핸들러 반환과 preload 선언이 어긋나면 `typecheck:node`/`typecheck:web`이 실패한다.
  - preload API를 `api.<도메인>.<동작>`으로 묶는다. 기존 평평한 이름은 이행 기간 별칭으로 남길지 재실측이 정한다.
  - renderer `01_Ipc` 클라이언트 — 컴포넌트·store가 부르는 단일 진입. `window.api` mock 헬퍼를 테스트 공용 하나로 모은다.
  - namespace가 구현 폴더와 어긋난 채널 14개를 재분류하고, 렌더러가 부르지 않는 채널 3개(`window.getBounds`, `window.setBounds`, `engine.versionState`)를 지운다.
  - 확인 응답(ack) 모양을 하나로 맞춘다.
- **건드릴 곳**: `shared/`의 IPC 계약, `main/01_Ipc`와 핸들러 등록부(등록 방식만, 도메인 로직은 그대로), `preload/index.ts`, `renderer/src/01_Ipc`(신설)와 `window.api` 호출부, 대응 테스트와 e2e 하네스의 `window.api` 가짜.
- **하지 않을 것**: main 도메인 로직의 중복 통합과 조립 지점 정리(G11), 테스트 미러 배치와 이름 규칙(G12), 채널의 의미·동작 변경(ack 모양 통일 말고), 새 채널, 저장 형식 변경, CSS 변경, 판정 장치 변경, 빌드 진입점 이동.
- **완료조건**
  - 채널 맵과 핸들러 반환 또는 preload 선언이 어긋나면 타입 검사가 실패한다(일부러 어긋낸 타입 테스트나 `@ts-expect-error` 고정으로 확인).
  - `renderer/src`의 컴포넌트·store에서 `window.api`를 직접 부르는 곳이 0이다(`01_Ipc` 클라이언트 자신과 근거가 적힌 예외만 남는다).
  - 안 쓰는 채널 3개가 지워졌고, 재분류한 채널 14개의 전후 표가 이 문서나 부속 문서에 있다.
  - 하드 게이트 다섯 종 exit 0, `npm test`는 Backlog 45의 부하 타임아웃 말고 실패 0. 테스트 수의 변화는 `collection-baseline.test.ts`에 사유와 함께 반영된다.
  - 화면: 빌드 CSS sha256 `090224c4…a3006e` 동일, 다섯 하네스 39건 통과, 92장 digest `e244ce5c…2b2192` 동일.
