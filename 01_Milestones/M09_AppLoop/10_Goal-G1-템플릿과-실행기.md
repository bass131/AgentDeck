## 목표

「프로그램 개발」 템플릿이 데이터 파일 하나로 있고, 앱 메인 프로세스의 실행기가 그 파일을 읽어 노드 순서와 게이트를 정한다. 게이트 판정은 한 길로만 나아가며, 판정 증거(검증 줄)는 실행기가 직접 쓴다. 가짜 세션·git·gh로 시험한다.

## 범위

- **만들 것**
  - `main/05_Loop/`의 템플릿 형식과 스키마 검사(외부 검사 라이브러리 없이), 템플릿 파일 `program-dev.json`(앱 자원, 읽기 전용).
  - 실행 상태 스키마 — 커서, goal 목록과 등급, 마지막 `USER-INPUT` 뒤의 FAIL 계수, 템플릿 id와 해시.
  - 실행기 상태 기계 — 판정 하나의 꼴(규칙·모델·사람 공통)로만 나아간다. 건너뛰기·강제 통과 API가 없다.
  - 규칙 게이트 — 실행기가 명령 포트로 검사를 돌리고 `PASS`/`FAIL` 줄을 직접 쓴다. 에이전트가 쓴 글은 노드를 나아가게 하지 못한다.
  - 등급 규칙 — 실행기가 계산한다(앱 소스 변경 줄 수, 템플릿이 적은 보호 경로, 애매하면 강).
  - 생존 문서 읽기·쓰기 — 작업 저장소의 `.agentdeck/`. 재개는 문서와 포트(git·gh) 상태에서 다시 유도한다.
  - 로드맵 재작성 — M09를 나누고 M10·M11 줄을 고친다.
- **건드릴 곳**
  - 판정 장치(헌법 3조 — 마일스톤 스펙 「건드릴 곳」에 있다): `98_Management/01_GateState/gate-config.json`의 `planPath`·`workPinPath`(1단계).
  - 판정 장치 밖: `02_Project/00_Source/main/05_Loop/`, `02_Project/01_TestCode/main/05_Loop/`, `02_Project/01_TestCode/collection-baseline.test.ts`(수집 수), `01_Milestones/M09_AppLoop/`, `01_Milestones/00_Roadmap.md`, M08 종결 기록 파일.
- **하지 않을 것**: 실제 Agent SDK 세션·git·gh 연결(G2), 화면과 IPC(G3), 새 의존성, CLI 하네스 변경.
- **완료조건**
  - 시험이 실제 템플릿 파일과 그 변형본(노드 빼기, 순서 바꾸기)으로 실행 순서가 템플릿을 그대로 따르는 것을 본다.
  - 시험이 규칙·모델·사람 게이트 각각의 불통과에서 다음 노드로 가지 않는 것과, 마지막 `USER-INPUT` 뒤 FAIL 셋이면 멈추는 것을 본다.
  - 시험이 에이전트가 쓴 「PASS」 글로는 노드가 나아가지 않는 것을 본다.
  - 시험이 재개 때 같은 노드를 다시 고르는 것과, 결정론적 단계가 확인 뒤 실행(이미 있으면 건너뜀)인 것을 본다.
  - 하드 게이트 다섯 종 exit 0, `npm test` 실패 0, 독립 검수 반영, goal PR의 `hard-gates` 통과, 정형 절차로 병합.
