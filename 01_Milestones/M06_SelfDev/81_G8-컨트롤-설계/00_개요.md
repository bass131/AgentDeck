# G8 사용자 컨트롤 설계 — 개요

## 한 문단 요약

지금 컨트롤은 저장소 훅, 설정 규칙, 앱 권한 콜백, GitHub 서버에 흩어져 있다. 그 대부분은 에이전트가 저장소나 디스크 파일을 고치거나 명령 글자를 바꾸면 끌 수 있다.
이 설계는 컨트롤을 「노드」 하나하나로 보고, 사용자만 넣고 빼는 앱의 공통 「컨트롤」 패널로 모은다.
되돌리기 어려운 행위는 노드에만 맡기지 않는다. 병합은 앱의 사람 전용 버튼으로 옮긴다. 에이전트 자격 증명에서는 관리 권한을 뺀다. 나중에는 에이전트와 사람의 GitHub 신원을 나눈다.

## 핵심 판단 다섯

1. **훅은 실수 방지 장치이고 보안 경계가 아니다.** 가드를 키워 의도적 우회를 막으려 하지 않는다. 경계는 에이전트가 끌 수 없는 것(보호 수준 L0)이다. 에이전트 자격 증명의 권한 범위와 사람의 그 자리 확인이 여기 든다(`20`).
2. **push와 병합은 GitHub에서 같은 권한이다.** 토큰만으로는 「PR까지만」을 만들 수 없다. 병합 분리는 세 단계로 간다. 앱 버튼과 에이전트 쪽 거부, 에이전트 자격 증명 교체, 신원 분리다(`40`).
3. **병합 버튼의 검사는 서버가 한다.** 에이전트가 쓰는 PASS 줄은 에이전트가 꾸밀 수 있다. 그래서 하드 게이트를 CI 필수 검사로 올리고, 버튼은 사람이 본 머리 커밋으로 병합을 고정한다(`40`).
4. **노드는 세 종류다.** 앱 소스의 코드 노드, GUI의 규칙 노드, GUI의 문장 노드(분류기가 읽는 자연어 규칙)다. 자기를 지키는 노드는 GUI로 지울 수 없는 잠금 노드로 둔다(`30`).
5. **앱 `자동`은 대부분의 턴에서 공식 분류기를 쓰지 않는다.** 시작 모드가 `acceptEdits`다. 공식 `auto`로 이으면 기준표에 없는 애매한 꼴을 분류기가 맡는다. 잇기 전에 공개 API로 잴 것이 여덟이다(`50`).

## 실사의 주요 발견

- 에이전트가 쓰는 `gh` 토큰은 `repo` 범위라 `master` 보호를 풀 수 있다. 막는 것은 가드의 글자 판독뿐이다.
- 앱은 실행을 열 때마다 userData의 엔진 폴더에서 SDK 코드를 불러온다. 에이전트가 그곳에 쓰면 앱 안 컨트롤이 모두 무력해진다. 그래서 엔진 경로가 보호 대상의 첫째다.
- 가드에 `timeout`이 없어 기본 600초다. 시간 초과는 통과로 떨어진다(공식 문서).
- 스폰 게이트 `20_plan-gate.cjs`는 M03 P4부터 배선이 없다.

## 사용자가 정할 것

- **마일스톤 배치**: M06을 이 설계로 닫고 컨트롤 작업을 새 마일스톤으로 세울지, M06 안에 이어 넣을지(`60`). 지금 결정 보드로 묻는다.
- **기준표의 각 행**: 특히 가드가 지금 차단하는 로컬 파괴 명령을 질문으로 완화할지(`50`). 컨트롤 골격 goal이 GUI로 옮기기 전까지 정하면 된다.
- **`classifyAllShell`**: 허용 규칙에 걸린 셸 명령도 분류기로 보낼지(`50` 실측 6 뒤).
- **GitHub 쪽 작업 시점**: CI 필수 검사 걸기, fine-grained 토큰 만들기와 keyring 로그인 정리, App·ruleset 설정. 사용자만 할 수 있다(`40`, `60`).
