## 목표

연습 저장소 `bass131/AgentDeck_Test`에서 앱만으로 작은 마일스톤 하나를 끝까지 돈다. 경로는 앱 안 브레인스토밍 → 스펙 승인 카드 → goal 둘 이상 → goal마다 CI 통과(강 등급이면 검수) → 마일스톤 브랜치 로컬 병합 → 회귀 → 마일스톤 PR → 사용자가 앱 병합 버튼으로 병합이다. 도중에 앱을 한 번 껐다 켜도 멈춘 노드부터 이어 가는 것을 실측한다.

## 범위

- **만들 것**
  - 실주행 준비 — 사용자가 이 PC의 gh·git 자격을 연습 저장소 전용 fine-grained 토큰으로 바꾼다(명령은 메인이 적는다). 메인은 연습 저장소를 `C:\Dev\AgentDeck_Test`에 clone하고, 앱을 개발 기동해 창을 2번 모니터에 둔다.
  - 실주행 — 연습 과제는 마일스톤 스펙 결정 대장의 2회차 4A(TypeScript·Node로 마크다운 문서의 깨진 상대 링크를 찾는 작은 CLI, 첫 goal이 GitHub Actions CI까지)다. 실행기의 CI 게이트는 검사 이름 `hard-gates`를 기다리고 규칙 게이트는 `npm run build`·`npm test`를 돌리므로, 브레인스토밍에서 이 둘을 스펙에 넣는다.
  - 재개 실측 — 완주 도중 앱을 한 번 끄고 다시 켜서, 연습 저장소의 생존 문서에서 멈춘 노드부터 이어 가는지 본다.
  - 실측 기록 — G2·G4가 공개 문서 밖이라 남긴 SDK·CLI 동작(훅 거부와 자동 허용의 순서, 자격 없는 환경에서의 엔진 기동, 훅 입력 `cwd`의 뜻, `gh pr create -R`, fine-grained 토큰으로 검사 결과 읽기, `strictMcpConfig`의 효과, 실제 모델의 `VERDICT` 줄 준수)을 실주행에서 본 값으로 적는다.
  - 완주를 막는 범위 안 결함의 수정 — 앱 소스와 시험. 완주와 무관한 발견은 Backlog에 한 줄로 남긴다.
  - 완주 기록 — goal·PR 번호, 사람 개입 횟수(브레인스토밍 답·승인·병합), 예외 호출의 횟수와 이유.
- **건드릴 곳**
  - 판정 장치(헌법 3조 — 스펙 「건드릴 곳」): `98_Management/01_GateState/gate-config.json`의 `planPath`(1단계).
  - 판정 장치 밖: `02_Project/00_Source/`(완주를 막는 결함만), `02_Project/01_TestCode/`, `01_Milestones/M09_AppLoop/`. 연습 저장소는 앱 실행기가 승인 목록 안에서만 쓴다(clone은 메인).
- **하지 않을 것**: 연습 저장소 `main` 병합(사용자의 앱 병합 버튼), 두 저장소의 설정·룰셋 변경(사용자 몫 — 필요하면 적어 준다), 메인이 연습 저장소에 직접 push·PR 만들기, 토큰 값을 채팅이나 파일에 남기기, CLI 하네스 변경, M10 몫(현황판·알림·사용량 한도).
- **완료조건**
  - 연습 저장소에서 위 경로로 마일스톤 하나를 앱만으로 완주했다. 사람 개입은 브레인스토밍 답, 승인 한 번, 병합 한 번이다(예외 호출은 횟수와 이유를 남김).
  - 완주 도중 앱을 한 번 껐다 켜도 멈춘 노드부터 이어 갔다(실측 한 번).
  - 실측 기록이 검증 기록 줄에 있다. 실주행 중 앱 소스를 고쳤으면 하드 게이트 다섯 종 exit 0, `npm test` 실패 0, 독립 검수 반영, goal PR의 `hard-gates` 통과, 정형 절차로 병합.
  - 사용자가 자격을 원래대로 되돌렸다.
