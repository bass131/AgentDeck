# Phase 08: 주석 다이어트 — 자명·stale·리뷰어용 주석 정리

> **상태**: pending · **마일스톤**: RS1 · **등급**: 보통(기계 반복·100% 가역·거동 무영향) · **담당**: 도메인 Worker 4종 + reviewer 표본 검증

## 🎯 목표

주석이 "코드가 못 보여주는 것"만 남는다 — 헌법 코딩 지침("주석은 코드 자체가 보여줄 수 없는 제약만") 정합. 코드는 한 줄도 안 바뀐다.

## ⏪ 사전 조건

- [ ] P03·P04·P05·P06·P07 완료 후 **마지막에 실행** — 다른 Phase들이 만지는 파일의 주석을 먼저 정리하면 diff 충돌·재작업만 생긴다.

## 📝 작업 내용 — 판정표가 정본

각 도메인 Worker(agent-backend / main-process / renderer / shared-ipc)가 자기 영역(`02_Source/**`)을 훑어 아래 판정표로 정리한다. **테스트(`99_Others/tests/**`)는 범위 밖**(양 대비 가치 낮음 — 필요하면 RS2).

### 삭제 3부류
1. **자명 주석** — 코드가 이미 말하는 것의 반복 (예: "카운터를 증가시킨다" 위에 `count++`). 다음 줄이 무엇을 하는지 다시 말하는 주석 전부.
2. **stale·시점 의존 서술** — 이미 거짓이 됐거나 완료되는 순간 거짓이 될 진행형 문장 ("후속 단계에서 한다", "아직 X는 안 됐다", 옛 좌표·옛 이름 언급). ⚠️ P03에서 이 부류가 3건 실측됐다(작업 순서 때문에 생긴 "조이면 깨진다" 류 미래형) — 같은 병의 잔존을 전수 수색. **타이브레이커**(보존 4부류-4와의 교차점): 양쪽 파일이 서로를 가리키는 *살아있는 상호참조*의 좌표가 어긋난 것이면 **정정**, 지난 작업 서사 속에 옛 이름·옛 좌표가 언급된 것이면 **삭제**다.
3. **리뷰어용 정당화** — 다음 독자가 아니라 그때의 리뷰어에게 말하는 문장 ("이 변경은 안전하다", "거동 불변이다", "~에서 이관됨" 같은 변경 이력 서술 — 이력은 git이 정본).

### 보존 4부류 (애매하면 보존 — 밤 보수 기준)
1. **제약·의도(왜)** — 코드가 못 보여주는 것: "왜 이 순서인가", "왜 이 생략이 의도인가"(예: claudeAgentRun 계열의 sessionStateGate 의도적 생략 근거 주석 — P06 분리로 파일·좌표가 바뀌므로 심볼로 찾는다), 엣지 케이스 근거.
2. **계약·지뢰 경고** — ⚠️ 마킹, discriminant/와이어 표면 불변 경고, ADR·CORE 참조, 신뢰경계 주의.
3. **공개 표면 JSDoc** — export 함수·타입의 계약 문서. (단 JSDoc *안의* 자명·stale 문장은 삭제 대상.)
4. **좌표 상호참조** — 파일 간 줄 번호 참조(knownModels ↔ runArgs 류). 좌표가 실제와 어긋나 있으면 삭제가 아니라 **정정**.

## ✅ 완료 조건

- [ ] **코드 불변의 기계 증명** (plan-auditor 🔴1 봉합 — 자기보고 금지, 절차 고정): 변경한 파일마다 ① base 버전을 `git show HEAD:<파일>`로 꺼내고 ② base와 작업본을 각각 esbuild로 변환(`npx esbuild --loader=ts` — 주석이 탈락된 출력이 나온다, vite 의존이라 이미 설치돼 있음) ③ 두 출력에 `git diff --no-index -w`가 **empty**임을 확인. 단 esbuild는 타입도 지우므로 타입 전용 변경은 이 방법에 안 잡힌다 — typecheck green + diff 육안 훑기를 보조로 병행하고, 세 증거를 모두 보고에 남긴다.
- [ ] `npm run typecheck`(node+web) 0 / `npm run test` passed 비감소·fail 집합이 **직전 Phase 마감 커밋 시점과 동일**(절대 목록을 박지 않는다 — 06·07 마감으로 바뀔 수 있음) / `npm run lint` 0
- [ ] 도메인별 통계 보고: 삭제 줄 수 · 부류별 건수 · 정정한 좌표 참조 건수
- [ ] reviewer 표본 검증 1회 — 점검 질문은 "지우면 안 되는 것(보존 4부류)을 지웠는가" 단 하나

## 📚 학습 포인트

- **주석의 반감기** — 자명 주석은 코드가 바뀌는 순간 거짓말이 되고, 시점 의존 주석은 작업이 끝나는 순간 거짓말이 된다. 살아남을 자격이 있는 주석은 "왜"뿐이다.
- 변경 이력을 주석으로 남기는 건 git과의 중복 — 이력의 정본은 커밋 본문이다.

## ⚠️ 함정

- **삭제가 공격적이면 안 된다** — 이 Phase의 유일한 실패 모드는 "지우면 안 되는 걸 지운 것". 애매하면 무조건 보존하고 목록으로 보고만.
- ⛔ `00_ipc/**`·`preload/**`·`.claude/**` 미접촉(지뢰 3 — 주석이라도 안 만진다. 00_ipc 주석 오기는 아침 안건에 이미 등재).
- **도구 지시 주석 전부는 판정 대상 자체가 아님**(plan-auditor 🔴2 봉합 — 개별 열거가 아니라 일반 규칙): `eslint-*` 지시 · `@ts-*` 지시 · `@vite-ignore` · `/// <reference` 삼중슬래시 지시 · `TODO`/`FIXME` — 무조건 보존. ⚠️ 특히 `@vite-ignore`(실측: `main/engineVersions.ts:477` SDK 동적 import 내부)는 지워도 **게이트 3종 어느 것에도 안 걸리고 빌드 거동만 바뀐다** — 겉보기가 노이즈 같아도 절대 접촉 금지.
- P06까지의 커밋이 전부 끝난 뒤에만 착수(사전 조건) — 미커밋 작업물 위에서 주석을 만지면 커밋 경계가 오염된다.
