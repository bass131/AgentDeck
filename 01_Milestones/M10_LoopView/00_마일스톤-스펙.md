## 목표

앱의 모드가 「채팅 · 작업」 둘이 되고, 작업 모드에서 사람은 늘 보이는 메인 대화와 이야기하며 마일스톤을 연다. 진행은 같은 화면의 세션 탭·그래프 탭·현황판과 알림으로 본다. 그 화면으로 연습 저장소의 마일스톤 하나를 완주한다.

## 범위

- **만들 것**
  - 모드 정리 — 「단일 에이전트」는 「채팅」, 새 「작업」 모드. 「멀티 에이전트」 모드는 코드와 시험까지 지운다. 사이드바 아래 「마일스톤 루프」 버튼과 따로 뜨던 루프 창(모달)도 없앤다.
  - 작업 단위는 작업 폴더 — 메인 대화, 실행기 상태, 세션 탭은 저장소가 아니라 작업 폴더(git worktree 하나, 지금은 기본 체크아웃)에 묶는다. 사이드바는 프로젝트(저장소) 아래에 작업 폴더를 한 단계 둔다. 워크트리를 새로 만들어 나란히 돌리는 일은 이번에 하지 않고, 나중에 더할 때 저장 형식을 바꾸지 않게만 한다(제안).
  - 메인 대화 — 작업 폴더마다 메인 대화 하나를 이어 쓴다. 새 메인 대화는 사용자가 열 때만 열린다.
    - 브레인스토밍 노드가 메인 대화 안의 여러 턴 대화가 된다. 질문 카드와 스펙 승인 카드는 대화 흐름 안에 뜬다.
    - goal이 도는 동안 실행기가 노드 시작·끝·FAIL·예외를 메인 대화에 사건으로 넣고, 메인이 짧게 말하며 사용자의 질문과 지시를 받는다. 순서와 게이트 판정은 실행기가 쥔다. 메인이 실행기에 하는 일은 정해 둔 몇 가지(멈춤, 이어 가기, Backlog에 적기)뿐이다(제안).
    - 메인 대화는 루프 일만 하고 저장소 파일을 직접 고치지 않는다.
  - 작업 모드 화면(시안 배치)
    - 사이드바: 최근 채팅 대신 프로젝트 목록(프로젝트 → 작업 폴더 → 메인 대화, 지난 마일스톤 기록), 「프로젝트 열기」.
    - 가운데: 맨 앞 「그래프」 탭, 메인 대화 탭, 노드 작업 세션 탭(보기 전용, 채팅 전체). 현황판의 노드 한 줄에서 연다.
    - 그래프 탭: n8n식 노드 캔버스(시안 「그래프 탭(캔버스)」) — 템플릿의 노드를 카드로 자동 배치하고 입출력 점과 선으로 잇는다. goal 단계는 반복 틀로 묶고, 실패·반려로 되돌아가는 길은 점선, 지금 위치는 강조한다. 노드를 누르면 오른쪽 「노드 설정」 탭에 이름·종류·실행할 명령·통과/실패 경로가 읽기 전용 칸으로 열린다. 이 칸과 노드 위치는 뒤의 그래프 편집이 그대로 고칠 수 있는 꼴로 둔다.
    - 오른쪽: 첫 탭 「현황판」(마일스톤 진척, goal, 노드 세션 한 줄, 기다리는 결정, 열린 PR과 병합 버튼, 최근 검증 기록), 둘째 탭 「파일·변경」(지금의 탐색기·변경된 파일·할 일·서브에이전트를 접어 넣음). 왼쪽 탐색기 열은 작업 모드에서 접는다.
  - 알림 — 비전 「알림」대로. 바로 알릴 사건(범위·완료조건 변경, FAIL 세 번)은 Windows 알림 한 번과 앱 안 표시, 나중에 봐도 될 사건(병합 대기)은 앱 안 표시만. 해결될 때까지 표시가 남고 같은 사건을 반복해 알리지 않는다. 사용량 한도 사건은 다음 마일스톤이다.
  - 로드맵 고치기 — M11 「헌장·Taste 문답과 사용량 한도」를 넣고 설치본과 업데이트를 M12로 민다. 그래프 편집(캔버스에서 노드 설정 바꾸기·잇기)과 워크트리별 작업 폴더를 뒤 마일스톤 후보로 적는다.

  - 모드가 「채팅 · 작업」 둘이고, 멀티 에이전트 모드의 코드·시험이 없다. 하드 게이트와 `npm test`가 그 상태에서 통과한다.
  - 작업 모드에서 브레인스토밍이 메인 대화 안의 여러 턴으로 이어져 스펙 승인까지 간다. 질문 카드와 승인 카드는 대화 안에 뜬다. goal 진행 중 메인 대화가 노드 사건을 말하고 사용자의 질문에 답한다(e2e 관찰).
