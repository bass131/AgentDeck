## 목표

처음 쓰는 사람이 설명서 없이 Claude 로그인 확인 → GitHub 계정 연결 → gh 확인 → 프로젝트 열기 → 헌장·Taste 문답 → 첫 마일스톤 시작까지 이어 가게 하는 「시작하기」 안내를 만든다(비전 `40_배포와-업데이트.md` 「완성형의 최소선」). 각 단계의 실제 일은 이미 있는 화면이 한다 — 안내는 상태를 읽어 보여 주고 그 화면으로 잇는다.

## 범위

- **만들 것**
  - 「시작하기」 안내 — 여섯 단계의 목록. 단계마다 상태(끝남·할 일·확인 중·막힘과 이유)와 그 일을 하는 화면으로 가는 버튼 하나.
    1. Claude Code 로그인 — 엔진의 사용 가능·인증 상태를 읽는다. 할 일이면 기존 로그인 안내로 잇는다.
    2. GitHub 계정 — goal 2의 연결 상태. 할 일이면 설정 「GitHub 계정」 칸을 연다.
    3. gh CLI — main이 `gh --version`을 돌려 있음·버전을 본다. 없으면 설치 안내(공식 주소 `https://cli.github.com`)와 「다시 확인」. 자격은 앱 토큰이 하므로 `gh auth`는 묻지 않는다.
    4. 프로젝트 열기 — 작업 폴더가 열려 있고 git 저장소인지. 할 일이면 기존 폴더 열기로 잇는다.
    5. 헌장·Taste — 열린 프로젝트에 헌장·Taste 문서(M12)가 있는지. 할 일이면 작업 모드의 「헌장·Taste」 문답으로 잇는다.
    6. 첫 마일스톤 — 그 프로젝트에서 마일스톤이 시작됐는지. 할 일이면 작업 모드에서 마일스톤을 여는 기존 진입점으로 잇는다.
  - 뜨는 때 — 처음 켤 때 저절로 뜬다. 여섯 단계가 모두 끝나거나 사람이 「나중에」로 닫으면 다시 저절로 뜨지 않고, 사이드바나 설정에서 다시 연다. 단계 상태는 열 때와 각 화면에서 돌아올 때 다시 읽는다.
  - 기존 시작 모달(새 버전 소개·엔진 알림)과 겹치지 않게 순서를 정한다.
  - 시험 — 단계 상태 판정(순수 함수), gh 확인(있음·없음·시간 초과), 뜨는 때와 다시 열기, 각 버튼이 맞는 화면을 여는지(렌더러 시험).
- **건드릴 곳**: `02_Project/00_Source/`, `02_Project/01_TestCode/`, `01_Milestones/M13_Installer/`, 판정 장치 `98_Management/01_GateState/gate-config.json`(`planPath` 전환, 1단계).
- **하지 않을 것**
  - 각 단계의 일 자체를 새로 만들기(로그인·기기 인증·폴더 열기·문답·마일스톤 열기는 기존 화면).
  - gh 자동 설치, Claude 로그인 대행, 자동 업데이트(goal 4), 실제 GitHub 승인(goal 6).
  - `.claude/`·두 헌법·`package.json` `scripts` 변경.
- **완료조건**
  - 시험이 여섯 단계의 상태 판정과 gh 확인(있음·없음·시간 초과), 뜨는 때(첫 실행·완료 뒤·「나중에」 뒤·다시 열기)를 묶는다.
  - 격리 앱 데이터의 빌드본 e2e(2번 모니터, 캡처)에서 첫 실행에 안내가 뜨고, GitHub 단계가 시험 서버로 연결되면 끝남으로 바뀌고, 프로젝트를 열면 그 단계가 끝남으로 바뀌며, 헌장·Taste와 첫 마일스톤 버튼이 작업 모드의 해당 화면을 연다. 「나중에」로 닫고 다시 켜면 저절로 뜨지 않고, 사이드바나 설정에서 다시 열린다.
