### 0. 맥락 — 왜 이게 Codex 몫인가

방금 Claude 세션이 A 스프린트(게이트 위생) 백로그 **13건 중 9건**을 해소했다. 남은 4건은 Claude가 게을러서 남긴 게 아니라 **CORE-12(엔진 격리)가 구조적으로 막아서** 남았다 — Claude는 `.codex/**` 와 `AGENTS.md` 를 **읽지도 쓰지도 못한다**. 그래서 이 4건은 전부 Codex 어댑터 쪽 일이다.

각 항목의 전문과 발견 경위는 `01_Phases/21_HR2-opus5-renewal/HR2-DONE.md` 「남긴 백로그」 절에 있다. 착수 전에 그 절의 4·7·10·13번을 읽어라.

### 1. 기동 조건 (먼저 확인)

`AGENTS.md`·`.codex/**`·`00_Documents/harness/core-manifest.json` 은 **봉인 안쪽**이다. ADR-033에 따라 하네스 유지보수 세션으로 기동해야 쓸 수 있다:

- `AGENTDECK_HARNESS_MAINTENANCE=1` + full-access 명시 기동
- ⚠️ **환경 변수는 훅 봉인만 해제하고 쓰기 권한을 주지 않는다** — 권한 전환이 별도로 필요하다(ADR-033 Sol adversarial 차단 #1). 둘 다 됐는지 착수 전에 확인해라.

봉인 해제 없이 시작하면 편집이 조용히 막히거나 중간에 끊긴다.

### 2. 작업 4건

#### 백로그 4 — Codex 기준선 재실측 ⭐ 이 항목이 가장 함정이 많다

**문제**: CLI 버전 드리프트(현행 `0.145.0` ≠ 기준선 `0.144.1`)로 계약이 **red** 다. `codex doctor` 의 3축 보고 중 `LIVE-CONFORMANCE` 가 baseline 튜플(cli·platform·rootProfile) 불일치로 `exit 3`(`REVALIDATION_REQUIRED`)를 낸다.

**⭐ 함정 (이 항목의 핵심)**: `00_Documents/harness/codex-baseline.json` 의 버전을 `0.145.0` 으로 덮어쓰면 **즉시 green** 이 된다. 그러나 그건 *재실측 없이 계약을 통과시키는 것*이다 — **게이트를 green으로 만드는 가장 빠른 길이 게이트를 무력화하는 길과 같다.** 이 저장소는 그 선택을 명시적으로 거부한다.

**올바른 절차** (ADR-033 "재실측·갱신은 attended 세션 절차"):
1. `codex doctor` 를 **실제로 돌려** 3축을 재실측한다 — `HOOK-GUARD`(차단 canary) / `OS-READ-BOUNDARY: UNENFORCED_EXPECTED`(격리 synthetic marker) / `LIVE-CONFORMANCE`.
2. 판정이 이전과 **같은지 달라졌는지**를 먼저 말하라. `UNENFORCED` → `ENFORCED` 처럼 **좋은 방향의 드리프트도 계약 재검토를 강제**한다(그 판정이 baseline 튜플에 묶여 있기 때문).
3. 실측 결과로 `codex-baseline.json` 을 갱신하고 **이력도 함께** 남긴다.
4. 재실측 출력 원문을 보고에 그대로 붙여라. "green 됐다"는 결론만으로는 채택하지 않는다.

**만약 재실측에서 판정이 달라졌다면** — 그건 계약 자체를 다시 볼 일이므로 임의로 갱신하지 말고 **영호에게 보고하고 멈춰라.**

#### 백로그 10 — CORE-06 v2의 Codex 어댑터 대칭 ⭐ 판단이 필요한 항목

**무슨 일이 있었나**: Claude 세션이 CORE-06을 **v2로 개정**했다. 의미 변경은 이렇다 —

> **명령형 비가역 6종**(`git push` · `gh pr create` · `gh pr merge` · `gh release` · `npm publish` · `npm run package`)은 **사람이 GO를 줘도 에이전트가 실행하지 않는다.** 승인으로 풀리는 게이트가 아니라 **실행 주체가 사람으로 고정**된 것이다.

이 설계를 고른 이유(같은 논리가 Codex에도 적용된다):
- 훅/정책은 payload만으로 *"이 명령을 사람이 승인했는가"* 를 **원리적으로 알 수 없다**.
- 승인 flag를 두면 **에이전트가 그 flag를 써서** 방어가 스스로를 무효화한다.
- 그래서 에이전트에겐 **항상 닫고**, 사람에게 실행 경로를 따로 열어 둔다. Claude 쪽은 영호가 프롬프트에 `! <명령>` 을 쳐서 로컬 셸로 실행한다(도구 호출이 아니라서 훅을 타지 않는다). **기능 손실은 0이다.**

**현재 Codex 쪽 상태 = v1 semantics**: `core-manifest.json` 의 `codex.verify` 는 execpolicy `prompt`(= 승인 후 에이전트가 실행)이고, `AGENTS.md` 도 v1 문장 그대로다.

**⭐ 위험의 형태**: `conformance-check.mjs` 는 **조항 `v` 와 CORE.md 헤더만 대조하고 어댑터별 준수는 보지 않는다.** 그래서 지금 **13/13 green인 채로 "두 어댑터 다 v2"로 읽힌다.** 이게 백로그 4번이 경계하는 것과 같은 형태의 위험이다.

**할 일**:
1. `00_Documents/harness/CORE.md` 의 CORE-06 v2 조문과 개정 블록을 읽어라(공통 코어라 Codex도 읽을 수 있다). 거기가 의미의 정본이다.
2. `.codex/**` 에서 v2 semantics를 구현한다 — execpolicy를 `prompt` 에서 **차단**으로 바꾸는 방향.
   - ⭐ **판단 필요**: Codex에는 Claude의 `!` prefix에 해당하는 "사람 직접 실행 경로"가 무엇인지 네가 확인해서 정해라. 그 경로가 없으면 v2를 그대로 이식하면 **기능이 죽는다** — 그때는 구현하지 말고 **영호에게 선택지를 제시하고 멈춰라**. Claude 쪽 v2가 성립한 전제가 "사람 경로가 늘 열려 있다"였다.
3. `AGENTS.md` 의 v1 문장을 v2로 개정한다.
4. `core-manifest.json` 의 **codex 항목만** 갱신한다. ⚠️ 같은 파일의 claude 항목은 건드리지 마라(Claude 세션이 소유).

#### 백로그 7 — 완료 보고 게이트의 Codex 대칭

완료 보고의 **HTML 선택제 전환**이 Claude 쪽에만 반영됐다. 같은 계약을 Codex가 독립 구현하는데 CORE-12로 Claude는 손댈 수 없어 비대칭이 남았다.

#### 백로그 13 — ADR-033:28의 rescue 프로필 경로 ⭐ 표기 문제가 아닐 수 있다

`ADR-033:28` 이 rescue 프로필(`agentdeck-rescue`)의 쓰기 허용 범위를 **옛 표기**로 서술한다:

```
02.Source/**  ·  99.Others/tests/**        ← 점 표기(개명 전)
02_Source/**  ·  99_Others/tests/**        ← 실제 폴더(현재)
```

Claude 세션은 ADR 산문의 옛 경로 45건 중 23건을 정정했는데 **이 한 줄만 손대지 못했다.** 산문이 아니라 **`.codex/**` 설정의 실제 값을 인용**하는 자리라, 설정을 봐야 어느 쪽이 틀렸는지 알 수 있는데 CORE-12가 그 접근을 막았기 때문이다.

**할 일 — 먼저 `.codex/` 설정의 실제 값을 확인하고, 두 갈래로 나뉜다**:

| 실제 설정값 | 의미 | 조치 |
|---|---|---|
| **옛 표기**(`02.Source/**`) | ⚠️ **기능 결함이다.** 그 경로의 폴더는 실재하지 않으므로 rescue 프로필이 **아무것도 쓸 수 없다.** | 설정을 신 표기로 고치고 + ADR-033 산문도 정정 + **왜 지금까지 아무도 몰랐는지**(= rescue를 안 썼거나 계약 테스트가 안 잡았다) 보고 |
| **신 표기**(`02_Source/**`) | 설정은 멀쩡하고 **문서만 낡았다** | ADR-033:28 산문만 정정 |

어느 쪽이었는지 **반드시 보고에 명시**해라. 이게 이 항목의 핵심 산출물이다.

### 3. 경계 (절대 규칙)

- **CORE-12 엔진 격리**: `.claude/hooks/**` 와 `.claude/state/**` 는 **읽기·쓰기·실행 전부 금지**(조문이 명시하는 범위). 그 밖의 `.claude/**`(정책·에이전트 정의·커맨드)도 **Claude 어댑터 소유**이므로 건드리지 마라 — 조문이 아니라 ADR-034 3층 구조의 소유권 문제다. Claude가 `.codex/**` 를 못 보는 것과 대칭이며, 공유하는 것은 **정책의 의미(공통 코어 `00_Documents/harness/CORE.md`)** 뿐이다.
  - 📌 **한쪽 훅 결함 수리를 다른 쪽 파일 복사로 하지 마라**(CORE-12 명문). 같은 의미라도 각자 payload 규약에 맞는 **독립 구현·독립 테스트**여야 한다 — 백로그 10을 처리할 때 특히 그렇다. Claude의 `dangerous-cmd-guard`·`shell-policy.mjs` 를 참고용으로도 열 수 없으니, CORE.md의 **의미**만 읽고 Codex 방식으로 새로 짜라.
- **CORE-06 v2**: `push`·`gh pr create/merge`·`gh release`·`npm publish`·`npm run package` 는 **에이전트가 실행하지 않는다.** 명령을 조립해 제시하고 영호가 직접 친다. (이 규칙을 지금 Codex에 이식하는 중이지만, **지금 세션에서도 이미 지켜라.**)
- **CORE-07**: `git reset --hard` · force push · `git clean` · `git add .` 류 금지. 커밋은 **명시 파일만** 스테이징.
- **CORE-11**: 헌법·ADR·CORE·정책 변경은 영호 단독 통제. 위 4건은 이미 승인된 범위지만, **범위 밖 변경이 필요해지면 하지 말고 보고**해라.
- **CORE-09**: conventional commits(`fix:`/`docs:`/`chore:`/`refactor:`).

     - CORE-12 조문이 격리하는 것은 정확히 `hooks/**` 와 `state/**` 뿐이다(*"Claude는 `.claude/hooks/**`·`.claude/state/**`만, Codex는 `.codex/hooks/**`·`.codex/state/**`만"*). **`.claude/CHANGELOG.md` 는 조문상 격리 대상이 아니다.**

     - 즉 **"어댑터 소유 파일"과 "전 저장소 이력"이 한 파일에서 충돌**한다. 임의로 정하지 말고 영호의 판단을 받아라.
