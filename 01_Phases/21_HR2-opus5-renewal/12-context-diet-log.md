## 4. description listing — 1차 미수행(2026-07-25) → 수행 완료(2026-07-26)

> **§4-A는 미룬 이유의 기록이고, §4-B가 결과다.** 앞을 지우지 않는 이유 = *왜 한 세션을 더 태웠는가*가 이 마일스톤의 학습이기 때문.

### 4-A. 1차 판정 — 미수행 (2026-07-25)

Phase 정의 §③은 에이전트 description 상위 4개의 압축을 지시하지만 **수행하지 않았다.**

| 근거 | 내용 |
|---|---|
| **검증 불가** | 완료 조건이 *"줄인 뒤 발화 프로브 1회, 안 뜨면 되돌린다"* 인데, 에이전트 정의 편집은 워처 문제로 **같은 세션에서 거짓 결과**를 낸다(메모리 「에이전트 정의 편집은 같은 세션에서 검증 불가」 — 이 창에서 기계 확정). 즉 프로브를 돌려도 그 결과를 믿을 수 없다 |
| **절감량 대비 위험** | 상위 3개(`work-run` 357 · `secretary` 319 · `agent-backend` 268자)를 30% 깎아도 ~60 tok. 발화가 죽으면 **절감이 아니라 기능 상실**이다 |
| **Phase 자체의 경고** | *"함부로 줄이지 않는다 — description은 자동발화 트리거다"* |

⇒ **P11(새 세션)으로 이관.** 실측 현황: 프로젝트 description 합계 3,046자 / **762 tok**(에이전트 10 · 스킬 2 · 커맨드 6).

영호가 `OPEN-GATE.bat`을 실행한 새 세션에서 처리했다(편집은 봉인 때문에 창이, 검증은 워처 때문에 새 세션이 필요 — 두 조건을 한 세션에서 만족시키는 유일한 방법).

**삭제 근거 = 전건 (c) 중복.** 다섯 파일 본문을 열어 대조했고, 지운 항목은 모두 본문에 **더 상세히** 존재한다(`agent-backend` turf의 파일별 설명 · `secretary`의 「왜 이 역할이 존재하는가」 절 · `coordinator` Hard rule 2의 4대조 · `main-process` turf의 모듈별 설명 · `shared-ipc` Hard rule 4). **이동처가 필요한 항목 0건, 근거 없는 삭제 0건.**

### ⭐ 4-C. P11 이관이 풀지 못한 것 — listing은 세션 시작 스냅샷이다

이관의 전제는 *"새 세션이면 발화 프로브를 믿을 수 있다"* 였다. **절반만 맞았다.**

- ✅ **이전 창 편집분에는 성립했다** — 이 세션 시작 시점의 시스템 listing이 디스크 값과 **글자 단위로 일치**했다(P02 full ID · P03 `disallowedTools`/coordinator 축소 반영분 포함). 워처가 죽어도 **세션 시작 시엔 디스크에서 읽는다**는 뜻이다.
- ❌ **이번 편집분에는 성립하지 않는다** — 편집 직후 같은 세션의 listing은 갱신되지 않았다. 즉 **"편집하는 세션"과 "검증하는 세션"은 구조적으로 겹칠 수 없다.** 세션을 하나 더 태워도 *그 세션의 편집*엔 같은 벽이 다시 선다. 무한 후퇴다.

⇒ **검증 방법을 바꿨다.** 프로브로 사후 확인하는 대신, **발화를 좌우하는 요소를 애초에 건드리지 않는 설계**로 리스크를 없앤다:

| 보존(불가침) | 삭제 대상 |
|---|---|
| `Use PROACTIVELY` 접두 · 경로 글롭(`02_Source/**` 등) · 트리거 조건절(*"≥10줄+등급≥보통 시 무조건"*) · 안전/승인 규칙 | ADR·Phase 번호 · 패키지·SDK 이름 · 부연 괄호 · 본문 중복 카탈로그 |

기계 대조: `git show HEAD:.claude/agents/<f>.md`의 description과 현재 값에서 트리거 토큰 출현 수를 비교 → **5/5 전부 before == after**. 실발화는 다음 세션 첫 턴에 자연 관측된다(안 뜨면 `git revert` 1건).

📌 **일반화**: *"세션 경계가 검증을 가능하게 한다"* 는 명제는 **읽기 시점이 세션 시작인 자원에만** 성립한다. 그 자원을 *그 세션에서 다시 쓰면* 검증은 또 밀린다. ⇒ **사후 프로브가 구조적으로 불가능한 대상은, 검증을 설계로 대체해야 한다.**

## 6. 학습

- **중복 제거와 삭제는 다르다.** 멀티에이전트 표 −503 tok은 정보를 하나도 잃지 않았다 — 같은 내용이 이미 두 곳에 더 상세히 있었다. 반면 "완료 폴더 보존" 1줄은 **유일 소유자**였고, grep 없이 지웠다면 그대로 소실이었다. **길이가 아니라 사본 수가 판정 기준이다.**
- **표를 지울 땐 표에만 있던 규칙을 먼저 건져낸다.** `chief-tech-operator` 승인 규칙은 표의 한 칸에 적혀 있었다. 행 단위로 "중복이냐"를 물으면 놓친다 — **셀 단위로** 물어야 했다.
- **자기 보호 문장.** 다이어트의 가장 큰 위험은 다음 다이어트다. §3-E에서 추가한 강제 출처 경고는 토큰을 쓰지만, *문서 규범 전용 문장이 왜 지워지면 안 되는지*를 헌법 안에 남긴다. 순 절감을 조금 깎아서 재발을 막는 거래다.
