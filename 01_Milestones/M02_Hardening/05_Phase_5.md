# M02 Phase 5 — 이주 잔재·무효 테스트 정리

## Phase 5 — 이주 잔재·무효 테스트 정리 · 태그: `cleanup` · 의존: Phase 4

**목표**: 하네스·루프 이주의 잔재 문서와 유효하지 않은 테스트 코드가 사용자 승인 목록대로만 정리되고(삭제는 사용자 직접 실행·워커는 이동만), 참조 무결과 테스트 기준선이 재실측으로 확인된다.

Steps

1. **Phase 4 마감·배선 인수** (인수 대조 절) — ① Phase 4 검증 기록에서 결과·세션 id·기준 HEAD를 읽는다. ② `git log`로 HEAD가 그 기준에서 전진했고 새 커밋 메시지에 `M02-P4` 토큰이 있는지 대조한다. ③ `git status`가 clean인지 확인한다. ④ hook-log에서 Phase 4 세션 id의 stop-gate 줄이 `allow`인지 확인한다. ⑤ **배선 확인** — 같은 세션 id의 **표피 훅 Stop 줄**을 찾는다. `verdict`가 `발화`든 `통과`든 배선 영수증으로 인정하고(`판정불가`면 사유를 함께 적는다), 줄이 없으면 배선 FAIL로 본다. 이때 그 줄에 `agent_id`가 실렸는지와 줄이 몇 건인지도 함께 기록한다 — Phase 4는 자기 Stop을 관측할 수 없어 이 실측은 여기서만 유효하다 (Preview 「실행 중 확정 항목」). ⑥ 하드 게이트 다섯 종 재실행 green. ⑦ 코디네이터가 같은 실물을 대조한다. 확인이 모이면 Phase 4 검증 기록에 배선 PASS·사후 게이트 PASS와 커밋·clean·정상 Stop 확인 줄을 append하고, 자기 세션 id와 기준 HEAD를 읽어 둔다. Stop을 새로 프로브하지 않는다 — 비차단 Stop 재프로브는 이 세션을 끝내 추기가 불가능해진다.
2. 적격 기준을 처분 형태별로 분리해 목록 작성 전에 고정한다 — 기준 밖 항목은 처분 목록에 올릴 수 없다.
   - 삭제 적격: (가) 검증 대상 기능이 저장소에 없음(v1 전용 포함), (나) 옵트인 사유(LIVE=1류 환경변수) 없이 상시 건너뛰는 죽은 스킵. **집행은 사용자 직접 실행뿐이다** (안건 6) — 워커는 어떤 삭제도 집행하지 않고 결과를 실측 확인만 한다.
   - 재생성 산출물: (다) 빌드·테스트가 재생성하는 로컬 산출물 — 「삭제 유지」 대 「재생성 허용(.gitignore 등재 확인으로 대체)」 두 안을 병기해 승인 문답에서 확정한다.
   - 이동 적격: (라) 살아 있는 재료지만 현 편제 밖 — 삭제 금지, 목적지 승인 필수, 집행은 워커가 `git mv`로 한다 (안건 3 해석 적용 — 계획 명시 + 계획 승인을 받은 내용 무변경 이동만 예외).
3. 이름 확정 처분 목록을 파일별 처분안·사유로 작성한다.
   - 이주 잔재: `01_Documents/` 13건은 이동 적격(라) — M03 재료라 삭제가 아니라 이주이며, 목적지는 후보 2안(`00_Documents/04_Design/` — 현 README가 UI·UX 문서 전용이라 소유권 확장 승인 필요 / `00_Documents/00_Architecture/`)과 제3안 여지를 병기해 사용자 선택 안건으로 올린다. 훅 주석 2건(10_start-brief.cjs·20_plan-gate.cjs)의 경로 갱신을 동반한다. `99_Others/`의 loop-design-handoff.md·deepagents-guide.html 처분안을 적는다.
   - 무효 테스트: skip 마커 46개 파일의 유효 옵트인·죽은 스킵 분류, 상시 실패 e2e 2건(multi-agent-ops·orig-probe)의 판정안(회귀 판정 시 처리는 안건 5의 확정 방향 — 기준선에 알려진 실패로 명기 + Backlog 이월), driver 문자열 히트 2건(main/read.test.ts·main/roots-security.test.ts)의 정밀 판독 결과.
   - 재생성 산출물: 로컬 산출물 3종의 최종 상태 두 안 병기. **실물 위치는 저장소 루트의 `out`·`test-results`·`artifacts`다** — `99_Others/` 아래 대응 경로는 없다.
   - 차분 고정: 파일별 삭제·유지 집합과 unit·e2e 수집의 예상 전후 차분(수집 파일 수·테스트 수)을 수치로 고정한다.
   - 검사 방식 고정: Step 6이 쓸 판정 방식을 항목별로 못 박는다. 이동 대상 문서 경로는 문자열 grep으로, 산출물 3종은 **루트 경로의 존재 여부 판정**으로 본다 — 짧은 단어를 그대로 grep하면 산문·코드의 일반 단어에 걸려 판정이 무의미해진다. 문자열로 찾아야 하는 항목이 있으면 경계 인식 패턴(`(^|[/\\])out([/\\]|$)` 형태)만 쓴다.
4. USER-INPUT — 처분 목록을 사용자 승인 게이트에 올린다. 명시 안건은 네 가지다 — ① 목록 자체, ② `01_Documents/` 13건의 목적지 소유권, ③ 산출물 3종의 최종 상태, ④ e2e 2건의 판정. 포괄 승인은 무효이고 목록 승인만 유효하다. 승인 요청과 함께 삭제 처분분의 **명령 수준 실행 목록**을 전달한다 — 삭제는 사용자가 직접 실행하기 때문이다.
5. 승인된 목록만, 승인된 경로로 집행한다.
   - 이동: 워커가 `git mv`로 집행하되 안건 3에서 확정된 헌법 8조 해석(건별 예외안)을 따른다. 훅 주석 경로 갱신을 동반하고, 이동된 13건 문서 내부의 옛 경로 자기 참조도 함께 갱신한다.
   - 삭제: 워커는 집행하지 않는다. 사용자가 직접 실행할 때까지 기다렸다가, 실행 후 대상 경로의 부재와 목록 밖 파일의 무변경을 실측 확인하고 결과를 검증 기록 줄로 남긴다. 대기 중에는 다른 Step으로 넘어가지 않는다.
   - 목록 밖 파일은 건드리지 않는다. `.claude/hooks/fixtures/`·`99_Others/scripts/run-e2e.cjs`·`99_Others/assets/`·`98_V1_Archive/`는 처분 대상이 아니다.
6. 참조 무결과 기준선을 재실측한다.
   - 참조 검사의 표면은 **활성 소비자 표면 하나뿐이다** — 「git tracked 전 파일 − append-only 역사 allowlist(`01_Milestones/M01_Bootstrap/`·`98_Management/00_ADR/`·`00_Documents/03_Reports/`) − 현 마일스톤 폴더(`01_Milestones/M02_Hardening/`)」. 이 표면에서 Step 3이 고정한 경로 문자열의 grep이 0건이어야 하며, 이동된 문서 자신의 내부 링크·평문 경로도 이 표면에 포함된다.
   - 현 마일스톤 폴더는 **전체가 처분 명세·검증 기록의 역사 표면**이다 — Steps의 실행 지시, DoD, 처분 목록, 검증 기록 어디든 옛 경로 이름이 남는 것이 정상이고, 0건도 하위 조건도 요구하지 않는다. 판정 로그에는 이 폴더를 제외했다는 사실과 제외 경로만 남긴다.
   - 산출물 3종은 grep이 아니라 루트 경로 `out`·`test-results`·`artifacts`의 존재 여부로 판정한다.
   - 링크 검사기(Phase 4 수리분)는 루트 README 표면의 보조 판정으로 실행한다 — 활성 소비자 표면 판정의 정본은 grep 전수다.
   - 수집 차분 — 집행 후 unit·e2e 수집 실측이 Step 3에서 고정한 예상 차분과 정확 일치해야 한다. collection-baseline의 판정을 하한(≥ 402)에서 집행 후 정확값 등호 판정으로 전환한다.
   - 산출물 3종의 최종 상태 — 승인이 「삭제 유지」면 모든 재실측이 끝난 뒤 최종 정리를 이 Step의 마지막 행위로 두되 집행은 사용자 직접 실행이고 워커는 부재 판정만 한다. 「재생성 허용」이면 .gitignore 등재를 확인한다.
   - start-brief·plan-gate 발화 프로브 정상, `npm test` 실패 0 재실측, e2e 차분 재실측과 기준선 갱신(`.claude/commands/gate.md` 세칙에 등재).
7. 종료 순서를 지킨다 — ① 하드 게이트, ② 검증 기록 추기(관측된 결과·세션 id·기준 HEAD까지만), ③ pin 마감, ④ 마감 커밋(`M02-P5` 토큰), ⑤ `git status` clean 확인, ⑥ Stop. ④⑤⑥ 확인은 **Phase 5 정상 Stop 뒤에 새로 여는 마감 세션**이 인수 대조로 수행해 이 Phase 검증 기록에 append한다 (Preview 마감 절차).

DoD

- 처분 목록 실물(적격 기준·차분 수치·검사 방식·삭제 실행 목록 포함)과 명시 안건 네 가지의 승인 [USER] 줄이 있다.
- 워커가 집행한 삭제가 0건이고, 승인된 삭제 전건이 사용자 직접 실행으로 이뤄졌음이 실측 확인 줄로 기록돼 있다.
- 활성 소비자 표면에서 이동·삭제 경로 grep이 0건이고, 제외한 두 표면의 경로 목록이 판정 로그에 명시돼 있다. 현 마일스톤 폴더는 판정 대상이 아니다.
- 산출물 3종의 판정이 루트 경로 존재 여부로 이뤄졌고, 짧은 단어의 무경계 grep은 쓰이지 않았다.
- 루트 README 링크 검사가 green이다.
- start-brief·plan-gate 발화 프로브가 hook-log 줄로 있고, Phase 4 검증 기록에 배선 PASS(표피 훅 Stop 줄과 그 `verdict`·`agent_id` 실측·줄 건수)·사후 게이트 PASS와 커밋(HEAD 전진 + `M02-P4` 토큰)·clean·정상 Stop 확인 줄이 append돼 있다.
- unit·e2e 수집 실측이 목록의 예상 차분과 정확 일치하고, collection-baseline이 정확값 등호 판정으로 갱신돼 있으며, `npm test`가 실패 0이고, e2e 기준선 갱신이 gate.md에 등재돼 있다.
- 산출물 3종의 최종 상태가 승인안대로다 (부재 판정 또는 .gitignore 등재 확인).
- 이 Phase의 세션 id와 기준 HEAD가 검증 기록 줄에 등재돼 있다.
- 하드 게이트 다섯 종이 전부 green이다.
- 마감 커밋·clean·정상 Stop은 이 Phase 안에서 판정하지 않는다 — 새 마감 세션이 append한 확인 줄로 판정한다.
