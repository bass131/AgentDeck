# M02 Phase 1 — 착륙지·헌법 문면·역할 신호·동등성 기준표

## Phase 1 — 착륙지·헌법 문면·역할 신호·동등성 기준표 · 태그: `structure`·`guard`·`harness` · 의존: 없음

**목표**: M02 계획이 저장소에 등재되고 좌표와 헌법 포인터가 안전 순서로 M02에 전환되며, 승인된 헌법 2조 문안이 두 헌법 파일에 반영되고, 워커 세션의 역할 신호가 실측으로 확정되며, 가드 동등성 기준표가 기대-실패 테스트로 실물화되고, tdd-guard가 `.claude/hooks/*.test.mjs`를 테스트로 인정해 이후 Phase의 훅 편집이 자충수에 걸리지 않는다.

Steps

1. 부트스트랩 ① (코디네이터) — `_MilestonePreview.md`와 Phase 파일 다섯을 `01_Milestones/M02_Hardening/`에 등재하고, 같은 폴더에 `01_Work_Pin.md`를 신설한다. M01 pin은 마감 상태 그대로 보존한다. 계획 승인 문답 안건 1의 판정이 끝나면 결정 대장의 [AI] 10건 태그를 각각 [USER]로 전환하고(기준점 이동 문법), **같은 편집에서 Preview 말미의 「발동 판정 실측」 문장도 승인 후 실측값(비가역 0 · 에이전트 단독 0 · 사용자 23 → 미발동, 스폰 통과 자격)으로 갱신한다** — 태그만 바꾸고 문장을 두면 사람용 정본이 기계 판정과 반대 상태를 말한다. 이 Step은 전부 `01_Milestones` 아래 편집이라 헌법 3조 안이다.
2. **기동 전 plan-gate 직접 구동** (코디네이터, 10턴 실질 결함) — Orca dispatch·worker-start는 Task·Agent 훅을 거치지 않아 plan-gate가 자동 발화하지 않는다 (AD-02). 그래서 아래 Step 3의 포인터 전환 워커와 Step 5 이후의 본워커를 포함해, **이 마일스톤의 모든 Orca 기동 직전에 코디네이터가 `20_plan-gate.cjs`를 합성 스폰 입력으로 직접 실행**하고 판정 4종(계획 검증·실패 카운터·결정 대장 tally·라우팅) 통과를 확인한다. 판정은 종료 코드가 아니라 hook-log 마지막 plan-gate 줄의 `verdict`와 stdout JSON 유무로 읽는다 — 통과·거부 모두 exit 0이기 때문이다 (fail-closed: 두 신호가 어긋나거나 로그 줄이 없으면 allow가 아닌 것으로 본다). 영수증(로그 줄 원문 또는 stdout 기록)을 해당 Phase 검증 기록에 남긴 뒤에만 기동하고, deny면 기동하지 않는다.
3. 부트스트랩 ② (포인터 전환 워커) — 루트 파일 편집이라 워커가 수행한다. 순서를 지킨다: 격리 선검증 → live 전환 → live 재실측 → 실패 시 복원.
   - **① 격리 선검증** — `CLAUDE_PROJECT_DIR`로 지정한 미러 뿌리에 `gate-config.json`을 M02 좌표로 두고 M02 계획 파일 여섯을 같은 상대 경로에 복사한 뒤, `20_plan-gate.cjs`를 합성 스폰 입력으로 단독 실행한다. 판정 4종 전부 통과여야 하며 tally는 USER 측 23·AI 0이어야 한다. live 저장소는 아직 손대지 않는다.
   - **② live 전환** — 선검증이 allow일 때만 진행한다. `gate-config.json`의 `planPath`·`workPinPath`와 루트 `CLAUDE.md`·`AGENTS.md`의 정체 선언·계획·pin 포인터를 M02 좌표로 동일하게 갱신한다 — gate-config만 바꾸면 두 헌법이 M01 정본을 가리켜 워커마다 다른 정본을 읽는다. 이 전환이 이 워커의 마지막 편집이다.
   - **③ live 재실측** — 같은 합성 입력으로 live 뿌리에서 단독 실행하고 Step 2의 판독 계약으로 읽는다. allow면 영수증(로그 줄 원문·tally 수치)을 남기고 종료한다.
   - **④ 실패 시 복원** — allow가 아니면 **같은 워커가 그 자리에서** gate-config 두 키와 두 헌법 파일의 세 지점을 M01 값으로 되돌리고, 복원 후 plan-gate를 재실행해 M01 좌표에서 allow가 회복됨을 실측한 뒤 FAIL 줄을 남기고 종료한다. 복원 기준값은 전환 전에 미리 기록해 둔다.
   이 워커는 구 포인터 아래에서 스폰되며 작업 범위는 위 네 단계뿐이다. Phase 1 본워커(Step 4 이후)는 live allow를 확인한 뒤 새 포인터 아래 top-level 세션으로 연다 (제약 절 실행 모델).
4. **역할 신호 선실측** ([USER] 결정 2). 본워커를 `claude --agent worker`로 연 직후, `01_Milestones` 밖의 무해한 편집 한 건(예: 이 Phase가 어차피 만들 테스트 파일의 최초 생성)을 시도하고 `30_role-gate.cjs`의 hook-log 줄에서 `role`이 `worker`인지 `main`인지 읽는다.
   - `worker`면 그대로 진행하고, 실측 줄(세션 id·`role`·판정 근거 필드)을 검증 기록에 남긴다.
   - `main`이면 role-gate가 `01_Milestones` 밖 편집을 deny하므로 이 Phase의 나머지가 전부 막힌다. 이때는 **작업을 멈추고 사용자에게 고지**한 뒤, 사용자가 직접 `MOODIE_SESSION_ROLE=worker`를 설정한 새 세션에서 재개한다 — 헌법 9조가 이 변수를 사용자 전용으로 두므로 에이전트가 스스로 켜거나 켜라고 지시하거나 스크립트에 심는 것은 금지다. 고지 시점에 `USER-INPUT` 줄을 남기고, 재개 후 채택 경로(env 회귀)를 PASS 줄로 남긴다.
   - 어느 경로든 결과는 이후 Phase 2~5의 기동 방식에 그대로 적용한다.
5. 헌법 문면 반영 — 안건 4에서 승인된 헌법 2조 문안을 루트 `CLAUDE.md`·`AGENTS.md`에 동일하게 반영한다 (해석은 M01 결정 대장 [USER] 2026-08-10 기확정, Backlog 4번). 두 파일 8조의 문면 차이(Backlog 14번 일부)도 이때 정합하고, 안건 3(git mv 해석)의 확정 결과 — 건별 예외안: 계획 명시 + 계획 승인을 받은 내용 무변경 이동만 예외 — 를 8조 문면에 반영한다. 이 본워커 세션의 세션 id와 기준 HEAD(`git rev-parse HEAD`)를 읽어 둔다 — 다음 Phase의 인수 대조가 쓰는 값이다.
6. tdd-guard 테스트 인정 선수리(Backlog 11번 전반부)의 Red를 먼저 쓴다 — `02_Project/01_TestCode/` 아래(현행 인정 경로)에, `.claude/hooks/*.test.mjs` 편집이 테스트 동반으로 판정되는지 검사하는 실패 테스트를 둔다.
7. `33_tdd-guard.cjs`의 인정 규칙을 수리해 위 테스트를 Green으로 만든다. 수리는 한 번의 원자적 편집으로 제한한다 — 추가 편집이 필요해지면 각 편집 전에 인정 테스트 파일을 먼저 손질해 미동반 카운터를 리셋한다. `npm run test:hooks` 출력은 vitest 요약이 아니라서 현행 카운터를 Green으로 리셋하지 못한다는 점을 전제로 움직인다. Green 증거 강도는 Phase 3의 몫이다.
8. 자체 러너에 기대-실패 플래그를 구현한다 — 의미론은 「플래그 항목은 실측이 기대 판정과 다르면 통과(Red 관측), 같으면 러너 실패(예상 밖 통과 — 플래그 제거를 강제)」로 고정하고, 러너 요약에 플래그 잔여 건수를 출력한다. 헬퍼 자체의 판정 동작은 자기 검증 케이스 2건(의도 실패 1·의도 통과 1)으로 실측한다.
9. Moodie `32_cmd-guard.cjs` 표면 전수 대조표를 작성한다 — 규칙 전건(rm 재귀의 -R·--recursive·후치 포함, git reset --hard, clean, checkout --, restore, branch -D, del /s, rmdir /s, Remove-Item -Recurse, push, npm publish, config --global)과 인용 벗기기·세그먼트 분할 동작을 열거하고, 항목마다 Moodie 판정·AgentDeck 현행 판정·기대 판정(동등 이상)을 적는다. 동등 명령 벡터로 플래그 순서·결합·축약 변형(`git branch -d -f`·`-df`·`-fd`·`--delete --force` 순서 역전 류)을 포함한다. heredoc이 붙은 명령은 pipeline 전체를 한 항목으로 등재하고 기대 판정에 「하류 실행 소비자·파일 sink 유무」를 적는다. push·publish 축은 승인 질의(ask)를 차단과 동등으로 등재한다 (M01 [USER] 2026-08-09).
10. 안건 2에서 조기 판정된 공통 한계 3종(변수 확장·명령 치환·cmd /c 접두)의 결과를 기준표 「공통 한계」 구획에 [USER] 판정 근거와 함께 등재한다 — 기각(수리하지 않음)이며 방어 담당은 Claude Code 내장 권한 분류기(모델 판정)로 명시한다. 이 구획은 동등성 판정과 기대-실패 집계에서 제외하고, 유지 대장에 존치 항목으로 남긴다.
11. 기준표를 표 구동 테스트(신규 `.claude/hooks/*.test.mjs` 한 파일)로 작성하고 `package.json`의 `test:hooks`에 node 실행 항목으로 배선한다. **이 테스트도 가드를 spawn하므로 공통 격리 헬퍼를 의무 사용한다** — `mkdtemp` 임시 미러를 만들어 `CLAUDE_PROJECT_DIR`로 주고 payload에 합성 `session_id`·`agent_id`를 넣는다. 헬퍼는 이 Step에서 공용 모듈로 만들고 Phase 2가 기존 `dangerous-cmd-guard.test.mjs`를 같은 헬퍼로 옮긴다. 현행 우회가 확인된 항목은 기대-실패 플래그로 등재해 하드 게이트를 유지하면서 Red를 기록하고, 실행해 플래그 항목의 실패를 관측한다.
12. 종료 순서를 지킨다 (제약 절) — ① 하드 게이트 다섯 종, ② 검증 기록 추기(게이트 결과·세션 id·기준 HEAD까지만 — 커밋·clean·Stop은 쓰지 않는다), ③ work-pin 마감 요약·스탬프, ④ 마감 커밋(메시지에 `M02-P1` 토큰), ⑤ `git status` clean 확인, ⑥ Stop.

DoD

- M02 계획 파일 여섯과 M02 pin이 실물로 있고, 태그 전환 후 tally가 USER 측 23·AI 0이며, Preview의 발동 판정 실측 문장이 같은 편집에서 갱신돼 있고, M01 pin은 마감 상태에서 불변이다.
- 이 Phase의 각 Orca 기동 직전에 코디네이터가 직접 구동한 plan-gate 영수증(hook-log 줄 또는 stdout 기록)이 검증 기록에 있다.
- 격리 미러 선검증의 allow 영수증이 live 전환 이전 시각으로, live 재실측의 allow 영수증이 전환 이후 시각으로 있다 — 판정은 exit 코드가 아니라 `verdict`와 stdout JSON 유무로 읽은 것이어야 한다. allow가 아니었던 경우 같은 워커의 복원 기록과 FAIL 줄이 있고 후속 워커는 스폰되지 않았다.
- gate-config 두 키와 루트 두 헌법의 정체 선언·계획·pin 포인터가 전부 M02 좌표를 가리킨다 (전환 성공 시).
- **역할 신호 실측 결과가 검증 기록 줄로 있다** — `claude --agent worker` 세션의 role-gate 판정이 `worker`였거나, `main`이었고 사용자 고지 뒤 사용자가 직접 설정한 env 회귀로 재개했다는 기록 중 하나다. 에이전트가 env를 켠 흔적은 없어야 한다 (헌법 9조).
- 헌법 2조 승인 문안이 [USER] 줄과 함께 두 헌법 파일에 반영돼 있고, 두 파일의 2조·8조 문면이 동일하다.
- tdd-guard 인정 테스트가 구현 전 Red·구현 후 Green이고, `.claude/hooks/*.test.mjs` 편집이 테스트 동반으로 판정되는 실측 로그 줄이 있다.
- 기대-실패 플래그 헬퍼의 자기 검증 케이스 2건이 통과한다.
- 동등성 기준표 테스트가 test:hooks에 배선돼 있고, 알려진 우회 표면 전건이 기대-실패 플래그로 등재돼 실패가 관측된다. 공통 한계 구획이 [USER] 판정 근거와 함께 실물로 있다.
- 이 Phase가 새로 만든 가드 spawn 테스트가 공통 격리 헬퍼를 쓰고, live hook-log에 합성 `session`·`agent_id` 줄이 0건이다.
- 이 Phase 마지막 세션의 세션 id와 기준 HEAD가 검증 기록 줄에 등재돼 있다 — Phase 2 인수 대조의 기준값이다.
- 하드 게이트 다섯 종이 전부 green이다.
- 마감 커밋(`M02-P1` 토큰)·clean·정상 Stop은 이 Phase 안에서 판정하지 않는다 — Phase 2 시작 인수 Step이 append한 확인 줄로 판정한다.
