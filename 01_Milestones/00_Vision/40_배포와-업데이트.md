# 배포와 업데이트

- 상태: 초안 · [개요](00_개요.md)

## 합의

- 배포본은 GitHub Release로 낸다.
- 한 번 설치하면 앱이 새 버전을 감지해 스스로 업데이트한다.
- Release는 소스와 같은 비공개 저장소에 둔다. 업데이트는 그 저장소에 협업자로 초대된 사람만 받는다.
- 완성형의 최소선: 처음 쓰는 사람이 설명서 없이 설치 → 계정 연결 → 프로젝트 열기 → 목표·Taste 쓰기 → 첫 마일스톤 시작까지 혼자 해낸다.

## 설치본 (제안)

- Windows 설치 파일 하나. macOS와 Linux는 지금 만들지 않는다.
- 코드 서명은 하지 않는다. 설치할 때 Windows 경고가 한 번 뜨는 것을 감수한다 — 인증서 비용을 아낀다.
- 개발 서버 없이 뜬다. 앱의 실행 트리는 작업 트리와 나뉜다(M07 컨트롤 보호의 전제).

## 업데이트 인증 (제안)

- 비공개 저장소의 Release 파일은 로그인 없이 받을 수 없다.
- 앱 안에 토큰을 넣지 않는다. 넣으면 설치 파일을 받은 누구나 그 토큰을 꺼낼 수 있다.
- 대신 앱이 쓰는 사람 자신의 GitHub 로그인으로 Release를 읽는다. 협업자가 아닌 사람은 업데이트를 받지 못한다.
- 이 해석은 사용자가 확인하지 않았다 — `90_열린-질문.md` 5.

## 남에게 건넬 수 있는 조건

- 유영호의 PC에만 있는 것에 기대지 않는다 — `C:\Dev\...` 경로, Second Brain, 유영호의 gh 로그인, Orca.
- 계정 연결은 처음 켤 때 앱이 안내한다. 쓰는 사람이 자기 Claude 계정과 GitHub 계정을 잇는다.
- Taste와 그래프 템플릿은 앱 안에 있다. 유영호의 전역 Taste는 따라가지 않는다 — 받는 사람은 자기 전역 Taste를 쓴다(제안).

## 사람 몫

- 릴리스를 내는 행위, 패키지 배포는 사람이 승인한다(헌법 10조의 승인 항목이 유지된다).
- 에이전트는 릴리스 후보를 빌드하고 릴리스 노트 초안을 쓴다(제안).
