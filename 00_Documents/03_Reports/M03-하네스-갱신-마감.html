위험 명령 가드의 회귀 2표면이 실패에서 통과로 뒤집히고, 실측하지 못했던 2표면은 닫히거나 실측 영수증을 갖는 것이 이 조항입니다. 회귀 2표면은 셸 실행기로 감싼 재귀 삭제와 환경변수 할당을 끼운 재귀 삭제입니다. 새 행 다섯을 먼저 올려 전부 통과되는 Red를 봤고(Phase 2 · 06:24:33), 수리 뒤 「통과 69 · 실패 0 · 기대-실패 플래그 잔여 0건」이 됐습니다(06:30:55). 미실측 2표면 가운데 PowerShell 도구는 설정의 거부 목록으로 닫았습니다(06:44:40 문법 확인 · 06:50:40 배선). 4. 마감 판정에서 봐야 할 것

이 넷은 마감을 막지는 않지만, 마감한다는 판정에 함께 실리는 사실입니다.

① 가드의 남은 한계 △ AD-05 존치

가드는 명령 문자열의 따옴표 상태를 직접 읽어 구분자와 명령 위치를 찾습니다. 이 판독이 실제 셸과 어긋나는 자리가 실측으로 남아 있습니다. 대부분은 일부러 비튼 입력이지만 하나는 다릅니다. 주석 줄에 따옴표가 홀수 개 있으면(예: # don't skip) 뒤의 여러 줄이 통째로 인용문으로 읽혀 검사를 통과합니다. 이 꼴은 수리 전부터 세 판 모두 통과였고, 자연스러운 입력에서도 납니다. 재론 조건은 둘입니다 — 실제 작업에서 우회가 관측되거나, 따옴표 판독을 셸 문법 파서로 바꾸는 식의 다른 접근을 계획에 올릴 때입니다. 이 밖에 1차 검수와 수리 중에 나온 가드 관찰(Backlog 18·24·28·31·32번)도 고치지 않은 채 남아 있습니다.

② 테스트 타임아웃 1건을 자원 경합으로 받아들일지 □ Backlog 33번

마지막 수리 커밋은 전체 테스트에서 실패 1건이 세 번 연속 재현된 상태로 들어갔습니다. 단독 실행 통과와 테스트 대상 코드 무변경이 근거입니다. 게이트 세칙의 자원 경합 부류 목록에는 이 파일이 없고, M02 마감 때도 같은 흔들림이 있었습니다. 이 판별을 받아들일지, 그리고 이 케이스의 처분을 어떻게 할지는 아직 정해지지 않았습니다.

③ 워커·리뷰어의 기록 규율 이탈 △ Backlog 23 · 35번 ⑤

Phase 2·3 워커가 셸 리다이렉트로 임시 로그를 남겼는데 기록 줄에는 없었습니다. Phase 3 워커가 실저장소 뿌리에서 훅을 직접 돌린 흔적도 hook-log에만 있었습니다. Phase 4 워커는 같은 종류를 스스로 기록했습니다. 재검수 리뷰어는 Write 도구가 없어 스크래치 입력을 Bash heredoc으로 만들었습니다. 모두 저장소 밖이지만, Bash 경유 파일 쓰기를 금지하는 헌법 8조의 취지와 어긋나는 운용입니다. 8조는 기계로 막지 않는 규범이라(유지 대장 AD-01), 워커마다 기준이 달랐다는 점이 남습니다.

④ 병합과 원격 push는 사용자 승인 게이트 □ 사용자 몫

마감 절차는 ① 검수 → ② 이 보고서 → ③ 하드 게이트 → ④ 인수 대조 추기 → ⑤ pin 마감 → ⑥ 마감 커밋 → ⑦ 사용자 마감 판정과 유지 대장 상태 확인 → ⑧ 작업 브랜치 병합과 원격 push 순서입니다. ③~⑥은 코디네이터가, ⑦과 ⑧은 사용자가 합니다. ⑧은 헌법 10조의 승인 게이트이고 에이전트가 단독으로 하지 않습니다.
