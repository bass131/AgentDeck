다섯 Phase가 계획대로 끝났고 검증 기록에는 FAIL이 한 줄도 없습니다. 마감 검수에서 리뷰어(1차)는 조항 1과 조항 3을 충족, 조항 2를 조건부 충족으로 봤고, Codex(교차)는 조항 1만 충족, 조항 2와 조항 3을 미충족으로 봤습니다. 갈린 지점은 모두 "수리한 표면이 잘못됐다"가 아니라 "아직 열거되지 않은 표면이 남았다"는 종류의 발견입니다. 어떤 발견도 이 마감 세션에서 수리하지 않았고, 최종 마감 판정은 사용자에게 남아 있습니다.

1. 완료선 세 조항의 증명 요약

완료선의 정본은 01_Milestones/M02_Hardening/_MilestonePreview.md의 「완료선」 절입니다. 조항마다 무엇으로 증명됐는지와, 마감 검수 두 축이 각각 어떻게 판정했는지를 함께 적습니다.

조항 1 — 검수 발견 전건 처리 리뷰어 충족 Codex 충족

M01 마감 검수에서 나온 발견 1~15번을 수리하거나 사용자 판정으로 명시적으로 기각하는 것이 이 조항입니다. Preview의 「검수 발견 처리 매핑」 표가 15건 전부를 Phase에 배정했고, 배정된 각 항목이 해당 Phase 검증 기록의 PASS 줄과 하나씩 대응합니다. 기각으로 처리된 것은 가드 공통 한계 세 종(변수 확장, $() 명령 치환, cmd /c 접두)뿐이고, 이 기각은 계획 승인 문답 안건 2의 사용자 판정 줄을 근거로 삼습니다. 검수 두 축이 각각 독립으로 매핑을 대조했고 누락이나 근거 없는 기각은 양쪽 모두 0건으로 봤습니다.

리뷰어: 충족. 다만 발견 1~15의 정본 파일(M01 Backlog)이 상태 표기를 갱신하지 않아 그 파일만 읽으면 미처리로 오독된다는 낮음 등급 지적이 붙었습니다.

Codex: 충족. 15건 전부가 처리 매핑과 유효한 Phase 검증 기록에 연결된다고 확인했습니다.

조항 2 — 가드가 Moodie 원본과 동등 이상임을 기계로 증명 리뷰어 조건부 충족 Codex 미충족

위험 명령 가드가 원본(Moodie 32_cmd-guard.cjs)이 잡던 명령 표면 전부와 그 이상을 잡는다는 것을, 사람의 진술이 아니라 테스트 스위트로 증명하는 것이 이 조항입니다. Phase 1이 원본 규칙을 전수 열거한 동등성 기준표 59행을 만들고 그것을 표 구동 테스트로 배선했으며, 그 시점에 현행이 통과시키던 18개 항목을 기대-실패 플래그로 등재해 Red를 기록했습니다. 기대-실패 플래그는 자체 러너에 두는 표시로, 그 항목이 실패해야 통과로 집계되고 예상 밖에 통과하면 러너가 실패해 플래그 제거를 강제합니다. Phase 2가 우회면을 수리해 이 18건을 전부 일반 판정으로 뒤집었고, 기준표 러너는 통과 61·실패 0·플래그 잔여 0건이 됐습니다. 테스트는 로직을 복제하지 않고 실제 가드를 별도 프로세스로 띄워 판정을 받으며, 임시 미러 폴더와 합성 세션 식별자를 써서 실저장소 로그를 오염시키지 않습니다.

리뷰어: 조건부 충족. 등재된 59행 자체는 기계 증명이 성립하지만, 셸 -c 접두와 env 할당 접두 실행이 원본은 차단하고 현행은 통과시키면서 기준표에도 기각 목록에도 올라 있지 않아 "원본 표면 전수"라는 주장에 구멍이 있다고 봤습니다.

Codex: 미충족. 같은 래퍼·중첩 셸 표면에 더해, 따옴표 안의 <<EOF를 진짜 heredoc으로 오인해 뒤 줄의 위험 명령을 검사에서 빼는 경로와, 원본 교차 구동이 불일치를 테스트 실패로 연결하지 않는다는 점을 들었습니다.

조항 3 — 상태 파일 동시 쓰기 무손실 재실측 리뷰어 충족 Codex 미충족

훅들이 공유하는 상태 파일을 두 세션이 동시에 쓸 때 기록이 사라지지 않는지를, 사실상 직렬이던 예전 실험이 아니라 진짜 동시 실행으로 다시 재는 것이 이 조항입니다. Phase 3이 동시 실행 러너를 새로 만들어 두 프로세스를 비동기로 띄우고 둘 다 준비된 것을 확인한 뒤 동시에 들여보냈습니다. 보호 없는 대본에서는 임계구간이 31밀리초 겹쳤고 한쪽 세션의 항목이 최종 파일에서 사라져 손실이 실제로 재현됐습니다. 수리는 배타 잠금 방식으로, 잠금 파일을 wx(있으면 실패하는 원자 생성)로 잡고 읽기부터 이름 바꾸기까지 전부 잠금 안에서 돌립니다. 잠금을 건 대본에서는 두 프로세스의 생존 구간이 86밀리초 겹치는데도 보호 구간은 겹치지 않았고 손실이 0이었습니다.

리뷰어: 충족. 진짜 동시 실행, 배타 잠금 실물, Red와 Green의 판정 조건 분리가 모두 재구동에서 확인된다고 봤습니다.

Codex: 미충족. 같은 세션끼리의 동시 갱신은 잠금 밖에서 계산한 값을 잠금 안에서 통째로 덮어써 여전히 손실될 수 있고, 15초가 지난 잠금을 소유자 생존 여부와 무관하게 회수하는 규칙이 배타성을 깰 수 있다고 봤습니다.

범위 추가 — 이주 잔재·무효 테스트 정리 리뷰어 충족 Codex 발견 없음

승인된 처분 목록만 집행하고 기준선을 다시 재는 데까지가 이 범위의 완결선입니다. 이동 12건은 워커가 git mv로 집행했고 삭제 2건은 워커가 손대지 않은 채 사용자가 직접 실행했습니다. 수집 차분은 사전 고정치와 정확히 일치했고, 테스트 수집 기준선 판정은 하한 비교에서 정확값 등호(417)로 바뀌었습니다.

마감 세션에서 하드 게이트 다섯 종(typecheck:node, typecheck:web, lint, test:hooks, build)을 다시 돌렸고 전부 exit 0이었습니다.

조항 3의 세부 증거 — 손실 재현과 잠금 규격
  • Red 판정은 두 조건이 함께 성립할 때만 인정했습니다 — 보호 없는 임계구간 겹침(31ms)과 최종 파일에서의 항목 소실(race-concurrent-b). 단순히 두 프로세스 생존 구간이 겹쳤다는 것(84ms)만으로는 세지 않았습니다.
  • Green 판정: 생존 구간 86ms 겹침, 보호 임계구간 -14ms(비겹침), 전 스코프 무손실.
  • 잠금 규격: wx 원자 생성, 획득 timeout 기본 5초, stale 잠금 회수 조건은 나이 15초 초과 또는 기록된 pid 사망. 세 훅(33_tdd-guard·40_pass-watcher·50_stop-gate) 전부 공통 헬퍼로 이관됐고 자체 rename 경로가 남지 않았음을 러너가 검사합니다.
  • 동시 실행 러너는 기존 순차 대본을 고치지 않고 따로 신설했습니다. 기존 대본은 세션 스코핑 회귀를 순차 순서로 판정하는 표면이라, 동시 기동으로 바꾸면 그 회귀 검사가 사라지기 때문입니다.

2. 다섯 Phase가 각각 무엇을 했는가

Phase 1부터 Phase 5까지 검증 기록에 남은 줄은 합계 PASS 62건, FAIL 0건, USER-INPUT 4건입니다. 각 Phase는 별도 워커 세션에서 실행됐고 커밋 하나씩으로 마감했습니다.

Phase 1 — 착륙지·헌법 문면·역할 신호·동등성 기준표 01d4cd2

계획 문서를 저장소에 등재하고 좌표 포인터를 M01에서 M02로 옮기는 일부터 했는데, 순서를 안전하게 잡아 임시 미러에서 먼저 통과를 확인한 뒤에야 실저장소 포인터를 바꿨습니다. 승인된 헌법 2조 문안을 두 헌법 파일에 같은 문면으로 반영했고 8조의 문면 차이도 정합했습니다. 워커 세션의 역할 신호를 실측해 claude --agent worker 기동에서 역할 게이트가 worker로 판정한다는 것을 확인했고, 그래서 사용자 전용 탈출구인 환경변수 회귀는 발동하지 않았습니다. 훅을 고치는 작업 자체가 훅에 막히는 자충수를 풀기 위해 tdd-guard가 훅 테스트 파일을 테스트로 인정하도록 먼저 수리했습니다. 마지막으로 원본 가드 표면을 전수 열거한 기준표 59행을 만들고 표 구동 테스트로 배선해 우회 표면 18건의 실패를 관측했습니다.

Phase 2 — 가드 우회면 수리·테스트 격리 3d12777

기대-실패 플래그 18건을 전부 0으로 뒤집는 것이 이 단계의 목표였고 그대로 달성했습니다. heredoc은 본문이 표준 출력으로만 소비될 때만 면제하고, 실행되거나 파일로 저장되는 경로가 하나라도 있으면 계속 검사하도록 판별을 바꿨습니다. 인용부를 통째로 버리던 처리를 따옴표만 벗겨 토큰을 보는 방식으로 교체해 git reset "--hard" 같은 우회를 되살렸고, 인용문 오탐은 머리 토큰 판정으로 계속 막았습니다. 가드를 띄우는 테스트를 전부 임시 미러로 옮겨 실저장소 로그와 분리했고, 가드의 판정마다 여섯 필드 로그 줄이 남도록 판정 로그를 신설했습니다. 설정의 가드 matcher 앵커를 ^Bash$로 고친 것이 이 세션의 마지막 설정 편집이었습니다.

Phase 3 — 게이트 판독·증거 강도 수리와 동시성 재실측 b972fb5

[높음] 1. 셸 -c 접두·env 할당 접두 실행이 Moodie가 잡던 표면인데 현행이 통과시키고, 기준표·기각 어디에도 등재돼 있지 않다
