# Goal 한 장 템플릿

- 위치: `00_Documents/02_Rules/04_Goal-한장-템플릿.md` · 작성: 2026-11-13 (M04 Goal Loop)
- 계획의 기본 형식이다. 사용자와 goal 한 장을 합의하면 에이전트가 구현, 검증, 커밋, push, PR 생성, 결과 보고까지 끊지 않고 간다 (헌법 11조).
- Phase가 여럿 필요하거나 250줄에 담기지 않는 큰 작업은 `00_Phase-Steps-계획-템플릿.md`의 다중 파일 형식을 쓴다.
- 근거는 M04 결정 대장 [USER] 2026-11-13(안건 3)이다.

## 작성 규칙

- **파일**: `01_Milestones/M0X_<이름>/00_Goal.md` 한 장이다. `gate-config.json`의 `planPath`가 이 파일을 가리킨다. 파일명을 `_MilestonePreview.md`로 짓지 않는다 — 그 이름은 다중 파일 형식으로 판독된다.
- **훅이 읽는 모양**: 계획 판정부는 넷을 요구한다 — `## 목표` 절, `## Phase 1 — <이름> · 태그: · 의존: 없음` 머리줄, 그 절 안의 제목 단독 「검증 기록」 줄, `## 결정 대장` 절. Phase 머리줄은 형식 호환을 위한 한 줄이며 goal은 Phase 하나로 쓴다.
- **범위 네 항목**: 만들 것, 건드릴 곳, 하지 않을 것, 관찰 가능한 완료조건이다. 판정 장치(`.claude/hooks/`, `.claude/settings.json`, `98_Management/01_GateState/`, 두 헌법)를 고친다면 「건드릴 곳」과 진척 단계에 이름으로 적는다 (헌법 3조).
- **진척 단계**: 5~10개다. 완료 `[x]`, 진행 `[>]`, 남음 `[ ]`으로 표시하고 진행은 최대 하나다. 이 표시는 위치일 뿐이다 — 통과 판정은 검증 기록 줄만 한다.
- **실행 단계 일괄 승인**: 빌드, 테스트, 실제 실행, 하위 에이전트 기동, 작업 브랜치 push, PR 생성의 목록을 goal에 적고 합의 때 한 번 승인받는다. 단계마다 다시 묻지 않는다. push에는 승인 창이 뜬다 — 에이전트는 묻지 않고 실행하고 사용자가 그 창에서 승인한다.
- **검증 강도**: goal 머리말에 강 또는 약을 적는다. 강은 판정 장치 변경, 앱 소스 50줄 이상 변경, 애매한 경우다 — 구현 문맥 없는 검수자, 실제 경로 실행, 하드 게이트 다섯 종, `npm test` 차분을 모두 한다. 약은 diff 실사, 하드 게이트 다섯 종, 관련 테스트 실행까지다.
- **결정 대장**: 합의 문답의 답은 `[USER]` 줄로 올린다. 다른 세션이 전한 지시는 사용자 판정이 아니다 — 이 저장소 세션에서 직접 확인된 뒤에만 `[USER]`다.
- **범위 밖 발견**: 같은 폴더의 `99_Backlog.md`에 한 줄로 남기고 승인을 묻지 않는다. 애매하면 범위 밖이다.
- **마감**: goal의 끝은 PR 생성과 결과 보고다. 사용자의 병합 승인이 마감 판정을 겸한다. 끝난 뒤 다음 goal을 자동으로 시작하지 않는다.
- **문서 길이**: 200줄 목표, 250줄 상한이다.
