## 목표

연습 저장소 `bass131/AgentDeck_Test`에서 작업 모드 화면만으로 마일스톤 M02를 끝까지 돈다. 메인 대화 안 브레인스토밍 → 대화 안 스펙 승인 → 목표 둘 이상 → 목표마다 CI(강 등급이면 검수) → 마일스톤 PR → 앱 병합 버튼이다. 도중에 앱을 한 번 껐다 켜도 메인 대화와 실행기가 멈춘 곳부터 이어 간다.

## 범위

- **만들 것**
  - 두 번째 마일스톤 준비(앱) — 지금은 실행 상태 파일이 있으면 시작을 거부하고, 옛 템플릿 해시의 상태는 열 때 막힌다(Backlog 20). 끝난 실행(`status: done`, 다이제스트 정상)은 새 마일스톤을 시작할 때 `.agentdeck/` 안의 보관 자리로 옮기고 새 실행을 연다. 템플릿 해시만 다른 끝난 실행은 막힘이 아니라 「끝난 실행 — 보관하고 새로 시작할 수 있어요」 안내로 본다. 끝나지 않은 실행·위조 상태의 기존 막힘과 래치는 그대로다.
  - 실주행 준비 — 사용자가 연습 저장소 전용 fine-grained 토큰을 한 번 만들어 저장소 밖 파일(`%USERPROFILE%\.agentdeck-practice\gh-token.txt`)에 둔다(사람 몫, 권한 목록은 메인이 적는다). e2e 구동기는 `G5_TOKEN_FILE`이 있으면 그 토큰을 앱 프로세스에만 `GH_TOKEN`과 git 자격 도우미(`gh auth git-credential`)로 넣는다 — 전역 gh 로그인은 그대로다. 메인은 연습 저장소 clone을 `main`(M01 병합 `7179924c` 뒤)으로 맞춘다.
  - 실주행 — 앱 빌드본을 2번 모니터에 띄우고 e2e 구동기(`m09-g5-practice-run.e2e.ts`)로 사람 몫(브레인스토밍 답, 스펙 승인, 병합 버튼)을 대행한다(5회차 [USER·위임]). 연습 과제는 M01의 링크 검사기에 작은 기능 둘(예: JSON 출력, 무시 패턴) — 브레인스토밍에서 메인이 정하고, `npm run build`·`npm test`와 `hard-gates`를 스펙에 넣는다.
  - 재개 실측 — 목표 진행 도중 앱을 한 번 껐다 켜서 메인 대화(이어 쓰기)와 실행기(멈춘 노드)가 이어 가는지 본다.
  - 알림 실관찰 — 바로 알릴 사건 한 번 이상(Windows 알림과 앱 안 표시, 누르면 그 폴더 작업 모드)과 병합 대기의 앱 안 표시를 본다(Backlog 17). 자연히 생기지 않으면 자동 모드 확인 막힘을 일부러 만들어 본다.
  - 장면 캡처 — 시안의 장면 여덟(채팅 모드, 브레인스토밍, 목표 진행, 사람 부름, 노드 세션, 그래프 탭, 파일·변경, 병합 대기)을 실제 화면으로 찍는다(마일스톤 결과 보고용).
  - 완주를 막는 범위 안 결함의 수정 — 앱 소스와 시험. 무관한 발견은 Backlog 한 줄.
  - 완주 기록 — 목표·PR 번호, 사람 개입 횟수, 예외 호출의 횟수와 이유.
- **건드릴 곳**: `02_Project/00_Source/`(실행기 상태 보관과 완주를 막는 결함만), `02_Project/01_TestCode/`(시험, 수집 기준선, e2e 구동기), `01_Milestones/M10_LoopView/`. 판정 장치 변경 없음(1단계 `gate-config.json` 전환만). 연습 저장소는 앱 실행기가 승인 목록 안에서만 쓴다(clone 맞추기는 메인).
- **하지 않을 것**: 연습 저장소 `main` 병합의 사람 몫 밖 대행(병합 버튼 한 번만), 두 저장소의 설정·룰셋 변경, 메인이 연습 저장소에 직접 push·PR, 토큰 값을 채팅·저장소 파일·로그에 남기기, 전역 gh·git 자격 바꾸기, 사용량 한도(M11), 그래프 편집, 워크트리, 로컬 현황판 변경.
- **완료조건**
  - 끝난 실행이 있는 저장소에서 새 마일스톤을 시작하면 옛 실행이 보관되고 새 실행이 열린다. 옛 해시의 끝난 실행은 막힘이 아니다. 끝나지 않은 실행·위조 상태는 지금처럼 막힌다(시험).
  - 연습 저장소에서 위 경로로 M02를 작업 모드 화면만으로 완주했다. 사람 개입은 브레인스토밍 답, 승인 한 번, 병합 한 번이다(예외는 횟수와 이유).
  - 도중 재기동 한 번 뒤 메인 대화와 실행기가 멈춘 곳부터 이어 갔다(실측).
  - 바로 알릴 사건의 Windows 알림과 앱 안 표시, 병합 대기의 앱 안 표시를 실주행에서 한 번 이상 봤다(실측).
  - 장면 여덟의 캡처가 있다.
  - 하드 게이트 다섯 종 exit 0, `npm test` 실패 0, 독립 검수 반영, goal PR의 `hard-gates` 통과, 정형 절차로 병합. 실주행 내내 전역 gh 로그인은 바뀌지 않았다.
