## 목표

단일 패널과 멀티 패널이 따로 구현한 실행 로직(전송·중단·권한·질문 응답·stale 감시)을 세션 포트 하나로 합치고, 그 위에서 단일·멀티로 복제된 UI(스레드 렌더, 선택기, 입력 팔레트, 입력창)를 합친다. 갈라진 동작은 기능이 더 완전한 쪽으로 맞춘다.

## 범위

- **만들 것**
  - 2단계 재실측이 적는 「차이 목록」 — 단일과 멀티가 다르게 동작하는 항목마다 위치 쌍, 지금 동작 둘, 맞출 쪽, 그 근거.
  - 세션 포트: `03_Agent/state/runtime.ts`(단일)와 `03_Agent/state/panelSession.ts`(멀티)의 전송·중단·권한 응답·질문 응답·stale 감시를 한 인터페이스로 합친다. 같은 상태가 전역 store, `bgRuns`, panelSession 모듈 전역 Map에 나뉘어 사는 것을 한 원천으로 모은다.
  - UI 통합: `Conversation.tsx`⇄`PanelView.tsx` 스레드 렌더, `ComposerPicker`⇄`PanelPicker`, 단일 쪽 팔레트 훅 셋⇄`useInputPalettes.ts`, `Composer`⇄`PanelComposer`를 각각 하나로 합친다.
  - 차이 목록의 각 항목에 테스트를 붙인다(새 동작을 고정하는 테스트가 먼저, 구현이 뒤 — TDD).
- **건드릴 곳**: `renderer/src/03_Agent`, `05_Conversation`, `06_Sessions`, `12_Window`(Sidebar·Shell·MultiWorkspace의 `'multi'/'single'` 분기), 대응 테스트.
- **하지 않을 것**: 새 기능, IPC 계약 변경(G10), main 쪽 변경(G11), CSS 규칙 변경(통합으로 안 쓰게 된 사본 CSS의 삭제는 제외), 화면 배치 자체(단일 Shell·멀티 그리드)의 통합, 판정 장치 변경.
- **완료조건**
  - `'multi'/'single'` 분기가 화면 배치(`12_Window`) 밖에 남지 않는다.
  - 차이 목록의 각 항목에 테스트가 있고 통과한다.
  - 사본으로 확인된 위치 쌍(위 UI 넷, 실행 다섯)이 각각 한 구현으로 줄었다.
  - 하드 게이트 다섯 종 exit 0, `npm test` 실패 0. 테스트 수의 변화는 `collection-baseline.test.ts`에 사유와 함께 반영된다.
  - 화면: 다섯 스크린샷 하네스 39건 통과. PNG가 바뀐 장은 차이 목록 항목으로 설명되고, 설명되지 않는 변화는 0이다.
