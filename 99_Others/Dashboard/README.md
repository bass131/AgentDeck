# AgentDeck 현황판

AgentDeck 저장소에서 지금 어떤 작업이 어디까지 왔는지를 한 화면에서 보는 **읽기 전용** 로컬 현황판이다.
Node 로컬 서버가 저장소 파일과 읽기 전용 git 명령을 읽고, 변경을 열린 화면에 SSE로 보낸다.
npm 의존성은 없다. Node 내장 모듈만 쓰며 Windows의 Node 24.15.0에서 확인했다.
구조와 시각 언어는 `C:\Dev\Second_Brain_Dashboard`(본보기)를 따른다. 색의 뜻과 토큰은 본보기 `design/DESIGN.md` 3·4절과 같다.
원래 별도 저장소(`C:\Dev\AgentDeck_Dashboard`)였고, 2026-11-15 M05 H3에서 커밋 이력째 이 폴더로 편입했다.

## Orca에서 열기

```powershell
Set-Location C:\Dev\AgentDeck\99_Others\Dashboard
node open-in-orca.mjs
```

서버가 없으면 창 없이 백그라운드로 시작하고, 준비되면 AgentDeck 작업 공간에 Orca 내부 브라우저 탭을 연다.
같은 URL의 탭이 있으면 새로 만들지 않는다. Orca 자체는 실행돼 있어야 한다.
이미 서버가 떠 있으면 탭만 여는 명령은 다음과 같다.

```powershell
orca tab create --url http://127.0.0.1:4319 --worktree path:C:/Dev/AgentDeck --json
```

전경 실행도 된다. `node server.mjs`로 띄우고 `http://127.0.0.1:4319/`에 접속한다. Ctrl+C로 끝낸다.

## 설정

`config.example.json`을 `config.local.json`으로 복사하고 값을 바꾼다. `config.local.json`은 개인 파일이라 `.gitignore`에 넣었다.

| 설정 | 의미 |
|---|---|
| `repoPath` | AgentDeck 저장소 절대경로. 현재 `C:/Dev/AgentDeck` |
| `port` | 루프백 포트. 4319 (본보기 Second Brain 현황판은 4318) |

설정을 바꾸면 서버를 다시 시작한다. `node server.mjs C:/경로/별도설정.json`도 된다.
판정 기준(FAIL 한도 3, hook-log 꼬리 크기 등)은 `lib/markdown.mjs`의 `RULES` 코드 상수다.

## 화면 구성 (2026-11-14 개편)

화면 맨 위는 세 질문에 한 줄씩 답한다. 아래로 갈수록 확인용 원문이다. 배치를 정한 연구는 `docs/배치-연구.md`에 있다.

1. **지금** — 세 줄의 답이다. 왼쪽은 질문, 오른쪽은 답이고, 좁은 폭에서는 질문이 답 위로 간다.
   - **지금 하는 일** — 「G9c 3단계 「구현 1」 진행 중」처럼 goal 번호와 지금 단계의 짧은 이름. 그 아래에 자동 검사 기록으로 본 최근 활동(「하위 에이전트가 코드를 읽고 있어요」)과 근거 줄이 있다.
   - **내 손이 필요한 일** — 병합 승인, 멈춘 단계, 질문, 결정 기록 게이트, 답을 기다리는 명령 승인. 없으면 「없음」이다. 알아 두면 좋은 사실(실패 1~2번, 10분 안에 막힌 검사, 읽지 못한 원문)은 그 아래 작은 줄이고, 인수인계 메모에 「사용자 몫」으로 적힌 정리 일은 접어 둔다.
   - **전체 중 어디쯤** — 마일스톤 이름, 「goal 16개 중 12개 완료, 지금 G9c, 남은 goal 3개」, goal 칩 줄(완료=초록 바탕과 PR 번호, 지금=파랑 채움, 남음=점선).
2. **G9c의 단계** — goal 이름, 검증 기록 한 줄(이 화면에서 기록 수는 여기에만 있다), 단계 목록. 단계는 짧은 이름만 보이고 눌러서 원문 줄을 펼친다.
3. **자동 검사 기록** — 검사가 막은 작업을 이유 문장과 함께 먼저 모으고, 그 아래 최근 흐름을 최신순으로 둔다. 세션 고르기와 「통과는 숨기기」가 있다.
4. **브랜치와 커밋** — AgentDeck의 현재 브랜치, 최근 커밋 제목, 원격과의 차이, 커밋하지 않은 파일 수. 파일 목록은 접혀 있다.
5. **원문과 참고** — 인수인계 메모(work-pin), 결정 기록(결정 대장), 미룬 일(Backlog), 마일스톤 목록, 원문을 읽은 상태. 기본은 접힘이고 펼친 상태는 브라우저에 기억한다.

폭은 현황판 영역 폭으로 판정한다. 1100px 이상은 2열, 그 아래는 1열, 720px 아래는 질문을 답 위에 두고 간격을 줄인다.
상태는 색과 모양과 글자를 함께 쓴다: 완료=초록 채운 원, 진행 중=파랑 고리, 남음=회색 점선 고리, 멈춤·막음=빨강 네모, 할 일·주의=노랑 세모.
자판은 `1`~`5` 영역 이동, `t` 밝기 바꾸기, `o` 원문 모두 펼치기·접기다. 「지금」이 화면 밖으로 나가면 상단 띠에 「지금 하는 일」 한 줄이 고정된다.

### 세 질문의 판정 (`lib/progress.mjs`)

문장은 짓지 않는다. 원문 글자를 규칙으로 줄이거나, 고정 문구에 원문 값을 넣는다. 원문으로 정할 수 없으면 「정하지 못했어요」와 이유를 보인다.

- **짧은 이름 (`shortName`)** — 「 — 」(앞뒤 공백 있는 줄표) 앞부분이다. 없으면 괄호·백틱 안을 덜어낸 글이고, 32자를 넘으면 첫 쉼표 앞 + 「외 N가지」다. 원문은 단계 줄을 펼치면 그대로 있다.
- **지금 하는 일 (`doingLine`)** — goal 제목 `M05 G9c — …`의 번호와, 진척 단계의 첫 `[>]` 항목. `[>]`가 없으면 「k단계까지 마쳤고 n단계 시작 전」, 「모두 마쳤어요」, 「종결됐어요」로 말한다.
- **최근 활동 (`summarizeActivity`)** — hook-log 꼬리에서 마지막 「응답 마침」(Stop) 뒤의 활동 8건을 고정 규칙으로 분류해 가장 많은 종류를 고른다(같으면 더 최근 것). 명령은 `cmd-guard`의 `cmd` 첫 실제 명령(`cd`·변수 대입은 건너뜀)으로 코드 읽기·테스트·빌드·커밋·원격·Orca·기타로 나누고, 파일 수정은 `edit-plan-gate`의 Edit·Write, 마침은 `surface-probe`의 Stop이다. `agent_id` 칸이 있으면 값이 있을 때 「하위 에이전트가」, null이면 「메인 세션이」를 붙이고, 칸이 없으면 누가 했는지 말하지 않는다. 마지막 활동이 10분보다 오래되면 화면 시계가 「마지막 활동은 N분 전이에요」로 바꾼다.
- **내 손이 필요한 일 (`judgeHand`)** — 머리말 「상태: 병합 대기」(PR 번호가 있으면 함께), 지금 단계 이름에 「병합 승인」, 마지막 검증 기록이 USER-INPUT, 실패 3번으로 멈춘 단계, 결정 대장 주도권 게이트 발동, 같은 세션에 그 뒤 기록이 없는 `cmd-guard` `ask`(10분 안만). 멈춤 둘은 빨강, 나머지는 노랑이다.
- **goal 목록 (`buildGoalList`)** — 현재 goal 폴더에서 제목이 `M숫자 G번호 — 이름`이고 머리말에 「상태:」가 있는 문서를 파일 이름 순서로 읽는다. 상태가 없는 같은 꼴의 제목(차이 목록·재실측 같은 부속 문서)은 goal이 아니다.
  아직 파일이 없는 goal은 같은 폴더 문서의 「## … goal 목록」 절에 있는 `### G10 — 이름` 머리에서 읽는다. 계획의 `G9`는 파일 `G9a`·`G9b`가 있으면 이미 있는 것으로 보고, `G1`이 `G10`을 덮지는 않는다.
  「상태: 종결」은 완료, 「실행 중」·「병합 대기」는 진행, 「초안」은 초안, 그 밖은 상태 미확인이다. PR 번호는 상태 글의 `PR 숫자`다. 다중 파일 형식의 옛 마일스톤에는 goal 목록이 없고 단계 수로만 말한다.

### 사람 문장의 판독 규칙

다중 파일 형식의 단계 문장에 쓴다. 문장은 만들지 않는다. LLM 호출도 없다. 아래 순서로 원문에 있는 문장만 쓴다.

1. 현재 계획 폴더(gate-config `planPath`가 있는 폴더)의 `00_현황판-문장.md`. 절 제목이 대상이고 `- 이름: 문장` 줄이 값이다.
   `## 마일스톤`은 `한 줄`·`목표`·`끝나면`, `## Phase N`은 `이름`·`진행 중`·`목표`·`완료`·`시작 전 필요`를 읽는다.
   다른 절, 다른 이름의 줄은 읽지 않고, 같은 이름이 두 번이면 첫 줄만 쓴다.
2. 이 파일이 없거나 `## 마일스톤` 절에 `한 줄`이 없으면, 계획 문서 `## 사람용 개요` 절의 첫 문단을 문장으로 나눠 머리에 쓴다(「계획 문서의 사람용 개요」 표시).
3. 그것도 없으면 계획 문서의 제목·표의 이름·목표를 그대로 보인다(짧은 이름 규칙을 거친다).

`시작 전 필요`는 노랑 「사용자가 할 일」로 강조한다. 대기 단계와, 검증 기록 줄이 아직 없는 진행 중 단계에서 보인다.
긴 문단(인수인계 메모의 좌표·마감 요약)은 `splitSentences`가 문장 끝(`.`·`?`·`!` 뒤 공백)에서 나눈다.
백틱·괄호·낫표·대괄호 안과 `1. ` 같은 번호 뒤에서는 나누지 않고, 글자는 버리지 않는다.

### 계획 문서의 두 형식

계획 문서는 두 가지 형식이 있다. 현황판은 계획 문서의 파일 이름으로 형식을 가른다.

- **goal 한 장** — 파일 이름이 `_MilestonePreview.md`가 아니면 이 형식이다. M04부터 기본이다. 문서 한 장에 Phase 절이 하나 있다.
- **다중 파일** — 파일 이름이 `_MilestonePreview.md`면 이 형식이다. M01부터 M03까지 썼다. 같은 폴더의 `NN_Phase_N.md`를 함께 읽는다.

AgentDeck의 goal 템플릿(`00_Documents/02_Rules/04_Goal-한장-템플릿.md`)도 같은 기준으로 두 형식을 가른다.

### goal 한 장의 단계 판정 (`judgeGoal`)

Phase 절 안의 「진척 단계」 목록에서 항목 하나가 단계 하나다. 값은 목록의 표시, 검증 기록 줄 수, 머리말의 「상태:」에서만 온다.

1. `[x]`는 완료, `[>]`는 진행 중, `[ ]`는 대기다. 그 밖의 표시는 대기로 보고 「원문 보기」에 알린다.
2. 지금 단계는 첫 `[>]` 항목이다. 다음은 첫 `[ ]` 항목이다. 항목 번호는 문서에 적힌 글자를 그대로 쓴다(예: `3b`).
3. `[>]`가 없어도 읽기 실패가 아니다. 문서에 적힌 대로 「n단계 중 첫 단계 전」, 「n단계 중 k단계까지 완료」, 「모두 완료」로 말한다.
4. 검증 기록은 goal 전체에 하나다. 「(기록 없음)」처럼 마커가 없는 줄은 세지 않고, 그러면 「검증 기록이 아직 없습니다」로 보인다.
5. 마지막 USER-INPUT 이후 FAIL이 3 이상이면 지금 단계가 멈춤이다. 지금 단계가 없으면 다음 단계가 멈춤이다.
6. 그 FAIL이 1이나 2면 주의다. 마지막 기록 줄이 USER-INPUT이어도 주의다. 이 줄은 질문을 적은 줄일 수도, 받은 답을 적은 줄일 수도 있어서, 그 줄의 글을 함께 보인다.
7. 머리말이 「상태: 종결」이면 종결로 보이고, 멈춤과 주의를 단계로 판정하지 않는다.

### 다중 파일의 단계 흐름 판정 (`judgeFlow`)

값은 검증 기록 줄 수, 최근 커밋 200개의 제목, 인수인계 메모의 「상태」 문장에서만 온다. 퍼센트 진행률은 없다.

1. **멈춤** — 마지막 USER-INPUT 이후 FAIL이 3 이상(헌법 7조). 다른 판정보다 먼저다.
2. **근거 ① 커밋** — 커밋 제목에 `<마일스톤 번호>-P<N>` 토큰(대소문자 무시, 예: `feat(M03-P1): …`)이 있는 단계는 완료,
   그런 커밋이 없는 첫 단계가 진행 중, 그 뒤는 대기다. 마일스톤 번호는 계획 문서 제목 첫머리의 `M숫자`다.
3. **근거 ② 메모** — git을 읽지 못했거나 마일스톤 번호가 없으면 인수인계 메모 「상태」 문장의 `Phase N`이 진행 중이고 그 앞은 완료다.
   문장이 `Phase N 완료`(종료·마감·끝)면 그다음 단계를 진행 중으로 읽는다.
4. **근거 ③ 기록** — 둘 다 없으면 검증 기록 줄이 있는 마지막 단계가 진행 중이다(없으면 첫 단계).

근거 ①과 메모의 문장이 다른 단계를 가리키면 「기록이 서로 달라요」(점선 태그)로 알리고 커밋 기준으로 보인다.
어느 근거를 썼는지는 「작업 단계」 아래 설명 줄에 쓴다. 단계 중간에 같은 토큰으로 커밋하면 그 단계가 일찍 완료로 보인다(이 저장소는 단계마다 마감 커밋 하나를 쓴다).

### 훅 판정의 고정 사전 (`lib/phrases.mjs`)

훅 기록은 `훅|판정|규칙` → `훅|판정` 순서로 사전에서 문장과 단계(통과·알림·막음·기록)를 찾는다.
사전에 없는 값은 문장을 만들지 않고 `훅 · 판정 · 규칙`을 기록된 글자 그대로 보인다. 식별자는 문장 아래 작은 글씨로 남는다.
`deny`·`block`은 사전과 무관하게 「막음」이다. 이유 원문은 「원문 보기」 안에 있다(400자까지).
최근 흐름에서 같은 세션의 통과가 이어지면 「검사 N건을 통과했습니다」 한 줄로 묶고, 알림·막음·사전에 없는 판정은 한 줄씩 둔다.
세션은 `session` 값의 앞 네 글자와 세션마다 다른 색 조각으로 가르고, `agent_id`가 있는 줄은 「하위」를 붙인다.

### 디자인 근거와 참고한 패턴

시각 언어(색의 뜻, 토큰, 글꼴, 움직임 원칙)는 사용자가 승인한 `C:\Dev\Second_Brain_Dashboard\design\DESIGN.md`를 따른다.
영역 머리의 영문 대문자는 내리고 한국어 제목만 남겼다. 좁은 폭에서 한국어 본문을 먼저 읽게 하려는 것이고, 본보기와 다른 점이다.
구성·상호작용은 아래 공개 자료의 패턴을 참고해 직접 구현했다. 코드와 에셋은 가져오지 않았다.

- GitLab Pajamas 「Mini pipeline graph」 — 단계 상태를 아이콘 줄로 압축하고 전체 상태는 따로 배지로 둔다 → goal 칩 줄.
- Tekton Dashboard 로그 보기 — 진행 중인 것만 펼치고 나머지는 접으며 접기 상태를 유지한다 → 「원문 보기」와 기억되는 접기 상태.
- openstatus 「Four iterations of an incident timeline」 — 최신순, 중요한 사건은 카드, 시스템 사건은 한 줄 → 막은 검사 카드와 묶인 통과 줄.

움직임은 실제 사건에만 묶는다: 값이 바뀐 항목의 파랑 변경 선, 바뀐 영역의 머리 선, 단계 상태가 바뀐 표시의 한 번 튐, 접기를 펼칠 때의 내려앉음.
같은 내용이면 영역을 다시 쓰지 않으므로 훅 기록이 초마다 들어와도 다른 영역은 깜빡이지 않는다. `prefers-reduced-motion`이면 모두 끈다.

## 수집 블록과 원문

모든 값은 저장소 파일과 읽기 전용 git 명령에서 읽는다. 진행률은 만들지 않는다.
아래는 수집 블록별 원문이다. 화면에서 3·4·7번과 1번의 pin 원문은 「원문과 참고」에 접혀 있다.

1. **현재 좌표** — `98_Management/01_GateState/gate-config.json`의 `planPath`·`workPinPath`를 따라간다.
   경로는 코드에 고정하지 않는다. 계획 문서의 `# ` 제목과 `- 마일스톤: … · 상태: …` 줄의 「상태:」 이후,
   pin의 「좌표」 절 줄들과 「마감 요약」 절(스탬프·바뀐 것·내린 결정·봐야 할 것)을 보인다.
   계획과 pin 포인터가 다른 폴더를 가리키면 점선 태그로 알린다.
2. **단계 흐름** — goal 한 장이면 그 문서의 「진척 단계」 목록과 Phase 절의 「검증 기록」을 읽는다.
   다중 파일이면 Preview 「Phase 흐름」 표의 이름·태그·목표와, 같은 폴더 `NN_Phase_N.md`의 Phase 절을 읽는다.
   Phase마다 「검증 기록」 아래 `- PASS`·`- FAIL`·`- USER-INPUT` 줄 수, 마지막 기록 줄, 마지막 USER-INPUT 이후 FAIL 수를 읽는다.
   그 수가 3 이상이면 멈춤이다. 줄 수는 단계 아래 작은 보조 표시와 「원문 보기」에만 나온다.
3. **결정 대장** — `- [USER]`·`- [USER·위임]`·`- [AI]`·`- [AI·비가역]` 줄 수, 주도권 게이트 판정, 남은 `[AI]` 줄 문면.
4. **마일스톤 목록** — `01_Milestones` 아래 폴더마다 `_MilestonePreview.md`의 상태 줄을 해석 없이 보인다.
5. **작업 사본** — 브랜치, HEAD 짧은 해시·제목, 미커밋·미추적 파일 목록, origin 대비 앞·뒤 커밋 수, 마지막 fetch 시각.
   비교 대상은 추적 브랜치 → 같은 이름의 `origin/<브랜치>` → `origin/HEAD`(기본 브랜치) 순서로 정하고, 어느 것인지 화면에 쓴다.
6. **훅 활동** — `98_Management/01_GateState/hook-log.jsonl`의 끝 512 KB에서 마지막 400줄만 읽는다.
   최근 120줄을 흐름으로 보이고, verdict가 `deny`·`block`인 줄을 「검사가 막은 작업」으로 따로 모은다. 세션별 줄 수·막음 수도 이 창에서 센다.
   잘렸을 수 있는 첫 줄은 버리고, JSON이 아닌 줄은 「읽지 못한 줄」로 센다.
7. **Backlog** — 현재 마일스톤 폴더에 `99_Backlog.md`가 있으면 `N. **제목**` 번호 줄의 굵은 제목을 절별로 보인다.
   파일이 없으면 실패가 아니라 「없음」(회색)이다. 이 블록만 원문 자체가 선택 사항이기 때문이다.

### plan-gate와 같은 판정식

결정 대장 집계와 검증 기록 집계는 plan-gate와 **같은 정규식**을 쓴다.
판정부는 M03 Phase 2에서 `.claude/hooks/_lib/plan-verdict.cjs`로 옮겨졌고, 시험은 훅 본체와 이 모듈을 함께 본다.
절은 `^##\s+`로 나누고, Preview 뒤에 `NN_Phase_N.md`를 번호순으로 이어 붙인 텍스트에서 판정한다.
「검증 기록」 절 머리는 `^검증 기록\s*$` 단독 줄뿐이고, 그 아래 Phase 절 끝까지를 센다.
`[USER·위임]`은 [USER] 쪽으로 세며, `[AI·비가역]`이 하나라도 있으면 「즉시 발동」, `[AI]` > [USER] 쪽이면 「문답 분기 발동」이다.
`test/drift.test.mjs`가 이 정규식들이 훅 원문에 글자 그대로 있는지 확인한다. 훅이 바뀌면 이 시험이 먼저 실패한다.

### 실패와 0건

파일이 없거나 읽기에 실패한 블록은 그 블록만 「수집 실패」(빨강, 경고 삼각형, 한국어 이유)로 그린다.
수 자리는 `null`이고 빗금으로 그려 0과 구별한다. 포인터를 못 읽으면 그에 기대는 블록도 「미확인」이 된다.
Phase 파일 하나를 못 읽으면 plan-gate처럼 Phase 흐름과 결정 대장이 함께 실패하지만, 마일스톤 이름은 Preview만 읽어 그대로 보인다.

## 실시간 연결

`GET /`는 화면, `GET /events`는 연결 직후와 변경 때 전체 `snapshot`과 15초 간격 `ping`을 보낸다.
감시는 저장소 전체를 재귀로 보되 `node_modules`와 `.git/objects`·`logs`·`hooks`·`lfs`는 거른다.
작업 사본 블록은 어떤 파일 변경에도 달라질 수 있어 확장자로 거르지 않는다.
변경은 180ms로 모으고, 변경이 끊이지 않아도 1.5초마다 한 번은 다시 수집한다.
감시를 시작하거나 유지하지 못하면 원천 오류로 표시하고 30초 간격 재수집으로 대체한다.
화면은 45초 무응답·연결 오류 때 3초 뒤 다시 연결하고, 30초 경과 또는 5회 실패 때 끊김 띠를 띄운다. 자동 재시도는 계속한다.
바뀐 항목은 직전 스냅샷과 키별로 비교해 왼쪽 파랑 변경 선으로 알린다. 글자 배지는 두지 않는다.

## 읽기 전용 보장

- 서버는 `127.0.0.1`에만 바인딩한다. GET·HEAD 밖의 요청은 405, 다른 Host는 403, 다른 Origin의 `/events`는 403이다.
- 저장소에 쓰는 API, 터미널로 텍스트를 넣는 API(본보기의 「답 보내기」), 임의 파일 열기 API는 없다.
- git은 `lib/git.mjs`의 목록(`rev-parse`·`log`·`status`·`rev-list`·`symbolic-ref`)만 셸 없이 실행한다.
  `--no-optional-locks`와 `GIT_OPTIONAL_LOCKS=0`으로 `git status`가 색인을 갱신해 쓰는 일도 막는다. `git fetch`는 하지 않는다.
- 화면에 넣는 원문 글은 모두 HTML 이스케이프하고, 굵게(`**`)와 인라인 코드(`` ` ``)만 살린다. CSP로 외부 스크립트·연결을 막는다.

## 로그·종료

로그와 PID 기록은 `%LOCALAPPDATA%\AgentDeckDashboard\`에만 둔다. 저장소 안이면 실행하지 않는다.
`server.log`는 백그라운드 서버 출력, `server.json`은 도우미가 시작한 프로세스의 PID와 주소다.
서버는 화면 생성물이나 수집 캐시를 디스크에 쓰지 않는다.
백그라운드 서버 종료는 기록된 PID가 이 현황판 프로세스인지 확인한 뒤 실행한다.

```powershell
$state = Get-Content "$env:LOCALAPPDATA\AgentDeckDashboard\server.json" -Raw | ConvertFrom-Json
$proc = Get-CimInstance Win32_Process -Filter "ProcessId=$($state.pid)"
if ($proc.Name -eq 'node.exe' -and $proc.CommandLine -like '*99_Others*Dashboard*server.mjs*') { Stop-Process -Id $state.pid }
```

## 본보기와 다른 점 · 남은 것

- 「답 보내기」와 페이지 토큰은 만들지 않았다. 쓰기 API가 없으므로 토큰도 필요 없다.
