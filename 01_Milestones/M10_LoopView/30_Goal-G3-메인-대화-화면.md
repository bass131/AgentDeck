# M10 G3 — 메인 대화 화면 · 작업 모드 가운데에 메인 대화가 보이고, 질문·승인 카드와 사건 줄이 대화 안에 뜬다

- 마일스톤: M10 (마일스톤 스펙 `01_Milestones/M10_LoopView/00_마일스톤-스펙.md`) · 작성: 2026-11-19 · 상태: 실행 중 · 검증 강도: 강(앱 소스 50줄 이상, 사람 판정 경계의 화면 쪽)
- 작업 브랜치: `feat/m10-g3-main-chat-view` · 기준 브랜치: `milestone/m10-loop-view`(`5e765317`, G2 병합 뒤).

## 목표

작업 모드의 가운데에 작업 폴더의 메인 대화가 보인다. 사람은 입력칸으로 말하고, 메인의 질문 카드와 스펙 승인 카드에 대화 안에서 답한다. 실행기 사건은 대화 흐름에 사건 줄로 끼고, 일시 정지와 새 메인 대화를 화면에서 다룬다. G2 엔진의 IPC(`loop.mainRead`·`mainSend`·`mainNew`·`mainState`)에 붙는다.

## 범위

- **만들 것**
  - 메인 대화 보기 — 작업 폴더를 받는 독립 컴포넌트(`13_Loop/` 아래). G4가 탭 하나로 그대로 올린다. 이번에는 작업 모드 몸체 가운데에 두고, 지금의 루프 화면은 옆의 좁은 열로 남긴다(G4가 현황판으로 바꾼다). 배치에 공을 들이지 않는다.
  - 대화 기록 그리기 — 사람 글(줄 섬·보냄), 메인 글(기존 `MarkdownView`), 사건 줄(종류별 모양), 알림(오류·저장 실패). 메인 깃발 사건(`flag-raised`·`flag-lowered`)은 사람의 이어 가기(`resumed`)와 눈에 띄게 다르게 그린다. 첫 읽기(`mainRead`)와 push(`mainState`)가 엇갈려도 낡은 보기로 되돌아가지 않는다.
  - 대화 안 카드 — 메인의 질문 카드(다시 묻는 카드 `restored` 표시)와 스펙 승인 카드(「스펙 승인 / 이어서 고치기」, 시안 장면 「브레인스토밍」)를 대화 흐름 안에 그린다. 카드에 답하는 곳은 한 곳뿐이다 — 메인 대화의 카드는 대화 안에서만 답하고 루프 화면에서는 뺀다. 승인 카드는 기존 승인 부품과 `decide` IPC(사람이 본 스펙 sha)를 그대로 쓴다.
  - 입력칸 — 글을 `loop.mainSend`로 보낸다. 실행기가 열려 있지 않으면 막고 까닭을 보인다. 메인이 도는 중(`mainBusy`)과 사람을 기다림(`mainWaiting`)을 보인다.
  - 일시 정지와 취소 — 깃발이 올라 있으면 대화 위에 표시와 「이어 가기」 버튼(사람이 깃발을 내리는 IPC, 판정 칸 없음). 「취소」는 대상(메인 턴 / 작업 세션)을 골라 보낸다(Backlog 9·12).
  - 새 메인 대화 — 확인을 한 번 받은 뒤 `loop.mainNew`.
  - 두 모드의 복원 — 작업 모드로 끈 뒤 다시 켜면 작업 모드와 그 작업 폴더로, 채팅 모드로 돌아가면 채팅의 마지막 대화로 뜬다(Backlog 6).
  - M09 실주행 구동기(`e2e/m09-g5-practice-run.e2e.ts`)의 선택자와 동작을 새 화면에 맞춘다(G6이 이 구동기를 쓴다).
- **건드릴 곳**: `02_Project/00_Source/renderer/src/`(`13_Loop/`, `12_Window/`, `00_App/`의 복원, 필요한 `05_Conversation/` 재사용 부품), main의 깃발 내리기·취소 대상 IPC(`main/01_Ipc/handlers/loop.ts`, `main/05_Loop/loopDriver.ts`), `shared/` IPC 계약, `02_Project/01_TestCode/`(시험, 수집 기준선, e2e 구동기), `01_Milestones/M10_LoopView/`. 판정 장치 변경 없음(1단계 `gate-config.json` 전환만).
- **하지 않을 것**: 작업 모드 배치(프로젝트 사이드바, 세션 탭, 오른쪽 현황판·「파일·변경」 탭 — G4), 그래프와 알림(G5), 연습 저장소 실주행(G6), 엔진 동작 변경(G2 범위 밖의 버그는 고치되 새 동작은 넣지 않음), 새 의존성.
- **완료조건**
  - 사람 판정은 사람만(화면 쪽): 승인·반려는 사람이 카드 버튼을 눌렀을 때만 `decide`로 가고, 메인 글(마크다운) 안의 어떤 내용도 그 길을 부르지 못한다. 깃발 내리기·취소 IPC는 판정 칸을 받지 않고 `USER-INPUT` 줄을 만들지 않으며 실행 상태를 바꾸지 않는다(시험).
  - 카드는 대화 안 한 곳에서만 답한다 — 같은 카드가 루프 화면에 다시 뜨지 않는다(시험).
  - 사건 줄이 종류별로 그려지고 깃발 사건이 사람의 이어 가기와 구별된다. 줄 섬·보냄·오류 알림·다시 묻는 카드가 보인다(시험).
  - 두 모드의 복원(시험).
  - 실제 앱(빌드본, 2번 모니터, 임시 userData)에서 작업 모드를 열면 메인 대화 화면이 가운데에 보이고, 열 수 있는 저장소에서 글 한 줄을 보내 메인의 답이 대화에 그려진다(캡처). 열 수 있는 저장소의 조건은 M09 구동기의 열기 경로를 따른다.
  - 하드 게이트 다섯 종 exit 0, `npm test` 실패 0, 독립 검수 반영, goal PR의 `hard-gates` 통과, 정형 절차로 병합.
