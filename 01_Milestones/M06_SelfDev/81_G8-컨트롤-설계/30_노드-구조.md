# 30 — 노드 구조와 공통 GUI

사용자 요청은 「각각 기능을 공통 GUI와 Node 단위로 삽입/삭제가 쉽게」다. 이 문서는 노드 하나의 모양, 노드가 사는 곳, 설정의 보호, GUI, 판정 순서를 정한다.

## 노드 하나의 모양

노드는 컨트롤 하나다. 모든 노드는 같은 여덟 칸을 갖는다.

| 칸 | 값 | 예 |
|---|---|---|
| 지점 | 세션 시작 · 도구 호출 전 · 도구 호출 후 · 턴 종료 · goal 전이 · 사람 버튼 | 위험 명령 가드는 「도구 호출 전(Bash)」 |
| 판정 주체 | 규칙 · 모델 · 사람 | 병합은 「사람」 |
| 결과 | 허용 · 질문 · 거부 · 통보 · 상태 전이 | 250줄 상한은 「통보」 |
| 보호 수준 | `20_위협-모델과-경계.md`의 L0~L3 | 저장소 훅은 L2 |
| 켜짐 | 켬 · 끔. 사용자만 바꾼다. 잠금 노드는 끌 수 없다 | |
| 실패 정책 | 노드가 오류를 내거나 시간을 넘길 때. 기본은 「막는다」 | |
| 시간 상한 | 초 단위. 반드시 적는다 | |
| 기록 | 판정마다 한 줄. 시각, 노드, 입력 요약, 결과, 사유 | 지금 hook-log와 같은 역할 |

- 「goal 전이」는 goal의 상태가 바뀌는 순간이다. 합의, PR 생성, 병합, 마감이 여기 든다.
- 실패 정책과 시간 상한이 필수인 이유: SDK 훅 콜백은 던지거나 잘못된 출력을 내면 기본이 `'continue'`(경고 뒤 진행)다. 공개 타입의 `onFailure: 'block'`을 노드마다 명시해야 열린 실패가 생기지 않는다(`sdk.d.ts` 1046~1056행). 가드의 시간 초과 통과(`10` 발견 2)와 같은 구멍을 앱 노드가 다시 만들지 않기 위해서다.

## 노드의 세 종류

넣고 빼기 쉬워야 하는 정도가 종류마다 다르다.

| 종류 | 만드는 법 | 넣고 빼는 사람 | 예 |
|---|---|---|---|
| 코드 노드 | 앱 소스에 노드 파일 하나와 등록 한 줄 | 개발 goal(코드 변경) | 병합 버튼, 루프 진입, 엔진·설정 쓰기 거부 |
| 규칙 노드 | GUI에서 행 추가. 도구 이름, 명령 패턴, 결과(허용·질문·거부) | 사용자(GUI) | 「`terraform apply`는 질문」 |
| 문장 노드 | GUI에서 문장 추가. 분류기가 읽는 자연어 규칙 | 사용자(GUI) | 「운영 DB에 쓰는 명령은 막는다」 |

- **잠금 노드**: 자기 자신을 지키는 컨트롤은 GUI로 지울 수 없게 앱 코드에 내장한다. 병합 거부, 엔진·설정 쓰기 거부가 여기 든다. 규칙 노드로 두면 지켜야 할 설정 파일 안에 자기를 지키는 규칙이 들어가 버린다.
- **규칙 노드의 집행**: 허용·거부는 SDK 인라인 설정(앱이 세션을 열 때 코드로 넘기는 설정 객체)의 `permissions.allow`·`deny`로 넣는다. 질문은 앱의 PreToolUse 콜백이 `ask`를 내는 방식으로 넣는다. G3 실측에서 훅의 `ask`는 모든 모드에서 규칙 제안 없이 와서 카드가 됐다. 인라인 `permissions.ask`는 규칙 제안을 달고 올 수 있다. 그러면 앱 `자동`·`Bypass`에서는 권한 콜백 169행이 카드 없이 허용한다. 이것은 실측 항목이다(`50`).
- **문장 노드의 집행**: 인라인 설정의 `autoMode`(`environment`·`allow`·`soft_deny`·`hard_deny`)로 넣는다. 각 목록의 맨 앞에는 글자 `"$defaults"`를 고정하고 GUI에서 뺄 수 없게 한다. 이것이 없으면 사용자 문장 하나가 그 목록의 내장 규칙 전체를 대체한다(공개 타입 `sdk.d.ts` 10080~10101행, 공식 문서 auto-mode-config).
- **코드 노드의 자리**: SDK `hooks` 옵션(함수로 넘기는 PreToolUse 콜백)과 `canUseTool` 콜백이다. 공식 문서는 호스트가 모든 호출을 보려면 PreToolUse 훅을 쓰라고 권한다(https://code.claude.com/docs/en/agent-sdk/permissions).

## 노드가 사는 곳 — 저장소 노드와 앱 노드

| 구분 | 거처 | 보호 수준 | 쓰임 |
|---|---|---|---|
| 저장소 노드 | `.claude/hooks/`, `.claude/settings.json` | L2~L3 | 저장소를 따라다닌다. CLI 세션과 앱 세션 모두에 걸린다 |
| 앱 노드 | 앱 소스(코드 노드)와 앱 설정 파일(규칙·문장 노드) | L1 | 앱 세션에만 걸린다 |

- 앱 노드가 L1이려면 전제 둘이 필요하다. 앱 실행 트리가 작업 트리와 나뉘어 있어야 한다(설치본, 또는 G6처럼 빌드본을 따로 띄움). 그리고 아래 「보호」가 엔진 경로까지 막아야 한다.
- 저장소 노드를 없애지 않는다. CLI로 일할 때도 같은 실수 방지가 필요하다.
- GUI는 저장소 노드도 목록에 보인다. 켜고 끄는 것은 앱 노드만 한다. 저장소 노드를 바꾸는 일은 헌법 3조대로 계획 문서의 단계로만 한다.

## 보호 — 노드 설정과 엔진

노드 설정 자체도 컨트롤이다. 에이전트가 설정 파일이나 엔진 코드를 바꾸면 나머지가 무의미해진다.

1. **보호 대상**: userData의 `controls.json`, `engine-config.json`, `engines/` 폴더.
2. **파일 도구 차단**: 인라인 설정에 `permissions.blockWritesOutsideWorkingDirectories: true`를 넣는다. 작업 폴더 밖으로의 Write·Edit·NotebookEdit를 모든 모드에서 거부하는 공개 옵션이다(`sdk.d.ts` 7498행). 보호 대상 경로에 대한 `permissions.deny`도 함께 넣는다.
3. **Bash 차단**: 잠금 코드 노드가 보호 대상 경로 글자가 든 Bash 명령을 거부한다. L3이라 실수만 막는다.
4. **바뀜 감지와 닫힌 실패**: GUI로 저장할 때 앱이 설정과 엔진 설정의 해시를 함께 적는다. 실행을 열 때 파일이 없거나 해시가 다르면 실행을 열지 않는다. 대신 「GUI 밖에서 바뀜」을 보이고, 사용자가 GUI에서 확인할 때까지 기다린다. 첫 실행과 파일 삭제를 구분하기 위해 「처음 설정함」 표시는 해시와 함께 둔다.
5. **엔진 교체 확인**: 활성 엔진 버전이 바뀌면 사람이 GUI에서 확인해야 다음 실행에 쓴다.
6. **CLI 세션**: 위 2·3은 앱 세션에만 걸린다. CLI 세션의 에이전트는 `Bash(node *)` 허용으로 userData를 질문 없이 쓸 수 있다. 저장소 `settings.json`에 보호 대상 경로의 거부 규칙을 더하는 일은 판정 장치 변경이라 이행 goal의 단계로 둔다(`60`).

이렇게 해도 L1이다. 되돌리기 어려운 행위를 이 보호에만 맡기지 않는 이유다(`40`).
G6처럼 빈 임시 userData로 띄우는 실주행에서는 사용자 노드가 없다. 실주행용 설정 내보내기·가져오기를 GUI에 둔다.

## 공통 GUI — 「컨트롤」 패널

- **목록**: 지점별로 묶는다. 행마다 이름, 판정 주체, 보호 수준 배지, 켜짐 토글, 최근 판정 수를 보인다. 저장소 노드의 토글은 잠겨 있고 「계획 단계로만 변경」이라고 보인다. 잠금 노드의 토글도 잠겨 있다.
- **상세**: 노드를 누르면 매개변수와 최근 판정 기록을 보인다. 규칙·문장 노드는 여기서 행을 추가하고 지운다.
- **문맥 버튼**: 사람이 판정하는 노드는 그 순간의 화면에도 버튼으로 나온다. PR 카드(앱이 PR 생성을 감지해 대화에 띄우는 카드)에 「병합」, 합의 질문에 「합의」·「고쳐서 다시」가 나온다.
- **바뀜 경고**: 보호 4의 감지가 걸리면 패널 맨 위에 경고를 띄운다.
- **반영 시점**: 토글과 행 변경은 다음 실행부터 반영한다. 실행 하나가 자율 턴으로 길게 이어질 수 있으므로, 실행 중에도 공개 API `applyFlagSettings`(`sdk.d.ts` 3134행, 실행 중 설정 병합)로 반영할 수 있는지 실측한다.

## 판정 순서

공식 SDK 평가 순서는 훅 → 거부 규칙 → 질문 규칙 → 모드 → 허용 규칙 → `canUseTool` 콜백이다(https://code.claude.com/docs/en/agent-sdk/permissions).

- 앱 코드 노드는 SDK `hooks` 콜백과 `canUseTool`에 들어간다. 저장소 훅은 SDK가 `settingSources`로 읽어 함께 돈다.
- 훅끼리의 우선순위는 「deny > defer > ask > allow」다(공식 hooks 문서). `defer`는 판정을 다음 단계로 넘기는 결과다. 노드 하나라도 거부하면 거부다.
- `auto` 모드의 분류기는 「모드」 자리에서 돈다. 공개 타입은 `auto`를 「모델 분류기가 호출마다 승인하거나 거부하고, 정하지 못하면 `canUseTool`로 묻는다」고 적는다(`sdk.d.ts` 2123행). 그래서 분류기가 정하지 못한 호출이 권한 콜백에 오고, 지금 169행은 그것을 허용한다. 이 분기의 의미를 다시 정하는 일이 `50`의 실측 2다.
